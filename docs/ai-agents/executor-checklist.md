# 実装役チェックリスト（executor-checklist）

> この文書は何か（専門用語なしの1行）:
> 実装役（CC・codex等）が便の作業前・commit前・PR前に必ず確認する共通チェックの正本。
> CLAUDE.md / AGENTS.md から参照される唯一の本文（ここ以外に複製しない）。

## §0 共通（全便で必ず）
- 1便1目的。指示に無い作業・宿題の混載をしない。複数の宿題が来たら停止して分割を求める。
- 指示に無いオプションは足さない・引かない（例: --draft を勝手に付けない）。迷ったら停止して確認。
- PR本文の「触るファイル」「削除するファイル」欄は機械が読む帳票。平打ち
  （行頭の-・空白・バッククォート・注記なしの素のパスのみ）。美観の整形は違反。
  良い例: docs/specs/foo/README.md ／ 悪い例: - `docs/specs/foo/README.md`（変更）
- 「削除するファイル」は git diff の実測で判定（削除・変更行のあるファイルを列挙。無ければ「なし」。推測・水増し・過少をしない）。
- 報告は指定された宛先へ全文（「報告する」=完了報告の本文に生出力を全文含める）。要約・判定を混ぜない。
- 完了報告に、指示の全項目の消化○×自己チェックを必ず添える。
- track-record の未記帳行があれば本便に相乗りして記帳する（design-partner.md §6）。
- ブロッカーは回避せず停止して報告。環境系FAIL（認証・ネットワーク等）のみ、1回だけ再試行してから報告。

## §1 調査便（recon）のとき
- 読み取り専用。編集は成果物（recon.md等）と台帳類のみ。
- 事実のみ・file:line必須・コマンド生出力をそのまま貼る。評価・提案・感想を書かない。
- 実測時の origin/main SHA を成果物冒頭に併記する。

## §2 実装便のとき
- 変更は指示に埋め込まれた「最終形の全文」をそのまま入れる。要約・改変・「改善」をしない。
- アンカーは行番号でなく本文テキスト。挿入前に同一見出し・同一番号・同一行の重複が無いか確認。
- 編集後、commit前に重複検査（表の行・見出しの二重を機械的に確認）。
- 正本・統治ファイル（docs/STANDARD-WORKFLOW.md／CLAUDE.md／AGENTS.md／design-partner.md等）に触れる便は
  危険ファイル変更PRとして扱い、欄の平打ちとPO GOを必ず踏む。
