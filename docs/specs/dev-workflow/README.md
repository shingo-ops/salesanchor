# 設計仕様書：本店リポジトリと作業名簿の運用（あるべき姿）

## 0. この文書の位置づけ

これは「現状がどうか」ではなく「こうあるべき」を定めた正本です（STANDARD-WORKFLOW §1.5 設計仕様書）。
この運用を直すときは、現状に合わせず、この理想形へ近づける方向で設計する。

## 1. 一言でいうと

本店は「受付」に徹する。工作机にしない。作業は必ず別室でやる。作業名簿は今の場所のまま動かさない。

## 2. 登場人物（言葉の定義）

| 呼び方 | 正体 | 役割 |
|---|---|---|
| 本店 | メインのリポジトリ | 受付。名簿を置き、別室を作り出す場所。ここで開発しない |
| 別室 | worktree | 実際に開発する個室。机ごとに独立 |
| 作業名簿 | .claude-pipeline/active-work.md | いまどの別室が動いているかの一覧。みんなで使う公式記録 |
| 関所 | pre-push / CI のチェック | 規約違反の push や PR を機械的に止める番人 |

## 3. あるべき姿（守るべき4原則）

- 原則A：本店は常に受付（main）に座っている。本店の中で開発・編集・commit をしない。本店の仕事は「名簿を見る」「別室を作る」だけ。
- 原則B：すべての作業は別室で、正規の道具で作る。別室は必ず scripts/new-worktree.sh で作る。手作りの別室は禁止（名簿登録が抜けて混戦の種になる）。
- 原則C：作業名簿は今の場所のまま、動かさない。名簿には自動ロボット（CI）と多数の参照がぶら下がっている。動かすと大工事になり、かえって事故を増やす。名簿の今の設計は正しい。
- 原則D：完了した別室は畳む。名簿の名前は DONE で残す。マージ／デプロイで役目を終えた別室は撤去する（普段は reaper が自動回収）。未保存物が残る別室は自動回収されず人の判断待ちになる。名簿の行は消さず DONE として記録に残す。本店は受付なので決して撤去しない。

## 4. ○×で確認できる合格条件（KGI）

| # | 合格条件 | 判定のしかた |
|---|---|---|
| KGI-1 | どの別室から push しても、本店の状態が一切変わらない | push 前後で本店 git status の差分が0行 |
| KGI-2 | ある別室の push 完走に、本店での手作業編集が0回 | 完走までに人が本店ファイルを編集した回数 = 0 |
| KGI-3 | 2つの別室で同時作業しても、互いの名簿行を巻き込まず両方 push できる | 衝突0件で両方 push 成功 |

## 5. なぜこの形なのか（理想の根拠）

混戦の原因は「規律のゆるみ」ではなく仕組みだった。別室を作る道具は、名簿に走り書きするだけで commit しない。
だから本店に走り書きが溜まり、本店が受付（main）でなく別の章に乗り移った瞬間、その章に滲む。
直すべきは名簿でなく本店の使い方。本店を受付に固定すれば、滲む経路そのものが消える。

## 6. やらないこと（スコープ外）

- 名簿（active-work.md）を別の場所へ移さない。
- CI の自動ロボット（auto-review / auto-done / deploy stamp 等）を改修しない。
- 過去の名簿の中身（DONE 行など）を消さない。記録は残す。
- 本番（tenant_004）には一切触れない。
