## 5. design（To-Be 六本柱・純理想・現状不参照・PO確定 2026-07-03）
たとえ: 優秀な管理人が24時間働く共同工房。
- 柱1 自動のホワイトボード: 「誰が何を使っているか」を工房そのものが書く板。
  手書き欄が存在しない=1。板と実物の突合不一致0。
- 柱2 残量メーター: 上限のある資源は詰まる前に鳴り、鳴ったら片付け係が自動で呼ばれる。
  上限は見張り役として残す。事前警報=満数、上限到達での停止=0。
- 柱3 貸出札: 壊すと全員が困る書類だけ着手前に札を取る。重複時のみSTOP、返却は完了と同時に自動。
  二重編集事故0・誤停止0・居座り札0。
- 柱4 通報の自動化: 関所の停止は本人が報告しなくても自動でPOへ届く。迂回は検知され消せない形で残る。
  迂回0・無申告停滞0・通知の人手作業0。
- 柱5 新陳代謝: 終わった机は自動で封をして畳まれる。「大掃除」という言葉が要らない。
  規定日数超の完了机0・手動一斉片付けの発生0。
- 柱6 単一の今: 全員が着手時に同じ最新の板とルールを読む。原本は1冊、矛盾は即解消便。
  矛盾未解消0・古い写真起因の誤判断0。
- 成長回路（G7）: 停止→板に1行（起因: 設計/実装/環境/外部）→対策→同じ×が続けば機械の関所へ格上げ、
  重すぎる関所は間引く。記録の型は agent-complete-design の1冊のみを使う。停止台帳は新ノートではなく
  各テーマの track-record を束ねる横断集計の窓として実現する。

```mermaid
flowchart LR
  A["着手: 最新を読む(柱6)"] --> B["机: 残量OK(柱2)・自動記帳(柱1)"]
  B --> C["危険書類なら札(柱3)"] --> D["作業→関所: 停止は自動通報(柱4)"]
  D --> E["完了: 札返却・板更新(柱1/3)"] --> F["机は自動で畳む(柱5)"]
```
