# KGI（設定配線SSOT）

この文書は、設定値を1か所に置き、全ての部品へ確実に届いたことを機械で確かめるための測り方をまとめたものです。
親: [README.md](./README.md)

## KGI

| # | 合格条件 | 測り方 | 合格ライン |
|---|---|---|---|
| K1 | backend へ渡す設定の一覧は docker-compose.yml だけが持つ | `scripts/blue-green-cutover.sh` 内で個別に設定名を書いている行数（`grep -n -E "^\s*--env \|^\s*-e "` の一致行数。`--env-file` は数えない） | 0行 |
| K2 | 既定値はコード側の1か所にだけ書く | `git grep -n -E ":-tenant_004" -- docker-compose.yml scripts/ .github/` の一致行数 | 0行 |
| K3 | 渡し忘れをCIが止める | 「backend のコードが読む設定名」と「compose の backend が渡す設定名」を突き合わせる検査が実在し、通す見本=緑・1件わざと抜いた見本=赤 | 1/1 |
| K4 | 本番起動後に実物で確かめる | デプロイ後の検査が backend コンテナ内の設定値を読み、期待と違えばデプロイを失敗させる。通す見本=成功・壊す見本=失敗 | 1/1 |
| K5 | 業務のON/OFFはDBの設定表を正本にする | `git grep -n "TCG_AUTO_ANALYZE" -- backend/app` のうち、環境変数を読む実行行の数 | 0行 |
| K6 | 設定を足す手順が1か所に書いてある | 手順書が実在し、足すべき箇所が名指しで書かれている（在る=1／無い=0） | 1 |

KPI: 達成KGI数 ◯/6

## 運用方針

段階に分ける。K1・K2・K3・K6 を先に満たし（配線の一本化と守り手）、K4（起動後の実測）を次に、
K5（DBへの一本化）は設定ページの設計と合流させて最後に行う。
K5 を後回しにしても K1〜K4 は独立して成立する。

`scripts/blue-green-cutover.sh` は関所が危険変更として扱うため、K1・K2 の実装はPO自筆GOを要し、単独PRとする。

## 設計送り事項（KGIでは決めない・design で決める）

- K3 の「コードが読む設定名」をどう取り出すか（静的走査の方式）
- K3 の突き合わせで、既定値を持つ設定や celery 専用の設定をどう扱うか
- K4 をどのスクリプトに置くか、本番へどの機体・どの鍵で入るか
- K5 でDBの設定表を読む際、DB接続前に必要な設定（接続先そのもの）との順序をどうするか
