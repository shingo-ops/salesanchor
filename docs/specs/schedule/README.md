# カレンダー（schedule）仕様書 — 表紙

> **この文書は何か（1行）**：カレンダー画面のあるべき姿とKGIを束ねる表紙。原文は `ideal-state.md`、物差しは `kgi.md`。

## 構成（3ファイル標準）

| ファイル | 役割 | 書き換え権限 |
|---|---|---|
| `README.md`（本書） | 表紙：概要・境界・ステータス・案内 | Planner |

## ステータス

- **KGI承認**: K1〜K8 承認済み（PO: shingo-ops・2026-07-02〜03）
- **導出ルール**: KGIは ideal-state.md **のみ**から導出。既存実装・過去reconの影響を受けない。

## 境界（兄弟ドメインとの接点・SSOTの向き）

| 接点 | SSOTの持ち主 | カレンダーの役割 |
|---|---|---|
| 受注の各期日（発送・入金 等） | 取引フロー `docs/specs/transaction-flow/` | 参照表示。**変更は確認ダイアログ経由で原本を更新**（コピー禁止） |
| 商品の販売日 | 商材マスタ系 | 同上 |
| リードのアクションプラン | リード（CRM）ドメイン | 同上 |
| やることフィード | **dashboard と共有の1本のリスト**（`docs/specs/dashboard/README.md` の構図参照） | 同一リストを時間の地図として表示。**食い違い0件**（kgi.md K5） |

原則：カレンダーは予定を映す**鏡＋操作窓口**。事実の保管庫（原本）は各源泉ドメイン。カレンダー固有の原本は「手動予定」のみ。ドラッグ等での期日変更は、確認ダイアログを経て**原本そのものを書き換える**（(a)確認つき双方向・2026-07-03 PO確定）。原本が1つで窓口が複数、は銀行口座とATMの関係と同じでSSOTを壊さない。

## 役割分担（手帳・診察室・呼び鈴モデル）

カレンダー＝**時間の地図**（いつ・どれくらい詰まっているか。CTAは各予定に添える）／ダッシュボード＝**羅針盤**（数字と行動の司令塔）／通知＝**呼び鈴**（開いていない時の導線）。詳細は dashboard 仕様書。
