# LINE解析 Gemini 書き写しの調整記録

- この記録の目的：LINE解析の Gemini の指示書と仕入元ルールについて、「いつ・何を変えて・精度がどう変わったか」と「PO の判断」と「起きた事故」を1か所に積み上げ、後から追えるようにする。
- なぜ既存の文書で足りないか：版ごとの設計書（docs/handoff/gemini-v8 … gemini-prompt-e、gemini-new-system-supplier-rules など）は PR 単位に分かれていて、版をまたいだ精度の推移と判断の一覧が無い。
- 社外秘の扱い：この記録には集計値・決まりの文・ファイルの場所と指紋（sha256）だけを書く。仕入元の名前・投稿の原文・判定の一覧は書かない（社外秘。memory feedback_confidential_analysis_records）。根拠の生データは手元の `~/CC報告ファイル-keep/` にあり、下の表から sha で指す。
- 記帳のしかた：試験を1回流すごとに [track-record.md](./track-record.md) に1行を足す。PO の判断が出たら下の「判断の決まり」に1行足す。事故が起きたら「事故と直し方」に1行足す。
- 記録の開始：2026-10-07（Opus。それ以前の内容は、各版の設計書から転記した）。

## 1. 役割の定義（PO の言葉）
- 「geminiの役割は原文を正しく商品ブロックごとに抽出すること、商品ブロック内の価格と数量を抽出すること」（2026-10-07）
- 数字の取り出し・商品の特定・要確認の判定は、後ろのシステムの仕事。
  - ただし Gemini 自身が「上下どちらの件か決まらない」行は、指示書の手順4の3で unsure に書かせ、受け取り側は捨てずに Gemini の要確認（`v102_flags["gemini_review"]`・件ごとの `gemini_review`）として、システムの要確認（review・post_review）とは別に残す。PO 決定 2026-10-09（「y：設計書を作り、レビューにかけてから」）。設計：[v102-gemini-unsure](../../handoff/v102-gemini-unsure/design.md)。
