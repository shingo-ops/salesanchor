# 金額の集約（money-consolidation）— 設計図

> この文書は何か（専門用語なしの1行）:
> 受注・請求・仕入・見積に散らばった金額を、「各金額は1つのテーブルにだけ記録し、他は参照で取得する」形に集約する設計。親テーマ「DB設計のSSOT化」の子。

親: ../README.md ／ あるべき姿・KGI: ../ideal-state.md, ../kgi.md

## 1. 現状（調査で確定した事実・2026-07-10 tenant_004実測）
- 受注は金額を order_financials（金額専用テーブル）に分離済み（total_amount/tax/shipping_fee/paid_at 等）。件数 orders=1 / order_financials=1。
- 請求（invoices）・見積（quotes）・仕入（purchase_orders）は、それぞれ自前の合計欄（total_amount/shipping_fee 等）を保持。件数 invoices=1 / quotes=0 / purchase_orders=0。
- invoices・quotes・order_financials は order_id で orders に接続。purchase_orders は company_id 等に接続。
- 診断：単純コピーではないが、各伝票が「自分の合計」を自前で持つため、食い違いの余地がある（K1/K2の芽）。

## 2. あるべき姿（この子の理想形・PO指示 2026-07-10）
- 全体の構造原則：「分けて背番号でつなぐ」。横長の1テーブルに詰め込まず、意味のまとまり（受注・明細・金額・発送等）ごとにテーブルを分け、受注番号など背番号で接続する。金額の入力先は1か所、他は参照で取得する（スプレッドシートの「入力欄は1つ・関数で引用」と同じ発想）。
- 請求書の金額：orderが正本。請求書発行＝order化と捉えるため、請求書テーブルは金額を自前で持たず、必要時はorderから取得する。
- 仕入れの金額：orderが正本。仕入れはすべてorderに紐づき、仕入れテーブル単体で金額を持たない。別画面で見せる場合もorderから取得する。
- 見積もりの金額：lead（またはdeal）が正本。見積はorder化前の仮の数値のためorderには紐づけない。ただし「誰に・いつ・何を・どれくらい・いくらで見積もったか」はlead/dealに紐づけて記録する。
- 絶対ルール：各金額は1つのテーブルにのみ記録する。他の場所が独自に数値を持つことを禁止する（参照のみ許可）。
- 合計・小計は、可能な限り明細から導く。ただし請求のように「発行時点の金額を証拠として固定すべきもの」は、その時点の値を正本テーブルに確定記録する（発行後に商品マスタが変わっても請求額は不変）。

## 3. なぜそうするか（KGIとの対応）
- K1（重複ゼロ）：各伝票が自前で持つ合計を廃し、金額の二重保持をなくす。
- K2（正本1か所）：請求・仕入=order、見積=lead/deal と正本を一意に定める。
- K3（参照で持つ）：正本以外は背番号で取得し、コピーを持たない。
- 分析容易性：金額・明細を「まとまりごとの表」に縦持ちすることで、商品別・月別・費目別の集計を容易にする。

## 4. 稼働前の前提
- 本番未稼働。既存データは捨てて理想形で新規構築してよい。現状分布（invoices/quotes/purchase_orders の自前金額欄）に引きずられない。

## 5. まだ決めていない（実装時に詰める）
- 「発行時点で固定する金額」と「明細から都度計算する金額」の線引きの具体化（どの数値を確定保存し、どれを計算で出すか）。
- order の金額を order 本体に持つか order_financials（金額専用テーブル）に持つか：技術判断として後者（分離）を軸に、実装時に確定。
- 為替・通貨をまたぐ場合の記録方法（currency 欄の扱い）。
