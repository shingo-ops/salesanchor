# リード データ辞書(欄の説明書)

> この文書は何か(専門用語なしの1行):
> リードのデータベースにある54個の欄それぞれについて「何のための欄か・どんな値が入るか・残すか捨てるか」を誰でも分かる言葉で記録した説明書。

親へのリンク: [README.md](README.md)

## 読み方

- 意図・値の例は、実測(データベースとプログラムの中身の確認)で確かめた範囲だけ書く。未確認の欄は正直に「未確認」と書く。分かったふりをして書かない。
- 「本番」= 本番データ56件のうち値が入っている件数(2026-07-19実測)。
- 「画面編集」= リード画面の更新対象リスト(_UPDATABLE_COLUMNS)に載っているか(2026-07-19実測)。
- 判定(案)は断捨離の現在の案。PO確定済みの決定には【PO決定】と明記。

## PO確定済みの決定(2026-07-19)

1. lead_code は id と統合する【PO決定】
2. id は lead_id に改名する(他のIDと見分けるため)【PO決定】
3. status は lead_status に改名する【PO決定】
4. 「きっかけ」は新設せず initiative(inbound=問い合わせ/outbound=営業)を採用する【PO決定】
5. 画面に出す項目はPOの24項目リストを正とする【PO決定】

※1〜3の実施はデータベース改築(危険作業)のため、正式手順(退避→試し→PO自筆GO)で別便。

## 未確認の潰し方(宿題)

「未確認」の欄は、プログラムの該当箇所を読む実測便で1つずつ埋める。埋めるたびに本辞書を更新する(推測で埋めない)。

## 維持の仕組み

- 守り手: 人手で守る。理由: 欄の増減はデータベース改築(migrations)を必ず通るため、改築便のカードに「本辞書の同時更新」を必須手順として含める運用とする。機械強制は断捨離完了後に別途設計。
