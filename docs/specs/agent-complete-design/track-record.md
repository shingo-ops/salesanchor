# エージェント完結の設計体制 — 定点観測台帳（track-record）

> この文書は何か（専門用語なしの1行）:
> 便（PR）ごとに「エージェントだけで綺麗に完了したか」を1行で記録し、
> 不具合・違反・停止があった便だけ5W2Hで詳しく残す台帳。

表紙: [README.md](./README.md) ／ あるべき姿: [ideal-state.md](./ideal-state.md) ／ KGI: [kgi.md](./kgi.md)

## 記帳ルール
- 1便（PR）＝1行。全部○なら備考は空欄。×か△が付いた便のみ、下の「5W2H詳細」に追記しリンクする。
- ルール違反・進行停止・指示の未消化も記帳対象（エラーだけが対象ではない）。
- 測定者はプランナー（指示を出した本人が、欲しい結果が返ったかを検品して記入する。実装役の自己申告にしない）。
- 備考には起因ラベルを付ける（起因: 設計／実装／環境／外部）。
  設計=プランナーの指示・設計の穴、実装=実装役の逸脱・脱落、環境=ツール・基盤の事情、外部=それ以外。
- マージ完了した便の行は要点のみ残す（詳細の原本はgit履歴が保存する）。

## 5W2H詳細
### [5W2H-001] 変更一巡便#1の初回指示脱落（2026-07-03）
- What(何が): 実装指示「7項目目+KGI⑧」が実行されず、別の宿題（GO確認・台帳始末）だけが実行された
- Who(誰が): 実装役（codex）。指示者はプランナー（Fable）、検知者もプランナー（main実測で発見）
- When(いつ): 2026-07-03 指示投入直後の作業中
- Where(どこで): 実装役の作業セッション内（Context compacted 直後）
- Why(なぜ): 複数の宿題が同一セッションに滞留した状態で記憶圧縮が走り、新しい方の指示が文脈から脱落した
- How(どうやって検知/回復): プランナーがmainを実測し未反映を確認→指示全文を再投入し「全項目の消化○×自己チェック」を義務化→完了
- How much(規模): 指示全文 約60行。損失は再投入1往復ぶんの時間のみ（誤実装・破壊なし）
- 教訓: 実装役への指示は1便1目的。完了報告に消化チェックを付けさせる。

### [5W2H-002] 転送専用の相談メッセージを実装役が実行（2026-07-03）
- What(何が): 別セッション宛の相談文（#AGENTS-01）を受領した実装役が、転送でなく処置（別便正本の編集・ブランチ作成）まで実行した
- Who(誰が): 実装役（codex）。相談文の作成者はプランナー（Fable）、検知者もプランナー
- When(いつ): 2026-07-03 相談文投入直後
- Where(どこで): 実装役セッション内。編集は release/go-record-transcription-auto-v2 の worktree に留まりpush は関所が阻止（main 無傷）
- Why(なぜ): 相談文に「転送専用・受領側は実行禁止」の明記がなく、実行可能な指示として解釈された（設計起因）
- How(検知/回復): プランナーが報告を検品し越境を検知→凍結指示で現状保全→相談#AGENTS-02で該当セッションに判断を返却
- How much(規模): 影響は未pushのworktree内変更のみ。損失は凍結・転送の1往復
- 教訓: 相談メッセージは冒頭に「転送専用・実行禁止」を明記する
