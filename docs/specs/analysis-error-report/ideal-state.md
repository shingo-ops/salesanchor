# あるべき姿 — 解析の誤り報告から自律修正まで（PO の言葉のみ）

> この文書は何か: 在庫表の解析結果の誤りを報告したら、AI が自分で直して確かめるまでの理想の流れを、PO の言葉だけで残した正本。Planner・Generator は書き換えない。
> 親: [README.md](./README.md)

## 1. 全体の流れ（PO 2026-10-17）
「サーバーからwebhookでDiscordにアラートを届ける、アラートが届いたらAgent Consoleにセッションを開いて対応するセッションを開く、Claude codeが原因と対策を完結に記載して解決策を考えて処理する、処理が完了したら再解析を実施して集計処理が正答しているかどうかを確認、正答したらDiscordに記録を残す、この自律解決が実現可能化教えてくれ」

## 2. 起動（PO 2026-10-17）
- 「理想としてはサーバー側でボタンが押されたらトリガーが発火してAgent consoleにセッションが立ち上がるようにしたい、セキュリティに問題が無いように作れるか？」
- 「自動でセッションを開始できるようにするほうが修正スピードが向上するため」
- 設計書 docs/handoff/ai-ops-247/design.md:174（案F 不採用）について「この記録を外して設計→外す」
- API キー（従量課金）を使う案: 「n」
- 「この端末で開発もしているので重い処理は入れたくない」

## 3. 報告の聞き方（PO 2026-10-17）
- 「何が間違ってますか？正解は？と質問形式で進めてほしい」
- 「何が間違っているかは複数選択できるようにして、選択したものに沿って次の項目で正解を聞く」
- 報告ボタンを在庫表を見られるスタッフ全員に開くか: 「n」（super admin だけ）

## 4. 直し方の決まり（PO 2026-10-17）
- 自動セッションが外部サイト（公式サイト等）を閲覧すること: 「許可する」
- 新商品の登録: AI が出典 URL 付きの候補表を Discord に出し、PO が Discord で y を押してから登録する形 → 「y」
- 値の決め方は [product-master/registration-rules.md](../product-master/registration-rules.md)（U2・U3 は PO 2026-10-17 決定）

## 5. 進め方の原則（PO 2026-10-17）
「推測は禁止して事実確認を怠らずに確実性を重視して最も効果があり、現状把握の粒度が細く、精度が高いエビデンスを確立して安全に進めてくれ。また配線とDBのSSOTは遵守してデータを分散させることは禁止。フロントエンドのパーツもデザイントークンとデザインシステム を遵守して、金型登録のないハードコードを禁止する。推測で自身で判断したり不透明無まま進めることは禁止、分からないことは聞いてくれ。確立したなら進める。」
