# KGI — テーマB: 受注調達・発注依頼（PO承認済み 2026-07-03／移植 2026-07-04）

判定は本番相当環境での画面確認・実測。○×は一義。

## KGI-B（候補提示と2段階発注）
- B1: 受注入力から調達候補が最大3件表示されるまで5分以内。各候補にラベル・
  一言説明・利益額（粗利＋消費税還付の合計）を表示
- B2: 「詳細」で商品別内訳・送料（梱包単位）・提供元別代行手数料・合計・利益・
  消費税還付を表示し、手計算と1円単位で一致
- B3: 候補によらず手動で組み合わせを選択できる
- B4: 候補選択から提供元別のLINE/Discord用発注メッセージ生成まで1分以内
- B5: 発注に「発注依頼中」「発注確定」の2状態が画面で区別表示される
- B6: 発注依頼で数量が仮押さえされ、別テナントの利用可能数が依頼数量ぶん
  減って表示される（表示はAの棚画面）。依頼中のまま24時間で自動解除され元に戻る
- B7: 提供元の回答数（0を含む）を数字1つで入力でき、本人の画面では入力から
  5分以内に不足分を反映した新候補（最大3件・同形式）が再提示される
- B8: 報告後に「発注を断る／回答数だけ確定」の2択が表示される。
  断る→仮押さえ解除・報告値を上限とした全量の新候補3件を5分以内に再提示。
  回答数だけ確定→調達進捗（必要数・確保済数・残数）を表示し、残数について
  当該提供元を除いた新候補3件を5分以内に再提示
- B9: 発注確定でAの棚が「回答数−引取数」に自動更新され、鮮度が
  「販売可（青）」に更新される（手計算と一致・棚の正本はテーマA）
- B10: 候補確定の直前に、対象提供元への在庫確認メッセージを1分以内に
  ワンタップ生成できる

## 運用方針
- 依頼中カード＝精算待ち伝票。アプリ外のやり取りは捕捉せず、人間の数字入力がトリガー

## 設計フェーズ送り事項
1. 直前確認の必須条件（金額閾値・鮮度切れ時）
2. 仮押さえの数量上限
3. 送料のAPI取得／テーブル方式の選定
4. Discord返信の下読み半自動化（回答候補のプリセット。確定は人間）
