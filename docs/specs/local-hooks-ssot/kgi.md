# 個人側検問の正本化 KGI(○×で測る・全10項目)

> この文書は何か(専門用語なしの1行):
> 個人側検問の正本化が合格かどうかを○×で判定する物差し。

親へのリンク: [README.md](README.md)

| # | 合格条件 | 測り方 | 合格ライン |
|---|---|---|---|
| H1 | 検問5本すべての原本(スクリプト全文)がリポジトリ内に存在する | リポジトリ内に原本がある検問数 | 5/5 |
| H2 | 検問5本すべてに説明書(何を・なぜ止めるか・不合格時にどうなるか)がある | 説明書がある検問数 | 5/5 |
| H3 | リポジトリ内の原本とパソコン側の実体が一字一句一致している | diff(突き合わせ)で差分ゼロの検問数 | 5/5 |
| H4 | 実体とリポジトリ原本のずれを検出する仕組みが動いている | ずれ検出の仕組みが在る=1/無い=0 | 1 |
| H5 | 検問の変更がPR以外で行われた場合に発見できる | H4の仕組みがずれとして検出する=1/しない=0 | 1 |
| H6 | 「不合格なのに操作が成立した」既知の穴(gh-scope-guardのマージ素通り)が塞がっている | 素通り再現テストで操作が止まる=1/成立してしまう=0 | 1 |
| H7 | 検問が止めた記録に「いつ・何を・なぜ」の3点が揃っている | 記録3点が揃う検問数 | 5/5 |
| H8 | 新しい環境への導入手順書があり、手順書どおりで5本が同じ設定で動く | 手順書がある=1/無い=0、導入テストで5本動作 | 1かつ5/5 |
| H9 | 検問のfailed表示が出た場合の実装者の行動ルール(停止して全文報告)が正本に明記されている | 明記がある=1/無い=0 | 1 |
| H10 | 先行3テーマ(ledger-guard・dev-continuity・evidence-registry)の調査結果と矛盾しない(重複調査ゼロ) | 先行成果への参照リンク数 | 3以上 |

KPI: 達成KGI数 ◯/10
