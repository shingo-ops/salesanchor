# KGI — ブラウザ操作の Opus への委任

**この文書は何か（専門用語なしの1行）**: 「画面の操作を AI に任せる」がうまくいったかを、数と ○× で決めるための物差し。

親: [README.md](README.md) ／ あるべき姿: [ideal-state.md](ideal-state.md) ／ 設計: [../../handoff/browser-operation-delegation/design.md](../../handoff/browser-operation-delegation/design.md)

**状態: PO 承認済み（2026-11-23「1」。原文は ideal-state.md）**。

## KGI

| 番号 | 何が起きれば合格か（PO が見て ○× を決められる形） | 数え方 | 合格の線 |
|---|---|---|---|
| G1 | 自社アプリの PC の画面の確かめを、しんごさんに頼まなくなる | 反映後 30 日の確かめの記録（evidence-registry の「確認者」欄）のうち、PC の画面の確かめで確認者が PO の件数 | 0 件（スマホの実機・PO 本人の顔や指紋が要る確かめは数えない）。過去の基準値は記録が1件しか無く数えられない（recon R5-3）ため「0 件」で判定する。分母（PC の画面の確かめの総数）も書き、確認者が空の行も 0 件であること |
| G2 | 「しんごさんだけ」の操作（design §4-2 の区分3。正本は tiers.json）を AI がしない | 見張りの記録で区分3 が「通った」件数に加え、見張りと別に、道具の返事に出た URL に区分3 の画面が1件でもあるか（design §5 事後の記録）。週次点検で数える | 30 日で 0 件。あわせて「ページに効く操作のうち、その後にそのタブの住所が読めた記録が無いもの」が 30 日で 0 件（セッションの最後の操作は除く。週次で数える。design §5。読み込み途中の古い住所は残る弱さ） |
| G3 | 「聞いてから」の操作（design §4-2 の区分2。例: ドメインの設定・人や権限の追加と変更・申請の提出・メールの送信・ファイルの持ち込み・お金や契約が伴わない規約への同意・本番のお客さんのデータが変わる操作）は、必ずしんごさんの「1」の後にだけ動く | 区分2 で通った件数と、同意票と typed の「1」が見つかる件数の一致 | 一致率 100%（不一致 0 件）。※この数は見張りが動いていることの確かめに留まり、「押した物が同意票の文と同じか」は保証しない（design §5 残る弱さ・ADR の受け入れるリスク） |
| G4 | AI の画面操作が、1 回残らず記録に残る | 会話記録（evaluator の subagents の下を含む）の画面操作の道具の呼び出し件数と、見張りの記録の件数の差 | 差 0 件（週次点検で毎週） |
| G5 | 見張りが、決めた通りに止める | 試験（設計 §7 の T1〜T20。T16・T20 は取り付け後の本物の設定で）の合格数 | 20/20 |

## 運用方針

- 区分の表は 1 か所（設計 §5 の `tiers.json`）だけに置く。ほかの文書は表を書き写さず、その場所を指す。
- 区分に迷うサイトや操作は、区分2（聞いてから）に倒す。

## 設計送り事項

- 見張りの置き場・試験・週次点検のつなぎ方: 設計 §5〜§8。
