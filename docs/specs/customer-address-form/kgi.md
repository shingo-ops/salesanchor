# KGI — お客様の住所フォームと住所の決まり（customer-address-form）

> この文書は何か：この仕事が「できた」と言える条件を、PO が見て ○× を付けられる形で並べたものです。

親: [README.md](README.md)　／　あるべき姿: [ideal-state.md](ideal-state.md)　／　決定: [decisions.md](../../handoff/customer-form-layout/decisions.md)

状態: 2026-11-24 案（PO 承認待ち）。

試す場所: テスト用の会社（テナント001）の登録リンクを PC の Chrome（横幅 1280）で開く。社内の画面はテナント001 の会社の画面。

## 決める前の事実（KGI に効くもの）

- 国番号は 191 か国のうち 137 か国が「+355」のような4文字、44 か国が3文字、9 か国が2文字（`frontend/src/constants/countries.ts` を数えた）。「+00」（3文字）の幅だと 137 か国の番号が欠ける。→ K2 は「+000」（4文字）の幅で案を作った。
- 今の国番号の欄は「+1 BS」と出る（米国の「+1」を選んでいても、一覧で先に来るバハマ（BS）の名前が付く）。番号だけの表示にするとこの食い違いは消える。

## KGI（○×で判定）

| # | KGI | ○ の条件 | 判定方法 |
|---|---|---|---|
| K1 | 言語切替が端に寄りすぎない | 言語切替のボタンが、見出し「Customer Registration」と同じ行の右側に出る（ボタンの縦の中心が見出しの上端〜下端の間）。3つのフォームすべて | 画面の目視＋欄の位置の数値（`getBoundingClientRect`） |
| K2 | 国番号の欄が中身に合った幅 | 国番号の欄に出るのは「+81」のような番号だけ。191 か国すべての番号が欠けずに見え、欄の幅は「+000」が入る大きさ（新しく登録した幅の金型で決まる） | 191 件を順に選んで欄の中身が欠けないか自動の試験で確かめる＋幅の数値 |
| K3 | City・State・ZIP が大手と同じ並び | City は1行を占める。State と ZIP は同じ行に並ぶ（2つの欄の上端が同じ高さ）。請求先・送り先・3つのフォームすべて | 欄の位置の数値 |
| K4 | 国は打つと候補が絞られる | 国の欄に「jap」と打つと候補に「Japan (JP)」が出る。選ぶと欄に入る | 画面の操作 |
| K5 | 住所1・2 は今のまま | 住所1・2 の欄の幅が今と同じ（フォームの横幅いっぱい） | 変更の前後で幅の数値が同じ |
| K6 | 送り先の住所は1行35文字まで | 送り先の住所1〜3のどれかに36文字入れると、その欄が赤くなり「35文字以内で入力してください」が出て、登録できない。35文字ちょうどは通る。画面を通さず直接送っても受け付けない | 画面の操作＋自動の試験（受け口に36文字を送ると断られる） |
| K7 | 送り先の住所は英字・数字・記号・空白だけ | 送り先の住所1〜3に「東京」または「é」を入れると、その欄が赤くなり「英字・数字・記号で入力してください」が出て、登録できない。画面を通さず直接送っても受け付けない | 画面の操作＋自動の試験 |
| K8 | 請求先は「同じ」を選んだ時だけ決まりが効く | 「Proceed to register.」を選んだ時は、請求先の住所に36文字や日本語を入れても登録できる。「Ship to the same address.」を選んだ時は、請求先の住所1〜3に K6・K7 と同じ決まりが効く | 画面の操作＋自動の試験 |
| K9 | 請求先に住所3がある | /register と /register/change-billing の請求先に Address Line 3 の欄がある。入れた値が会社の住所の住所3として保存される | 画面の目視＋保存された住所3の値 |
| K10 | 見積書の紙に住所3が出る | 住所3の入った会社で見積書の PDF を作ると、宛名の住所に住所3が出る | PDF の目視＋自動の試験 |
| K11 | 社内の画面からも決まり外の送り先は入らない | 社内の会社の画面の住所の窓（送り先）と、注文ごとの発送の欄で、K6・K7 と同じことが起きる。請求先の住所は今までどおり自由 | 画面の操作＋自動の試験 |
| K12 | 今ある住所は消えず変わらない | 反映の前後で、本番の決まり外の住所の数が同じ（例: テナント004 の送り先は35文字超え5件・英字等以外3件。2026-11-24 時点）。その住所を社内の画面で開いて保存しようとした時だけ赤くなる | 本番の読み取り専用の道で反映前後に数える |
| K13 | 決まりの置き場所は1つ | 35文字と文字の種類の決まりは、受け口（API）側の1か所で決め、3つの道（お客様のフォーム・社内の住所の窓・注文ごとの発送の欄）が同じものを使う。画面の側の赤くする判定も1か所の部品にまとめる | コードの検索で、決まりを書いた場所が受け口1か所・画面1か所 |
| K14 | 直書きが増えない | 色・幅・余白は登録済みのデザイントークンと金型だけで書く。画面の文字は翻訳キー経由で、日本語と英語の両方にある。決まりの確かめ（CI）がすべて緑 | CI の結果＋差分の検索（新しい px・色の直書き 0 件） |
