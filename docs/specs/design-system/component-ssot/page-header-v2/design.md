## 1. ヘッダーの住人リスト（規格表・KGI④⑤の判定基準）

### 許可（この4種のみ）
| 住人 | 規格 | 手本ページ |
|---|---|---|
| 題名・説明文 | page-title 金型（PageLayout navKey/titleText＋subtitleKey）。位置・字体は金型独占 | 全ページ（移行済み） |
| タブ切替（表示モード・ソート） | 金型 tab ボタン。選択中のみネイビー、他は無色 | ダッシュボード（マネジメント/プレイヤー）・カレンダー（日/週/月） |
| 設定系ボタン | 金型 ghost ボタン（無色）。複数並べてよい。そのページの設定・補助メニューを開く用途のみ | 受信箱（テンプレート/FAQ/歯車） |
| ページ固有の期間ナビ | 金型部品（Button secondary/ghost）で組んだ道具は可。字体は説明文級まで | カレンダー（今日・‹›・期間ラベル） |

### 実行ボタンの置き場（改訂4・2段ルール）
| 条件 | 置き場 | 手本 |
|---|---|---|
| 本文にフィルタ・検索行が在る | その行の右端（同一行・page-content-actions をフィルタ行内の右寄せ要素として使う） | 顧客管理>リード |
| フィルタ・検索行が無い | 一覧直上の右寄せ行（page-content-actions 単独行） | 便3a現行形 |

### 禁止（ヘッダーに置いてはいけない）
| 禁止物 | 理由 | 行き先 |
|---|---|---|
| 戻るボタン（全様式） | ideal-state 改訂2。ナビはブラウザ戻る/サイドメニュー/サブメニュー | 撤去（KGI③=0） |
| 新規作成・保存・発行等の実行ボタン | ideal-state 改訂3。ヘッダーは設定のみ | 本文側（表の上・フォーム下等）へ移動 |
| パンくず・親名の併記 | ideal-state 改訂1 | 廃止（KGI②=0） |
| 生button・手書きstyle | ボタンは金型部品のみ | Button部品へ置換（KGI⑧=0） |
| 題名級字体（font-xl等） | 題名の独占（KGI⑦=0） | 説明文級（font-sm〜md）へ |
| 金型を包む外枠のpadding | 位置ズレの原因（#2965実測） | 削除（金型余白に一本化） |

## 2. ボタン金型の種類（KGI⑧・既存 frontend/src/components/Button の規格化）
| 種類 | 見た目 | 用途 | ヘッダー内 |
|---|---|---|---|
| primary | 濃ネイビー | 本文の主操作（新規作成・保存等）。1画面1個まで | 禁止 |
| secondary | 薄枠 | 補助操作 | 期間ナビのみ可 |
| ghost | 無色 | 設定系・アイコンボタン | 可 |
| tab | 選択中のみネイビー・他無色 | 表示切替・ソート | 可 |
大きさ（sm/md）・角丸・余白・字体は金型が独占。ページ側は種類と文言のみ指定。className によるフォルム上書き・インラインstyleは禁止。
現状の生button実装（btn-primary/btn-secondary/btn-ghost クラス直書き）は Button 部品へ段階置換する。

## 3. 番人（KGI⑥・新設 frontend/scripts/check-page-header.js）
check-page-layout.js の兄弟として新設し、CI（design-token-guard 系 workflow）へ配線。検査項目:
(a) PageLayout を包む外枠セレクタに padding が無い（対象CSSの静的検査）
(b) headerLeft/headerAction ブロック内の生 <button・style={{ の検出 → 赤
(c) 戻る系文言（common.back・← 等）のヘッダー内検出 → 赤
(d) ヘッダー関連CSSでの font-xl 使用検出 → 赤
(e) ページ tsx の生 <h1 検出 → 赤（check-page-layout の h1 盲点をここで修正）
受入: 違反サンプルブランチで (a)〜(e) 各1件が赤くなることを実測してから本採用（KGI⑥の合格条件）。

## 5. 弊害・トレードオフ（空欄不可）
- 新規作成ボタンの位置が23ページで変わる（ヘッダー右端→本文側）。慣れの再学習が要る。
- 戻るボタン撤去後、サブメニューの無い子ページ（ダッシュボード子4等）の戻り道はブラウザ戻る/サイドメニューの2択。迷わないかは PO 目視で確認する。
- 主役色（primary）1画面1個ルールで、請求書詳細等の複数濃色ボタンは1個を除き薄色化。どれを主役にするかは便4で状態別に PO 提示。
- 番人(b)の静的検査は変数参照型（別行定義）を見逃す可能性があり、初版は検出網に限界がある（残余リスクとして明記。全数調査の再実施で補完）。
