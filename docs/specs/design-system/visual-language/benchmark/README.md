## 測り方（3つを組み合わせる）

1. **部品の構造データ**（`adb shell uiautomator dump`）: 部品の位置・大きさ・押せるか・アプリ内部の名札。
2. **写真の画素の測定**（`adb exec-out screencap -p` → 自作の集計）: 色、文字の実際の高さ、区切り線の有無。構造データに色は入っていないため必須。
3. **許可された操作での画面移動**: 一覧の項目を開く／戻る／タブ切替／メニューを開いて閉じる の4つだけ（手順書 §0-4）。

**撮影の前に必ず前面のアプリを証拠で確認する**（`dumpsys window` の `mCurrentFocus`）。目的のアプリが前面だと確認できなければ撮らずに中止する。この関所を入れる前に1度、ターミナルの画面を測定対象と誤認した事故があったため、手順に組み込んだ。

## この方法の限界（越えられない壁）

| 取れないもの | 理由 |
|---|---|
| フォントサイズ | 構造データに含まれない。画素から測れるのは「書かれている文字に依存するインクの高さ」までで、下限値にしかならない |
| アプリが「重要でない」と印を付けた部品 | 構造データは支援技術向けの木構造を使うため、その印が付いた部品は最初から現れない |
| Meta Business Suite の部品の意味 | 名札がほぼ付いていない（1件は `(name removed)`）。位置と大きさは測れるが、何の部品かは断定できない |

## 横断して分かったこと（両アプリ共通の型）

| 観測事実 | WhatsApp | Meta Business Suite |
|---|---|---|
| 一覧の行の高さ | 228px = **76dp** | 234px = **78dp** |
| 押せる範囲 | 行全体（1080x228px・全幅） | 行全体（1080x234px・全幅） |
| 行と行の区切り線 | **無い** | **無い**（境目の画素は背景と同じ） |
| 一覧の上の検索/絞り込み | 検索バー 高さ48dp | 絞り込みチップ 高さ43dp |
| 下部ナビ | 4項目・帯の高さ80dp・アイコン枠48dp | 5項目・各56x44dp・中央の丸ボタン48x48dp |
| 表示テーマ（観測時） | 暗い（背景 `#0a1014`） | 明るい（背景 `#ffffff`） |

**要点**: どちらも「小さな部品を押させない」設計で、**一覧は行をまるごと押させる**。行の高さは 76〜78dp に収束している。区切り線は使わず、余白と背景色で行を分けている。

## 我々（salesanchor）との差（事実のみ。対処は design.md で設計する）

- 受信箱をスマホ幅（390px）で測った段階1の結果は、押す場所が44px未満の部品が **33/52件**（[../../../../handoff/app-visual-language/stage1-baseline.md](../../../../handoff/app-visual-language/stage1-baseline.md)）。
- 上記のお手本2本は、同じ問題を「部品を大きくする」ではなく「**行全体を押せる範囲にする**」で解いている。
- 390px 幅で `.inbox-right-panel` が画面外（y=844）に積まれている状態は、お手本の「スマホは1列で画面を切り替える」とは異なる。

## 守った決まり（手順書 §0）

- 元データ（写真・構造データ）は**リポジトリに入れていない**。スマホ内の専用フォルダ1つ（`/root/vl-benchmark-raw/`）にまとめてあり、この PR がマージされたあとに削除する。
- 人の名前・メッセージ本文・電話番号・メールアドレス・アカウント名は**書いていない**。部品表は文字情報を出力しない作りにしている。
- 文字入力はしていない（`adb shell input text` はロック解除の暗証番号にのみ使用。PO許可 2026-10-10。ベンチマーク対象アプリへの入力は一切なし）。
- 送信・削除・転送・アーカイブ・ブロック・通話・録音・設定変更・ログアウトは一切していない。
- **未読の会話は開いていない**（開くと既読が相手に伝わり取り消せないため）。未読バッジの有無を構造データで判定し、未読が無い会話のみを開いた。
- Meta の案内カードは「閉じる」と明示されたボタンのみを押した。「投稿を作成」は押していない。
