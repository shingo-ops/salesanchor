## 取得に使ったコマンド

```bash
# 前面のアプリを確認（これが目的のアプリでなければ撮らずに中止する）
adb shell dumpsys window | grep -m1 "mCurrentFocus="
# 写真
adb exec-out screencap -p > <名前>.png
# 部品の構造（位置・大きさ・押せるか）
adb shell uiautomator dump /sdcard/d.xml && adb pull /sdcard/d.xml
# 画面サイズと密度
adb shell wm size ; adb shell wm density
```

数値の出し方: 部品の位置・大きさは構造データの `bounds` から、色は写真の画素の最頻値から集計した（集計スクリプトは `png.py` / `analyze.py` 相当の処理＝目で見た推定値は使っていない）。

## 4. 長押しメニューの作り（選択モードの操作バー）

**開き方**: 吹き出しの中心を同じ座標で1秒押す（`adb shell input swipe <x> <y> <x> <y> 1000`）。
**閉じ方**: 戻る（`keyevent 4`）。**項目は1つも選んでいない**（手順書 §0-5）。閉じた後に構造データを再取得し、選択モードの部品（`action_mode_close_button`）が消えていること・会話の画面に戻っていることを確認した。

長押しすると、上部バーが**選択モードの操作バー**に置き換わる。項目は左端の閉じるボタンを含めて6つ。

| 項目（アプリのUI表記） | 位置(x,y)px | 大きさpx | 大きさdp |
|---|---|---|---|
| 閉じる（`action_mode_close_button`） | 0,123 | 168x144 | 56x48 |
| 返信 | 384,123 | 144x144 | 48x48 |
| メッセージにスターを付ける | 528,123 | 144x144 | 48x48 |
| 削除 | 672,123 | 144x144 | 48x48 |
| 転送 | 816,123 | 144x144 | 48x48 |
| 他のオプション（`menuitem_overflow`） | 960,123 | 120x144 | **40x48（横幅が44dp未満）** |

**設計の要点**: 操作は**画面上部の帯に横並び**で置かれ、吹き出しの近くにポップアップを出す方式ではない。アイコンは48x48dpで揃い、間隔はアイコン幅と同じ144px刻み（x=384/528/672/816/960）。選択モードに入っても**入力欄はそのまま残る**。

## 5. 取り扱いの注記

この画面の構造データには**電話番号を含む部品**（相手情報のヘッダーの説明文）が存在する。本メモは部品表に文字情報を一切出力しない作りにしているため混入していないが、生データは引き続きリポジトリ外に置く。
