# WhatsApp — 配色の構造（色そのものではなく、役割と面積比）

> この文書は何か（専門用語なしの1行）: どの色を何に使い、画面のどれだけを占めさせているかという「配色の組み立て方」の記録。salesanchor のネイビー＋白に写すための参照。

親: [README.md](README.md) / 寸法: [whatsapp-reproduction-spec.md](whatsapp-reproduction-spec.md)

- 記録日: 2026-10-11 / PO の方針: **salesanchor のテーマカラーはネイビーと白。色は移さず、配色の組み立て方だけを参照する**
- 測り方: 写真の画素を3px間隔で標本化し、色ごとの出現率を数えた（`PIL` + `numpy`）。明度差は WCAG の計算式で算出した。
- ライトモードの取得について: 端末を一時的にライトへ切り替えて撮影し、**撮影後にダークへ戻した**（`adb shell cmd uimode night no` → 撮影 → `night yes`。戻したことを `cmd uimode night` の出力で確認済み）。

## 1. 最大の発見 — 明暗を切り替えても面積比が変わらない

会話一覧の画面全体で、色ごとの出現率を測った結果。

| 役割 | ダークの色 | 占有率 | ライトの色 | 占有率 |
|---|---|---|---|---|
| **画面の地** | `#0a1014` | **79.7%** | `#ffffff` | **79.6%** |
| **2段目の面**（入力欄・検索欄） | `#23282c` | **5.2%** | `#f6f5f4` | **5.2%** |
| 輪郭・影の黒 | `#000000` | 1.7% | `#000000` | 1.7% |
| **強調色（濃）** | `#21c063` | **1.5%** | `#1daa61` | **1.7%** |
| 主要文字 | `#f7f8fa` | 1.4% | （黒系） | — |
| 補助文字 | `#8d9599` | 1.1% | `#5b6368` | 1.1% |
| 強調色の薄い面（選択中のタブの下地） | `#103529` | 0.5% | `#d9fdd3` | 1.0% |

**地が79.6%と79.7%、2段目の面が5.2%で両モード同一、強調色が1.5%と1.7%。** 偶然では一致しない。つまり配色は「色の集まり」ではなく**役割ごとの面積比**として設計されていて、明暗の切替は**同じ役割に別の色を差し替えるだけ**で行われている。

## 2. 配色の組み立て方（5つの決まりとして読み取れること）

1. **画面の80%は1色**。地の色を1つ決め、それで画面の大半を埋める。
2. **面は2段だけ**。地（80%）と、その上の面（5%）。2段目は**入力欄と検索欄にしか使っていない**。カードごとに面を増やしていない。
3. **強調色は画面の1.5〜1.7%**。送信ボタン・未読バッジ・選択中の印だけ。**面として広く塗らない。**
4. **文字は2段**（主要＋補助）で合わせて2.5%。3段目（さらに薄い文字）は見当たらない。
5. **強調色には「濃い版」と「薄い面の版」の2つを持つ**。濃い方は丸いボタンとバッジ、薄い方は選択中のタブの下地（1%以下）。

## 3. 文字と面の明度差（WCAG比・4.5:1が本文の基準）

| モード | 組み合わせ | 比 |
|---|---|---|
| ライト | 主要文字 `#12181c` / 面 `#ffffff` | **17.9:1** |
| ダーク | 主要文字 `#f7f8fa` / 地 `#0a1014` | **18.0:1** |
| ダーク | 主要文字 / 入力欄 `#20272b` | 14.3:1 |
| ライト | 補助文字 `#5b6368` / 入力欄 `#f6f5f4` | 5.6:1 |
| ライト | 強調色 `#1daa61` / 面 `#ffffff` | **3.0:1** |
| ダーク | 強調色 `#21c063` / 地 `#0a1014` | 8.0:1 |

**要点**: 主要文字の明度差が**ライト17.9:1・ダーク18.0:1でほぼ同一**。明暗で読みやすさを変えていない。

一方、ライトの強調色は **3.0:1 で本文の基準に届かない**。だから**強調色を文字色として使っていない**（緑はボタンの地と小さな印にしか使われていない）。

## 4. salesanchor（ネイविー＋白）への写し方

salesanchor の現行トークン（`frontend/src/index.css`）の明度差を同じ式で測った。

| 組み合わせ | 比 | 判定 |
|---|---|---|
| 主要文字 `#1a202c` / 面 `#ffffff` | 16.3:1 | WhatsApp（17.9:1）と同水準 |
| 補助文字 `#4a5568` / 面 | 7.5:1 | 十分 |
| 非強調 `#718096` / 面 | **4.0:1** | **本文の基準4.5:1に届かない** |
| ネイビー `#1e3a8a` / 面 | **10.4:1** | WhatsApp の緑（3.0:1）より**はるかに強い** |
| 白 / ネイビー `#1e3a8a` | 10.4:1 | 両方向で成立 |

### 役割の対応表（案・design.md で決める）

| 役割 | WhatsApp の面積比 | salesanchor の割り当て案 |
|---|---|---|
| 画面の地（80%） | 1色 | `--bg-surface #ffffff`（行・カード）。ページ地の `--bg-primary #f5f7fa` と2つあるため**どちらを「地」にするか決める必要がある** |
| 2段目の面（5%） | 入力欄・検索欄のみ | `--bg-subtle #f7fafc` を**入力欄と検索欄に限定**する |
| 主要文字 | 1.4% | `--text-primary #1a202c` |
| 補助文字 | 1.1% | `--text-secondary #4a5568`。`--text-muted #718096` は4.0:1なので**本文には使わない** |
| 強調色・濃（1.5%） | 丸いボタン・バッジ | `--accent #1e3a8a`（ネイビー）。**使用面積を1.5〜2%に抑える** |
| 強調色・薄い面（1%以下） | 選択中の下地 | `--link-active-bg #ebeff8` が相当 |

### ここで分かる差（事実。対処は design.md で設計する）

1. **salesanchor は面の段が多い**。`--bg-primary` / `--bg-surface` / `--bg-subtle` / `--bg-hover` / `--bg-active` の5段に対し、WhatsApp は実質**2段**。段を増やすほど「どれを使うか」の判断が必要になり、ばらつきの原因になる。
2. **ネイビーは緑より強い（10.4:1 対 3.0:1）**。WhatsApp は緑が弱いため文字色に使えず、ボタンの地と小さな印に限定している。ネイビーは文字色にも面にも使えるので、**同じ割合で使うと画面が重くなる**。面積比1.5〜2%という上限は、色の強さに関わらず守る価値がある。
3. **`--text-muted #718096` は4.0:1**で本文の基準を満たさない。WhatsApp は文字を2段しか持たない。3段目を持つなら用途を「本文以外」に限る決まりが必要。

## 5. 取得にあたって触った設定（記録）

端末の表示モードを一時的にライトへ切り替えた（`cmd uimode night no`）。**撮影後にダーク（`night yes`）へ戻し、出力で確認した**。WhatsApp アプリ内の設定は変更していない（システムに追従したため）。
