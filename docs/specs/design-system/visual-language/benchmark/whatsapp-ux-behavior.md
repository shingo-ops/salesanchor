# WhatsApp — 操作感（動き・速さ・画面のつながり）

> この文書は何か（専門用語なしの1行）: 押したときに何が起きるか、どれくらいの速さで起きるかを数字にした記録。見た目ではなく「使った感じ」の記録。

親: [README.md](README.md) / 見た目の寸法: [whatsapp-reproduction-spec.md](whatsapp-reproduction-spec.md)

- 記録日: 2026-10-11 / 端末: 1080x2340px・密度480dpi
- 録画は使っていない（この端末に動画を解析する道具が無いため）。代わりに**Androidが持つ描画フレームの記録**（`dumpsys gfxinfo <アプリ> framestats`）と**端末内で計った経過時間**を使った。

## 取得に使ったコマンド

```bash
# 画面の書き換え速度と、操作中の全フレームの時刻
adb shell dumpsys gfxinfo com.whatsapp reset   # 記録をリセット
adb shell input tap <x> <y>                    # 操作を1回だけ行う
adb shell dumpsys gfxinfo com.whatsapp framestats

# アプリを開くまでの時間（Android標準の計測）
adb shell am start -W -n com.whatsapp/.Main

# タップから目的の画面が出るまでの時間（端末内で計測。adb往復の影響を受けない）
adb shell 'T0=$(date +%s%N); input tap <x> <y>; while :; do \
  case "$(dumpsys window | grep -m1 mCurrentFocus)" in *Conversation*) \
  echo $(( ($(date +%s%N)-T0)/1000000 )); break;; esac; done'
```

`framestats` の列は `IntendedVsync`（描き始める予定の時刻）と `FrameCompleted`（描き終わった時刻）を使い、ナノ秒からミリ秒に換算した。50ms以上の間隔が空いたところで区切り、連続して描いている区間を「ひとまとまりの動き」として数えた。

## 1. 画面の書き換え速度

| 項目 | 実測 |
|---|---|
| フレーム間隔 | **8.33 ms** → **120 Hz の画面** |
| 1フレームの処理時間 | 中央値 **3.3 ms** / 平均 4.1 ms / 最大 36.3 ms |
| 8.33ms を超えたフレーム | 7 / 113 件 |

**要点**: 1フレームあたりの予算は8.33msで、WhatsApp は中央値3.3msで描いている（予算の4割）。余裕を持って作られている。

## 2. 操作ごとの速さ

| 操作 | 連続して描いたフレーム数 | かかった時間 |
|---|---|---|
| アプリを開く | — | **54 ms**（`am start -W` の WaitTime） |
| 一覧の行をタップ → 会話の画面が出る | — | **98 ms**（端末内で計測） |
| 会話を開く動き（描画が落ち着くまで） | 108 | **586 ms** |
| **戻る（会話 → 一覧）** | 10 | **85 ms** |
| タブ切替（チャット → コミュニティ） | 76 | **628 ms** |
| タブ切替（コミュニティ → チャット） | 76 | **628 ms** |

**要点1**: **戻るが圧倒的に速い**（85ms）。開くとき（586ms）の7分の1。戻る操作には動きをほとんど付けず、即座に前の画面を出している。

**要点2**: タブ切替は**両方向で76フレーム・628msが完全に一致**した。偶然ではなく、決まった長さの動きが設定されている。

**注意（この数値の限界）**: 「連続して描いた区間」は**動きそのものと中身の読み込みの両方**を含む。動きだけの長さは分離できていない。また、動きの**向き（横からスライドか、重なって出るか）や加減速の曲線**は、この方法では取れない。取るには画面の動きを遅くする設定変更（開発者向けオプションのアニメーション速度）が必要で、PO の許可が要る。

## 3. タップ数と画面のつながり

| 今いる画面 | 操作 | 行き先 | タップ数 |
|---|---|---|---|
| 会話一覧 | 行をタップ | 会話の画面 | 1 |
| 会話一覧 | 行の**顔写真**をタップ | プロフィール写真（行とは別の当たり判定） | 1 |
| 会話一覧 | 下部ナビをタップ | 別のタブ | 1 |
| 会話一覧 | 右上の︙ | メニュー（6項目・入れ子なし） | 1 |
| 会話の画面 | 戻る | 会話一覧 | 1 |
| 会話の画面 | 上部バーの相手名をタップ | 連絡先情報 | 1 |
| 会話の画面 | 右上の︙ | メニュー（8項目・入れ子なし） | 1 |
| 会話の画面 | 吹き出しを長押し | 選択モード（上部バーが置き換わる） | 1（長押し） |
| 別の会話に移る | 戻る → 行をタップ | 会話の画面 | **2** |

**画面の深さは3段**（一覧 → 会話 → 連絡先情報）。メニューに入れ子（サブメニュー）は無い。

## 4. 当たり判定が入れ子になっている

会話一覧の行は、**押せる範囲の中にもう1つ押せる範囲がある**。

- 行全体（360x76dp）をタップ → 会話を開く
- その中の顔写真の列（72x68dp）をタップ → プロフィール写真

つまり「行はまるごと押せる」を守りながら、顔写真だけは別の行き先を持たせている。再現するときはこの入れ子を再現しないと操作感が変わる。

## 5. 状態の変化（観測できたもの）

| 変化 | 観測 |
|---|---|
| 未読 → 既読 | 会話を開く前は行に未読バッジ（20x20dp）があり、開いた後は**その部品が構造データから消えた**。行の高さは変わらない |
| 通常 → 選択モード | 長押しで**上部バーだけが置き換わる**。入力欄・吹き出し・下の余白はそのまま残る。画面遷移は起きない |
| 選択モード → 通常 | 戻るで解除。選択モードの部品（`action_mode_close_button`）が消えることで確認した |

## 6. 中身が無いときの画面（空の状態）

| 画面 | 空のときに出るもの |
|---|---|
| コミュニティのタブ | 絵（228x212dp）＋ 見出し ＋ 説明 ＋ 行動を促すボタン（312x48dp）＋ 「例を見る」リンク。部品は58個 |
| メッセージが0件の会話 | 相手の案内カード（`info` 286x78dp）と `contextCardLayout`（300x310dp）。**吹き出しは0個**で、長押しの対象も存在しない |

**要点**: 空のときに「何も無い」とは出さず、**絵・説明・次にやることのボタン**を必ず置いている。

## 7. アプリを開き直したときの挙動

`am start com.whatsapp/.Main` でアプリを前に出すと、**常にコミュニティのタブ**が選ばれた状態になる（`community_fragment` の有無で確認）。直前に見ていたタブを覚えていない。チャット一覧を出すには下部ナビを1回押す必要がある。

## 8. 割り込みの作法

会話の上部バーから連絡先情報へ進む途中で、**プライバシーのお知らせ**が下から被さって出た（`PrivacyDisclosureContainerActivity`）。

- 形: 下から出るシート。つかみ手（`wds_bottom_sheet_handle_view` 32x24dp）＋ 見出し ＋ 箇条書き3つ ＋ 脚注 ＋ 全幅のボタン（312x48dp）
- 作法: **目的の画面は裏で既に開いており**、お知らせを閉じるとそのまま目的の画面が現れた。目的地へ行く前に別画面へ飛ばすのではなく、**目的地の上に重ねている**

この OK ボタンは設定変更に当たる恐れがあるため押していない（戻るで閉じた）。

## 9. この文書で取れていない操作感

| 項目 | 理由 |
|---|---|
| 動きの向きと加減速（横スライドか・曲線か） | フレームの時刻は取れるが絵の変化は追えない。画面の動きを遅くする設定変更が必要で PO 許可待ち |
| スクロールの手触り（慣性・端での跳ね返り） | スクロールは手順書 §0-4 の許可された4操作に含まれない。PO 判断が必要 |
| 読み込み中の表示 | 観測できる場面を作れていない（1度だけ一覧が「読み込み中…」に戻る現象を段階1で観測済み） |
| エラー時の表示 | 意図的に失敗させる操作が禁止されているため取得不能 |
| キーボードが出たときのレイアウト変化 | キーボードを開く操作が §0-3 で禁止。PO 判断が必要 |
| 送信したときの反応 | 送信は §0-5 で禁止 |
