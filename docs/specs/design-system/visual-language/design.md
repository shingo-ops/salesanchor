## 1. 目的（PO原文の要約。原文は ideal-state.md）
- 金型（`frontend/src/components/`）を美しくし、その結果として全画面の見た目を良くする。
- ベンチマークは Meta Business Suite と WhatsApp。メッセージ型の画面を、PCでもスマホでも使いやすくする。
- 色はネイビーと白を維持する。
- 範囲はフロントエンドの使い勝手のみ。DB・API・配線は触らない。

## 3. 現状（recon の要点。詳細と根拠は recon.md）

## 4. 方針: 3層を分け、正本を増やさない
1. **値**: `tokens.css` と `index.css`。既存の正本のまま。新しい値は親テーマの手順で追加する（例: 行間・字間の段）。
2. **金型**: `components/`。既存の正本のまま。直すのはここで、ページ側で見た目を上書きしない。
3. **組み合わせ方（このテーマの成果物）**: 次の4点を、トークン名と金型名だけで書く。値は書かない。
   - 文字の役割の使い分け
   - 余白のリズム（部品の内側・部品の間・区画の間に、どの段を使うか）
   - 密度（一覧の1行の高さなど）
   - 画面幅ごとの並び方（スマホ: 1列で画面を切り替える／タブレット／PC: 一覧・会話・詳細の3列）

## 5. ベンチマークの読み取り（PO決定: スマホ内で記録する案A）
- 方式: 人が押し、AIは記録する。スマホのClaude Codeが Termux の adb で、画面写真・部品の構造・画面録画を撮る。手順は承認済み計画の「案Aの手順書」。AIによるタップと入力は禁止する。
- 最初の1画面で、写真が黒くないか、構造データに部品が出ているかを確かめる。どちらかがダメならそこで止めて、POに相談する。
- 元データには顧客の情報が含まれうる。リポジトリに入れず、観察メモを作ったら削除する。観察メモには数値と構造だけを書き、このフォルダ内の観察メモ（ファイル名は作成時に決める。現在は未作成）に置く。
- 観察メモはあくまで参考資料で、他社の値をそのまま写すことはしない。採用する値は既存トークンの段に当てはめる。当てはまる段がない場合は、トークン追加の提案としてPOに諮る。
