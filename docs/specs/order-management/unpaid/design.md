# design:受注管理(未入金)— 未入金案件の見せ方

> この文書は何か(素人向け1行説明):未入金ページで、何を先に見せ、どこから催促や入金確認へ進めるかを定める設計書です。

親(あるべき姿+KGI)へのリンク: [README.md](./README.md)

## 1. スコープ
本designは未入金ページの見せ方のみを定める。請求書発行後の未入金案件を一覧で追い、催促と入金確認を迷わず実行できる状態を作る。

## 2. recon(現状把握)
PO指示(2026-07-06)により、現行UIとの突合はこのdesignでは行わない。現状との差分把握が必要なら実装便のreconで扱う。

## 3. 設計判断(6点)
1. ページの先頭に、未入金件数・期限超過件数・本日期限件数の要約を置く。
2. 一覧の主列は、顧客名・請求書番号・金額・支払期日・残日数・最後の連絡・次の操作とする。
3. 残日数は期限が近いほど強く、期限超過は最も強く見える状態にする。
4. 各行には、催促メッセージ作成、入金確認、メモ追記、請求書確認の入口を置く。
5. 催促の入口は一覧上の行内アクションを主導線とし、詳細パネルでも同じ操作を繰り返せるようにする。
6. 入金確認が完了した注文は未入金一覧から消え、親テーマの次ステータスへ置き換わる。

## 4. 図解の扱い
この子テーマでは本文を正本とし、図解は必要になった時点で親テーマの共通骨格に合わせて追加する。

## 5. 弊害・トレードオフ
1. 行内アクションを増やすほど一覧は賑やかになるが、未入金は処理速度が重要なので操作導線を優先する。
2. 要約カードを置くと一覧の密度は下がるが、期限超過の見落としを減らせる。
3. 詳細パネルを持つと画面は広く使うが、メモと催促文の確認が速くなる。

## 6. 受入基準
- KGI K1〜K5 を満たすこと。
- 未入金から入金確認へ進める導線が一覧と詳細の両方から分かること。
- 期限超過案件が一目で分かること。

## 7. 維持の仕組み
- 本designの変更は README と kgi.md と同時に見直す。
- 行内アクションの追加・削除は、未入金の処理速度に影響するため、PRで差分を明示する。
