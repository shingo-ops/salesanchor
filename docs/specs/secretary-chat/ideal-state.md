## PO の言葉（2026-11-01 チャット）

- 「テナント001と004二だけアプリにチャットアイコンを右下に出して押すとチャットボットと話すメニューが開く機能を付けられる？VPS内にサブスクでclaude codeやcodex、grokが呼び出せる環境を作るのであればアプリのフロントエンドにチャットしながら依頼ができるメニューを作ってほしい、理解できる？」
- Opus が「（１）3社の約束を読んで、月額の契約でこの使い方ができるか確かめる（２）本番のサーバーに置いてよいか、外に置くほうがよいかを比べる」と示した。
  - PO の回答は「（１）…→禁止　（２）…→サーバーの中に置くが安全面も考慮する、例えば004のAIは他のテナントに干渉できない、001も001以外のデータには干渉できない」。
- 約束を調べずに月額の契約で動かした場合のおそれについて、PO は「規約違反に該当した場合にどう見つかる？」「サーバーから使った場合にサーバーから使ってると判断される？」と質問した。
- 「ちなみに今のVPSのメモリとディスクで動く？」
- 「チャットボットとして使うなら足りる？チャットボット件、Aさんの請求書作ってとか〇〇のデータを〇〇してとか依頼したらやってくれる、これをスケジュールに追加してって依頼したらスケジュール入れてくれたり秘書と営業事務の2役をチャットボットとして担当してほしい」
- Opus が「作る前に下書きを見せ、『作る』ボタンを押したら作る」形を示した。
  - PO の回答は「1」（その形にする）。
- Opus が最初にチャットを使える人を「しんごさんだけで始めて、うまく動いたら広げる」「001と004の管理者の人たち」「001と004の全員」から選ぶよう尋ねた。
  - PO の回答は「1」（しんごさんだけで始めて、うまく動いたら広げる）。
- 進め方について（このテーマにも適用）:「推測は禁止して事実確認を怠らずに確実性を重視して最も効果があり、現状把握の粒度が細く、精度が高いエビデンスを確立して安全に進めてくれ。また配線とDBのSSOTは遵守してデータを分散させることは禁止。フロントエンドのパーツもデザイントークンとデザインシステム を遵守して、金型登録のないハードコードを禁止する。推測で自身で判断したり不透明無まま進めることは禁止、分からないことは聞いてくれ。確立したなら進める。」
- 説明について:「非エンジニアの素人にも理解できるように分かりやすく説明してくれ。」
- Opus が合格の基準 K1〜K6（kgi.md）で決めてよいかを尋ねた。
  - PO の回答は「1」（この6つで決める）。同じ返事で次を指示した:「離席するので、このセッションだけで最後まで完結させる。設計者はopus,調査と実装者はsonnetと分担させてサブエージェントを展開、haikuは不具合が起きるため使用を禁止。GO記録やSSHへの無制限鍵へのアクセス等、必要な権限は全て必要な場合は使用して良い許可を与える。PRマージ、デプロイまで完走させてくれ。」
