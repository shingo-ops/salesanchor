# KGI — ログイン方式

この文書は、「ログインを自社サーバーに移し、顔・指紋でもログインできる」が達成できたかを ○× で判定する条件です。

親: [README.md](README.md)

状態: PO 承認済み（2026-10-13 チャット「y」。設計 design.md と同時に承認）。中身は PO の回答（2026-10-13「y,新規パスワードを発行する…」「n」「n,二段階認証は次の便で…」「y」＝発行は使用中の全員）を反映

## KGI（○× で判定）

| # | 条件 | 判定のしかた |
|---|---|---|
| K1 | 移行のとき、public.users で使用中（is_active=true）の全員（2026-10-13 時点 10 人。再設定メールの試験用に作る試験ユーザー 1 人は含まない）に新しいパスワードを発行し、PO の Mac のファイル（PO のアカウントだけが読める）に書き出す。全員がそのパスワードでログインできる（失敗 0 人） | ファイルの行数＝対象者数。切替後に last_login が更新された使用中の人数＝対象者数 |
| K2 | 登録した端末で、パスワードを打たずに顔か指紋だけでログインできる | 本番で PO の端末 1 台で実演（画面録画）。データベースに登録 1 行 |
| K3 | ログイン情報（パスワードの暗号化データ・パスキー）は自社データベースの決まった表にだけあり、Firebase の登録ユーザーは 0 人 | Firebase の書き出しで総数 0。DB の該当表の行数 |
| K4 | パスワードを忘れた人・端末をなくした人が、ログイン画面からメールを送り、届いたリンクで自分で新しいパスワードを設定してログインできる | 試験ユーザーで実演。リンクは 1 回使うと無効・期限切れも無効 |
| K5 | K4 のメールは自社の送信設定（salesanchor.jp のアドレス）から送られ、Gmail の受信箱に届く（迷惑メールに入らない） | Gmail の試験アカウントで受信箱を目視。メールのヘッダで SPF・DKIM・DMARC が pass |

## 今回の範囲の外
- 二段階認証（認証アプリ）は次の便で、任意で設定する項目として追加する（PO 2026-10-13）

## 変えない約束

- 人の正本は public.users.id（ADR-1008）。ログイン情報は users に紐づけ、別の場所に人の名簿を作らない
- テナントの判定はデータベースの user.tenant_id のまま
- 画面は components/ の金型・デザイントークン・i18n（ja/en 同一キー）を使う。金型の無い部品は作らない（必要なら金型を先に登録）
