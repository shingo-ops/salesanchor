# KGI — ログイン方式

この文書は、「ログインを自社サーバーに移し、顔・指紋でもログインできる」が達成できたかを ○× で判定する条件です。

親: [README.md](README.md)

状態: PO 承認済み（2026-10-13 チャット「y」。設計 design.md と同時に承認）。中身は PO の回答（2026-10-13「y,新規パスワードを発行する…」「n」「n,二段階認証は次の便で…」「y」＝発行は使用中の全員）を反映

## KGI（○× で判定）

| # | 条件 | 判定のしかた |
|---|---|---|
| K1 | 移行のとき、public.users で使用中（is_active=true）の全員（2026-10-13 時点 10 人。再設定メールの試験用に作る試験ユーザー 1 人は含まない）に新しいパスワードを発行し、PO の Mac のファイル（PO のアカウントだけが読める）に書き出す。全員がそのパスワードでログインできる（失敗 0 人） | ファイルの行数＝対象者数。切替後に last_login が更新された使用中の人数＝対象者数 |
| K2 | 登録した端末で、パスワードを打たずに顔か指紋だけでログインできる | 本番で PO の端末 1 台で実演（画面録画）。データベースに登録 1 行 |
| K3 | ログイン情報（パスワードの暗号化データ・パスキー）は自社データベースの決まった表にだけあり、Firebase の登録ユーザーは 0 人 | Firebase の書き出しで総数 0。DB の該当表の行数 |
| K4 | パスワードを忘れた人・端末をなくした人が、ログイン画面からメールを送り、届いたリンクで自分で新しいパスワードを設定してログインできる | 試験ユーザーで実演。リンクは 1 回使うと無効・期限切れも無効 |
| K5 | K4 のメールは自社の送信設定（salesanchor.jp のアドレス）から送られ、Gmail の受信箱に届く（迷惑メールに入らない） | Gmail の試験アカウントで受信箱を目視。メールのヘッダで SPF・DKIM・DMARC が pass |

## 今回の範囲の外
- 二段階認証（認証アプリ）は次の便で、任意で設定する項目として追加する（PO 2026-10-13）

## 変えない約束

- 人の正本は public.users.id（ADR-1008）。ログイン情報は users に紐づけ、別の場所に人の名簿を作らない
- テナントの判定はデータベースの user.tenant_id のまま
- 画面は components/ の金型・デザイントークン・i18n（ja/en 同一キー）を使う。金型の無い部品は作らない（必要なら金型を先に登録）

## KGI 追加 — パスキーの自動の候補（PO 承認 2026-11-24 チャット「1」）

あるべき姿: [ideal-state.md](ideal-state.md)「2026-11-23〜24」。引き継ぎ: [../../handoff/passkey-autofill-first/](../../handoff/passkey-autofill-first/)

| # | 条件 | 判定のしかた |
|---|---|---|
| P1 | PO の Mac の Chrome・iPhone の Safari・Android の Chrome の3台で、ログイン画面のメール欄を押すとパスキーの候補が出る。選んで顔か指紋だけで、パスワードを打たずにログインできる | PO の目視（3台）。本番 public.auth_events に passkey/login/verify の成功が PO の id で3台分（user_agent が Mac・iPhone・Android）ある |
| P2 | Chrome（149 以降）で、その機械にパスキーがあるとき、「パスキーでログイン」を押すと、すぐ顔・指紋の画面が出る（「スマホで読み取る」等の選ぶ画面を挟まない） | PO の Mac の Chrome で目視 |
| P3 | Chrome（149 以降）で、その機械にパスキーが無いとき、同じボタンを押すと「この機械にはパスキーがありません」と画面に出る。そこからスマホで読み取ってログインする道も残る | PO の Mac の Chrome のシークレット窓（Chrome は必ず「無い」扱いにする）で目視 |
| P4 | Safari・iPhone・Chrome 148 以前では、「パスキーでログイン」ボタンは今と同じ動きのまま | PO の iPhone で目視 |
| P5 | パスワードでのログインは今と同じに使える。反映後14日間、毎朝の自動点検のログインが毎日成功する | 本番 public.auth_events の自動点検の係のログイン成功が14日すべてにある |
| P6 | 表も列も増やさない（ブラウザが持つパスキーの情報だけを使う） | PR の差分に migrations が無い |
| P7 | 画面の文字は ja・en の両方にあり、部品は components/ の金型とデザイントークンだけを使う | CI の i18n・UI ガバナンスの必須チェックが緑 |

### KPI（目安・判定は KGI）

### 変えない約束（この追加分）
- サーバーのパスキーの設定（名前ごと保存・本人確認必須・候補を端末に任せる）は変えない
- 知らない機械の確認（ADR-1055）の決まりは変えない
