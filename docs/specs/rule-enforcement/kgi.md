## KGI（2026-10-27 PO 承認・○×で判定）

| # | KGI | 判定 |
|---|---|---|
| G1 | 決まりの文書にある「〜禁止」「必ず〜」をすべて書き出し、1つずつ「機械で止める」か「止めない（理由）」に仕分ける。未仕分け 0 件 | 決まりの文書の中で決まりの語を含む行が、全部どれかの台帳項目か「決まりではない（理由）」に振り分けられている（台帳検査が数える） |
| G2 | 「機械で止める」と決めた決まりごとに、わざと違反した変更が取り込みの関所で止まり本番に出ない。手元の Claude・人の手・ほかの AI・クラウドの AI の経路でも同じ | 違反の見本の試験が全件「止まった」、経路ごとの試しの PR が BLOCKED |
| G3 | 関所を素通りできる立場が 0。例外を残すなら PO が名前を承認した分だけで、使われたら知らせが届く | 現在の素通りできる立場の一覧＝PO 承認済みの一覧 |
| G4 | 関所と同じ検査を提出の前にも自動で走らせ、わざと違反した変更が提出の前に「違反あり」と分かる | 台帳で「提出前に分かる」とした全項目で、違反の見本に提出前の検査が失敗を返す |
| G5 | 新しい決まりを足すとき、仕分けを決めないと取り込めない | 決まりの文書に決まりの行を足し台帳を変えない試しの PR が BLOCKED |

## PO 確認待ち（設計審査1回目で見つかった範囲の確認）

1. 決まりの文書（G1 で数える範囲）: AGENTS.md、CLAUDE.md、frontend/AGENTS.md、backend/AGENTS.md、frontend/CLAUDE.md、backend/CLAUDE.md、docs/STANDARD-WORKFLOW.md、docs/ai-agents/ 配下の全 .md、docs/specs/branch-operations/README.md。ADR は数えない（理由: 日々の作業に効く決まりは上の文書に書き写す決まりで、ADR は経緯と理由の記録）
2. 素通りの範囲（G3）: 「素通りできる立場」に、本番に触れる main 以外の道も数える
   - 本番の鍵（本番のサーバー・DB・外部サービスに届く鍵。名前の一覧は R0 で確定して PO が承認）は、main からしか使えないようにする。recon 時点で見つかった手動起動 6 本に限らず、push や PR で動く自動作業も含む
   - 本番の VPS と PO の Mac にある自前の実行機（GitHub の自動作業を動かす機械）も、鍵が無くても本番や PO の Mac に届く道として数える。フォークからの PR で動く道も含む
   - PO 名義の強い鍵（PIPELINE_PAT）も素通りの道として数え、扱いを PO が決める
   - PO 本人の VPS 直接作業と、PO 本人による関所の設定変更は、PO だけの例外として残し、関所の設定変更は週次点検で知らせる

- develop ブランチ（本番に出ない。新規作業での使用は禁止済み `docs/specs/branch-operations/README.md:97-103`）
