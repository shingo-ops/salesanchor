1. はじめに（30秒でわかる要点）

この資料は、salesanchor を「外部のサービスと自動でつなぐ（＝連携する）」ために必要な手順を、各社の公式情報から調べてまとめたものです。つなぐ相手は大きく2つのグループに分かれます。

  • 書類の保管 … Googleドライブ。請求書・発注書・送り状などの PDF や一覧データ（CSV）を自動で保存します。
  • 配送 … 送り状の発行・送料の確認・荷物の追跡などを自動化します。海外3社（FedEx・DHL・UPS）と国内2社（ヤマト運輸・佐川急便）が対象です。
いそがしい人向け・結論
  1. まずは Googleドライブ への自動保存から始めるのが一番ラクです。
  2. 配送は、いきなり全自動にせず、まず 「CSVファイルの受け渡し」 から始めると早く効果が出ます。
  3. 国内2社（ヤマト・佐川）は契約や打ち合わせに 数か月 かかります。使う予定があるなら早めに相談を。

2. かんたん用語集

この資料に出てくる言葉を、ざっくり説明します。

API（エーピーアイ）
サービスとサービスが自動でやり取りするための「窓口」。人が画面をポチポチ操作しなくても、システム同士が直接データを渡し合えるようになります。
連携
2つのサービスを自動でつなぐこと。「salesanchor とヤマトを連携する」＝両者がデータを自動でやり取りできる状態にする、ということ。
法人契約 / アカウント
各社と結ぶ「会社としての利用契約」。配送各社は、この契約がないと連携できません。
送り状（ラベル）
荷物に貼る伝票のこと。
CSV（シーエスブイ）
Excel で開ける一覧データのファイル。全自動でなくても、ファイルを受け渡しするだけで連携できる場合に使います。
練習用環境 / 本番環境
テスト用の環境（練習用）と、実際にお客様の荷物を動かす環境（本番）。多くのサービスは練習用で試してから本番に切り替えます。
認証
「正しい利用者かどうか」を確認する仕組み。鍵や合言葉のようなものだと思ってください。

4. おすすめの進め方

いきなり全部つなぐのではなく、ラクで効果の大きいものから順番に進めるのがおすすめです。

  1. ステップ1：Googleドライブへの自動保存（一番早い・手続きも軽い）
    すでに Google カレンダー連携で使っている Google の仕組みをそのまま使えるため、追加の手間が小さく済みます。これで請求書・発注書・送り状などの「保存場所」が決まります。
  2. ステップ2：海外3社（UPS・FedEx・DHL）の連携
    UPS と FedEx は自分たちで登録できて早いです。FedEx の「送り状発行」だけはサンプル提出 → 審査（約3営業日）が必要。DHL は申込のあとに DHL 側の承認が入ります。
  3. ステップ3：国内2社（ヤマト運輸・佐川急便）
    どちらも契約＋打ち合わせ＋数か月の準備期間＋利用料がかかります。すぐにはつなげません。まずは 「CSVファイルの受け渡し」（ヤマト B2クラウド／佐川 e飛伝Ⅲ）から始め、全自動の連携は本格運用に入ってから追加します。
送料の自動計算について：海外3社は送料を自動で取り出せますが、国内2社（ヤマト・佐川）は送料を自動計算する公式の窓口が見当たりません。そのため、料金表（運賃表）を salesanchor 側に持たせて計算する想定になります。

5. Googleドライブ

Googleドライブ

難しさ 低 ★
ひとことで：請求書・送り状などの PDF/CSV を自動でドライブに保存できます。今回の中で一番ラクに始められる連携です。

何ができる

  • 書類（請求書・発注書・送り状の PDF/CSV）を自動でアップロード
  • フォルダの自動整理／共有リンクの発行／ファイル検索

始めるのに必要なもの

  • Google の管理画面での設定だけ。すでに Google カレンダー連携で使っている Google の仕組みをそのまま流用できるので、新しい申請はほぼ不要です。
  • 今のところ標準利用は無料です。

進め方

  1. Google の管理画面でドライブ機能をオンにする
  2. 保存方法を選ぶ（下の2通り）
  3. （必要に応じて）公開のための確認手続き

保存方法は2通り

方法A. 各社それぞれのドライブに保存B. 自社専用の共有ドライブにまとめて保存（おすすめ）
どこに保存利用企業ごとの Google ドライブ自社で管理する共有ドライブ
手続き会社ごとに許可をもらう必要あり自社内で完結するので手続きが軽い

期間・費用

  • 期間：すぐ〜数日。
  • 費用：いまは基本無料。※2026年内に「使いすぎた分だけ課金」する仕組みが始まる予定（90日前に告知あり）。

注意したいこと

❗ 保存先のおとし穴：「自社専用の保存用アカウント」は、それ自体が保存容量を持てない仕組みです。そのため個人用ドライブには直接書き込めません。必ず「共有ドライブ」に保存する形にします（ここを間違えるとエラーになります）。
💡 ポイント：大量の書類を一気に保存すると上限に当たることがあるため、少しずつ順番に送る作りにしておくと安全です。

6. FedEx

FedEx

難しさ 中 ★★
ひとことで：海外発送の送料確認・送り状発行・追跡を自動化できます。自分たちで登録できますが、送り状発行だけは審査があります。

何ができる

  • 送料と日数の見積（日本 → 海外）
  • 国際送り状＋税関書類の発行
  • 荷物の追跡／集荷依頼

始めるのに必要なもの

  • FedEx の法人配送契約（アカウント番号）

進め方

  1. 開発者向けサイトで登録（無料）
  2. 会社情報・配送アカウントを登録
  3. 使うメニューを選ぶ → 練習用の鍵が発行される
  4. 本番へ切り替え

期間・費用

  • 期間：アカウントがあれば数日〜。ただし送り状発行（ラベル）はサンプルを提出して審査（約3営業日）が必要です。
  • 費用：連携の利用自体は無料。配送料は実費。

注意したいこと

⚠️ 期限：古い接続方式は2026年6月1日で終了予定です。新しく作る場合は最初から新方式なので影響はありません。

7. DHL

DHL

難しさ 中 ★★
ひとことで：「MyDHL API」という1つの窓口で、見積・送り状・追跡・集荷・関税の見積まで全部まかなえます。

何ができる

  • 送料の見積（自社の契約料金込み）／関税・着地コストの見積
  • 送り状＋通関書類＋集荷をまとめて手配
  • 荷物の追跡

始めるのに必要なもの

  • DHL Express の法人契約（アカウント番号）。未契約なら、口座開設の相談から始めます。

進め方

  1. 開発者向けサイトで登録
  2. MyDHL API を選んで申込
  3. DHL が内容を確認して承認
  4. 鍵が発行される

期間・費用

  • 期間：数日〜数週間（DHL の承認待ちが入ります）。
  • 費用：連携の利用料の明示はなし。配送料は契約料金（実費）。
💡 ポイント：練習用の環境は1日500回までお試しできます。

8. UPS

UPS

難しさ 中 ★★
ひとことで：海外3社の中では自分たちで登録しやすく、最短で始めやすい連携です。

何ができる

  • 送料の見積／送り状発行／追跡／集荷依頼

始めるのに必要なもの

  • UPS のアカウント番号（6桁）

進め方

  1. 開発者向けサイトで登録
  2. アカウント番号をひもづける
  3. 使うメニューを追加 → 鍵を取得
  4. 練習用環境から、つなぎ先を切り替えるだけで本番化（特別な審査は原則不要）

期間・費用

  • 期間：最短 数日。
  • 費用：連携の利用は無料。配送料は実費。
⚠️ 注意：古い接続方式（アクセスキー）は廃止済みです。新しく作る場合は新方式のみを使います。

9. ヤマト運輸

ヤマト運輸

難しさ 高 ★★★
ひとことで：自分たちだけでは始められず、契約＋営業担当との打ち合わせが必須。準備に数か月かかります。

何ができる

  • 送り状発行／追跡／集荷
  • ※送料を事前に計算する公式の窓口は見当たりませんでした。

始めるのに必要なもの

  • 法人（掛売り＝請求書払い）契約
  • ヤマトビジネスメンバーズ（会員サービス）への登録
  • 別途、API の契約

進め方

  1. 法人契約・審査
  2. 会員の本登録
  3. 営業担当と打ち合わせ
  4. 練習用環境 → 本番（開発開始から本番まで約3か月）

期間・費用

  • 期間：約3か月。
  • 費用：会員登録・CSV方式（B2クラウドの画面操作）は無料。API方式は1件発行ごとの従量課金（条件により月額固定費）。

注意したいこと

❗ 重要：ヤマトの「配送連携API」は“ネット通販 → 購入者への発送”には使えない決まりです（フリマ・返品などが対象）。salesanchor の「会社 → お客様への発送」では、「B2クラウド」が正規ルートになります（打ち合わせで要確認）。
💡 ポイント：最初は「CSVファイルの取り込み」から始めるのが現実的です。

10. 佐川急便

佐川急便

難しさ 高 ★★★
ひとことで：こちらも契約＋営業担当との打ち合わせが必須。「API」が2種類あるので、用途を間違えないよう注意が必要です。

何ができる

  • 送り状発行（PDF）・問い合わせ番号の採番／追跡／集荷／配達日時の変更
  • ※送料を計算する公式の窓口は見当たりませんでした。

始めるのに必要なもの

  • 飛脚宅配便の法人契約（顧客コード）
  • 「API オプション」の追加契約

進め方

  1. 専用フォームから問い合わせ → 佐川から返答・打ち合わせ
  2. 申込 → 利用 ID 発行＋仕様書の受け取り
  3. 接続テスト → 利用開始（送り状発行 API は申請後 1〜2週間で承認）

期間・費用

  • 期間：契約後 1〜2週間（送り状発行 API）。契約・打ち合わせを含めると、もっと前から準備が必要です。
  • 費用：「スマートAPI」は無料。送り状発行 API（オプション）は商談で見積。専用プリンタは月額レンタル（約1,078〜2,255円）。

注意したいこと

❗ 2種類の API に注意：「スマートAPI」は配送状況の確認・日時変更が中心で、送り状発行や送料計算は含みません。送り状を発行したい場合は、別契約の「送り状発行API」が必要です。
💡 ポイント：最初は「e飛伝Ⅲ」というシステムへの CSV 取り込みが、いちばん低コストで始められます。

11. まとめ・次の一歩

  • すぐできる：Googleドライブの自動保存を整える（書類の保存場所が決まります）。
  • 早めに動く：国内2社（ヤマト・佐川）は時間がかかるので、使う予定があれば今のうちに営業窓口へ相談。
  • 段階的に：まず CSV の受け渡しで効果を出し、全自動の連携はそのあと順番に追加。
  • 送料の自動計算：海外3社は自動で取得できるが、国内2社は料金表を salesanchor 側に持たせて計算する想定。

12. 担当エンジニア向けメモ

※ここから先は実装担当者向けの技術的な補足です。一般の方は読み飛ばして構いません。

実装メモ（横断）
  • 設計方針：ADR-021 の「eLogi-first ＋ 出力アダプタ層を抽象化」に各社実装を載せる。sandbox / production・API バージョン文字列・アカウント番号は設定値化。
  • 認証・トークン：FedEx（60分）・UPS（実効1時間）はトークンをキャッシュ必須（毎リクエスト発行は IP スロットルで 403）。DHL の MyDHL API は Basic 認証（全社的に OAuth2 へ移行中）。UPS は旧 Access Key 廃止済 → OAuth2 client_credentials。Google はサービスアカウント＋共有ドライブ（My Drive 直書き不可。drive.file スコープ推奨で CASA を回避）。
  • 送料計算：海外3社は Rate API で取得。国内2社は公式 API が確認できず → タリフ（運賃表）をアプリ側に保持して算出（ADR-095/101/103 の「キャリア別数式は後日」に接続）。
  • リードタイム：ヤマト 約3か月／佐川 送り状発行 API は申請後 1〜2週間。国内2社の営業窓口着手は早めに。
  • 要確認の不確実点：DHL アカウント番号の桁数／各社の従量課金有無・レート上限の正確値／ヤマト「配送連携API」の用途制約と認証方式／佐川・ヤマトの認証方式（契約後の仕様書で開示）／マルチテナント時の各社アカウント構成（自社1アカウント集約 か テナント別か）。
  • 関連 ADR：ADR-021（受注管理・eLogi/出力アダプタ層）／ADR-093・094（売上管理・Google Drive エクスポート）／ADR-095・101・103（送料・関税の数式は保留）。本資料はこれらに続く別 ADR 起案の前提資料。
