# ADR-103: 発送・出荷タイミング（同梱既定／分割オプトイン・出荷予定計算・発送元マスタ）（ADR-SA-09）

## Status
Accepted

## Date
2026-06-04（起案: Hikky-dev / PO: shingo-ops）

## Context（背景）

引当で複数発送元に分かれることがある。顧客は送料・関税の関係で同梱を望むことが多いが、急ぎは分割もある。

---

## Decision（What / Why / Scope）

### 確定した設計

#### 1. 発送元マスタ（出荷計算のSSOT）

自社倉庫・各仕入元（提供元と同一エンティティ）が持つ項目：

| 項目 |
|---|
| カットオフ時刻 |
| 取り寄せリードタイム |
| 発送代行可否 |
| 対応運送会社 |

#### 2. 既定＝同梱

複数仕入元は自社へ取り寄せ→翌日/翌々日に1梱包で発送。

出荷予定日 ＝ 最遅取り寄せ ＋ 梱包時間

#### 3. 分割発送＝顧客承認時のみ（オプトイン）

注文（請求書発行時）に**「分割発送可否」フラグ**（既定OFF＝同梱）。

**分割成立の条件（両方必須）:**

| 条件 | 内容 |
|---|---|
| ①顧客承認 | 注文フラグ ON |
| ②発送代行可否 | 提供元の発送代行可否 ON |

- 顧客OKでも直送不可な分は自社経由
- 分割時＝提供元から顧客へ直送

#### 4. 出荷予定の自動計算

| 条件 | 出荷予定 |
|---|---|
| 自社A・カットオフ前 | 即日 |
| 同梱（取り寄せあり） | 最遅取り寄せ ＋ 梱包 → 翌日・翌々日 |
| 分割発送 | 各提供元の最速 |

### 仕組み（意図）

発送元の数＋同梱/分割で出荷スピードが自動決定。見積/受注時点で正確な納期を提示でき、A/Bの信頼設計と噛み合う。「即納と思ったら取り寄せ」事故を構造で防止。

---

## 実装上の注意（誤実装防止）

- 「分割発送可否」フラグは**請求書発行段階で確定**（システム分岐＋人の引き継ぎ判断の両方に効く）。
- 送料の正確な数式はキャリア連携の段（後日）。
- 発送元マスタの項目（＝仕入元マスタと統合）は後日定義。
