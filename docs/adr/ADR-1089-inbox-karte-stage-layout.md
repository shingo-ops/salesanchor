## PO の言葉（2026-11-24 チャット・原文）

- 「リード・アサイン後の商談中・成約後の顧客、それぞれの段階で見える内容を分けて表示してくれ」
- 「テーブルにしてカラムを分けて一覧にしてくれ」→ 表を見て「1,これで1度作成してみてほしい」

## What（何を決めるか）

1. カルテのタブと項目の置き場所は、段階ごとに次の表のとおりにする。表の言葉は「その段階でその項目を出すタブ」。「出さない」はその段階では画面に出さない。

| 項目 | リード | 商談中 | 成約後 |
|---|---|---|---|
| 呼び名 | 商談 | 商談 | 顧客 |
| 国 | 商談 | 商談 | 顧客 |
| 取り扱いタイトル | 商談 | 商談 | 顧客 |
| 販売形態 | 商談 | 商談 | 顧客 |
| 顧客タイプ | 出さない | 商談 | 顧客 |
| 次回アクション・次回アクション日 | 商談 | 商談 | 顧客 |
| 返信速度 | 商談 | 商談 | 商談（記録） |
| 温度感 | 商談 | 商談 | 商談（記録） |
| 想定規模 | 商談 | 商談 | 商談（記録） |
| 課題・ニーズ | 出さない | 商談 | 商談（記録） |
| 競合確認 | 出さない | 商談 | 商談（記録） |
| 月間見込み金額・1件単価・月間頻度 | 出さない | 商談 | 商談（記録） |
| 商談メモ | 出さない | 商談 | 商談（記録） |
| 実績サマリー | 出さない | 出さない | 顧客 |
| CS・関係性メモ | 出さない | 出さない | 顧客 |
| メール・電話番号・Discord・Messenger・Instagram | 連絡先 | 連絡先 | 連絡先 |

| | リード | 商談中 | 成約後 |
|---|---|---|---|
| 出すタブ（左から順） | 商談・連絡先 | 商談・連絡先 | 顧客・連絡先・商談 |
| 最初に開くタブ | 商談 | 商談 | 顧客 |

2. 段階の対応（ADR-109 の内部の名前）: リード＝`lead`、商談中＝`negotiating`、成約後＝`existing_customer`・`follow_up_short`・`follow_up_long`。
3. 上の 5 つ以外の段階（失注 `lost`・対象外 `out_of_scope` など）は、PO の表に無いため、今の見せ方（タブ 商談・顧客・連絡先、最初は商談、項目は今の置き場所）をそのまま残す（見出しの並びだけは What 7 に合わせる）。変えるときは PO が決める。
4. 置き場所の表は frontend の 1 か所（`frontend/src/pages/inbox/karteLayout.ts`）だけに書く。最初に開くタブの決め方（`useInboxState.ts`）も、タブの並びと項目の出し分け（`InboxKartePanel.tsx`）も、ここを読む。同じ段階の一覧を別の場所に書かない。
5. 画面に出さないのは見せ方だけ。データは消さない・保存の中身も変えない（保存は今もカルテの全部の値を送る）。段階が戻れば、その段階の項目がまた見える。
6. 開いている間に段階が変わり、今のタブがその段階に無くなったときは、その段階の最初のタブを見せる。
7. 見出しは今の 8 つ（基本・取引プロフィール・次のアクション・見極め・商談規模・メモ・実績サマリー・引き継ぎ）を使い、この順で並べる。中の項目が 1 つも無い見出しは出さない。返信速度は「次のアクション」から「見極め」の先頭へ移す（成約後に商談タブへ残す返信速度が「次のアクション」の見出しの下に 1 つだけ残ると、意味が合わないため）。

## Why（なぜ）

- 商談中は商談に要る情報が 1 つのタブにまとまり、タブを行き来しなくて済む（PO の言葉）。
- 成約後は今後の付き合いに要る情報が最初に開くタブに並び、商談の見極めの項目は記録として後ろのタブに下がる（PO の言葉）。
- ADR-108 の「顧客タブは段階によらず同一」は、成約前に顧客タブを開く意味が薄く、PO の使い方と合わない。
- 置き場所を 1 か所に書けば、段階の一覧が散らばらない（今は `useInboxState.ts:658` に成約後の段階の一覧が直書きされている）。

## 代わりの案

- タブはそのままで、最初に開くタブだけ変える（今の形）: PO の依頼「見える内容を分けて」を満たさない。
- 段階ごとに別の部品を 3 つ作る: 同じ入力欄の作りが 3 か所に写され、直すときに食い違う。

## 影響

- 画面だけ（frontend の .ts/.tsx と試験）。backend・DB・migrations・本番の scripts・CSS・翻訳の文は変えない。
- カルテの画面の基準画像 2 枚（`karte-lead-deal`・`karte-customer-company`）は中身が変わるため、作り直す。
- スマホの受信箱（LINE 型・別に作っている）は、このカルテの部品を使っていない（`KarteTabContent` の呼び元は `InboxKartePanel.tsx` と試験 1 本だけ・recon §1）。

## 受入条件

- [ ] リードのカルテのタブは 商談・連絡先 の 2 つで、最初は商談。商談タブに出るのは上の表の「リード＝商談」の項目だけ。
- [ ] 商談中のカルテのタブは 商談・連絡先 の 2 つで、最初は商談。商談タブに実績サマリーと CS・関係性メモは出ない。
- [ ] 成約後のカルテのタブは 顧客・連絡先・商談 の順で、最初は顧客。顧客タブ・商談タブの項目は上の表のとおり。
- [ ] 失注・対象外のカルテのタブと、項目がどのタブに出るかは今と同じ。
- [ ] 置き場所の表が書かれているのは `karteLayout.ts` の 1 か所だけ。
