# ADR-121: 標準ワークフローの強制（process-artifacts gate ＋ 単一の正SOP）

## ステータス
採択（提案日: 2026-06-09）

## 文脈（なぜ）
- 開発が複数環境（web / terminal / Codex）＋AI主体で行われ、標準手順の順守が**ソフト（個人/AIの自律）**に依存していた。
- 外部エビデンス：**ソフトな順守は形骸化する**（業績・時間圧で無視され「守る人次第」になる）。改善活動の約7割が持続しない。効果は"仕組みの存在"でなく"本物の運用"から出る（WHO手術チェックリストの成功例と効果ゼロ例の対比）。
- 自社分析：直近の失敗は配管/プロセス起因が中心で、**品質起因のゲート却下はゼロ**。＝「順守を保証する仕組み」自体が欠けていた。

## 決定（何を）
1. 標準手順を**単一の正** `docs/STANDARD-WORKFLOW.md` に集約。各環境はコピーせず**指す／同期する**。
2. 合流点（develop）に **process-artifacts gate** を置き、成果物（KGI / recon / 設計）が**揃い・本物**（file:line実在・各受入基準に検証リンク・相互参照・外部事例欄記入）・**不明ゼロ**であることを検査する。
3. 危ない変更（`migrations/`・`deploy.yml`・本番スクリプト）の特例は**認可された人間（PO＋開発パートナー）の承認**でのみ。緊急は**後追い宿題＋自動期限監視**。
4. 定着は**"軽く自動な" governance**（自動ダッシュボード・自動起票・週次監視）で担保する。

## 影響・トレードオフ
- 着手前の手間が増える（＝「準備9割」の狙いどおり）。緊急時は承認＋後追いで速度を確保。
- ゲートの除去・弱体化は**不可逆操作＝PO確認必須**。
