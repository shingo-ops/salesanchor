# ADR-105: トラブル／返金（ADR-SA-11）

## Status
Accepted

## Date
2026-06-04（起案: Hikky-dev / PO: shingo-ops）

## Context（背景）

受注ステータスの「トラブル」分岐の中身。現行「トラブル情報」列（理由/対応方法/返送/返金/検品/在庫表記入/完了）がある。

---

## Decision（What / Why / Scope）

### 確定した設計

#### 1. フロー

```
発生（担当者・発生日・理由）
  └→ 対応方法決定
        └→ 返送（必要時）
              返送ラベル発行
                └→ 送付
                      └→ 顧客返送
                            └→ 検品
        └→ 在庫処理
              └→ 返金
                    └→ 完了（解決で受注ステータスへ復帰）
```

#### 2. 理由・対応方法＝選択肢（ジャンル）＋詳細自由記入欄

**理由の選択肢（例）:**

| 理由 |
|---|
| 破損 |
| 誤送 |
| 未着（INR） |
| 不良 |
| 顧客都合 |

**対応方法の選択肢（例）:**

| 対応 |
|---|
| 全額返金 |
| 一部返金 |
| 返品&返金 |
| 再送 |
| 交換 |

#### 3. 返金実行

| 決済方法 | 方法 |
|---|---|
| PayPal | API自動返金 |
| Wise | 手動 |

返金額・返金方法を記録。

#### 4. 返品の在庫処理＝ユーザー選択（3択必須）

| 選択肢 | 内容 |
|---|---|
| ①そのまま戻す | 自社A在庫へ元コンディションで戻す |
| ②状態を変更して戻す | 在庫マスタのConditionを変更して戻す（例：Sealed→開封品） |
| ③破棄 | 在庫に戻さない |

#### 5. 自動波及

| 波及先 | 内容 |
|---|---|
| P&L | 返金額・返送料を販管費に自動計上 → 利益減 |
| 在庫 | ①②は自社A反映 / ③は反映なし |

### 仕組み（意図）

ジャンルで集計・分析でき個別事情は詳細に書ける（ポカヨケ＋柔軟性）。状態変化に必ず余地を残す。返金・返品が在庫とP&Lへ正しく波及。

---

## 実装上の注意（誤実装防止）

- 理由・対応方法は**選択肢必須＋自由詳細**（自由記述のみにしない＝集計のため）。
- 返品在庫戻しは**そのまま/状態変更/破棄の3択を必ず用意**（returnを無条件に元コンディションで戻さない）。
- 返金額・返送料は**P&Lへ自動連携**（手で二重計上しない）。
