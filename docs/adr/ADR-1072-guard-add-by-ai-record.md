# ADR-1072: AI が足した見張りを、マージ済み PR で記録できるようにする（ADR-1034 決定2の一部を改める）

## What（何を決めたか）

1. 週次点検（`scripts/dev/consent-audit.py`）は、~/.claude の見張りの登録（user:hooks）と見張りの本体（hook_files）の変化のうち、設計 §5 の「強める変更」に当たるものに限って、マージ済み PR の番号（`PR#n`）での記録を認める。当たらない変化は今までどおり異常（B）とする。
2. 「強める変更」は次のどれかで、点検が機械で判定する。①本体を足す ②登録を足す ③登録の組に命令を足すだけの入れ替え ④本体の中身の書き換えのうち、その見張りの試験ファイルの行が1行も消えたり変わったりしていないもの。どれも、PR #n のマージの版の `scripts/agent-hooks/<名前>/` にある台帳札（guard-manifest.json）に書かれたファイル・命令と一致することを条件にする。
3. 見張りを ~/.claude に入れるのは、共通の台本 1 本（scripts/agent-hooks/install-guard.sh）だけとし、Opus か実行役が流してよい。台本は足すだけで、外す処理を持たない。Claude Code の自動判定の例外 HKI-1 を PO が導入時に1回だけ `!` で足す。
4. 次は ADR-1034 のまま変えない: 見張りを外す・弱める変更、見張りごとの install.sh・rollback.sh の実行、permissions.deny／ask／defaultMode、確認を省く設定、autoMode の文、danger_ops、共通の台本と点検の判定部分そのものの変更（PO の「1」で記録）。

## Why（なぜ）

- PO は非エンジニアで、見張りを足す作業は AI と実行役だけで行う方針（PO 2026-11-09）。
- 今は AI が設計・審査・マージした見張りでも、入れるには PO の `!`、記録には PO の「1」が要る。記録の道が無いので、2026-11-02 と 2026-11-09 の週次点検で、AI が PR で入れた見張りが毎回異常（B）に出た（設計の現在地 観測した事実 1・5）。毎週の異常が本当の異常を埋もれさせる。
- 見張りを外す変更まで PR 番号で通すと、Opus は自分でマージできるため、ADR-1034 が閉じた穴が開く。足す・強める変更だけを機械で見分けて通せば、外す・弱める変更は必ず PO の目に届く。

## 受け入れたリスク

- 試験を消さずに本体だけで止める範囲を狭める直し、または機械の検査に当たらない書き方で試験を無効にする直しは、点検で見分けられない。審査役の確認項目（「この PR は見張りの止める範囲を狭めていないか」）に頼る（設計 §8 の1）。
- 本体に確認を飛ばす返事を隠して入れる直しは、機械の検査に当たらない書き方では見分けられない（設計 §8 の2）。
- 見張りの本体はフックとして何でも実行できる。設定の変化は今までどおり週次点検で B に出るが、それ以外の動きは審査役に頼る（設計 §8 の3）。
- 審査役が中身を読まずに APPROVE できる（ADR-1029）。Opus は自分でマージできる。この2つを前提に、上の3つのリスクを受け入れる（設計 §8 の6）。

## 戻し方

PO が `!` で HKI-1 を外し、点検の §5 の分岐を入れた PR を revert する。共通の台本で入れた見張りを外すのは、今までどおり見張りごとの rollback.sh を PO の `!` で流す。

## 測り方

- K1: マージ済み PR で入れた見張りが週次点検の B に出る件数。今 3件（2026-11-09）→ 導入後の毎週 0件。
- K2: 見張りを外す・弱める変更が B に出る割合。100% のまま（試験 A3〜A5・A8・A9・A11・A12）。
- K3: 見張りを入れるために PO が `!` を打つ回数。導入時の1回を除き 0回。

## 維持の仕組み

- 守り手: agent-console の定期実行「同意と権限の週次点検」と、その結果を読む Opus。
- 判定の動作は `scripts/dev/permission-delegation-tests.py` の試験（A1〜A5・A7〜A12）で守る。
