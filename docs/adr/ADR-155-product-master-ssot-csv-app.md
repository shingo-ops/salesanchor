# ADR-155: 商品マスタデータの更新手段を CSV 取り込みとアプリ画面に一本化する

| 項目 | 内容 |
|------|------|
| ステータス | Accepted |
| 作成日 | 2026-09-16 |
| 起案 | しんごさん（PO） |
| 関連 | .github/workflows/migration-guard.yml チェック7 |

---

## ひとことで

商品マスタの値は CSV とアプリだけで管理する。マイグレーションでの値の書き込みは CI で自動的に止める。

## 背景（2026-09-16 実測）

- 商品マスタ（`public.products`）に同一商品「ムニキスゼロ」が 3 件登録されていた。ユーザーが検索すると重複が表示され、クレームが発生した。
- 原因は、複数のマイグレーションが段階的に同じ商品を投入したこと。初期シード・MEGA シード（`20260615`）・GAS 商品マスタ（`20260903`）の 3 経路で同一商品が異なる ID・異なる名前で登録された。
- CSV 取り込み機能は商品コードの重複を検知して上書きする仕組みを持つが、マイグレーション経由の投入はこのルートを通らないため重複が防止されなかった。
- 型番（mark）の誤登録も発生した（PM0198 MEGAドリームex: M3 → 正しくは M2a）。

## 決定

1. 商品マスタデータの正規の更新手段は **CSV 取り込み**と**アプリ画面**の 2 経路のみとする。
2. マイグレーションは商品マスタ関連テーブルの**構造変更**（列追加・型変更・索引追加等）にのみ使用する。値の操作（INSERT / UPDATE / DELETE）は禁止する。
3. 保護対象テーブルは以下の 4 つ:
   - `public.products`（商品マスタ本体）
   - `tcg_products`（テナント別商品マスタ）
   - `product_search_keywords`（検索キーワード）
   - `product_exclude_keywords`（除外キーワード）
4. `migration-guard.yml` にチェック 7 を追加し、上記テーブルへの INSERT / UPDATE / DELETE を含むマイグレーション SQL を CI で自動ブロックする。
5. 既存のマイグレーションで投入された重複データは、正規レコード（CSV/アプリ経由）のみ残してクリーンアップする。

## 理由

- データの情報源（SSOT）を一本化することで、重複・競合・型番ズレを構造的に防止する。
- ルールの明文化だけでは将来の違反を防げないため、CI による技術的な強制が必要。

## 弊害・トレードオフ

- 初期データ投入にもマイグレーションを使えなくなる。新規テナント立ち上げ時は CSV 取り込みを使う必要がある。
- 既存のデータ投入マイグレーション（`20260604`〜`20260905`）は実行済みのため影響なし。新規マイグレーションのみがブロック対象。

## 検証基準

| 基準 | 検証方法 |
|------|---------|
| チェック 7 が動作する | 保護テーブルへの INSERT を含むテスト migration で CI が赤になる |
| 構造変更は通る | ALTER TABLE を含む migration で CI が緑になる |
| 重複が解消される | 「ムニキスゼロ」検索で 1 件のみ表示される |
