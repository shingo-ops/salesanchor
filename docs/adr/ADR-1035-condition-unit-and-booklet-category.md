## What（何を決めたか）

1. 状態の単位（`line_conditions.unit_id`）を次のように揃える。
   - Pack 系の状態（Unsearched pack・Searched pack・AR confirmed pack）と、プロモパック系の未開封・開封済みは **Pack**。
   - Opened case は **Case**。
   - Box 系はすでに Box、そのほかの Case 系はすでに Case なので変えない。
   - 鑑定品（PSA）・シングル系・Error・Bulk は空のまま。
2. 単位の上書きの規則は変えない。
   - 状態が原文の語で決まったとき（R1〜R3）は、状態の単位を優先する。
     - 例外（ADR-1036）: 箱系の商品で単位が「個」・無記入の行は、状態が語で決まっていても値段で Box／Case／Pack を決め、状態をその単位の群の同じ種類に写す。
   - 既定の状態のときは、単位が空の場合にだけ埋める。
3. 新しい区分「ブックレット系」（`PC_BOOKLET`）をつくる。状態は群 `booklet` の 2 つ。
   - **With booklet**（ブックレット付き）：語が当たらないときの既定。basis は「R9:ブックレット既定」。単位は Booklet（冊）。
   - **Without booklet**（ブックレット無し）：「ブックレット無し」「冊子なし」などの語で決まる。単位は空で、原文の単位語に従う。
4. BASE SHOP リミテッドカードコレクション（440415）を、ブックレット系へ付け替える。
5. 便1（単位のデータだけ）と便2（ブックレット系）に分けて反映し、便ごとに測る。
6. 追補（2026-10-20、PO「1」）: 新しい区分「サプライ系」（`PC_SUPPLY`）をつくる。カード用品（スリーブ・セイバー・サイドローダー）の受け皿にする。
   - 状態は群 `supply` の 1 つ（**Supply**、basis「R10:サプライ既定」、単位は新しい単位 **Bag**（袋））。
   - What 2 の例外: サプライ系の商品だけは、既定の状態でも、書かれた単位より状態の単位（Bag）を優先する。用品の原文は「100枚入」と中身の枚数を書くため、今の規則では必ず Piece（枚）になり、PO の決定「100枚入り1袋を1つと数える」に合わないため。ほかの区分の規則は変えない。
   - 作品「サプライ」と、細分類「スリーブ」「セイバー」「サイドローダー」（小分類 SUPPLY の下）をつくる。
   - 詳しくは `docs/handoff/supply-category/design.md`。

詳しくは `docs/handoff/condition-unit-booklet/design.md` に書いた。

## Why

- 状態から単位が一意に決まるのに、状態の単位が空のままになっていた。そのため、原文に単位語が無い行が「単位不明」で要確認に回っていた。試算では、要確認タブのうち 6 行がこれで外れる。
- 冊子の商品をシングル系に入れると、状態が Single になる。そのため、冊子が付いているかどうかを表せず、既定の単位も持てない。区分を分ければ、ADR-1031 と同じ仕組みのまま、ほかの区分の判定には触れずに済む。

## 戻し方

- 便1：6 行の unit_id を NULL に戻し、再解析する。
- 便2：2 行を is_active=false にし、440415 を区分 2 に戻して再解析し、コードを revert する。
- 追補（サプライ系）：`docs/handoff/supply-category/design.md` の戻し方。

## 測り方

`docs/handoff/condition-unit-booklet/design.md` の受入条件 K1〜K7。

## 維持の仕組み

- 状態を足すときは、単位も同時に決める。単位を空にするときは、理由を note に書く。
- ブックレット系への付け替えは、登録規則 C3 の候補表を出してから行う。
