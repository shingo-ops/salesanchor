# ADR-104: 入金確認・受注ステータスライフサイクル・完了・売上P&L（ADR-SA-10）

## Status
Accepted（報酬の計算ルールは後日＝ADR-095付録1）

## Date
2026-06-04（起案: Hikky-dev / PO: shingo-ops）

## Context（背景）

実機 app/orders に既にステータス分け（支払い待ち/仕入れ中/発送待ち/完了/トラブル/キャンセル）がある。売上情報（P&L）は現行スプレッドシートに精緻な列が存在するが、受注一覧の売上/粗利等は未設定。

---

## Decision（What / Why / Scope）

### 確定した設計

#### 1. 受注ステータス・ライフサイクル

```
支払い待ち
  └→（入金確認）→ 仕入れ中
                     └→ 発送待ち
                           └→ 完了

※ トラブル / キャンセル は進行中から分岐
```

**各遷移トリガ:**

| 遷移 | トリガ |
|---|---|
| 支払い待ち → 仕入れ中 | 入金確認（PayPal API＝自動 / API不使用＝手動チェックで「支払い確認済み」） |
| 仕入れ中 → 発送待ち | 仕入れ提供元が確定。内部に発注サブフロー（ADR-102） |
| 発送待ち → 完了 | 梱包・ラベル発行 → 集荷 → **顧客へ発送通知（追跡番号付き）を自動送信** → 送信完了で**自動完了** |

#### 2. 完了の定義

**入金確認済み ＋ 発送完了**（両方が揃って完了）。予約販売は確定数・完了フラグで管理。

#### 3. 売上P&L＝全自動計算

**手入力カラムにしない**。

```
売上高
  − 売上原価
      仕入れ費用
    ＋ 仕入れ送料
    ＋ PayPal/WISE手数料
    ＋ 外注費用
    ＋ 荷造運賃
    ＋ 各役割報酬
  ＝ 売上総利益（率）

  − 販管費
      広告費
    ＋ 返送料
    ＋ 返金額
    ＋ インセンティブ
  ＝ 営業利益（率）

  ＋ 消費税還付（輸出免税で仕入れ消費税が還付）
  ＝ 消費税還付込
```

**データ源:**

| 項目 | データ源 |
|---|---|
| 売上高 | 請求書 |
| 原価 | **発注の実額（仕入れ情報）** |
| 手数料 | 決済 |
| 返金・返送 | トラブル情報（ADR-105） |
| 消費税還付 | 自動計算 |

#### 4. 報酬（歩合）＝テナント設定（後日定義）

役割別（営業/受注/発送/仕入れ/トラブル）。担当者・業務・テナントで変動。

### 仕組み（意図）

P&Lは手入力せず他の箱から積み上げ。「売値と原価の分離」によりLv2で原価が下がれば利益が自動で上がる。締めまで一気通貫で自動。利益の可視化が正確に。

---

## 実装上の注意（誤実装防止）

- **売上/粗利/粗利率/仕入/報酬は手入力カラムにしない**（自動計算）。
- 受注一覧UXは別パートナー実装中のため本ADRは扱わない（**売上・利益は別ページ＝売上管理**で表示）。サイドメニューのステータス分けは確定。
- API不使用時の入金確認は**手動チェック必須**（自動受領確認が困難なため）。手動で確認済みにしたら仕入れへ進める。
- 発送通知の自動送信完了をトリガに**自動完了**（手動で完了ボタンを押させない）。
- 報酬ルールはハードコードせずテナント設定（後日）。
