## What（何を決めたか）

1. パスワードが正しくても、いつもの機械でなければトークンを出さない。待つ機械に2けたの番号を出し、いつもの機械に候補3つを出す。正しい番号で許可、違う番号でその依頼だけ取り消し、「私ではない」で取り消しと、押した機械以外の全部のログアウト。
2. いつもの機械は Cookie `sa_device`（乱数・HttpOnly・Secure・SameSite=Strict・path `/api/v1/auth`・180日）で見分け、DB `public.user_trusted_devices` には hash だけを置く。IP は判定に使わない。
3. 承認の依頼は DB `public.auth_login_requests` に30分置く。許可・拒否・発行は条件付きの更新で1回だけ通し、本人の依頼だけを操作できる。承認する側の機械は、アクセストークンの組の id から引く。知らせは SSE の人単位の宛先 `rt:u:{user_id}`（ADR-1016 改訂 2026-11-01）、ホーム画面のアプリへの通知（web push・通知を許可した機械だけ。**2026-11-03 PO「3」で止めた**＝本体に鍵を渡さない。再開の条件は `docs/handoff/auth-new-device-approval/stageC-stop-webpush-card.md` §9）、メール（リンクなし）。いつもの機械の画面では、許可待ちの依頼をお知らせの鈴に出し、行を押すと詳しい画面（機械・場所の目安・時刻と「私ではありません」「私です」→番号3つから選ぶ）を開く。詳しい画面は、行を押すと画面の真ん中の小窓で開く（**改訂 2026-11-05 段E**・`docs/handoff/auth-new-device-approval/stageE-badge-modal-card.md`）。自動で開く小窓は使わない（**改訂 2026-11-05 PO「1」**・依頼の正本は `public.auth_login_requests` のまま写さない・`docs/handoff/auth-new-device-approval/stageD-notice-detail-card.md`）。
4. いつもの機械が無い人は、予備の合言葉（10個・1回ずつ・見出し4文字＋本体50ビット・本体は argon2 の hash だけを保存・間違いは口座の失敗回数に数える）で入る。それも無い人は super admin が本人確認のうえ管理画面で許可し、許可した人と確認の方法を残す。自分の依頼は自分で許可できない。
5. パスキーでのログインは許可を求めず、その機械をいつもの機械に加えてメールで知らせる。一度もログインしていない人の最初のログインは、その機械を最初のいつもの機械にする。固定の締切（`AUTH_DEVICE_BOOTSTRAP_CUTOFF`）より前に始まったログインは、次の更新でいつもの機械にする。締切より後に始まり機械の無いログインは通さない。
6. 全部のログアウトは共通の関数1つで行い、アクセストークンに組の id を入れて、失効した組のアクセストークンも次の要求で拒む。
7. 記録は既存の `public.auth_events` に、誰か・理由・初めての機械か を足して残す。許可待ち（202）は `auth_pending` として成功と分ける。パスワード・合言葉・Cookie の値は残さない。
8. 場所の目安は DB-IP IP to City Lite（CC BY 4.0）を読み、出す画面とメールに出どころを表示する。読めなければ「不明」とし、認証は止めない。
9. 入れ方は `AUTH_DEVICE_APPROVAL`（off / enforce・既定 off）。off はログインの止め方が今と同じ（機械の登録もしない。6 の失効の確かめだけは off でも効く）。点検専用の人には管理用の命令で印を発行し、点検はその印でログインする。
10. 新しい表（`user_trusted_devices`・`auth_login_requests`・`user_recovery_codes`・`user_push_subscriptions`）には RLS を付けない。ADR-1018 Decision 6 が認証トークンの表に付けないと決めたのと同じ理由で、ログイン前・会社が決まる前に hash の一致で1行を引くため。生の値は保存せず hash だけを置き、本人の行は `user_id` で絞る。
11. （**改訂 2026-11-22 提案中**）Meta 審査用の会社（会社006「Sales Anchor App Review」）だけに、知らない機械からの確認を外すスイッチを置く。**目的: Meta の審査員は登録していない機械からログインするので、確認で止められてログインできないことを防ぐために付けた機能。** ふだんは守りの穴になるため、**ほかの会社に広げることは禁止**（PO 2026-11-22）。印とスイッチは会社の正本 `public.tenants` の2列（`meta_review_tenant`・`meta_review_login_until`）だけに置き、データベースの決まりで「印の無い会社は ON にできない」「印は1社だけ」にする。ON にできるのは super admin（と、PO に頼まれた Claude Opus が同じ画面から）だけで、ON は最長14日で自動で OFF に戻る。会社006の中の super admin の人には効かない。ON で入った回は機械を登録せず、記録に `meta_review` を残し、本人に知らせメールを送る。会社006の人（super admin でない）の、機械の無い組では、ON／OFF に関わらずパスキーと予備の合言葉を作らせず、ほかの人の機械を許可させない。会社006の人には、最初のログインの機械の登録（D5）もしない。手で OFF にしたら機械の無い組をすぐ失効させる（OFF の後に入口を残さない）。切り替えは会社別の監査記録に残す。見回り（定期の点検）は作らず、自動で OFF になった日時を画面に出す（PO 2026-11-22「1」）。会社006に無いメールアドレスで試した回（打ち間違い）は履歴に出さない（打ったアドレスを残さないため。PO 2026-11-22「1」）。画面は利用者管理の「ログインの許可待ち」の下の「Meta審査用」で、スイッチとログイン履歴を出す。設計 `docs/handoff/auth-new-device-approval/review-exempt-design.md`。

## Why（なぜ）

- パスワードは漏れる前提で守る。大手（Meta・Google・Apple）は、認識していない機械では、すでに信頼された機械での確認か復旧コードを求める（kgi.md の一次資料）。
- 押すだけの承認は通知を何度も送られて押してしまう手口に弱いので、番号を選ぶ形にする（ADR-1048 で審査済み）。
- 依頼を DB に置くのは、管理者の許可と、その記録を残すため（Redis の5分では足りない）。
- 記録の置き場を増やさないため、既存の auth_events に列を足す。今は誰のログインか・失敗の理由が残っていない（recon:E）。
- 今は全部のログアウトが2か所に直書きされ、アクセストークン（最長900秒）は人単位で止められない（recon:C）。
- （What 11）Meta の申請は、審査員がアプリに入れるログイン情報を求める。審査員は登録していない機械から入るため、確認で止まると審査が進まない（`docs/handoff/auth-new-device-approval/review-exempt-recon.md` の E・J）。本番の設定を全員 off にすると全員の守りが外れるので、会社006だけ・審査の間だけ・最長14日にする。会社の番号をプログラムに書かず、データベースの決まりで1社に閉じるのは、ほかの会社に広がる道を機械で塞ぐため。

## 影響

- ログインの応答に 202（許可待ち）が増える。画面はそれに応じる。
- 新しい表4つ（web push の購読を含む）と列の追加（すべて追加だけ）。クラウドの相談係 AI に見せる列の分類に、新しい列を伏せる側で足す。
- 依存 `maxminddb` と `pywebpush` を足す。場所データを毎月取りに行く。web push の鍵（VAPID）を秘密に置く。

## 戻し方

What 11 は、画面のスイッチを OFF にするか、14日たてば元に戻る。印を外すときは `UPDATE public.tenants SET meta_review_login_until = NULL, meta_review_tenant = false WHERE meta_review_tenant`。列は残す。

`AUTH_DEVICE_APPROVAL` を off に戻す。off はログインの止め方が今と同じ。もう一度 enforce にするときは締切を新しくする。表と列は残す。web push は本体に VAPID の鍵を渡さなければ送らない（2026-11-03 から渡していない。deploy.yml の書き戻し3行を外した）。
