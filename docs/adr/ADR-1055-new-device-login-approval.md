## What（何を決めたか）

1. パスワードが正しくても、いつもの機械でなければトークンを出さない。待つ機械に2けたの番号を出し、いつもの機械に候補3つを出す。正しい番号で許可、違う番号でその依頼だけ取り消し、「私ではない」で取り消しと、押した機械以外の全部のログアウト。
2. いつもの機械は Cookie `sa_device`（乱数・HttpOnly・Secure・SameSite=Strict・path `/api/v1/auth`・180日）で見分け、DB `public.user_trusted_devices` には hash だけを置く。IP は判定に使わない。
3. 承認の依頼は DB `public.auth_login_requests` に30分置く。許可・拒否・発行は条件付きの更新で1回だけ通す。知らせは SSE の人単位の宛先 `rt:u:{user_id}`（ADR-1016 改訂 2026-11-01）、ホーム画面のアプリへの通知（web push・通知を許可した機械だけ）、メール（リンクなし）。
4. いつもの機械が無い人は、予備の合言葉（10個・1回ずつ・見出し4文字＋本体50ビット・本体は argon2 の hash だけを保存・間違いは口座の失敗回数に数える）で入る。それも無い人は super admin が本人確認のうえ管理画面で許可し、許可した人と確認の方法を残す。自分の依頼は自分で許可できない。
5. パスキーでのログインは許可を求めず、その機械をいつもの機械に加えてメールで知らせる。一度もログインしていない人の最初のログインは、その機械を最初のいつもの機械にする。固定の締切（`AUTH_DEVICE_BOOTSTRAP_CUTOFF`）より前に始まったログインは、次の更新でいつもの機械にする。締切より後に始まり機械の無いログインは通さない。
6. 全部のログアウトは共通の関数1つで行い、アクセストークンに組の id を入れて、失効した組のアクセストークンも次の要求で拒む。
7. 記録は既存の `public.auth_events` に、誰か・理由・初めての機械か を足して残す。許可待ち（202）は `auth_pending` として成功と分ける。パスワード・合言葉・Cookie の値は残さない。
8. 場所の目安は DB-IP IP to City Lite（CC BY 4.0）を読み、出す画面とメールに出どころを表示する。読めなければ「不明」とし、認証は止めない。
9. 入れ方は `AUTH_DEVICE_APPROVAL`（off / enforce・既定 off）。off は今と全く同じ動き（機械の登録もしない）。点検専用の人には管理用の命令で印を発行し、点検はその印でログインする。

## Why（なぜ）

- パスワードは漏れる前提で守る。大手（Meta・Google・Apple）は、認識していない機械では、すでに信頼された機械での確認か復旧コードを求める（kgi.md の一次資料）。
- 押すだけの承認は通知を何度も送られて押してしまう手口に弱いので、番号を選ぶ形にする（ADR-1048 で審査済み）。
- 依頼を DB に置くのは、管理者の許可と、その記録を残すため（Redis の5分では足りない）。
- 記録の置き場を増やさないため、既存の auth_events に列を足す。今は誰のログインか・失敗の理由が残っていない（recon:E）。
- 今は全部のログアウトが2か所に直書きされ、アクセストークン（最長900秒）は人単位で止められない（recon:C）。

## 影響

- ログインの応答に 202（許可待ち）が増える。画面はそれに応じる。
- 新しい表4つ（web push の購読を含む）と列の追加（すべて追加だけ）。クラウドの相談係 AI に見せる列の分類に、新しい列を伏せる側で足す。
- 依存 `maxminddb` と `pywebpush` を足す。場所データを毎月取りに行く。web push の鍵（VAPID）を秘密に置く。

## 戻し方

`AUTH_DEVICE_APPROVAL` を off に戻す。off は今と同じ動き。表と列は残す。web push は VAPID の秘密を消せば送らない。
