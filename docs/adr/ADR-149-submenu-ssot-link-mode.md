# ADR-149: サイドメニューの共通部品(SubMenu)へのSSOT集約とリンク型対応

**Status:** Accepted
**Date:** 2026-06-28
**Authors:** shingo-ops
**Related:** ADR-087(hub-shell レイアウト標準: hub-subnav-item の NavLink 使用を規定), ADR-067(SubMenu の色トークン強制), ADR-144(UI共通部品の遵守ガバナンス)

---

## Context（背景・問題）

アプリ内のサイドメニューは、ページごとに個別実装されており、共通部品が使われていない。recon（docs/handoff/submenu-link-mode/recon.md）で全数調査した結果、ナビゲーション用途のサイドメニューは7個存在し、その実装方式は以下の4系統に分かれていた。

- 別ページへ遷移する縦メニュー（hub-subnav の raw JSX）: 管理センター・顧客ハブ
- 同一ページ内で表示を切り替える縦メニュー: ロール一覧・注文の絞り込み
- アプリ全体ナビ（DesktopShell）: 別カテゴリ
- 操作パネル/タブ（予定ページ・受信箱）: メニューではない

一方、共通部品 `src/components/SubMenu.tsx` は存在するが、本番機能ページでの採用はゼロ（デザイン見本ページのみ）。さらに SubMenu は「同一ページ内で選択を切り替える（onChange）」用途にしか対応しておらず、「別ページへ遷移する（リンク）」用途に対応していなかった。このため、遷移型メニュー（管理センター・顧客ハブ）を SubMenu に寄せることができず、SSOT 化が進められなかった。

## Decision（決定）

### 1. SubMenu を全サイドメニューのSSOT（単一の正本）とする

対象スコープは「項目を選ぶ縦メニュー」に限定する（スコープA）。対象は管理センター・顧客ハブ・ロール・注文の絞り込み。アプリ全体ナビ（DesktopShell）・予定ページの操作パネル・受信箱タブは、性質が異なるため本SSOTの対象外とする。

### 2. SubMenu に「リンク型（ドア型）」を追加する

SubMenuItem に任意フィールド `to?: string` を追加する。`to` を指定した項目は NavLink として描画され、押下でルーティング遷移する（リンク型）。`to` 未指定の項目は従来どおり onClick で onChange を呼ぶ（コールバック型）。これにより、遷移型・切替型の両メニューを単一部品で表現できる。

### 3. 段階移行（1ページ＝1PR）

一斉置換は行わない。(a) SubMenu へのリンク型追加（本PR #2650）→ (b) 管理センター・顧客ハブの置換 → (c) ロールの置換、の順で、各PRを単一テーマで進める。ロールについては、従来あった階層インデントと色の縦ラインを廃止し、フラットな縦並びとする（PO合意済み）。

### 4. ADR-087 との関係

ADR-087 は hub-* CSSクラスの命名統一を定めており、その一覧表で hub-subnav-item が NavLink を使うことを想定している。本ADRはそれと矛盾せず、SubMenu 部品側に NavLink 対応を実装することで ADR-087 の想定を部品レベルで実現する。

---

## Consequences（結果・トレードオフ）

- 利点: 全サイドメニューが単一部品を参照し、見た目・操作・アクセシビリティが一元管理される。
- トレードオフ: リンク型は `<a>` で描画されるため、既存CSSによっては下線等の見た目差が出る可能性がある。これは置換側PR（管理センター等）の画面確認で検証する。
- 移行期間中は、未置換ページと置換済みページが混在する。段階移行のため許容する。
