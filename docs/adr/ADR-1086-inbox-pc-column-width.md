## What（何を決めたか）

1. PC 帯（窓の幅 1280px 以上）の受信箱の3列は、一覧とカルテを「比率」で広げ、「最大の幅」で止める。残りはすべて会話欄に回す。
2. 比率は、3列に使える幅に対して 一覧 27%・カルテ 35%（PO 提示の 1280px の数字 330:463:420 から）。CSS では親の箱に合わせて 一覧 41.6%・カルテ 34.6% と書く（design.md §3-1）。
3. 最大の幅は 一覧 330px・カルテ 480px。
4. 値はすべて `frontend/src/tokens.css` に名前を付けて置き、`min(比率, 最大の幅)` で使う。
5. タブレット帯（768〜1279px）とスマホ帯（767px 以下）は変えない。カルテの引き出しは見本どおり 396px のまま。

## Why（なぜ）

- 今は一覧 443px・カルテ 396px の固定で、1280px の窓では会話欄が 346px しかない（recon.md §3-2）。PO の目的は会話欄を広く取ること。
- 3列とも比率だけにすると、1920px の窓で会話欄が 694px になり今（986px）より狭くなる。最大の幅で止めると、測った5幅すべてで会話欄が今より広い（design.md §2）。
- `min()` は書き出し先（Chrome 87・Safari 14）で使える。外枠を基準にする単位（`cqw`）は Safari 14 で使えない（`frontend/vite.config.ts:18`）。
- ADR-064 のパネル幅の記述は「根拠にしてはならない」と同 ADR に書かれており、PC 帯の幅を決める有効な記録が無かった（recon.md §1）。

## Scope

- 変更: `frontend/src/tokens.css`（一覧の固定幅 1 つを外し、比率と最大の幅 4 つを足す）・`frontend/src/pages/inbox/InboxPage.css`（一覧とカルテの width の 2 行）。
- 変更なし: タブレット帯・スマホ帯の CSS・`--karte-panel-width`（396px）・画面の部品（.tsx）・API・DB。
- 幅の数字を変えるときは本 ADR を更新する。
