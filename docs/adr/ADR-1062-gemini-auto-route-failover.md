## What（何を決めたか）

1. Gemini への道は「直接」と「prod2 の中継」の2つ。どちらで呼ぶかは `backend/app/services/gemini_route.py` の1か所だけで決める。
2. 直接の道で「この国からは使えません」（HTTP 400・"location is not supported"）と断られたら、同じ呼び出しを中継の道ですぐやり直す。
3. 道に届かない（つなぐ段階の失敗・中継の失敗）ときは、もう一方の道ですぐやり直す。1回の呼び出しで切り替えは1回まで。
4. 切り替えて成功した道は、そのプロセスで10分覚える。最初の道は、覚えた道が無ければ環境変数（GEMINI_PROXY_URL があれば中継）で決める。
5. 解析と訳す機能の両方がこの道の選び方を使う。訳す機能は古い部品（google.generativeai）をやめ、新しい部品（google-genai）にする。
6. 直前30分に解析の成功が0回で失敗が1回以上なら、断られ方に関係なく管理者用 Discord に1通送る。戻ったらもう1通送る。5分ごとに見る。
7. 道を自動で切り替えたことは、向きごとに24時間に1通だけ Discord に送る。
8. 失敗の記録（validation_result）に、断りの理由の文（reason）を残す。今の raw と category は変えない。

## Why（なぜ）

- 2026-11-05 は 08:49 から 19:25 まで解析が73回続けて失敗し、だれも気づかなかった（recon §1）。10/02 にも同じ断りがあった。Google 側の判定は外から確かめられず、また起きると考えて備える。
- 気づかなかったのは、送り直しと諦めの知らせが HTTP 429/500/502/503/504 だけを見ていて、400 を数えないから（recon §2）。断られ方を足していく方式では、次の知らない断られ方でまた黙る。→「成功が無い」ことだけを見る。
- 過去7日の記録に当てはめると、この見張りは今日の停止で 08:50 に鳴り、ほかの日の空振りは0だった（recon §8）。
- 中継だけにすると、prod2 が止まったときに解析が止まる。両方の道を持ち、断られた方から逃げる形にする。
- 訳す機能の古い部品は、道がプロセス全体の環境変数で決まり、呼び出しごとに変えられない（recon §4）。今日も backend の訳だけが取り残された（recon §1）。

## 受け入れるリスク

- 両方の道が同時に使えないときは切り替えでは直らない。見張りが30分で知らせる。
- Redis が止まっていると見張りは黙る（送りすぎを防ぐため）。ADR-1050 の諦めの知らせと同じ弱さ。
- Google が断りの文を変えると切り替わらない。見張りが30分で知らせ、reason に新しい文が残る。
- 投稿の少ない時間に1件の失敗で鳴ることがある。2026-11-19 に2週間の回数を数え、空振り2回以上なら条件を見直す。

## 対象外

- 作品比べの道具（`backend/app/services/tcg_work_comparison_svc.py`）。人が明示で呼ぶだけで、自動では動かない。
- 送り直しの条件（ADR-1050）。
