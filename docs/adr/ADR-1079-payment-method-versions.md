# ADR-1079: 請求書の振込先を「版」で持ち、直しても消しても前の内容を残す

## What（何を決めたか）

1. 振込先の一覧の1行と、その詳細（銀行または Wise）の1行を、まとめて「版」1つとする。版の中身（地域・種類・表示名・詳細の全項目）は後から変えない。
2. 振込先を直すときは、新しい版を足し、前の版に「次の版の番号」（superseded_by_id）を入れる。前の版の行は残る。
3. 振込先を消すときは、消した時刻（deleted_at）を入れて隠す。行は残る。
4. 選択肢に出すのは「今の版」（次の版が無く、消されておらず、使う設定のもの）だけにする。
5. B2B の請求書は、選んだ版の番号（payment_method_id）だけを持つ。口座番号や振込先の写しは請求書に持たない。PDF と詳細画面は、その番号で版を読む。
6. 上の1〜3は DB の見張り（トリガー）でも守る。詳細の表は直す・消すを断る。一覧の表は消すを断り、版の中身の列を直すことを断る。次の版の番号と消した時刻は、空から値へ1回だけ入れられる。並び順と「使う・使わない」は版を作らずに直せる。
7. 下書きの請求書が指す版が「今の版」でなくなったら、発行を止めて選び直してもらう。

## Why（なぜ）

- PO が、振込先は会社情報の画面で直せて消せること、請求書の作成画面では登録名で選ぶだけで消せないこと、直しても前のデータを消さずに残すことを求めた（2026-11-14「振込先は直せるし消せるが請求書の作成画面では消せないようにしたい、プルダウンで登録名で選択すると登録情報が反映されるようにしたい」「修正されてもデータを消すのではなく更新する形で前のデータも保持しておく仕組みは実現できる？」→ 版の案に「1,」）。
- ADR-1061 の形（直すと上書き・消すと CASCADE で消える）では、前の内容が残らない。発行済みの請求書を守るには請求書に写しを持つしかなかった。
- 写しに口座番号を入れると、請求書の表に口座番号の列ができる。運用の確認の道は、隠す列を持つ表をまるごと断る（migrations/20261031_210000_create_ops_case.sql:202〜:227 の is_denied_source）。請求書の表ごと確認できなくなる。
- 版の番号だけを持てば、口座番号は今の振込先の詳細の表だけに残る（1か所）。ADR-1061 決定9 の列名による隠し方がそのまま効く。
- 版は消えないので、請求書の番号はいつも元の版を指す。発行済みの請求書は、後で振込先を直しても消しても、作った時の振込先を出し続ける。
- 直した履歴を別の表に持つ案は取らない。今の版と前の版が別の表になり、請求書がどちらを指すかで読み方が2つに割れるため。
- 本番の振込先の表は全社0行（2026-11-14 reader 鍵で数えた）。形を変えても消える値は無い。

## 影響

- 振込先の登録画面（ADR-1061 の残りの便）は、直す＝新しい版を足す、消す＝消した時刻を入れる、で作る。前の版の一覧を画面に出すかは、その便で決める。
- 閲覧者の請求書の発行元の写し（docs/handoff/viewer-contract-stage/design.md:268。振込先の全項目を写す）を版の番号に替えるかは、閲覧者の請求書の便の設計で決める。本 ADR では変えない。
- 会社を消すときは、スキーマごと消す（backend/app/routers/super_admin_tenants.py:167 の DROP SCHEMA ... CASCADE）。行ごとの見張りには当たらない。
- 試験 backend/tests/test_tenant_issuer_tables_pg.py の「一覧を消すと詳細も消える」の確かめは、「消すことを DB が断る」に変わる。

## 受け入れたリスク

- 振込先の行は消えずに増え続ける。1社の振込先の直しは年に数回の見込みで、行の数は問題にならない（数えて確かめるのは便の後の本番の確認）。
- 人が DB に直接入って版の中身を直すことは、見張りが断る。直したいときも新しい版を足す。間違えて入れた版は「消す」で隠す。

## 戻し方

- 見張り（トリガー）と関数を外し、足した2列を外せば ADR-1061 の形に戻る。手順は便 V の移行の先頭の注記に書く。外す前に、請求書が指している古い版を確かめる（外すと古い版を消せるようになるため）。

## 未解決

- なし（前の版を画面で見せるかは、登録画面の便で決める）。
