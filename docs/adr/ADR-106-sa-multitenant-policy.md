# ADR-106: マルチテナント＆「標準エンジン＋テナント別ポリシー」方針（ADR-SA-12）

## Status
Accepted

## Date
2026-06-04（起案: Hikky-dev / PO: shingo-ops）

## Context（背景）

A専業/B専業/A+B混在、送料・関税・報酬・集計条件・有効期限・テンプレ色などテナントごとに運用が違う。コードは分けたくない。

---

## Decision（What / Why / Scope）

### 確定した設計

#### 1. テナント分離

テナントの顧客・商品・注文・発行者情報・発送元設定は **DBのRLS（行レベルセキュリティ）で会社ごとに完全分離**。SSOTの「1か所」の単位がテナント単位になるだけ。

#### 2. 「標準エンジン＋テナント別ポリシー」

**エンジン（自動計算ロジック）は全社共通。差異はテナント設定（ポリシー）で吸収。**

**テナント設定の対象:**

| カテゴリ | 設定項目 | 参照ADR |
|---|---|---|
| 在庫 | 在庫ソースA/B | ADR-099 |
| 在庫 | 集計フィルタ | ADR-099 |
| 発送 | 発送元（カットオフ/リードタイム/代行可否） | ADR-103 |
| 発送 | 同梱分割既定 | ADR-103 |
| 書類 | 有効期限 | ADR-101 |
| 書類 | 関税ポリシー | ADR-101 |
| 書類 | 発行モード | ADR-101 |
| 書類 | テンプレ色/ロゴ/発行者情報 | ADR-101 |
| 報酬 | 報酬ルール | ADR-104 |

#### 3. 顧客登録のテナント決定

**署名トークンでテナントを決定**（ADR-097）。誤テナント混入を構造で防止。

### 仕組み（意図）

「構造は固定、変数だけ各社」。本ADRセット全体に一貫する設計パターン。1コードベースで多様な事業者を収容。

---

## 実装上の注意（誤実装防止）

- テナント分岐を**if文の散在でなくテナント設定（ポリシー）の注入**で実装（エンジンは共通のまま）。
- RLSのテナント境界を越える参照を作らない。
- トークン由来以外でテナントIDを確定しない。
