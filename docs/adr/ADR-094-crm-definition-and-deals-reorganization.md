# ADR-094: CRM定義の明文化と「案件」→「商談」へのリネーム・CRM移管

## Status
**Proposed** — 未着手・実装禁止。

> ⚠️ **実装着手禁止**
> POの明示的な指示なしに実装を開始してはなりません。

## Context

### 現状の問題

1. **名称の曖昧さ**: 「案件」という名称は何を管理するページか直感的に伝わらない。
2. **配置の不一致**: 「案件」は管理センターの「データ」セクションに置かれているが、
   概念的にはリード管理の延長（商談フェーズ）であり、CRMハブに属する。
3. **CRMの定義が未明文化**: `/crm/` 配下に何を置くべきかの原則がない。

### 現在のナビゲーション構造

```
CRM（/crm/）
  ├── リード
  ├── 会社
  └── アーカイブ

管理センター（/management-center/）
  └── データ
        ├── 案件        ← ここが問題
        ├── 仕入元
        └── 発注書
```

### データモデル上のフロー

```
Lead（見込み客）
  ↓ converted_deal_id で案件化（商談開始）
Deal（商談中）← lead_id で逆参照、確度・金額・ステージを管理
  ↓ won（成約）
Order → 売上管理（ADR-093）
```

`Deal` は `Lead` のライフサイクルの延長であり、リード管理と同じCRMの文脈に属する。

## Decision

### 1. CRMの定義

`/crm/` 配下は **「成約前の顧客関係管理」** を担う。具体的には：

- **対象**: リード（見込み客）・商談（交渉中）・会社（顧客情報）
- **対象外**: 受注・請求書・売上（成約後の業務オペレーション）・仕入元・発注書（バックオフィス）

```
CRM = 見込み客の発掘 → 商談 → 成約 までの管理
```

### 2. 「案件」→「商談」リネーム

| 変更前 | 変更後 | 理由 |
|---|---|---|
| 案件（nav.deals） | 商談（nav.deals） | 「商談中のリード」という役割を直接表現 |
| Deals | Deals（英語は維持） | 英語圏での一般用語として適切 |

### 3. 管理センター → CRM への移管

```
変更後:

CRM（/crm/）
  ├── リード          （見込み客の全リスト）
  ├── 商談            （商談中のパイプライン管理）← 移動
  ├── 会社
  └── アーカイブ

管理センター（/management-center/）
  └── データ
        ├── 仕入元
        └── 発注書      （案件は削除）
```

## Scope

| 変更対象 | 内容 |
|---|---|
| `frontend/src/pages/crm/CustomerHubPage.tsx` | サブナビに「商談」追加 |
| `frontend/src/pages/management-center/ManagementCenterPage.tsx` | データセクションから `deals` を削除 |
| `frontend/src/App.tsx` | `/crm/deals` ルート追加、`/management-center/deals` を redirect に変更 |
| `frontend/src/i18n/ja.json` / `en.json` | `nav.deals` の表示名を「商談」/ "Deals" に変更 |
| `frontend/tests-e2e/` | ナビゲーション変更に伴う spec 更新 |

後方互換リダイレクト: `/management-center/deals` → `/crm/deals`

## Consequences

- DealsPageのコンポーネント・APIエンドポイント・DBテーブルは変更なし（ルートと表示名のみ）
- リードページの「案件化」ボタン遷移先を `/crm/deals` に更新が必要
- 既存のブックマーク・外部リンクはリダイレクトで継続動作
