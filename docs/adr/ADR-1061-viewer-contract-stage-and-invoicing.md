## What（何を決めたか）

1. 閲覧者の状態に contracting（契約手続き中）を足す。見られる期限は既存の trial_expires_at の1列で持つ。
2. 手続きの段階は列で持たず、履歴と請求書の行から決める。
3. 商材・プラン・含む機能・契約を、トレカ商品のマスタと B2B の請求書から分けた表に置く。プランは買い切りとサブスクを行で表す。
4. 税率は tax_rates の1か所に適用日つきで置く。請求書は発行日の率を写す。
5. 閲覧者の請求書は viewer_invoices と明細の2表に置き、発行時点の宛先と発行元を写す。名簿が消えても請求書の行は残す。
6. 会社の情報は1つの項目を1か所に置き、差出人を載せる書類はすべて1つの読み出しの道（get_issuer）で読む。書類に載せる会社名・メール・サイト・住所・電話・インボイス登録の有無と番号は、会社ごとのスキーマの tenant_issuer_profiles に国内用と海外用の1行ずつ置く（住所と電話の決まりは住所の国で分ける）。振込先は同じスキーマに、一覧の表 tenant_invoice_payment_methods と、種類ごとの詳細の表（銀行 tenant_invoice_payment_bank・Wise tenant_invoice_payment_wise）を1対1で置く（PO 2026-11-10「１」）。種類は銀行口座と Wise の2つで、詳細は (id, tenant_id, method_type) の外部キーで一覧と種類を合わせる。複数置き、請求書の作成時に1つ選んで写す。PayPal は振込先に置かず、正本は public.tenant_paypal_config のまま（PO 2026-11-09）。Wise は支払いリンクを持たない（PO 2026-11-09）。送金はメールで受ける（AI の読み。PO の提案の項目にメールアドレスがあるため。試しの送金で確かめる）。印影と既定の言語は会社情報（tenant_profile）のまま。都道府県は public.prefectures の1か所に置く。会社情報の古い6列（会社名の2つ・メール・サイト・住所・電話）は読むだけにし、消す（PO 2026-11-10）。消す順番は、新しい置き場所への切り替え → 古い列を読む発注書と FedEx の申請書の口を別の設計で消す → 入れ直していない会社を数えて0件 → 6列を消す、の4段（design.md §3-4）。海外の電話はアプリ共通の決まり（ADR-126）どおり「+」付きで保存する（PO 2026-11-10）。今の書類のうち B2B の請求書もこの道へ切り替え、国内向けか海外向けかは作るときに取引先の既定の請求先の国で自動で決めて請求書に持つ（日本なら国内向け、それ以外は海外向け）。その行が登録有のときだけ、B2B の請求書の PDF に登録番号の1行を載せる（PO 2026-11-07）。国を決められない取引先（既定の請求先が無い、または国が空）には請求書を作らせず、請求先の国を入れる案内を出す（PO 2026-11-07）。見積書は今回変えない（PO 2026-11-07「見積もりは今回はパス」）。見積書の PDF は、取引先の情報が無い場面でも使うため、取引先の国で決めず海外用を載せる（PO 2026-11-07）。発注書と FedEx の申請書は使わないので切り替えず、別の設計で件数を数えてから消す（PO 2026-11-06・2026-11-10）。古い6列は、この2つの口が消えるまで消さない。
7. 再発行は前の請求書を無効にして新しい番号で出す。
8. お試しまで進んだ人の名簿は、見られる期限（停止の人は最後の停止記録との遅い方）から3年残す。今の90日の決まり（docs/handoff/gas-viewer-fresh-fast/design.md:523〜:524）を置き換える。ADR-1019 には Q7 も90日も書かれていない。
9. 振込先の口座番号（銀行の bank_account_number と Wise の iban）は、相談係の道に加えて Mac の AI の読み取りの道（ai_ro）からも列ごと隠す（PO 2026-11-11）。ADR-1052 の「Mac の道は変えない」を、この2列に限って改める。隠し方は列名の拒否の一覧に account_number と ^iban$ を足す。一覧の正本は backend/app/ops/readonly_query.py の DENY_COLUMN_RE とし、同じ文字を持つ SQL の2か所が一致することを試験で毎回確かめる。
10. 商材とプランは、最高管理者だけが開く画面で足し、名前と金額を直し、消さずに「使わない」へ切り替える（PO 2026-11-09）。

## Why（なぜ）

- PO が、入金までの間も在庫表を見られるようにし、手続きの抜けを防ぎたいと決めた（docs/specs/viewer-contract-invoicing/ideal-state.md）。
- 今後サブスクやツール全体の提供があるため、金額と機能を行で足せる形にする。
- 税率の変更で発行済みの請求書が変わってはいけない。
- 請求書は7年残す決まりがあり、名簿の3年と寿命が違う。
- 再登録の防止のため、PO が3年残すと決めた。
- 口座番号は、知られると振込先の詐欺に使われうるため、PO が Mac の AI の道からも隠すと決めた（2026-11-11）。他の会社情報は今の請求先の表と同じく見えるままにし、調べ物に要る情報は残す。
- 古い6列を残し続けると、同じ会社名や住所が2か所に残り食い違う。PO が消す方向を決めた（2026-11-10）。
- 経緯: 2026-11-05 に PO は海外と国内で請求書の項目をすべて分けると決めた。2026-11-06 に一度、会社名・メール・サイトとインボイス登録は会社に1つ（PO「1」「2」）としたが、同日に PO が「国内と海外で登録できるようにする」「これも国内と海外で2つ、分社している場合に備えて」と改めた。分社すると、国内と海外で会社名も登録番号も別になるため。
- 会社名と住所を請求書のための表と会社情報の2か所に持つと、直し忘れで書類ごとに食い違う。PO が1か所にまとめて読む形を選んだ（2026-11-06「1」）。国内用と海外用で分ける項目がすべて同じ単位（region ごとに1つの値）になったので、1つの表の1行にまとめた。書類が読む行が1つになり、項目ごとに別の表を引かずに済む。
- 国内向けか海外向けかは、人が選ぶと取引先の国と食い違う書類ができる。PO の問い「顧客情報の住所で自動的にシステムが判断する仕組みに出来る？」を受け、作るときに1回だけ決めて請求書に持つ。PDF を出すたびに決め直すと、取引先の国を直したときに作り済みの請求書の会社情報が入れ替わるため。本番の主な会社では、取引先51社のうち48社が自動で決まる（2026-11-06 件数のみ数えた）。残る3社は決められないため、推測で片方に寄せず、請求先の国を入れるまで請求書を作らせない（PO 2026-11-07「請求書は顧客情報が登録されていないと作れない仕組みにしたいので1」）。

## 影響

- 公開ポリシーの書き換えが要る。
- 最初の自動削除が 2026-12-19 に起きるため、3年の変更とポリシーの改訂を、その14日以上前（2026-12-05 まで）に本番へ入れる。ポリシーの効力発生日は改訂日から14日以上あと、かつ 2026-12-19 以前にする。
- B2B の請求書は、会社情報を入れ直した後、請求書に決まった側（国内用か海外用）の行の会社名・メール・サイトと、欄をつないだ住所とハイフンなしの電話が載る。その行が登録有のときだけ登録番号の1行が載る。見積書は海外用の行が載り、登録番号は載らない。発注書と FedEx の申請書は変わらない。design.md §6。
- 請求先の国が空か、既定の請求先が無い取引先では、国内向けか海外向けかを決められない。その取引先には請求書を作らせず、請求先の国を入れる案内を出す（PO 2026-11-07。design.md §3-4）。
