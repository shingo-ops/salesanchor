SA-12 未着手

テナントポリシー基盤

標準エンジン＋テナント別ポリシー — 計算ロジックは全社共通。違いはテナント設定（ポリシー）が吸収する。

① 一言でいうと

「コードは1つ。会社ごとの違いは "ポリシー（設定値）" で吸収する。在庫・発送・書類・報酬のルールが会社で違っても、同じエンジンで全社を動かす。」

A 専業・B 専業・A+B 混在、送料・関税・報酬・集計条件がテナントごとに違います。 SA-12 では、計算ロジック（エンジン）を全社で共通にし、 差異はテナント設定（ポリシー）として注入することで コードを会社ごとに分岐させません。 さらにテナント間のデータは DB の RLS（行レベルセキュリティ）で完全分離します。

③ 仕組みの図解 — エンジン＋ポリシー注入モデル

エンジンは何も変えず、ポリシーを差し替えるだけで全テナントに対応します。 データは RLS で物理的に分離されているため、アプリのバグでも混入が起きません。

④ 4原則との対応表
原則SA-12での実現方法
SSOT 各テナントのポリシーはテナント設定テーブルの 1 か所に集約。ロジック中に散在する if 文でテナント差異を持たない。テナントの SSOT 単位は会社ごと（RLS がテナント境界を保証）。
2本背骨 SA-12 は横断的なインフラ。背骨①・②の計算（集計フィルタ・発送タイミング等）をエンジンが行い、ポリシーが各テナントの挙動を決める。
派生値 テナントごとの在庫優先順位・発送タイミング・書類金額はポリシーと元データから計算（保存しない）。計算ルールの変更はポリシーの更新のみで反映される。
ポカヨケ テナント ID を署名トークン経由でのみ確定（ADR-097 連動）。RLS で DB 層の誤混入を構造的に防止。ポリシー注入を if 文の代替とすることで「コード修正なし」の新テナント追加を実現。
⑤ 用語ミニ辞典
ポリシー（テナント設定）
在庫ソース・集計フィルタ・発送カットオフ・関税ポリシー・発行者情報など、テナントごとに異なる設定値の総称。エンジンに注入されて挙動を決める。
共通エンジン
在庫計算・発送タイミング・書類生成・報酬計算のロジック本体。ポリシーを引数として受け取り、テナント分岐の if 文を一切持たない。
RLS（行レベルセキュリティ）
PostgreSQL の機能。各行に「このテナントだけが読み書きできる」制約を DB 層で設定する。アプリがバグを持っていてもテナント間のデータ混入が起きない。
ポリシー注入
実行時にテナントの設定値をエンジンに渡す設計パターン。if 文でテナントを分岐させる代わりに「設定を変えるだけ」で挙動が変わる。
