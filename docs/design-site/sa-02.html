SA-02 進行中 80%

会話ログ＋会社集計ビュー

顧客マスタ／CRMデータモデル（背骨①の具体設計）— Excelの1行61列を「顧客カルテ」に再設計する

このページで分かること
  • 顧客マスタを「1人1枚のカルテ」にする理由が分かる
  • 商談・会話ログ・住所帳が顧客にどう紐づくかが分かる
  • 累計取引額やLTVを手入力せず、注文から自動計算する流れが分かる
① 一言でいうと

「顧客1人に1枚のカルテ。取引・会話・実績はそこから自動で集計される。」

現在のスプレッドシートでは、1人の顧客の情報が「連絡先・商談・会話・実績」として 61列の1行に詰め込まれています。 SA-02では、これを顧客マスタ（永続）・商談（初成約まで）・会話ログ（1件1行） の3つの箱に整理します。実績（累計取引額・LTV）は注文から自動計算されます。

③ 仕組みの図解 — データの流れ
読み方: 左の顧客マスタを起点に、商談・会話ログ・住所帳が紐づきます。注文は顧客IDと商品IDを参照し、累計売上やLTVは注文から自動計算されます。

顧客マスタは変更しない・削除しない永続情報。 実績（累計・LTV）は注文から計算するため、注文データを修正すれば実績も自動で正しくなります。

④ 4原則との対応表
原則 SA-02での実現方法
SSOT 住所（配送先D）は顧客マスタの子テーブル（1:N）に1か所保存。 注文・請求書はIDで参照し、住所をコピー保存しない。 （例外: 出荷スナップショットはADR-101で別途設計）
2本背骨 顧客マスタ = 背骨①の具体実装。商談・会話ログはすべて顧客IDで紐づく。 注文（交差点）に至るまでの顧客側の全データがここで管理される。
派生値 累計取引額・月間売上見込・LTV・初回取引日・会話数・会話要約は すべて書き込み禁止の自動計算カラム。 注文または会話ログを変更すれば自動で再計算される。
ポカヨケ 失注理由・対象外理由は選択式必須（自由記述不可）。 返信速度はAPIが自動入力（手動上書きは可）。 信頼度カラムは廃止（測定できない指標を入力欄にしない）。
⑤ 用語ミニ辞典
顧客マスタ（背骨①）
顧客の永続情報（名前・国・顧客タイプ・流入経路など）。変更はするが削除しない。
商談（SFA）
初成約までの一時的なフロー情報。常連客型なので顧客1人につき基本1件。進捗・温度感・失注理由を持つ。
会話ログ
顧客との1回のやり取り（1件1行）。原文・翻訳・送受信フラグ・商談解析などを持つ。
住所帳（配送先D）
1顧客に複数の配送先を登録できる子テーブル。注文はここを参照（コピーしない）。
累計取引額 / LTV
派生値。手入力禁止。注文テーブルから集計して自動表示される。
失注理由（選択式）
なぜ成約しなかったかの理由を選択肢から選ぶ必須項目。自由記述は別欄に追加可。
返信速度
API送受信ログから自動計算（手動上書き可）。「何時間で返信したか」の指標。

# ゴール（KGI）— 本番でこれが観測できたら成功 種別
G1a API/Webhook 連携済みチャネルで受信したメッセージの 100% が 自動で会話ログに保存され、1 人の連絡先（contact）に紐づく。 取りこぼしは自動検知（アラート）できる データフロー（自動）
G1b 未連携チャネルのやり取りはスレッド欄からチャット感覚（1 分以内）で手動記録でき、 自動取り込みと同じログ・同じ集計・同じ翻訳/解析・同じスレッド表示に乗る データフロー（手動）
G2 会話数・最終会話日時・会話要約は自動計算のみ。 手入力できる画面・カラムが 0 箇所 派生値（ADR-095 原則）

G4 会話に関する同じ事実（要約・最終会話日時など）を手入力で二重に持つ場所が 0 箇所 SSOT

現在: フェーズ⑤ 本番反映済み（80%）。KGI G1〜G4 の本番実測でフェーズ⑥（100%）になります。
