## 2. フェーズ定義と進捗率（全件共通の物差し）

誰が見ても同じ意味になるよう、進捗率はフェーズ完了で機械的に決める。

| フェーズ | 完了条件 | 進捗率 |
|---------|---------|--------|
| ① KGI承認 | 定量的なゴールをShingoが承認 | 15% |
| ② recon完了 | Terminal CCが実コードを file:line 付きで突合し、差分表が埋まる | 35% |
| ③ 設計確定 | 設計docがreconとADRを相互参照して完成（What/Whyのみ） | 50% |
| ④ 実装マージ | PRがdevelopにマージ（process-artifactsゲート通過） | 75% |
| ⑤ 本番反映 | CI緑→本番デプロイ＋smoke通過 | 90% |
| ⑥ KGI実測達成 | 本番でKGIの数値・状態が観測できた | 100% |

- recon＝実コード調査のこと。**推測禁止、引用は必ず file:line**。
- 「在るだけの書類」は成果物ではない。各フェーズの完了条件＝中身が揃っていること。

## 3. 進め方ルール

1. **一括禁止・1件ずつ**。着手順は SA-02 → 03 → 04 → 05 → 06 → 07 → 12（依存順。変更はShingo判断）。SEC-MASTER は横断セキュリティ基盤として、SEC-01 から1領域ずつ別管理で進める。
2. 各件とも標準フロー（正本: `docs/STANDARD-WORKFLOW.md`）に従う: ①KGI（PO承認）→ ②recon → ③設計 → 実装 → 検証ゲート。
3. **完了判定にはSA-01チェックシートを必ず通す**（SSOT・派生値・ポカヨケの横断確認）。
4. 不可逆な変更（migrations / deploy.yml / 本番scripts）を含む本番投入は**Shingoの明示GO必須**。それ以外はCI緑でデプロイまで進めてよい（2026-06-10合意）。
5. この総合表は**フェーズが進むたびに更新**する（更新者＝そのフェーズの担当）。更新されない進捗表は嘘になるため、実装PRに進捗表の更新を含める。
