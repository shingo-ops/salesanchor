# design：本番サーバー上の作業の委任（ADR-1003 追記）

参照: docs/handoff/standing-prod-ops-delegation/recon.md、ADR-1003「追記（2026-11-02）」、ADR-1034、ADR-1033、docs/handoff/gas-viewer-fresh-fast/design.md の Q12。

## 目的
PO が設計で合意した作業を、本番サーバーの段で PO の手を借りずに最後まで進める。危ない点は設計の段階で PO に説明する。

## 変更前 → 変更後
- 前: 無制限鍵での変更を伴う作業は、作業ごとに PO の GO（AGENTS.md:26）。自動の安全判定が毎回止め、PO の `!` 実行が要った（7件/週）。
- 後: PO が合意した設計の作業手順に書かれ、審査役が APPROVE した行は、Opus 本人が控えを取ってから実行してよい。条件6つ・除外・毎週の照合は ADR-1003 追記を正とする。

## 対象と対象外
- 対象: AGENTS.md:26 の1行、ADR-1003 の追記、opus-delegation.md の節と履歴、gas-viewer-fresh-fast/design.md の Q12 への注記。マージ後に PO の `!` で自動の安全判定の許可の行を1つ足す。
- 対象外: コード・DB・CI・見張り（フック）の中身。担当（サブエージェント・クラウド）への無制限鍵の利用。閲覧者のアカウントの操作（Q12）。
- 別の作業として残すもの（未着手）: 定期の点検の指示に「毎週の照合」2つを足すこと。agent-console 側の変更なので、この PR では扱わない。それまでは、毎週の同意と権限の点検のセッションで Opus が手で行う。

## 代替案
| 案 | 結果 | 理由 |
|---|---|---|
| A 作業ごとに期限付きの許可を足す（FNT-1 の形） | 不採用 | 足すたびに PO の `!` が要り、PO の「再度許可を取りに来なくてもいい」に反する |
| B 条件付きの常設の許可（本案） | 採用 | PO の手は最初の1回だけ。危ない点は設計の段階で説明済みのものに限る |
| C 無条件で無制限鍵を許す | 不採用 | 手順書に無い行や消す操作まで通る |

## 書き換える止める行の文面
今の設定には、本番の容器の再起動を止める行がある（recon.md「今の自動の安全判定の止める行」、記録用の番号 a2585405）。この行は「PO の決定なしには」止める、という意味なので残す。そのうえで、上の許可の行の条件を満たす手順書の行が「PO の決定」に当たることを書き足す。それ以外の再起動は、今までどおり止まる。PO の `!` の台本で、次の文面にそのまま置き換える（元の文面と一字一句同じ行が無ければ、台本は何も変えずに止まる）。

```
Bash(docker compose restart *) — container restarts on prod are forbidden without PO decision; the default Remote Shell Writes rule may not fully cover docker compose restart on prod hosts specifically. A restart line that is written in a PO-agreed design runbook and meets every condition of STANDING-PROD-1 (ADR-1003 addendum 2026-11-02), run by the main Opus session only, counts as a PO decision; every other restart stays blocked.
```

## 記録用の番号
権限の記録帳と毎週の点検（consent-audit.py）は、設定の1行を sha256 の先頭8桁で見分ける。PO の台本は、取り出した文面の8桁が下と一致しなければ、何も変えずに止まる（審査を通った文面と同じであることの確かめ）。

| 何か | 記録帳の操作 | 8桁 |
|---|---|---|
| 足す許可の行（autoMode.allow） | add | ef426399 |
| 元の止める行（autoMode.soft_deny） | remove | a2585405 |
| 新しい止める行（autoMode.soft_deny） | add | aaad6762 |

根拠の形: 止める行は PO の記録が要る種類で、PR 番号は根拠として数えられない（consent-audit.py の PR_ONLY_TARGETS は repo-allow と repo-hooks だけ）。そこで3件とも、会話の同意票（ADR-1033）を根拠にする。同意票には操作を3つ並べ、それぞれに上の8桁を書く。PO が「1」で答えたあと、Opus が鍵（`consent:<票の sha256>:<「1」の時刻>`）を伝え、PO が台本に付けて `!` で1回実行する。台本は操作番号 1・2・3 を付けて3件を記録する（同じ鍵を2件に使うと点検が通らないため）。

## PO への説明（条件3・受け入れたリスク）
2026-11-02 の会話の返事で、普通の言葉で説明する。説明すること: ①担当（ほかの AI）が無制限鍵を使っても機械では止まらない ②気づくのは毎週の照合で、最大1週間遅れる ③本番の容器の再起動を止める行を、合意した手順書の行に限って通す形に書き換える。PO が台本を実行することを、この説明への承認とする。

### 呼び出しが無制限鍵を使うかの判定
1. 文面の中の ssh・scp・rsync・sftp の呼び出しを取り出す。ファイルに書くだけの heredoc（`cat >`・`tee` に渡すもの）の中の文章は数えない（10-27 の README の誤判定を防ぐ）。`bash`・`sh`・`ssh` に渡す heredoc と `bash -c "…"` の中身は数える（実行されるため）。
2. その呼び出しで `-i` か `IdentityFile` に `manual-only` があれば「使う」。
3. 無ければ行き先の名前（`prod1` など）を `ssh -G <名前>` で解く（通信はしない。手元の ssh の設定を読むだけ）。出てきた identityfile に `manual-only` があれば「使う」。
4. 文面から呼ばれる台本（拡張子 .sh・.py）が今もあれば、その中身に 1〜3 を当てる。台本が消えていれば「台本が読めない」の印を付ける。
