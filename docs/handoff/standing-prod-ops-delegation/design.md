# design：本番サーバー上の作業の委任（ADR-1003 追記）

参照: docs/handoff/standing-prod-ops-delegation/recon.md、ADR-1003「追記（2026-11-02）」、ADR-1034、ADR-1033、docs/handoff/gas-viewer-fresh-fast/design.md の Q12。

## 目的
PO が設計で合意した作業を、本番サーバーの段で PO の手を借りずに最後まで進める。危ない点は設計の段階で PO に説明する。

## 変更前 → 変更後
- 前: 無制限鍵での変更を伴う作業は、作業ごとに PO の GO（AGENTS.md:26）。自動の安全判定が毎回止め、PO の `!` 実行が要った（7件/週）。
- 後: PO が合意した設計の作業手順に書かれ、審査役が APPROVE した行は、Opus 本人が控えを取ってから実行してよい。条件6つ・除外・毎週の照合は ADR-1003 追記を正とする。

## 対象と対象外
- 対象: AGENTS.md:26 の1行、ADR-1003 の追記、opus-delegation.md の節と履歴、gas-viewer-fresh-fast/design.md の Q12 への注記。マージ後に PO の `!` で自動の安全判定の許可の行を1つ足す。
- 対象外: コード・DB・CI・見張り（フック）の中身。担当（サブエージェント・クラウド）への無制限鍵の利用。閲覧者のアカウントの操作（Q12）。
- 別の作業として残すもの（未着手）: 定期の点検の指示に「毎週の照合」2つを足すこと。agent-console 側の変更なので、この PR では扱わない。それまでは、毎週の同意と権限の点検のセッションで Opus が手で行う。

## 代替案
| 案 | 結果 | 理由 |
|---|---|---|
| A 作業ごとに期限付きの許可を足す（FNT-1 の形） | 不採用 | 足すたびに PO の `!` が要り、PO の「再度許可を取りに来なくてもいい」に反する |
| B 条件付きの常設の許可（本案） | 採用 | PO の手は最初の1回だけ。危ない点は設計の段階で説明済みのものに限る |
| C 無条件で無制限鍵を許す | 不採用 | 手順書に無い行や消す操作まで通る |

## 足す許可の行の文面
~/.claude/settings.json の autoMode.allow に、次の1行をそのまま足す（PO の `!` で1回）。

```
STANDING-PROD-1（常設・PO 2026-11-02 決定・ADR-1003 追記 2026-11-02・PR #5020）: PO と会話している手元のメインの会話の Claude Opus だけは（サブエージェント・クラウドの依頼・定期実行はモデルを問わず含めない）、~/.ssh/manual-only/id_ed25519 で ubuntu@49.212.137.46（prod1）と ubuntu@49.212.160.98（prod2）へ ssh し、PO の決定を記録した設計（design.md・ADR）に属する作業手順（RUNBOOK・カード）に書かれ、審査役（reviewer・model opus）が APPROVE した版と一字一句同じ行を実行してよい。その設計に危ない操作の表と PO 承認の原文があり、操作が表に載っていること。書き込み・停止・再起動を含む（ファイルの配置と片付け、docker compose の起動・再起動・一時コンテナ、プロセスの停止、DB の接続切り、手順書に書かれた台本と SQL、backup.sh）。書き込み・停止・再起動の前に控えを取り、実行ごとに ~/CC報告ファイル-keep/prod-ops/YYYYMMDD.md に記録する。含まない: 手順書に無い行と値を書き換えた行、表やスキーマの削除・条件の無い削除や大量の削除・TRUNCATE、ファイルの一括削除、Docker volume の削除、仕組みの秘密（サーバーの鍵・DB のパスワード・API キー・トークン）の表示や作成や変更、アプリ利用者のパスワードの値を画面に出すこと、SSH とファイアウォールの設定の変更、人間の鍵の変更、閲覧者のアカウントの操作、見張りと権限の設定の変更、結果が手順書の想定と違ったあとの次の操作。
```

## リスクと対処
ADR-1003 追記「弊害と対処」を正とする。主なもの: 担当のセッションが無制限鍵を使っても機械では止まらない（受け入れたリスク）。毎週の照合の2つ目で、最大1週間遅れて見つける。

## 維持の仕組み
- 守り手: 毎週の同意と権限の点検で行う照合2つ（ADR-1003 追記「毎週の照合」）。記録の置き場所は `~/CC報告ファイル-keep/prod-ops/`、点検の記録は `~/CC報告ファイル-keep/consent-weekly/`。許可の行の足し引きは `scripts/dev/consent-audit.py` が記録帳と照らす。
- 解除: PO の「委譲停止」。

## 外部・過去事例の参照と我々への応用
- 外部事例: 該当なし。理由: 自社の PO と AI の間の承認の決め方であり、数値の裏付けがある外部事例を当てはめられない。
- 過去事例（自社）: 2026-10-26 の Approve の許可（28793f25）と 11-01 のクラウドの担当の許可（0c57a9f8）は、足した後の止まりが 0 件になった（autonomy-inventory/20261102.md）。ただし 0c57a9f8 は記録帳に記録の行が無く、11-02 の点検で異常として出た（consent-weekly/20261102-changes-analysis.md）。期限付きの FNT-1・FNX-1 は期限切れのまま残り、11-02 の点検で外した。
- 我々への応用: 「条件を書いた許可の行」の形を常設にする。記録の漏れの反省から、PO の台本で足すと同時に記録帳に書く。期限切れの反省から、期限ではなく条件と毎週の照合で守る。
