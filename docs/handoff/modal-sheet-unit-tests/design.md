## ① 区分：A（操作の変更なし・見た目の変更なし・**製品コードの変更なし**）

足すのはテストファイル2本だけ。**色・寸法・文言・レイアウト・挙動は一切変わらない**（CSS も製品の .tsx も触らない）。

**なぜ必要か**: `Modal` は43ファイル、`Sheet` は2ファイルで使われているのに
**単体テストが1件も無い**（recon §1）。便7・便8 で金型の内部を2回続けて直したが、

開閉・読み上げ名・大きさ・背景クリック・フッタの有無といった**公開された振る舞いは誰も見ていない**。
次に誰かが金型を触ったとき、壊れても気づけない。

- `frontend/src/components/Modal.test.tsx`（新規）・`frontend/src/components/Sheet.test.tsx`（新規）＝**金型の隣**。
- テスト名は**英語**（辞書の日本語禁止ルールに触れないため）。説明は日本語コメント。

### 4-4. 手元の全体回しは不安定（実測・2026-10-27）

`npm run test:unit`（全体）を**この端末で**回すと、**毎回違うテストが時間切れで落ちる**。実測3回:

| 回 | 条件 | 総件数 | 失敗 |
|---|---|---|---|
| 1 | 新テストあり・単独実行 | 1769 | **3件** |
| 2 | 新テストあり（JSON 形式） | 1775（＝既存1753＋新規22） | **1件**（`frontend/src/pages/super-admin/components/SoldOutResultsPanel.test.tsx`） |
| 3 | **新テストを一時的に外して**実行 | 1719 | **5件**（`OrderLeadButtonMigration`・`InventoryPage.noechopatch`・`InventoryPage.tablelayout`・`NeedsReviewTabsPanel.timing`・`SoldOutResultsPanel`） |

**新テストを外した方が失敗が多い**＝この不安定さは**元からあるもので本便とは無関係**。
落ちるのはすべて `Modal`/`Sheet` と無関係な画面のテストで、**単独で回すと緑**
（`frontend/src/pages/super-admin/components/SoldOutResultsPanel.test.tsx` 単独＝9件すべて緑を実測）。原因はこの端末の遅さによる時間切れ
（1回の全体回しに 666〜900 秒かかり、うち環境準備が 1665 秒）。
→ **「手元で全体緑」は合格基準に置けない。判定は CI の必須チェック `Frontend unit tests（内部）`** に委ねる。

## ⑨ 外部・過去事例の参照と我々への応用

- **社内の先例 `frontend/src/components/Drawer.test.tsx`**: 同じ金型群で「大きさ・任意プロパティ・✕ の呼び分け」を
  測る形がすでにある。本便はそれを `Modal`・`Sheet` に広げるだけで、**新しい作法は作らない**。
- **社内の過去事例（便6〜便8）**: 「空振りで緑」を何度も踏んだ。テストだけの便は特に危ないので、
  **製品を一時的に壊して赤になることを確かめる**手順（C3）を基準に入れた。
- **正直な限界（審査で訂正済み）**: 当初ここには「単体テストはフォーカスの実移動を測れない」と書いていたが、
  **誤り**だった。jsdom は `focus()`／`document.activeElement` を実装しており、**カーソルの移動と復帰は測れる**
  （M12・M13・S8・S9 で実測）。本当に測れないのは **①Tab キーの既定移動**（ブラウザは消えた要素の位置を
  起点として覚える＝便7 の独立審査 B-1）と **②`inert` の効き**（jsdom は未実装＝便8 の一次情報）。
  この2つは便7・便8 で入れた画面検査が担当する。
