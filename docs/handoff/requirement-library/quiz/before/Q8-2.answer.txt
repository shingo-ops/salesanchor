# 計画: Gemini が断られたら切り替えずに失敗で終わらせる

調査は読み取り専用です。行番号は調査担当の報告によるもので、私は自分で開いて確かめていません。実装前に開き直して確認します。

## 現状（調査結果）
- **別モデル・別プロバイダ・ルールベースへの切り替えはありません。**
- 「断られたら別の道へ」にあたるのは、**直接と prod2 中継の道の自動切り替え**だけです。
  - 実装は `backend/app/services/gemini_route.py:189-218` です。
  - 対象は位置拒否（HTTP 400 "location is not supported"）と、道に届かないエラーです。
  - 設計は ADR-1062（Proposed）です。
- 同じモデルでの送り直しもあります。これは別の道ではありません。
  - その場で 2 秒後と 8 秒後に送り直します（`line_analysis_v102_svc.py:466-516`）。
  - 10 分ごとの見回りもあります（`tasks/tcg_extraction_recovery.py:269-340`）。
  - 設計は ADR-1050（Proposed）です。
- 失敗の扱いは既に整っています。
  - v102 は `RecordError("API_ERROR")` を出します。
  - `extraction_jobs.status='error'` と `extraction_attempts.phase='failed'` が残ります。
- 安全フィルタ（`SAFETY` など）を検知する処理は `backend/app` にありません。

## 方針
解釈は「道の自動切り替えをやめ、断られたら 1 本の道で失敗に倒す」です。送り直しは残します（下の確認事項を参照）。

1. **ADR を先に直す（ADR 優先の決まり）。**
   - ADR-1062 を、自動切り替えをやめる内容に改めます。または廃止して新しい ADR で置き換えます。
   - ADR-1062 は `docs/adr/FEATURE-INDEX.md` に載っていないので、載せるかも決めます。
   - ADR 起案は PO の役目なので、案を出して PO の確認を取ります。
   - 直したら `node scripts/generate-adr-index.js` を実行します。
2. **コードを単純にする。**
   - `gemini_route.py` の切り替え処理と、30 分成功が無いときの通知を外します。
   - 道は設定で決めた 1 本だけにします。
   - 道の状態を持つ Redis キーと環境変数があれば、不要な分を整理します。
   - 呼び出し元は、拒否を既存の失敗の道（`API_ERROR` → `status='error'`）にそのまま流します。
3. **docs を直す。**
   - `runbooks/gemini-egress-emergency.md` を、手で道を替える手順に書き直します。
   - ADR-1062 を参照している箇所を直します。
4. **テストを直す。**
   - 切り替えを前提にしたテストを消すか、「拒否は失敗で終わる」テストに替えます。
   - 位置拒否のときに中継へ行かないことを確かめるテストを足します。

## 進め方
- 作業は `bash scripts/new-worktree.sh release/gemini-no-route-fallback` で作った場所で行います。
- 作業前に `./scripts/dev/executor-preflight.sh` を実行し、`docs/ai-agents/executor-checklist.md` を読みます。
- 変更は `backend/AGENTS.md` の決まりに従います。
- この環境では push までです。PR は手元で `shingo-cc` 名義で作ります。PR 本文に「### 標準ワークフロー確認」を入れます。

## 確認したい点
- **送り直し（ADR-1050）は残してよいか。** 「そのまま失敗」を厳密に取るなら、送り直しも外します。ただし一時的なエラーで失敗が増えます。私は、道の切り替えだけをやめて送り直しは残す案をすすめます。
- **prod2 中継は今も本番で使っているか。** 日本のサーバーから位置拒否が出ているなら、切り替えをやめると解析が止まります。先に、直接の道だけで通ることを確かめる必要があります。
- **安全フィルタの拒否を明示的に失敗として検知するか。** 今は検知がありません。この計画には含めていません。

## 検証
- backend の pytest で、変更した切り替え処理と v102 の失敗系を流します。
- pre-push の検査が通ることを確かめます。
- ステージングがあれば、わざと位置拒否にして、中継へ行かずに `status='error'` で終わることを確かめます。
