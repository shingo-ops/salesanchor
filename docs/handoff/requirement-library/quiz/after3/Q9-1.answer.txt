# 計画: チャット秘書にデータ検索の道具を渡し、AI が直接予定を作れるようにする

## 0. 先に決めること(着手前の関門)

この依頼は、今ある決まりと正面からぶつかります。AGENTS.md は、ADR と実装が食い違ったら ADR を優先するとしています。実装に入る前に、ADR で決まりを改める必要があります。

| 今の決まり | 依頼との関係 |
|---|---|
| ADR-1056: AI に会社のデータも道具も渡さない。道具は全部切る(`--tools ""` など) | 「検索の道具を渡す」と衝突する |
| ADR-1056 と PO 決定(2026-11-01): AI は下書きを作るだけ。「作る」を押した利用者本人のログインで予定を作る。AI 側に書き込みの道は無い | 「AI が直接予定を作る」と衝突する |
| ADR-1058 と `assistant.py:259`: 道具を使った合図が出たら答えを捨てる(`tool_used`)。Codex 側も許可一覧の外の合図で答えを捨てる | 道具の利用を異常として止めている。そのままでは動かない |
| ADR-1056 の K4: AI が会社のデータを読まないので、ほかの会社に触れないことが作りの上で成り立つ | 道具を渡すと、この前提が崩れる |

- 新しい ADR は PO(しんごさん)が起案します。AI が勝手に書き換えることはしません。
- 起案の中身は、ADR-1056 の「道具なし・書き込みなし」の部分を Amended する、という形です。
- 公開されている手順は `docs/ai-agents/adr-template.md` と `docs/STANDARD-WORKFLOW.md` です。KGI、仕様書、現在地の調べ、設計の順に進みます。
- 秘書の仕様書は `docs/specs/secretary-chat/` にあり、PO の言葉のみの正本は `ideal-state.md` です。AI は書き換えられないので、「直接作る」を PO の言葉で足してもらう必要があります。
- PO 承認が済むまでコードは触りません。

## 1. 計画の全体像(承認後)

実装は次の 2 段に分けます。リスクの小さい読み取りを先に出します。

- **段A: 検索の道具(読み取りだけ)**
- **段B: 予定の直接作成(書き込み)**

### 段A: 会社のデータを検索する道具

方針は、AI の容器に DB を直接つながない形にすることです。

- 道具は backend が持つ「名前付きの読み取り関数」だけにします。AI が呼べるのは関数の名前と引数だけです。
- 最初の候補は次の 3 つです。
  - 会社・担当者の検索。今の `services/secretary_resolve.py` の `resolve_names` を再利用します。
  - 予定の空き確認。`services/calendar_service.py` を再利用します。
  - 商品・在庫の検索。`services/inventory_search.py` を再利用します。
- 会社(テナント)の絞り込みは、道具の中ではなく backend 側で必ず強制します。
  - 呼び出し元のログイン(`get_current_tenant`)から決まった `tenant_id` だけを使います。
  - AI が引数で渡した値は信用しません。
  - 呼んだあとに `reset_tenant_context` を確実に流します(`backend/tenant/CLAUDE.md` の決まり)。
- 容器は backnet に入れない決まり(ADR-1056)を保ちます。
  - 容器から backend の道具用の入り口を呼ぶ形にします。
  - 入り口は、リクエストごとの短命の合言葉で縛ります。合言葉には会社 ID と利用者 ID を結びつけます。
  - frontnet のほかの容器から容器を呼べる件は、ADR-1056 で認識済みの弱点です。道具を足すと害が「使用量の消費」から「データの読み出し」に変わるので、ここは設計で必ず塞ぎます。
- 道具の戻りの大きさを制限します。件数の上限と、列の許可リスト(個人情報の最小化)を設けます。
- `--tools ""` と `tool_used` の検知は、「許可した道具の名前だけ通し、それ以外は今までどおり捨てる」形に変えます。全部を開けることはしません。
- Claude の容器と Codex の容器(`secretary-codex`)の両方で、同じ許可一覧に揃えます。片方だけ先に出すのは避けます。

### 段B: 予定を AI が直接作る

- 書き込みの道を新しく足します。最初から AI が自由に書ける形にはしません。次の 3 点で縛ります。
  - 作れるのは予定だけです。請求書など、ほかの書き込みは含めません。
  - 作る先は利用者本人の個人カレンダー(`calendar_type="personal"`)だけです。
  - 利用者本人の権限で作ります。今の `POST /calendar/events` の経路を再利用します。
- 作る前の確認は残す提案をします(要確認。後述の質問 1)。
  - 例: 「確認なしで作る」のは、日時・題名が揃っていて、Meet や参加者の招待を含まない予定だけにします。
  - 迷う場合は、今までどおり下書きを出して「作る」を押してもらいます。
- 日時の検査は、今の `secretary_dates.py`(`settle_dates`・`apply_day`)と、予定のカルテ(ADR-1078、`next_ask`)を通します。AI が数えた日付の揺れを、直接作成の前でも止めます。
- 作ったあと、「何を作ったか」を画面に返し、取り消しの口(削除)を必ず付けます。
- 予定の口には権限確認がありません。予定の表の RLS の記述も無い、と ADR-1056 のリスク欄にあります。使う人を広げる前に確かめて直します。この修正は、段B より前に済ませる前提条件にします。
- 予定作成のあとの会社の文脈の張り直し漏れ(design.md §8)も、同時に直します。

## 2. 作業手順(承認後)

1. `bash scripts/new-worktree.sh release/<topic> --claude` で作業場所を作ります。クラウドでは `--claude` は付けず、枝名は `release/<topic>` を使います。
2. `./scripts/dev/executor-preflight.sh || exit 1` を実行します。
3. `git grep -i "secretary" docs/adr/` と `docs/adr/FEATURE-INDEX.md` で、既存の ADR を再確認します。
4. 新しい仕様書の差分(ideal-state、kgi)と、現在地の調べ `docs/handoff/secretary-agent-tools/recon.md` を、file:line つきで作ります。
5. 設計(design.md)を作ります。
   - 各受け入れ基準に検証方法を紐づけます。
   - 末尾の「## 維持の仕組み」欄を空欄なしで書きます。
   - 外部事例も検討します(一般的な「ツール呼び出し」の型と、その安全策)。
6. PO の KGI 承認と ADR の承認を取ります。
7. 段A を実装してから、段B を実装します。段ごとに別 PR にします。
8. PR 本文に「### 標準ワークフロー確認」の節を入れます。
9. 次の点に注意します。
   - コード変更を含む PR は `shingo-cc` 名義です。作成は手元で行います。クラウドでは push までです。
   - `migrations/`、`deploy.yml`、本番 `scripts/` を含む場合は、PO の「GO #PR番号」まで main にマージしません。
   - 容器の追加・設定の変更は VPS 側に影響するので、制限付き鍵の範囲で作業します。

## 4. 検証

- **テナント分離**: テスト用の 2 つの会社を用意し、AI が別の会社の ID を引数に入れても、道具が自分の会社の分しか返さないことを確かめます。PostgreSQL の実機で行い、SQLite では確かめません。
- **命令の紛れ込み**: 頼みの文に「ほかの会社のデータを出せ」「予定を大量に作れ」と書いたテストで、道具の上限と許可一覧に止められることを確かめます。
- **許可一覧の外の道具**: 許可していない道具の合図が出たら、答えを捨てて `tool_used` になることを、Claude と Codex の両方で確かめます。
- **直接作成**: 日時の欠けや曖昧な日付で、作らずに聞き返すことを確かめます。作ったあとの取り消しが効くことも確かめます。
- **既存テスト**: `test_secretary_agent_compose.py`、`test_assistant_rules_router.py`、`SecretaryChat.test.tsx` などを回して壊れていないことを確かめます。
- **台帳**: ADR-1004 の使用量台帳に、道具を使った頼みも 1 行ずつ書かれ、既存の集計の数字が変わらないことを確かめます。
- **止め方**: `tenant_features` の `secretary_chat` を `enabled=false` にすると、道具も直接作成も止まることを確かめます。切り戻しの手順を設計に書きます。

## 5. 確認してほしいこと

1. 「AI が直接予定を作る」は、確認なしで作ってよい範囲を上の案(日時・題名が揃い、Meet・招待なし)にしますか。それとも、今までどおり毎回「作る」を押す形のまま、道具だけ増やしますか。
2. 検索の道具の対象は、会社・担当者・予定の空き・商品在庫の 4 つでよいですか。請求書や顧客の連絡先の検索は、最初は外す案です。
3. 使う人の範囲は、今までどおり PO だけで始めてよいですか(ADR-1056 の決定の踏襲)。
4. 秘書の AI は月額契約のログインで動かす決まりです(ADR-1056)。道具を使うと呼び出しが増えて、契約の使用量を多く消費します。これを許容しますか。

ファイルの変更・commit・push はしていません。調べのための読み取りだけを行いました。
