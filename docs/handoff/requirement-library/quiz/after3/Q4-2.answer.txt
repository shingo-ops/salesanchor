## 見つかった食い違い（事実）

- ADR-1027（`docs/adr/ADR-1027-bundle-sale-reading.md`）は、PO の指定（2026-10-17）で「まとめ売りは値段を割らない。値段はまとめ1つの値段、数量はまとめの数」と決めています。例の行「40パックセット/¥24,000 残り15」は、24,000円・数量15・`bundle_size=40`・単位 Pack で保存する決まりです。
- 「1パック600円（÷40、数量×40）」は、ADR-1021 便2 の旧方式です。ADR-1027 がこれを置き換えました。
- コードにもその置き換えが入っています。`line_analysis_v102_svc.py` の `_apply_bundle` は割らずに `bundle_size` を入れます。`_apply_bulk_price` は、まとめ売りと決まった行を通しません。
- `AGENTS.md` では「ADR と実装が食い違うときは ADR を優先する。逆はしない」です。

## 計画

### 手順0: PO への確認（実装の前）

次のどちらの意図かを PO に聞きます。

- **(a) 表示や検索で「1パックいくら」が欲しい。** ADR-1027 のまま、保存は割りません。1パックの値は `price ÷ bundle_size` で計算して出します。ADR の変更は不要です。
- **(b) 保存そのものを1パック600円にしたい。** ADR-1027 の変更（ADR 起案）が必要です。ADR は PO が起案します。

1. 1パック単価を出す場所を決めます。候補は、配信 SQL（`tcg_distribution_svc.py` の `dist_base`）の追加列か、画面側の計算です。

### 手順2b:（b）の場合

1. ADR 起案の後、実装に着手します。
2. 実装は ADR-1021 便2 の復活に近い形です。
3. `bundle_size` の読み取りは残し、保存値だけを割ります。
4. 影響する箇所は次のとおりです。
   - 単価の確かめ（`v102_unit_price_check_svc.py`）
   - 価格の引き継ぎ

6. migration が必要なら、ADR-136 の GO 手順を通します。
7. 本番の再解析には PO の GO が要ります。
