# 計画: 「40パックセット ¥24,000」を 1パック600円で保存する

## 結論（先に確認が必要）

この依頼は、PO が決めた既存の決定と逆向きです。実装に入る前に、PO の判断が要ります。

- `ADR-1027`（まとめ売りは値段を割らずに保存する）の決定 3 は、まとめ売りと決まった行について値段・数量を「割らない・掛けない」としています。
- `docs/specs/bundle-sale/ideal-state.md` の「値段: まとめ1つの値段。割らない」と、`kgi.md` の K1・K2 も同じです。K1 は、この行を「商品名 40パックセット／Pack／24,000円／15」と出すことを合格条件にしています。
- ADR-1027 の決定 7 は、以前の「値段÷N にそろえる」換算（ADR-1021 便2）を意図的にやめています。今回の依頼はその復活にあたります。
- `AGENTS.md` では、ADR と実装が食い違うときは ADR を優先し、コードを ADR に寄せます。逆はしません。
- ADR の起案と直しは PO の仕事です。

現状の保存は、この行を次のように持ちます。
- `bundle_size`=40
- 単位=Pack
- 値段=24,000
- 数量=15

商品名の欄は配信の時に「商品名 40パックセット」と組み立てます（`tcg_distribution_svc.py:265-276`）。

## 方針の選択肢（PO に聞くこと）

**案A（推奨）: 保存は今のまま。在庫表に「1パック 600円」を表示用の派生値として足す**
- 24,000 ÷ `bundle_size`(40) = 600 を、配信・表示の時に計算して出します。
- ADR-1027 に反せず、K1〜K6 も崩れません。
- 元の値（24,000）が残るので、安全に元へ戻せます。

**案B: 保存する値段そのものを 600 にする**
- 先に ADR-1027 の追補（決定 3 と 7 の変更、K1・K2 の改訂）を PO が起案し、承認する必要があります。
- 実装はその後です。
- 24,000 が失われないよう、まとめ値段の保存先（列か `price_basis`）を別に決めます。

## 実装の段取り（案A の場合）

1. 作業前の手順
   - `./scripts/dev/executor-preflight.sh` を実行します。
   - `docs/ai-agents/executor-checklist.md` を読みます。
   - `bash scripts/new-worktree.sh release/bundle-unit-price-display --claude` で作業場所を作ります。
2. 設計の追記
   - `docs/handoff/bundle-sale/design.md` に、表示用の1単位価格の節を足します。
   - 割り算の端数の扱い（切り捨てか小数表示か）を決めます。
   - 24,000÷40 は割り切れますが、割り切れない場合の表示が要ります。
3. 配信側の計算
   - `backend/app/services/tcg_distribution_svc.py` の、商品名を組み立てている箇所の隣に、`bundle_size IS NOT NULL` の行だけ `price / bundle_size` を返す列を足します。
   - まとめ売りでない行は従来どおり変えません。
   - 閲覧ページ（ADR-1019）、GAS 在庫一覧、アプリ在庫表のどれに出すかは、PO に決めてもらいます。
4. 画面（アプリ在庫表）
   - `frontend/AGENTS.md` と `docs/CC_UI_GOVERNANCE.md` を先に読みます。
   - 文言は `frontend/src/locales/ja.json` と `en.json` の両方に足します（ADR-027）。
5. テスト
   - 次のテストを `backend/tests/test_inventory_distribution_rows.py` に足します。
     - 40パックセット/24,000 で 600 と出ること。
     - まとめ売りでない行、および `bundle_size` が NULL の行が変わらないこと。
     - 割り切れない場合の表示。
   - 既存の `test_v102_bundle.py` と `test_v102_bulk_price.py` が通ることを確認します。
6. PR
   - `shingo-cc` 名義で作ります。
   - 本文に「### 標準ワークフロー確認」の節を入れます。

## 検証

- 追加テストと既存の bundle 系テストを CI で通します。
- 本番の行の再解析や書き換えは不要です（案A は保存を変えないため）。
- 反映後は、配信行の照合 SQL で次を確認します。
  - 24,000 の行が 600 と表示されること。
  - 保存値が 24,000 のままであること。
- 本番 DB の読み取りは、reader 鍵の道（ADR-1024）で行います。

## 案B を選ぶ場合の追加作業

- ADR 追補は PO が起案します。起案後に `node scripts/generate-adr-index.js` を実行します。
- `_apply_bundle`（`line_analysis_v102_svc.py:1080`）を変更します。
- 既存のまとめ売りの行を再解析します。この手順は `docs/runbooks/bundle-sale-new-wording.md` の手順5 にあります。
  - 前の値を全列保存し、書き戻しの SQL を先に用意します。
  - 実行の前に、同意票で PO の確認を取ります（ADR-1033）。
- `bundle_size` と一緒に、単価の確かめ・価格の引き継ぎ・買取単位の判定から外している箇所（ADR-1027 決定 6）を見直します。見直しは、まとめの値と1単位の値が混ざらないことを確かめるためです。
- 今回の依頼は、案A でよいか案B かを PO が決めるまで、実装に進めません。
