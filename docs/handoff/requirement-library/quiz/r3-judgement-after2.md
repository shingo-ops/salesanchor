## 4. なぜ Q1 だけ変わらないか（実物で確かめたこと）

- 決まりの中身のうち「会社はリードの子。受信箱から送る登録フォームでお客様が登録して作る」は、索引 `docs/adr/FEATURE-INDEX.md:39` の補足の欄にだけ書いてある。「画面から手で作る道は直さない」はどの書類にも無く、[../quiz.md](../quiz.md) §2 の判定の定義にだけある。
- AI が開いた `deal-removal/design.md` には、「顧客登録フォームに記入をしてもらい顧客テーブルが作成され」（11 行目）はあるが、顧客画面の「新規登録」をどうするかは書いていない。`customer-management/README.md`（全 23 行）にも書いていない。ADR-097 は登録フォームの作り方の決まりで、手で作る道を閉じるとは書いていない。
- 顧客画面の「新規登録」ボタンを消すかどうかは、2026-11-13 に PO 判断待ちのまま残っている（書類に決定が無い）。
- 見張りの文のかっこの中は、設計（[../design.md](../design.md) 便2 の「文の形」）では「ADR-097（会社はリードの子）」と決まりの中身の例を示していた。実装は索引の機能キーワード（「会社 / 顧客情報 / …」）を出している（`.claude/hooks/requirement-context.py` 136 行目 `{label}（{kw}）`）。設計で「かっこの中に索引の補足を出す」と言葉で決めるのを入れ忘れたのが原因で、補足の中身は AI に渡っていない。
