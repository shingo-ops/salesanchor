# POカード: 同じ投稿に同じ商品が2行以上あるときの表示（便SP）

設計者: Opus（2026-10-12）。状態: 設計案（PO 承認済みの決まりに沿う。PO の追加判断は「残る判断」に記載）。

## PO の決定（2026-10-12）
- 決まりの中身（同日、別の応答で決定。記録は設計者のセッション記録）:
  - 同じ仕入元・同じ投稿・同じ商品・同じ状態の行で、括弧の書き込み（発送条件など）が違うものはまとめない。
  - ランク（状態A-・状態B など）だけが違うものはまとめる。数量は合計し、価格は高い方を取る。
- 着手（原文）: 「同じ投稿に同じ商品が2行あるときの、行をまとめる決まり→進める」

- まとめ方の切り替え（原文）: 「行をまとめる件を、在庫一覧で ON／OFF できるようにする→する、カスタム設定ページを作り、在庫表ページのヘッダーアクションにアイコンボタンを設定してそこからカスタムで在庫表の見え方を整えられるようにする」
  - これを受けて、範囲を2便に分けます。
    - この便（SP1）: 表示する行の決め方を直す（is_current を投稿単位にする）。在庫一覧には、同じ投稿の同じ商品の行がすべて別々の行として出る。
    - 次の便（SP2）: まとめる番号を付ける。在庫表の設定ページと ON／OFF の切り替えを作る。設計は別のフォルダに置く。
  - 下の K2・K5 は SP2 で判定します。

## 何が変わるか（利用者に見える変化）
- 在庫一覧で、同じ投稿の同じ商品・同じ状態の行のうち、備考（発送日の文字）が違うものは、すべて別々の行で出る。今は1行しか出ず、どの行が出るかは解析し直すたびに入れ替わる。
- 同じ投稿の「状態A-」と「状態B」は1行にまとまる。数量は合計、価格は高い方になる。
- 同じ投稿を何度解析し直しても、在庫一覧に出る行は変わらない。

## 残る判断（PO）
- R1: 「ダメージ小／大」のように、原文で程度が書き分けてあっても、システムの状態の根拠が同じ語（R2:ダメージ）の行は、この便ではまとめずに別々の行で出す。まとめる場合は、程度の語をマスタに登録する別の便になる。
