# design: LINE のお知らせ34件と、お知らせだけから生まれた仕入元8件の片付け（段階1の後始末・その1）

- 状態: 設計案作成済み／自己審査 APPROVE（§8、実行前の確認2点つき）／PO の実装承認待ち
- 調査: `docs/handoff/line-system-notice-cleanup/recon.md`（R1〜R11、2026-09-30 本番読み取り）
- 対象ADR: `docs/adr/ADR-158-product-level-supersession.md`（source_messages.is_active／置き換えの前提。本便は置き換えの規則を変えず、お知らせで押し出された投稿を元に戻すだけ）
- 前の便: PR #3861（お知らせを取り込まない。2026-09-30 本番反映、反映後のお知らせ0件を確認済み）
- PO の決定（2026-09-30）: 片付けは「記録は残し、無効にして（旧）印を付ける」方式で設計に進む（y）

## 1. 目的（PO から見える変化）
1. 仕入元の一覧・ダッシュボード・確認画面に、LINE のお知らせ（招待・退会・アナウンス等）が「最新の投稿」として出なくなる
2. お知らせに押し出されていた本物の最新投稿（いとう あ、Mie (*´ω`*)、RAITO の各チャネル）が、最新の投稿として戻る
3. お知らせだけから生まれた仕入元8件が、有効な仕入元の一覧から消える（記録は（旧）付きで残る）

## 2. 事実（recon より）
- お知らせ34行のうち有効（is_active=TRUE）は10行。24行は既に無効（recon R2）
- シートへの配信には0件（配信は pid_resolved 等で除外、recon R2・R10）。is_active は配信の条件に入っていない（`backend/app/services/tcg_distribution_svc.py:223`）→ 本便は配信を変えない
- is_active を見る画面・集計: `backend/app/routers/super_admin_suppliers.py:799`、`backend/app/routers/super_admin_suppliers.py:951`、`backend/app/services/tcg_analysis_dashboard_svc.py:482`、`backend/app/services/tcg_analysis_review_svc.py:38`（recon R3）
- 有効なお知らせ10行のチャネル: 7つは幽霊仕入元、3つは本物の仕入元（SP-00255 いとう あ、SP-00317 Mie (*´ω`*)、SP-00234 RAITO）。本物の3チャネルは、お知らせを無効にしても前の投稿は自動では戻らない（置き換えは片方向、`backend/app/services/tcg_line_import_svc.py:454`）
- 幽霊仕入元8件（SP-00245/247/254/260/276/285/302/310）の他表からの参照は、ルール39の一括付与のリンク1件（id=290、SP-00276）のみ（recon R4）
- suppliers は保護表（`.github/workflows/migration-guard.yml:416`）→ 変更はマイグレーションに書けない。過去2回の整理と同じく、手動 SSH（DRY-RUN→COMMIT）＋記録用の何もしないマイグレーション（手本: `migrations/20260924_060000_cleanup_supplier_name_duplicates.sql`）

- `backend/app/services/tcg_line_system_events.py` の SYSTEM_EVENT_PATTERNS の末尾に2つ追加（既存13パターンは変えない）: `("note_posted", re.compile(r"^.+?がノートに投稿しました。?$"))`、`("voice_call_start", re.compile(r"^.+?グループ音声通話が開始されました。?$"))`
