# ADR 案 — 本線への合流は GitHub 純正の順番待ちの列を通す（草案・PO 未承認）

- 状態: 草案。PO が設計を承認したら docs/adr/ に番号を付けて置き、`node scripts/generate-adr-index.js` で索引を作り直す。
- 置き換える物: ADR-135:66 の「merge queue は今回は採らない・コスト過大」。覚え書き「若い番号に譲る」（PO 2026-09-29）。
- 設計: docs/handoff/merge-queue-org/design.md

## 決めたこと（What）

1. リポジトリを会社名義 GEN-RYU-System に、名前を変えずに移す。
2. 本線の ruleset に merge queue の規則を足す（MERGE・同時に確かめる数 5・一度に入れる数 1・制限 60 分・失敗していない PR だけ）。strict は外す。bypass は作らない。
3. 本線の必須の確かめは全部 `merge_group` で起動する。合わせた形で壊れうる物は列で確かめ直し、PR 本文と PR 差分だけで決まる物は列では job の条件で飛ばす。
4. 列の詰まりを 15 分ごとに、設定のずれを週 1 で見張り、PO に Discord で知らせる。
5. 危険 PR の GO（ADR-136）は列に入れる前に受け取る。

## なぜ（Why）

- 1 日 46 件の合流・確かめ 20 分超・strict 有効で、PR が追い越されるたびに確かめをやり直していた（#5335 で 9 回）。覚え書きの決まりは機械で守らせる物が 0 で、守られなかった。
- 純正の列は個人名義では使えず（公式: organization の public リポジトリ）、会社名義が必要。
- 外部事例（GitHub 社・Atlassian・Shopify）の共通点: 列の中で確かめる・列を通らない道を塞ぐ・同時数を量に合わせる。失敗例（Shopify v1・2026-04-23 の純正列の不具合）の手当てとして、見張りと merge 方式を選ぶ。
