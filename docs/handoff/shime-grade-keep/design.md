# design: 品質の言葉つきの〆が、別の品質の在庫まで閉じないようにする

関連 recon: `docs/handoff/shime-grade-keep/recon.md`

関連 ADR（recon §4）: ADR-1032（復活止め）、ADR-1035（要確認0件化）、ADR-1023（状態の価値の順位）、ADR-1073（箱の〆の全状態）。前例: 状態の辞書の本番変更 `docs/handoff/condition-unit-booklet/data/`、監査行つきの現行の直し ADR-1032 What 4。

状態: 設計案作成済み（2026-11-13、Opus）。PO の方針の承認: 2026-11-13 毎朝点検の報告の選択肢「1」（品質の言葉つきの〆で別品質の在庫を閉じない直し方を設計する）。PO の選択: 2026-11-14「1」（テープに切れ込みがある品＝傷みのあるカートン Damaged case）。便2 は不要になった（§3-2）。便1 の事前確認 01_precheck を本番の読み取りで流して期待どおり（§3-1）。設計審査（クラウド）: 未実施。本番の辞書の変更: 未。

## 1. 目的と成功条件

- 目的: 仕入元が同じ商品を品質違いで2行出し、片方だけを「〆」たとき、もう片方の在庫を売り切れ扱いにしない。今は両方が外に出なくなる（recon §1）。
- 利用者に見える変化: 在庫の画面と配信で、〆られていない品質の在庫が残る。
- 変えないもの: 商品×状態の組ごとに最新の投稿の行が現行、という規則（ADR-1032 の守ること）。状態の辞書のほかの語。

| 基準 | 検証方法 |
|---|---|
| K1 今回の言葉が状態として読める | 便1 の適用後、03_verify で「切れ込み」を含む辞書の行が id 13（Damaged case）の1行だけ。照合は語が文に含まれるかで見る（`backend/app/services/tcg_analyzer_svc.py:273-288`・`:851-864`）ので、今回の2行の文（どちらも「切れ込み」を含む）は Damaged case の語に当たる。Case の除外語・Opened case の語には「切れ込み」が無い（precheck_bin1.txt・recon §2-3）。○ = 03_verify が1行。実際の投稿での確認は K5 |
| K2 ほかの投稿の状態が変わらない | 前: 直近180日で原文に「切れ込み」を含む行は2行（recon §3、kirekomi.txt）。便1 の適用の直前に同じ問い合わせを流し、2行のままなら○。3行以上なら、増えた行を全部見て、選んだ状態が正しいかを確かめてから適用する |

| K4 同じ種類が再び起きたら当日に見つかる | 便3 のあと、毎朝の〆の点検の手順に「品質違いの2行の片方だけの〆で両方が閉じた組」を数える問い合わせが入り、11/13 の投稿で1組を数える（再現）。以後の点検で1組以上出たら × として PO に上げる |
| K5 同じ種類の消しすぎが増えない | 便1 の反映から14日、毎朝の〆の点検の手順2b の「消しすぎ」が0件 |

## 2. 方針と、採らなかった案

- 採る: 状態の辞書に、品質の違いを表す言葉を足す（便1）。仕組みに手を入れず、状態の違いとして読ませれば、今の「組ごとに最新」の規則のままで〆は自分の状態だけを閉じる（recon §2 の 1〜5）。
  - 影響は直近180日で今回の2行だけ（recon §3）。
- 採らない案 A: 状態とは別に「品質の違い」を持たせ、現行の行を (商品, 状態, 品質) で決める。現行の決め方・配信・在庫の画面の全部が変わり、ADR-1032 の守ることを変える大きな変更になる。同じ種類は直近30日で1組（recon §3）で、変更の大きさに見合わない。
- 採らない案 B: 〆の文に辞書に無い言葉が残り、前の投稿に同じ組の行が2行以上あるとき、〆を要確認にする。要確認の行も現行の決め方に入るので、A品は外れたまま（recon §2-6）。隠れる害は同じで、要確認が増えるだけ。
- 同じ種類の再発は、仕組みで防ぐ代わりに当日に見つける（便3）。新しい言葉が出たら便1 と同じ手順で辞書に足す。

## 3. 変更の内容

### 3-1. 便1 状態の辞書に「切れ込み」を足す（本番のマスタの変更。コードは触らない）
- 対象: public.line_conditions の1行の search_kw に「切れ込み」を1語足す。足す先は PO が選ぶ（§5）。
  - 候補1: カートンの傷み（code CN0002、canonical Damaged case、value_rank 2）。
  - 候補2: カートンの開封済み（code CN0009、canonical Opened case、value_rank 3）。
- 箱（Sealed box 系）には足さない。直近180日に箱の行で「切れ込み」は無い（recon §3）。
- 手順は前例 `docs/handoff/condition-unit-booklet/data/` と同じ4本の SQL（01_precheck・02_apply・03_verify・04_rollback）を `docs/handoff/shime-grade-keep/data/` に置く。
  - 01: 対象の行の search_kw の今の値を出し、「切れ込み」がどの行にも無いことを確かめる。
  - 02: 対象の行の search_kw の末尾に `,切れ込み` を足す（1行だけ更新。更新件数が1でなければ取り消す）。
  - 03: 01 と同じ問い合わせで、対象の行にだけ「切れ込み」があることを確かめる。
  - 04: 足した語だけを取り除く。
- 足す先: id 13（CN0002 Damaged case、app_kubun 箱系大）。2026-11-14 の 01_precheck の結果: 対象の行1行・「切れ込み」を含む辞書の行0・直近180日の原文で「切れ込み」を含む行2（作業記録 precheck_bin1.txt）。
- 辞書は解析のたびに読み直す（`load_condition_entries` が毎回 `public.conditions` を読む。`public.conditions` は `public.line_conditions` の VIEW：`migrations/20261017_120000_line_conditions_value_rank.sql:47`）。再起動・再解析は要らない。
- 実行は設計審査の合格のあと、Opus が PO の委任（PO 合意済みの本番のデータの変更）に基づき 02_apply を DRY-RUN → COMMIT の順で流し、03_verify で確かめる。

### 3-2. 便2 今回の A品の在庫を戻す → 不要（2026-11-14 取りやめ）
- 仕入元が 11/14 07:08 JST に新しい投稿で、このカートンを「残1・175,000円」で出した（品質の書き分けは無い）。その行が (420436, Case) の最新として現行になっている（作業記録 pre1.txt・raw_d.txt）。仕入元の今の在庫はこの投稿が正しいので、古い投稿の A品の行を戻すと、売り切れた数を出すおそれがある。
- 過去の解析結果は再解析しない（ADR-1032 の見張りで、古い投稿の行は戻らない。recon §2-7）。

### 3-3. 便3 毎朝の点検に見張りを足す（文書だけ）
- `docs/handoff/shime-review-exclude/design.md` §12-8 の毎朝の〆の点検の手順に 2d を足す: 直近の点検の範囲で、1投稿に同じ商品×状態の In Stock が値段違いで2行以上あり、次の同じ組の行が状態を語で決めていない Sold out の組を出し、1組ずつ原文を見て、片方だけの〆なら「消しすぎ」として報告する。
- 問い合わせは recon §3 の dup_soldout と同じ形（作業記録の dup_soldout.sql）。

## 4. リスクと対処

| リスク | 対処 |
|---|---|
| 「切れ込み」がほかの文脈（例: 箱でない商品の説明）に当たる | 足す先をカートンの状態の行だけにする。その行の適用区分（app_kubun）の値は未確認なので、便1 の 01_precheck で出して確かめる。K2 で適用の直前に件数を数え直す |
| 選んだ状態が仕事の上の扱いと違う | 足す先は PO が選ぶ。04_rollback で語だけを外せる |
| 同じ種類の別の言葉が出る | 便3 で当日に見つけ、便1 と同じ手順で足す |

## 5. PO に決めてもらうこと

- 決定済み（2026-11-14 PO「1」）: 「テープに切れ込みがある品（正規品保証つき）」はカートンの傷み（Damaged case）として扱う。

## 6. 戻し方と測り方

- 戻し方: 便1 は 04_rollback（足した語だけを外す）。便3 は文書の差し戻し。
- 測り方: §1 の K1〜K5。基準値は recon §3（180日で2行・30日で11組中1組）。

## 7. 維持の仕組み

- 毎朝の〆の点検（手順2b と便3 の2d）が、同じ種類の消しすぎを当日に数える。
- 状態の辞書の変更は前例と同じ4本の SQL で残し、戻せる形にする。

## 8. 外部事例

該当なし。社内の状態の辞書の語の不足で、外部の事例は判断の根拠にならない（今回の影響の大きさは本番の実測 recon §3 で決めた）。
