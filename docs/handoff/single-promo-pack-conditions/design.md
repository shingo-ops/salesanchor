# design: シングル系の状態5つ と プロモパック系の区分（v102）

状態: **PO 承認済み**（2026-10-19「y」。承認したのは、この設計で実装に進むことと、付け替え候補のうち 440525・466083・466077 の 3 商品を先に移すこと）。自分での審査（Architect）: APPROVE。起案は 2026-10-19、Opus。現状の調べは [recon.md](./recon.md)、判断の記録は [ADR-1031](../../adr/ADR-1031-single-and-promo-pack-conditions.md)。

## 目的（PO の言葉）

> 状態は何にするのが適切か？ → n,PSA10などの状態をSingleの状態に追加する

> シングル系はプロモも分類される？プロモだと未開封とかも出てくるがシングルカードは未開封は無いのでプロモ系は分類して違うカテゴリを作ったほうが良いか？

> パックで配られたものでも箱系の区分にすると箱系は区分が全く違いので合致する状態が存在しない

> 先に値だけ用意しておき、状態なしは全て未開封に当てる、箱系と同じ仕組みを出来る？

利用者に見える変化は2つあります。

- **シングル系の商品**: 今は状態が決まらず「Error」になり、配信に出ない行があります。これを PSA10／PSA9／PSA8／PSA7以下／Single の5つのどれかに決めます。
- **パックで配られたプロモ**: 新しい区分「プロモパック系」に移します。状態は「未開封」を既定にし、「開封済み」「PSA10」の語があればその状態にします。

## 対象と対象外

- 対象は次の4つです。
  - v102 の状態の判定（`_resolve_condition`）
  - 状態マスタの新しい行（8行：single 5・promo_pack 3）
  - 区分マスタの新しい行（1行）
  - 区分の付け替え（パック形が確かめられた商品だけ）
- 対象外は次のとおりです。
  - v6・v10・v101・shadow・単位の復元・GAS の判定ロジック。共通の読み込みが新しい行を返さないので、挙動は変わりません。
  - 箱系・セット系・バルク系・区分なしの行。試算での変化は 0 行でした（recon 本番の観測 3.）。
  - 状態の色の新設。新しい状態は既定の色で出ます。色を付けるかは別の便で決めます。

1. 適用区分（app_kubun）は、新しい行に「シングル系」「プロモパック系」と入れます。単位の区分（箱系・パック系・単品系など）の名前には一致しないので、群を絞らずに呼んでも当たりません。二重の安全策です。
2. 新しい行の価値順（value_rank）は ADR-1023 と同じ規則で扱います。「PSA10 と PSA9 が混在」のように2つ以上当たったときは、価値の低い方を採ります。本番では、2つ以上当たる行は 0 でした。

## 値（記録 SQL で入れる。migration には書かない＝ADR-1007）

- PSA の語の正規表現は、全角・大文字小文字・区切り（空白／-／:）を許します。後ろに数字が続く書き方は外します。
- 例：PSA10 の正規表現は `(?i)[pｐＰ][sｓＳ][aａＡ][\s　\-－:：]?(10|１０)(?![0-9０-９])`。

| 群 | 状態 | 適用区分 | match_type | 当てる語 | value_rank | effect |
|---|---|---|---|---|---|---|
| single | PSA10 | シングル系 | REGEX | PSA10 | 1 | OUTPUT |
| single | PSA9 | シングル系 | REGEX | PSA9 | 2 | OUTPUT |
| single | PSA8 | シングル系 | REGEX | PSA8 | 3 | OUTPUT |
| single | PSA7以下 | シングル系 | REGEX | PSA1〜PSA7 | 4 | OUTPUT |
| single | Single | シングル系 | KEYWORD | なし（既定。コードの R7 だけが返す） | 5 | OUTPUT |
| promo_pack | 未開封 | プロモパック系 | KEYWORD | なし（既定。コードの R8 だけが返す） | 1 | OUTPUT |
| promo_pack | 開封済み | プロモパック系 | REGEX | `(?<!未)開封(?!前)` に加え、「開封していない／開封なし／開封不可」を除外する | 2 | OUTPUT |
| promo_pack | PSA10 | プロモパック系 | REGEX | PSA10 | 3 | OUTPUT |
| promo_pack | PSA9以下 | — | — | 作らない（実例が無い。PO 案は3つ） | — | — |

1. 語の無い行は、Bulk（CN0014）と同じく「search_kw 空の KEYWORD」にします。この形はどの文にも当たらず、コードの既定の分岐だけが返します。
2. 状態名（canonical）は表の文字のとおりにします。既存の名前とは重ならないことを確かめました（recon 15.）。canonical に一意の制約は無いので、群をまたいで「PSA10」が2行あっても DB の制約には触れません。v102 の名前の引き当ては群の行の中で行います（実装カードで指定します）。
3. promo_pack の価値順（value_rank）は、3つの状態の価値の上下を決めるためのものではありません。2つ以上の状態が当たった行は 3. の要確認に回すので、順位で選ばれることはありません。並び順の都合だけで付けた数字です。

## 代替案

1. **CN0008 の適用区分を「枚系」に直し、全区分で単品の状態を判定する案（fix7 の F 案）**: 採りません。
   - v6・v10・v101 にも影響が出ます。
   - 箱系の 13 行が要確認になります。
2. **プロモを箱系に入れる案**: 採りません（PO の n）。箱系の状態（Sealed box など）は、プロモパックの状態と合いません。
3. **PSA の語を KEYWORD のまま使う案**: 採りません。「psa10ar」のような書き方で PSA1 に当たり、PSA7以下と誤ります（recon 8.）。

## リスクと対処

| リスク | 対処 |
|---|---|
| 新しい行が v6 などに混ざり、判定が変わる | 1. の既定 False と、適用区分の名前の二重の安全策。テストで v6 経路の結果が変わらないことを確かめる |
| 実装より先に行を入れ、名前が引けずに FLAG_SINGLE へ落ちる | 順序を固定する。①コードの反映（行が無い間は今と同じ）→ ②行と区分の SQL → ③対象 job の再解析 |

| 「PSA8以下」は PSA8 になる | シングル系の本番行には今のところ無い（以前の例はバルク系の行で、この変更の対象外）。出たら見直す |
| GAS 在庫一覧の色 | 既定の色で出る（壊れない）。色を付けるかは別の便で決める |

## 戻し方

- 状態の行と区分は、記録した rollback SQL で戻します。新しい 8 行を is_active=false にし、3 商品を区分 2 に戻し、対象 job を再解析します。そうすると判定は今と同じになります。
- コードは PR を revert します。行が無効になっていれば、revert の前でも今と同じ動きです。
- CHECK 制約は広げたままでも害はありません（値が無ければ使われません）。

## 維持の仕組み

- シングル系・プロモパック系に状態を足すときは、群と順位を決め、行を記録 SQL で入れます（ADR-1023 と同じ手順）。
- 区分の付け替えは、共用マスタの登録規則（`docs/specs/product-master/registration-rules.md` C3）に従い、候補表を出してから行います。

## 外部・過去事例の参照と我々への応用

- 社内の前例 ADR-1021（バルク系の既定状態 Bulk）: 区分で既定の状態を決め、basis を R4 で始めず、語の無い行は search_kw を空にしました。同じ形を R7・R8 に使います。
- 社内の前例 ADR-1023（価値順）: 群と順位の列をそのまま使い、群を2つ足します。
- 外部事例: 該当なし。社内の状態マスタの判定規則を変える話で、外部の数値を根拠に使う種類の決めごとではないため、外部事例は使いません。PSA の格付け（1〜10）の意味は公開情報ですが、ここでは状態の名前に使うだけです。
