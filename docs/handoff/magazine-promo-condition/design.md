# design: プロモパック系の新しい状態「雑誌付き」（v102）

状態: **設計案（PO 承認前）**。方針は PO が決めた（2026-10-20）。この設計の自己審査は下の「審査」にある。起案は 2026-10-20、Opus。
- 現状の調べは [recon.md](./recon.md)
- 判断の根拠は ADR-1023、ADR-1031、ADR-1035、ADR-1007（新しい ADR は作らない。既存の群に1行足すだけで、各 ADR の「維持の仕組み」の範囲に収まるため）

## 目的（PO の言葉）

> 肉ルフィはブックレットのほうが良いのか？それともプロモパックであるべき？ワンピースは雑誌付録が多いので判断に困る、雑誌付きと書かれていればプロモパック内の状態に雑誌付きと入れるべきか？ブックレットに登録するべきか

> 1（プロモパック系のまま、状態「雑誌付き」を足す。設計して見せてから入れる）

使う人から見て変わることは、次のとおり。

- プロモパック系の商品で、原文に「雑誌付き」と書かれた行は、状態が「雑誌付き」になる。数え方の単位は冊。
- 今は「雑誌付き」の行も「雑誌無し」の行も、どちらも「未開封」になり、区別がつかない（recon「実コードでの確認」）。
- 「雑誌無し」の行と、雑誌について何も書かれていない行は、今までどおり「未開封」のまま。

## 対象と対象外

| 対象 | 対象外 |
|---|---|
| 状態マスタに1行足す（群 promo_pack・区分プロモパック系） | コードの変更。migration。画面の変更。i18n |
| 足したあと、保留中の3行（肉ルフィ「雑誌付き袋とじ未開封」）を再解析する | シングル系の雑誌付録（424591 CHOPPER's など）。群が違うので、この状態は使われない |
| | 「付録」「本誌付き」など、ほかの言い方。直近30日の区分11では0件だった |
| | 既存の3行（未開封・開封済み・PSA10）の値の変更 |

## 変更前と変更後

### 足す1行（public.line_conditions）

| 列 | 値 | 理由 |
|---|---|---|
| code | CN0025 | 固定の番号。最大値から採らない（前例 ADR-1035 便2）。CN0025 は未使用（recon） |
| canonical | 雑誌付き | PO の言葉。群 promo_pack のほかの状態も日本語 |
| app_kubun | プロモパック系 | 群 promo_pack の既存行と同じ |
| priority | 2 | 開封済み・PSA10 と同じ。検索で当たる状態（R2）にする |
| match_type / search_kw | REGEX `雑誌[\s　]*(付き\|つき)` | 「雑誌付き」を拾い、「雑誌無し」は拾わない。「雑誌付録」も拾わない（「付き」「つき」のときだけ当たるため） |
| exclude_kw | 空 | |

| unit_id | 17（Booklet＝冊） | 品物は雑誌そのものなので冊で数える。保留中の3行も今は Booklet なので、単位は変わらない（recon の表） |

| note | 「プロモパック系で雑誌付きと書かれた行の状態。単位は冊（ADR-1023/1031/1035、2026-10-20 PO）」 | |

## 代替案と、選ばなかった理由

| 案 | 選ばなかった理由 |
|---|---|
| ブックレット系に移す | PO が「1」でプロモパック系に残すと決めた。ブックレット系の既定は「1冊」なので、多数ある「雑誌無し」の行まで冊で数えてしまう |
| 単位を空にする | 「雑誌付き」の行の単位が、原文の語や Gemini の読みしだいになる。今の3行の Booklet と食い違うおそれがある |
| 順位を NULL にする | 開封済みと一緒に書かれたとき開封済みが勝ち、雑誌付きの事実が消える。どちらにしても要確認は付く |
| 順位を2にして既存行をずらす | 既存の2行を書き換えることになり、変更が増える。どれを上に並べるかの商売上の判断を、まだもらっていない |

## リスクと対処

| リスク | 対処 |
|---|---|
| 正規表現が別の書き方を拾う | 当たるのは区分11の商品の行だけ。直近30日では424590の「雑誌付き」15件だけが当てはまる。適用前に、同じ正規表現で本番の区分11の原文を数え、15件と合うかを確かめる（K3） |
| 状態の並び（在庫表の並び）で雑誌付きが最後になる | 並びにしか効かない。並べ替えたいと言われたら、value_rank だけを直す（記録 SQL 1文） |
| GAS 在庫一覧で表示が崩れる | まだ確かめていない。適用後に目視で確かめる（K6） |
| 戻すときに解析結果が状態 id を参照していて消せない | 戻しは is_active=false と、3行の再解析にする。01_precheck で外部キーの有無を確かめ、消せるなら DELETE を併記する |
| 93行の再解析の前に入れると、保留の3行を戻す前提が崩れる | 順番を固定する。93行の再解析の COMMIT と post の後に、この記録 SQL を流す |

## 手順（便は1つ）

1. Sonnet がこのフォルダに data/01_precheck.sql・02_apply.sql・03_verify.sql・04_rollback.sql を書く。書き方は docs/handoff/condition-unit-booklet/data/bin2/ に合わせる（件数が違えば 1/0 で止まり、終わり方は -v end で指定）。コードは書かない。
2. Opus が SQL を読んで確かめる。
3. 01_precheck を流し、02_apply を DRY-RUN（ROLLBACK）で流す。
4. COMMIT で流す。
5. 03_verify を流す。
6. 保留の3行だけを、既存の再解析の台本と同じ作りで再解析する（3 item・job は該当分）。台本は Sonnet が書き、Opus が読む。dryrun → commit → post の順。
7. 記録を docs PR にまとめる。

本番への書き込みは、手順4と手順6の commit だけ。どちらも PO が `!` で1行実行する（manual-only の鍵を使うため）。

## 測り方と、変わったかどうか

- 基準値: 群 promo_pack は3行。保留3行の状態は未開封・R8。
- 正答率の採点（po-sheet11）では、雑誌の行の状態と単位は採点外。なので、正答率の数字は動かない見込み。今回の目的は、値段の違う「雑誌付き」と「雑誌無し」を見分けられるようにすること。

## 維持の仕組み

- 状態を足すときの規則は ADR-1023・1035 の「維持の仕組み」のとおり（群・順位・単位を同時に決め、記録 SQL で入れる）。この設計はその手順に沿った1件目の追加で、記録 SQL を前例として残す。
- 書き方が増えたとき（「付録」「本誌付き」など）は、CN0025 の search_kw を直す。これは検索語の扱いなので、記録 SQL 1文で入れる。

## 外部事例

使わない。社内の状態マスタに1行足すだけの変更で、外の事例が判断材料にならないため。
