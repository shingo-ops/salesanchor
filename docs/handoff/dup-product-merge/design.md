# 設計：商品マスタの二重登録3組の統合（2026-10-05）

状態：設計案作成済み／Opus 自己審査 APPROVE（§7）／PO 承認済み（2026-10-05「参照先を1つに統合してSSOTさせる」、SQL と件数に「はい」）。実行の結果は README.md の「実行記録」を参照。

## 1. 目的（PO に見える変化）
- 同じ商品が2行で登録されていた3組を、1行にまとめる。3組は DUAL EVOLUTION［FB09］、LIMIT OVER COLLECTION - THE RIVALS -、同 - THE HEROES -。
- 解析の結果・ダッシュボード・買取の数字が、商品ごとに1つにまとまる（SSOT）。
- LINE 解析の新方式で、2つの候補が並んで決めきれなかった投稿が、1つに決まる（v9 の試験で 23件）。

## 2. 現在地（recon.md の要約）
- 公式の確認：3組とも、公式では1商品である（README.md に URL と引用）。
- 2行の違い：記号・発売日・作品・検索の語は同じ。
  - 古い行（226・625・626）には、単価・入数・英語名がある。
  - 新しい行（PM0226・PM0224・PM0223、2026-09-14 に作成）には、分類（Box・メーカー）だけがある。
  - PM0226 の中分類は「ポケモンカード」で、誤っていた。ドラゴンボールの 78商品のうち、この1行だけがこうなっていた。
- 新しい行を参照しているデータ
  - analysis_results：167
  - extraction_items.resolved_product_code：17
  - buyback_shop_products：1
  - 過去の記録の表（スナップショット・バックアップ・生の応答）：多数
- 同じ組み合わせは1行だけ、という一意の制約にはぶつからない。is_current の印は、21の区切りで「今の値」が2行になる（アプリの規則で付け直すと 18行が変わる）。

## 3. 既存の ADR との関係
- ADR-155（商品マスタの SSOT）：重複を解消して SSOT に寄せる変更である。値の変更は、PO の決定で SQL によって直接行う。デッキビルドの修正 #3966 と MEGAドリームex の修正 #3968 と同じ扱い。
- 前例：scripts/one-time/cleanup-product-duplicates.sql（2026-09-17、PM 系の重複 203件。参照を付け替えたあとに物理削除した）。

## 4. 変更
- 残す行は 226（DB-FB09）・625（YGO-LOCR）・626（YGO-LOCH）。
- 新しい行の 440561・440572・440571 は、is_active=false にする。物理削除はしない。
- 付け替える：analysis_results.product_id、extraction_items.resolved_product_code、buyback_shop_products.product_id。
- is_current の印は、影響のある区切りの中だけで、アプリと同じ規則で付け直す（tcg_analyzer_svc.py:1759-1791）。
- 付け替えない

  - 理由：その時点の記録だから。

## 5. 代替案と選んだ理由
- 新しい行を残す案：同じ作品の他の商品と、品番の付け方も分類も合わない。中分類の誤りもある。そのため古い行を残した。
- 物理削除の案（9/17 の前例）：元に戻しにくい。参照の制約が NO ACTION のため、検索の語の削除も要る。今回は is_active=false にし、元に戻せる形にした。
- 新しい行にしかない分類（Box・メーカー・division）を古い行に移す案：同じ作品の他の商品には入っていない値なので、移さない。

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| 付け替えで、ダッシュボードなどの集計の数字が変わる | まとまるのが意図した変化である。残す行の件数が「前の件数＋付け替えた件数」になることを、SQL の中で照合する |
| is_current の誤った付け直し | アプリの規則を写した。区切りを影響のある範囲に限り、変わる行の数（8・6・4、true への変更は 0）を照合する |
| 作品の参照の digest が変わる | マスタを編集するときは、いつも起きる今の動きである。試験の時間を避ける |
| 誤りがあった場合 | audit_log の new_values に、付け替えた行の id と is_current の旧値をすべて残す。rollback.sql はその行だけを元に戻す。実行するには PO の新しい判断が要る |
