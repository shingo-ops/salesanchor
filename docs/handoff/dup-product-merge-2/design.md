# 設計：商品マスタの二重登録10組の統合（2回目、2026-10-05）

状態：設計案作成済み／Opus 自己審査 APPROVE（§7）／PO 承認済み（2026-10-05「2.はい」）。実行の結果は README.md の「実行記録」を参照。

## 1. 目的（PO に見える変化）
- 同じ商品が2行で登録されていた10組を、1行にまとめる。10組は、ユニオンアリーナのプレシャスブースターパック 勝利の女神：NIKKE［PC02BT］の1組と、ディズニー ロルカナの9弾（9組）。
- 解析の結果・Gemini の選択の記録が、商品ごとに1つにまとまる（SSOT）。

## 2. 現在地（recon.md の要約）
- 公式の確認：10組とも、公式の名前・発売日（PC02BT は商品名の品番も）で同じ1商品である。URL と引用は README.md にある。
- 2行の違い：57列のうち、組ごとに14〜15列が違う。
  - ロルカナ
    - PM 行は日本語の名前で、公式の発売日・分類（division・manufacturer・product_category）を持つ。
    - LOR 行は英語＋日本語の名前で、発売日は空。
  - PC02BT
    - UA 行の名前は「プレシャス 勝利の女神：NIKKE」で、unit_price を持つ。
    - PM0225 は除外の語（WS／ヴァイス／ヴァイスシュヴァルツ）を持つ。
- 参照（03:16Z の時点）
  - analysis_results：75
  - extraction_items.resolved_product_code：73
  - buyback：0
  - extraction_shadow_results：0
  - テナントの表・在庫：0
- 毎回流し直される migration 20260604_010000_seed_product_marks.sql は、名前が完全に一致する行の mark だけを書き換える。この20行の名前・コード・mark は、その一覧に無い。

## 3. 既存の ADR との関係
- ADR-155：重複を解消して SSOT に寄せる。値の変更は、PO の決定のもとで SQL によって行う（#3966・#3968・#3969 と同じ扱い）。
- ADR-1006（Proposed）：product_code は意味を持たない連番になる予定である。そのため、残す行を選ぶ基準は品番の付け方ではなく、公式の情報（発売日・名前）をどれだけ持っているかで決めた。

## 4. 変更
- 残す行と無効にする行
  - PC02BT：398（UA-PC02BT）を残し、440573（PM0225）を無効にする。
  - ロルカナ：PM 行を残し、LOR 行を無効にする（9組。対応は README.md の表）。
- 付け替える：analysis_results.product_id、extraction_items.resolved_product_code、extraction_shadow_results.product_id（この時点では0件）、buyback_shop_products（0件）。
- is_current の印は、影響のある区切りの中だけで、アプリの規則（tcg_analyzer_svc.py:1759-1791）で付け直す。
  - 同じ時刻の行が並んだときの決め方（is_current DESC, id）を足した。今の印を変えないためである（1区切り）。
- 検索の語と除外の語：無効にする行の語のうち、残す行に無いものを足す（正規化して重なりを確認、position は続きの番号）。
  - ロルカナの英語＋日本語の語、NIKKE の除外の語3つを引き継ぐ。
- 無効にする行は is_active=false にする。物理削除はしない。
- 付け替えない：スナップショット、バックアップの表、extraction_attempts、work_reference_snapshot、pid_basis の文字列（その時点の記録だから）。

## 5. 代替案と選んだ理由
- LOR 行を残し、語を引き継がない案：日本語だけの投稿で2件が決まらなくなった（試算 A）。
- LOR 行を残し、語を引き継ぐ案：崩れは0件だが、公式の発売日と分類を持たない行が残る。
- 採用した案は、PM 行を残し、語を引き継ぐもの。崩れは0件で、公式の情報も持つ。

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| NIKKE に引き継ぐ除外の語「WS」は短く、文の中のどこにあっても当たる（除外の語には語の境界の条件が無い） | 無効にする行で今も使っている語である。v9 の試験では崩れ0件だった。誤って外れる件は、精度の測定で見ていく |
| 投稿が増え、件数がずれる | 件数は SQL を作る直前に数え直し、その数で完全一致を照合する。ずれたら全体を取り消して止まる |
| 作品の参照の digest が変わる | マスタを編集するときは、いつも起きる今の動きである |
| 誤りがあった場合 | audit_log の new_values に、付け替えた行・印を変えた行・足した語の id をすべて残す。rollback.sql はその行だけを元に戻す。実行するには PO の新しい判断が要る |
