## 受け入れ基準

| 基準 | 検証方法 |
|------|---------|
| 違反を含む見本カードで exit 1 を返し、違反した検査式の番号を出力する | `scripts/tests/card-lint/bad-*.txt` を1件ずつ通し、期待した番号が出ることを確認 |
| 正常な見本カードで exit 0 を返し、何も出力しない | `scripts/tests/card-lint/good-01.txt` を通し、出力が空であることを確認 |
| 引数が無いときは使い方を出して exit 2 | 引数なしで実行し、exit コードを確認 |
| すべての検査式が BSD grep と BSD awk で動く | 各式を単独で実行し、`grep -P` を使っていないことを確認（`grep -c "grep -P" scripts/card-lint.sh` が 0） |
| 本セッションで起きた停止6件のうち、検査式にできるものをすべて検出する | 実際に止まったカードの本文を見本として通し、検出されることを確認 |
| 実行時間を実測して記録する（見積り値は書かない） | `time` を付けて1回計測し、本文書に追記 |
| 誤検知がない（正常なカードを止めない） | 本セッションで通った便のカード本文を通し、exit 0 になることを確認 |

## 技術 How・KPI

### KPI

- 検査式の本数: 25本（既存23＋新規2）
- 本セッションの停止6件のうち検出できる件数: 4件（残り2件はカードが正しく、検査対象外）
- 誤検知: 0件

### 置き場と形

- `scripts/card-lint.sh`（新規）。既存55本と同じディレクトリ・同じ書式（`#!/bin/bash`・用途コメント・使い方・exit コードの意味・`set -u`）
- 入力: カードのテキストファイル（引数1つ）
- 出力: 違反があれば1行1件で「L番号 検査名 該当行番号」。無ければ何も出さない
- exit 0 = 違反なし ／ exit 1 = 違反あり ／ exit 2 = 使い方の誤り
- `set -e` は使わない（違反を全部集めてから返すため）

### 検査式（25本・BSD grep で書ける形）

**そのまま書けるもの（20本）**

| 番号 | 検査 | 判定 |
|---|---|---|
| L02 | プレースホルダ | `<` と `>` に挟まれた日本語がある |
| L03 | 終端合図 | `END OF CARD` が0件 |
| L04 | 受領確認 | `受領確認` が0件 |
| L06 | psql の誤検知パターン | `psql` を含む行に `<<`・`-f `・`\| psql` がある |
| L07 | 読み取り専用 | `psql` があるのに `default_transaction_read_only` が無い |
| L08 | PR 作成 | `gh pr create` を直接呼んでいる |
| L09 | マージの引数 | `gh-pr-merge-safe.sh` の後に数字が続く |
| L10 | 本文ファイル | `--body-file` の値が `<` で始まる |
| L11 | 削除 | `rm ` を含む |
| L12 | worktree | `git worktree add` を直接呼んでいる |
| L14 | 下書き | `--draft` を含む |
| L15 | 停止時の報告 | `停止` が本文に0件 |
| L16 | timeout | `timeout ` を含む |
| L17 | 変数展開 | `git show $SHA:` を引用符なしで使っている |
| L18 | 素通り | `--admin` または `--auto` を含む |
| L20 | フェンス | 外側がバッククォート3つで、本文にも同じものがある |
| L21 | gh の範囲 | `gh run view` または `gh run watch` を含む |
| L22 | 許可の自己発行 | `.claude/permits` への直接アクセス |
| L23 | 危険語 | `DELETE FROM`・`TRUNCATE` 等を本文またはコマンドに含む |
| L05 | 自己参照 | 出力先のディレクトリと、列挙対象のディレクトリが同じ |

**書き直すもの（3本・否定先読みが使えないため2段階にする）**

| 番号 | 検査 | 直した判定 |
|---|---|---|
| L01 | `cd ` で始まらないコマンド行 | 手順のコマンド行を抜き、そこから `^[[:space:]]*cd ` で始まる行を `grep -v` で除いた残りが1行でもあれば違反 |
| L13 | ブランチ名 | `-b ` を含む行を抜き、`-b release/` と `-b hotfix/` に当たる行を `grep -v` で除いた残りが1行でもあれば違反 |
| L19 | 上限のない一覧系 | `gh run list`・`git branch -r`・`gh pr list` を含む行を抜き、`head`・`--limit`・`-c ` に当たる行を `grep -v` で除いた残りが1行でもあれば違反 |

**新規（2本・本セッションの実測から）**

| 番号 | 検査 | 判定 | 出所 |
|---|---|---|---|
| L24 | 1コマンドが長すぎる | 1行の文字数が 200 を超える行がある（閾値は暫定。recon 不明点#1 で実測後に改める） | 2026-09-08 実測。400字超と600字超で `SyntaxError: Invalid or unexpected token` |
| L25 | バッククォートを含む検索語 | ダブルクォートの中にバッククォートがある | 2026-09-07 実測。カード全体が投入時に壊れた |

### 検査対象の切り出し

「手順のコマンド行」は、`手順` で始まる見出し行の次以降で、空行でも見出しでもない行とする。BSD awk で範囲指定して抜く。

### テスト

`scripts/tests/card-lint/` に見本を置く。

| ファイル | 中身 |
|---|---|
| `good-01.txt` | 本セッションで通ったカード（CARD-GUARDS-STAGE-01 相当） |
| `bad-l01.txt` | `cd ` で始まらない行を含む |
| `bad-l02.txt` | プレースホルダを含む |
| `bad-l23.txt` | 危険語を含む |
| `bad-l24.txt` | 200字を超える行を含む |

見本は最小限（各10行程度）にする。実際のカード全文は使わない（長く、輸送で崩れるため）。

### 導入順序

1. `scripts/card-lint.sh` と見本を作る（本設計の範囲）
2. 手で動かして受け入れ基準を満たすことを確かめる
3. 誤検知が0になるまで式を直す
4. UserPromptSubmit フックへ接続する（**本設計の範囲外**・backlog #2・`~/.claude/settings.json` を触るため GO 対象）

3 が済むまで接続しない。誤検知があるまま接続すると、正常なカードが止まり、運用が回らなくなる。

## 弊害・トレードオフ

- 既知のパターンしか止められない。新しい停止は起きる → 対策: 停止のたびに式を1本足す（guards.md の維持の仕組み）。KPI の K4（停止から検査式への変換率）で追う。
- 誤検知が出ると、正常なカードが止まって運用が滞る → 対策: 導入順序の3を守る。誤検知0を受け入れ基準に入れる。
- L24 の閾値200字は暫定 → 対策: recon 不明点#1 を実測してから確定。それまでは警告として扱い、止めない。
- 検査はカードのテキストだけを見る。実行環境の状態（ブランチ・ファイルの実在）は見ない → 対策: それは PreToolUse の既存ガードと第3段の CI が担う。
- 私（設計パートナー）が lint を通さずにカードを出せてしまう → 対策: 接続の便で UserPromptSubmit に置き、貼られた時点で自動的に走らせる。それまでは PO が手で走らせる。
- 見本カードが実際のカードと乖離すると、検査が現実を反映しなくなる → 対策: 停止が起きたら、そのカードの該当部分を見本に足す。
