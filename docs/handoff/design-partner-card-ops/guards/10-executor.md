## 10. 実行役の制約（CC / Codex）

| 観点 | CC | Codex | 出所 |
|---|---|---|---|
| カードに無い確認 | 補うことがある | 補わない | CARD-CODEX-PROBE-01 |
| プレースホルダ | 補って進むことがある | 着手前に停止 | CARD-OPS-PR-03 |
| 散文の指示 | 組み立てることがある | 実行しない | CARD-OPS-PR-05 |
| `rm` / `rm -f` | 実行する | 環境が拒否 | CI-32・CV-32 |
| 長いヒアドキュメント | 284行通過 | 107行通過・157行拒否 | CARD-KW-PR-02・CARD-OPS-PR-03b |
| コマンドのタイムアウト | 長い sleep 可 | 30秒で打ち切り | MERGE-FIX-08（未検証） |
| worktree のパスを文脈から補う | 補う | 補わない | CV-36（未検証） |
| カード形式でない指示書 | — | 正しく拒否 | 事例9（未検証） |
| 交代時 | 挙動確認カード（7観点）を1便挟む | 同左 | card-ops §2 |

| カードの拒否 | — | 本文の長さと無関係に自己判断で拒否することがある。実行役の申告で「60行でも107行でも実行できた」と訂正済み | 2026-09-07 実測 |
| フックのスクリプトを書き換える | その書き換えを行ったプロンプトには適用されない。次のプロンプトから効く。書き換え直後に動いていないと判断しない | 2026-09-08 実測 |
| フックを設定ファイルに書く | 書いただけでは有効にならない。Codex は起動時に Review を求め、承認するまで Active が 0 のまま | 2026-09-08 実測 |
| UserPromptSubmit で exit 0 のとき stderr に出す | 画面に出ない。画面に出すには stdout に systemMessage の JSON を出す。exit 2 のときは stderr がブロック理由として使われる | 2026-09-08 実測・公式ドキュメント確認 |
| フックが発火したかを実行役に聞く | 分からない。フックの出力は実行役の応答より前に表示されるため、実行役自身には見えていない。確認は PO の画面でしかできない | 2026-09-08 実測 |
| ラッパーが探すスクリプトが見つからない | マージしても git pull するまでローカルの作業コピーに来ない。ローカル main がコンフリクトで塞がっていると来ない。固定の場所を最後の候補にしておく | 2026-09-08 実測 |
| 報告ファイルが空で返る | 手順の一部が実行されないことがある。原因は未確定。長い出力を出す手順はリダイレクトで報告に残し、次便で実在を確かめる | 2026-09-08 実測 |
