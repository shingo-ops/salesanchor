# design：無制限鍵は、読み取りなら恒常許可、変更なら作業ごとに GO

- 作成：2026-09-30（Opus 設計担当）
- 状態：PO が許可済み（2026-09-30「CLAUDE.md のこのルール変更を許可する」）
- 根拠：[recon.md](./recon.md)

## 目的
PO の恒常の許可を、サブエージェントが必ず読む CLAUDE.md に書く。これで、読み取りの調査で止まらないようにする。変更を伴う作業は、これまでどおり作業ごとに PO の GO が要る。

## 変更前と変更後（`CLAUDE.md`「VPS 直作業禁止」節。行数は4行のまま）
- 変更前
  - エージェントは制限付き鍵のみを使う
  - 無制限鍵は、作業ごとに permit-danger.sh 相当の承認が要る
- 変更後
  - 読み取りだけの調査（SELECT・ログや設定の表示・`ss`/`ps`/`systemctl status`・接続確認）は、恒常許可で使ってよい
  - 変更を伴う作業は、作業ごとに PO の GO が要る。設計担当が、GO の原文を依頼文と PR に書き写す
  - 鍵の値を表示しないこと、人間の鍵を変えないことは、そのまま残す

## 対象外
- 鍵そのものや、サーバーの設定は変えない
- ADR を新しく作らない。ADR-1003 の運用を補う変更である

## 基準と検証方法
| 基準 | 検証方法 |
|---|---|
| CLAUDE.md が120行以内 | `node frontend/scripts/check-claude-size.js` が PASSED |
| 読み取りの調査で止まらない | マージ後、サブエージェントに prod1・prod2 の読み取り調査を1件頼み、鍵のルールを理由に止まらないこと |
| 変更を伴う作業は、GO なしでは進まない | 設計担当の依頼文に GO の原文があるときだけ実行する（運用で確かめる） |

## リスクと戻し方
- リスク：読み取りのつもりで、変更を伴うコマンドを実行してしまう → 書き込みは、これまでどおり自動の安全チェックとフックで止まる
- 戻し方：この PR を revert する

## 維持の仕組み
- 守り手：PO（ルールを変えたいときに判断する）／Opus 設計担当（依頼文に GO の原文を書き写す）
