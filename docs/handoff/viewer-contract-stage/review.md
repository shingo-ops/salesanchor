### 2人とも同じ結論のもの

- 国内と海外は1つの表で持つ。表を分ける先例は無い。根拠: migrations/030_create_company_contact_subtables.sql:46-58。
- 決まりを切り替える鍵は region でなく country_code にする（レビュアー（4））。
- 都道府県の一覧は「画面と DB の CHECK が同じ1か所を読む」とは書いたままでは作れない。PostgreSQL の CHECK は別の表を読めない。案A: public の都道府県の表（JIS 01〜47）に外部キー。案B: backend の定数を正本にして CI で突き合わせる。
- 海外の電話の決まりが ADR-126:98（+付き6〜15桁）と食い違う。
- A23 の並び。KGI が PO 未承認（kgi.md:5）なので実装カードに渡せない。

### レビュアーだけの指摘（要約）

- 住所の列名を company_addresses の名前（address_line_1・address_line_2・city・state・zip・country_code）に揃える。仕入先の先例を recon に足す。
- インボイス登録の有無と番号は事業者単位の事実。国内用・海外用の2行に持つと二重になる。→ PO 確認。
- 海外住所の案を §7「PO に決めてもらうこと」に入れる。
- 受入条件の不足: 住所5欄と電話、配信されないこと、フォント無しで止める、メール失敗、番号の重複なし、公開ポリシーの文、ドライブの見守り。
- A22 が指す ADR-142 の検証は実在しない。試験の中身を書く。
- public の請求書の表の RLS（ADR-1018:12 の観点）。
- 振込先の変更履歴と権限の絞り込み。→ PO 確認。

- API の約束、FEATURE-INDEX の誤記、金型の名前、外部キーを張らない理由の書き直し。
