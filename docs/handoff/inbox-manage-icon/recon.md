# recon: 検索欄の右に同じアイコンが2つ並んでいる（現状把握）

調査日 2026-10-13 / ブランチ `release/inbox-manage-icon`（`origin/main` 起点）

PO 指摘: 「検査欄の右側だが同じアイコンが2つ並んでるので分かりづらい、管理側のタブを変更してアイコンだけにしたいが svg で適したアイコンはある？」
PO 選択: **丸いチェック**（2026-10-13）

## A. 指摘は事実（実装で確認）

`frontend/src/pages/inbox/InboxConversationList.tsx` の検索欄に2つのボタンが並ぶ。

| ボタン | アイコン | 文言 |
|---|---|---|
| 絞り込み | `NAV_ICONS.filter`（`size={ICON.md}`） | なし |
| 管理 | **`NAV_ICONS.filter`**（`size={13}`・`weight="fill"`） | 「管理」 |

**同じ `filter` アイコンを2つ使っていた。**

実機の実測（1080x2340 @480dpi）: 絞り込み `(711,168)-(822,276)`／管理 `(843,171)-(1056,273)` ＝**隣り合っている**。

## B. あわせて見つかった規約違反

| # | 事実 | 根拠 |
|---|---|---|
| B1 | 管理のアイコンサイズが `size={13}`＝**生の数値** | 同ファイルの該当行。`frontend/src/constants/iconSizes.ts` のトークン（`sm:14 / md:16 / base:20 / lg:24 / xl:48`）を通していない |
| B2 | 同ファイルに `size={14}` が**5箇所** | 同ファイルの grep 結果。`ICON.sm` が 14 なので**同値**（見た目は変わらない） |
| B3 | `frontend/src/constants/iconSizes.ts` は**自動生成ファイル**（「Do not edit this file」）＝新しいサイズは足せない | 同ファイルの冒頭コメント |

## C. アイコンの供給元と在庫

| # | 事実 | 根拠 |
|---|---|---|
| C1 | 供給元は **@heroicons/react**（`24/solid` と `24/outline`） | `frontend/src/constants/icons.tsx` の import 文 |
| C2 | `frontend/CLAUDE.md` は「lucide-react で確認」と書いているが、**実体は heroicons** | C1 との食い違い。記載が古い |
| C3 | `CheckCircleIcon` は**未登録だがライブラリに在庫あり**（`node_modules/@heroicons/react/24/solid/` と `24/outline/` に存在） | ファイル一覧 |
| C4 | outline と solid を使い分ける前例がある（`heart: HeartOutline` / `heartFilled: Heart`） | `frontend/src/constants/icons.tsx` の `INBOX_ACTION_ICONS` |
| C5 | 登録の型は `const Name = hi(HeroIcon);` → グループに追加 | 同ファイルの既存行 |

## D. このボタンの実際の動作

| # | 事実 | 根拠 |
|---|---|---|
| D1 | 主な動作は `toggleSelectMode`（**選択モードに入る**・`aria-pressed`） | `frontend/src/pages/inbox/InboxConversationList.tsx` の該当ボタン |
| D2 | 選択モードでないときはドロップダウン（「すべて既読にする」）も持つ | 同ファイルの `manageOpen` の分岐 |
| D3 | 選択モードに入ると一括アクションバー（既読・未読・除外・削除）が出る | 同ファイルの `selectMode` の分岐 |

**選択モードを表すアイコンとしては丸いチェックが通例**（Gmail・iOS）。未選択の状態で「すでに選び終わった」ように見せないため **outline** を使う（C4 の前例と同じ使い分け）。

## E. ADR との関係

| # | 事実 | 根拠 |
|---|---|---|
| E1 | **ADR-064（Inbox Meta 完全再現・PC）は管理ボタンに言及していない**（grep で0件） | `docs/adr/ADR-064-inbox-meta-exact-replica.md` |
| E2 | ADR-144 は「UI部品新設時は `components/` の金型を先確認」。本便は**新しい部品を作らず**、登録済みのアイコン群に1つ追加するだけ | `CLAUDE.md` の UIガバナンス節 |
| E3 | アイコン追加の手順は `frontend/CLAUDE.md` の「アイコン管理」に定義（`frontend/src/constants/icons.tsx` に追加 → import → `aria-hidden="true"` 付与） | 同ファイル |

## F. 文言を隠す範囲の判断材料

| # | 事実 | 根拠 |
|---|---|---|
| F1 | 絞り込みボタンは**スマホでしか出ない**（PC・タブレットでは非表示） | `frontend/src/pages/inbox/InboxPage.css` の `.icon-btn.inbox-mobile-filter-toggle { display: none; }` と `@media` 内の表示指定 |
| F2 | したがって「同じアイコンが2つ並ぶ」問題は**スマホだけで起きる** | F1 から |
| F3 | 管理ボタン自体は PC でも出る（検索欄は左パネルの中） | `frontend/src/pages/inbox/InboxConversationList.tsx` の構造 |

**判断**: アイコンの差し替えは**全幅で行う**（filter は意味が合っておらず PC でも誤り）。**文言を隠すのはスマホだけ**にする（PC は「管理」の文言を残す）。
