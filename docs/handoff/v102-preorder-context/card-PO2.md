# 実装カード PO2: 先の日付の読み方を PO 決定に合わせる（翌日までは在庫・前の月は今年）（便PO2）

設計者: Opus（2026-10-12）。前便: #4158（49acb712f マージ。v102_status_context.py を追加。規則の行は未投入）。
PO 決定（原文、2026-10-12）:
- 「y：投稿の翌日までの発送は在庫のままにします。→y,発送日の情報は発送日情報に記載する条件で」
- 2月・4月・6月入荷分は来年か →「今年が過ぎてしまっているのであれば来年」
- 10月の投稿の「9/30入荷」→「これは今年だと考える」
- 境目「投稿月の1つ前の月までは今年、それより前の月は来年」→「y」
※「発送日情報に記載する」（保存先）は PO 判断待ちのため本便に含めない。

## 1. 変更（v102_status_context.py だけ＋テスト。ほかは触らない）
1-1. 年の決め方（_period_end）:
  - 月の差 back = (posted.month - month) mod 12 を求める（0＝同じ月、1＝1つ前の月。1月の投稿の12月は back=1）。
  - back == 0 → 投稿日の年。
  - 1 <= back <= CURRENT_YEAR_BACK_MONTHS（新しい名前付き定数＝1）→ 「過ぎた月」として扱う：年は、その月が投稿月より後なら投稿年−1（1月の投稿の12月）、そうでなければ投稿年。期限は投稿日より前になるので当たらない。
  - それ以外 → 月が投稿月より前なら翌年、後なら投稿年（今の動き）。
  - 日付として成り立たない（2/30 等）は今どおり None。
1-2. 翌日の扱い（_date_ahead）: 当たりの条件を「期限 > 投稿日 + NEXT_DAY_GRACE_DAYS 日」に変える（新しい名前付き定数＝1）。つまり期限が投稿日の翌日以前なら当たらない。
1-3. 定数は既存の EARLY_PART_END_DAY・MIDDLE_PART_END_DAY の近くに、PO 決定を1行コメントで添えて置く。RELEASE_AHEAD・HEADING は変えない。
1-4. design: docs/handoff/v102-preorder-context/design.md の「決め直しの規則」の先の日付の説明と §7 を、上の決定に合わせて書き換え、PO 決定の原文を足す（設計者の文言をそのまま使う。下の「design 差し替え文」）。

- 「決め直しの規則」の先の日付の行を次に置き換える:

  「PO 決定（2026-10-12）：投稿の翌日までの発送は在庫のまま（「y：投稿の翌日までの発送は在庫のままにします。→y,発送日の情報は発送日情報に記載する条件で」）。過ぎた月は来年（「今年が過ぎてしまっているのであれば来年」）、ただし投稿月の1つ前の月は今年（「これは今年だと考える」、境目に「y」）。便PO2 で反映。発送日の文字の保存先は PO 判断待ち。」
