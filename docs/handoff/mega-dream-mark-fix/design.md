# 設計：MEGAドリームex（PM0198）の記号の修正 M3 → M2a（2026-10-05）

状態：設計案作成済み／Opus 自己審査 APPROVE（§7）／PO 承認済み（2026-10-05「修正してくれ」）。実行の結果は README.md の「実行記録」を参照。

## 1. 目的（PO に見える変化）
- 「ムニキスゼロ [M3]」のような投稿が、ムニキスゼロ（M3）と MEGAドリームex の2候補で決めきれていなかった。これを、ムニキスゼロ1つに決まるようにする。
- 「M2a」と書かれた投稿が、MEGAドリームex に決まるようにする。

## 2. 現在地（recon.md の要約）
- PM0198（MEGAドリームex）の記号は M3 だった。ムニキスゼロ（product_code M3）と同じだった。
- 公式の品番は M2a で、発売は 2025年11月28日だった。根拠は pokemon-card.com のカード検索 card/48585 と /ex/m2a/（URL と引用は README.md）。
- ADR-155:21 にも「PM0198 は M2a」とある。
- v9 の試験では、16件がこの原因で ambiguous だった。

## 3. 既存の ADR との関係
- ADR-155（商品マスタの SSOT は CSV とアプリ画面）
  - デッキビルドの修正（#3966）と同じく、PO の決定で例外として SQL で直接直した。
  - アプリの保存と同じ手順を再現した。行のロック、旧値の照合、audit_log の1行がそれにあたる。

## 4. 変更（前 → 後）
| id | code | 欄 | 前 | 後 |
|---|---|---|---|---|
| 440559 | PM0198 | mark | M3 | M2a |

- 商品名・検索の語・除外の語は変えない。SQL の中で、変わっていないことも照合する。

## 5. 代替案と選んだ理由
- 記号を空にする案：「M2a」の投稿で決まらなくなる。公式の品番がある以上、正しい値を入れた。

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| 空白を除いて比べるため、「M2 a」「M2ab」が M2a に当たる（extraction_judgement_svc.py:38-39, 57-59）。「M2 a」はインフェルノX（M2）との ambiguous になる | v9 の試験に該当は 0件だった。ambiguous は要確認に回るため、誤った確定にはならない |
| v6 で「M2a」が PM0198 に決まるようになる（tcg_analyzer_svc.py:1219-1224） | 公式の品番どおりなので、意図した変化である。「M3」は前も後も id 12（ムニキスゼロ）のまま |
