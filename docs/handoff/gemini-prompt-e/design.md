# design: Gemini の指示書 e（手順を上から順に実行する形に組み直す）

- 作成：2026-10-06 Opus（設計）
- PO の指示（2026-10-06）
  - 冒頭に「# 役割と目的／あなたは人格・意図・価値観を持たない。以下の手順を上から順に必ず実行せよ。」を入れる。
  - セクションごとに「# 1」から番号を付ける。
  - セクションごとに例文と出力例を付ける。
  - 以前の Gemini 解析の指示書を、書き方の構成の参考にする。
- PO 承認（2026-10-06）：「この指示書 e で、指示書 d のときと同じ試しをしてよいですか？」→「y」
- recon：docs/handoff/gemini-prompt-e/recon.md
- 関係する ADR：ADR-100、ADR-1004、ADR-085、ADR-154
- 前の版：docs/handoff/gemini-prompt-d/design.md

## 1. 目的（KGI）
- まとめ書きの行と親の見出しを、Gemini が lines に入れてしまう誤りを減らす。
  - 対象の5投稿について、各5回の試行で入れた回数を数える。
  - 比べる値：c は 9/25、d は 7/25。
- 素直な投稿で、行を正しく選べた数（正解表の19投稿の40件）を下げない。
  - 比べる値：c は 38/40 と 36/40、d は 33/40。

## 2. 現在地（事実。詳細は手元のみ：/tmp/CC報告ファイル/v102/）
- 指示書 d（PR #3994）の試しの結果
  - 試験A：※…発送分の2投稿は、c の 1/5・1/5 から 0/5・0/5 に減った。親の見出しの2投稿は、4/5・3/5 のまま変わらなかった。
  - 試験B：33/40 で、c より下がった。7件すべてが同じ投稿（50646e19）で、L59「ワンピースBOX カートン」が余分に入った。
- c と d は、決まりを種類ごとに並べた書き方で、実行する順番が決まっていない。
- PO が示した以前の解析用の指示書は、「# 役割と目的」と番号付きの手順で、上から順に実行させる形だった。

## 3. 変更
- 指示書 raw_copy_v101_e.txt を足す。本文は設計者（Opus）が書き、実装担当は1文字も変えない。
- 中身の決まりは c と同じにする。d の確かめ方（名前の違う商品が2つ以上）は使わない。
- 構成は、次の手順を上から順に実行する形にする。
  - # 1 件を作る
  - # 2 商品名の行を足す
  - # 3 件だけに付く行を足す
  - # 4 価格と価格のあいだの行を、どちらかの件に入れる
  - # 5 入れてはいけない行を外す
  - # 6 価格と数量を写す
  - # 7 出力
  - 各手順に、例文と出力例を1つずつ付ける。
- prompt_ab のコードは変えない。--prompt-name raw_copy_v101_e で使える。

## 4. 触らない
- 本番の抽出経路、既存の指示書（a〜d）、prompt_ab.py ほかのコード、DB、仕入元ルール、migrations、deploy.yml、scripts/、フロントエンド

## 5. 試験と受入条件
### 5-1. 試験（マージと本番反映の後。手順は d と同じ）
- 試験A：まとめ書きの行がある5投稿 × --repeat 5。上限 0.25 USD。
- 試験B：正解表の19投稿 × --repeat 1。上限 0.25 USD。
- 設定：--config v102 --prompt-name raw_copy_v101_e

### 5-2. 受入条件
| 基準 | 検証方法 |
|---|---|
| 指示書 e が、設計者の本文と1文字も違わない | cmp |
| prompt_ab で e を指定できる | test_prompt_ab.py に足すテスト（resolve_prompt_path で raw_copy_v101_e を解決できる） |
| 本番の経路が変わらない | 差分のファイルが、指示書・tests・docs・台帳だけである |
| CI が緑 | gh pr checks |
| まとめ書きの行を入れた回数が、c（9/25）より減る | 試験A |
| 素直な投稿の行の正答率が、c より下がらない | 試験B（正解の行 G1） |

## 6. 外部・過去事例の参照と我々への応用
- 社内の過去事例：PO が示した以前の Gemini 解析の指示書。役割と目的、番号付きの手順、出力例で構成されていた。
- Google の公式資料（Context7、2026-10-06）
  - Gemini 3 では、答えをそろえるために、指示に明確な決まりを書く（https://ai.google.dev/gemini-api/docs/gemini-3）。
  - 例は「正しくできた姿」を見せる（https://ai.google.dev/gemini-api/docs/prompting-strategies）。
- 我々への応用
  - 決まりの中身は変えず、実行の順番と、手順ごとの例をはっきりさせる。
  - 足した行をあとから外す手順を、独立させる。

## 7. リスクと戻し方
- リスク：c にあった例のうち4つを外したため、その形で正答率が下がるおそれがある。
  - 対策：試験Bで、素直な投稿の正答率を確かめる。
- 戻し方：この PR を revert する。指示書は --prompt-name で選ぶので、使わなければ影響しない。

## 維持の仕組み
- 記録：JSONL の prompt_name で、どの指示書で流したかを後から確かめられる。
- 守り手: backend/tests/test_prompt_ab.py が CI で毎回通ること。
- 担当：本番の経路に入れるときは、別の設計と PR で行う。
