# design: 解析の正答率を正しく測る仕組み

親: [LINE解析の調整記録](../../specs/line-analysis-tuning/README.md)／現在地: [recon.md](./recon.md)

この文書は何か: 解析が正しく読めているかを、毎回同じ物差しで、全部の項目について測るための設計です（KGI は PO 承認済み 2026-10-20「1」）。

- 状態: 設計案作成済み・KGI PO 承認済み（2026-10-20「1」）・便1着手（手元のファイルだけ）
- 区分: 既存テーマ line-analysis-tuning の延長（docs/STANDARD-WORKFLOW.md:65-75）
- 社外秘: 正解表そのものと判定の一覧は `~/CC報告ファイル-keep/` に置く。リポジトリには決まり・集計値・sha256 だけを書く（line-analysis-tuning/README.md の扱いと同じ）。

## 1. 目的（PO の言葉）

> 現在の解析システムの正答率を推測せずに調査、gemini の抽出、システムの抽出の正答率を、あなたが読み解くことは出来る？ 前回は予約商品を予約と捉えていなかったり漏れが合った、どうしたらあなたでも正答率を正しく測れるようになる？（2026-10-20）

PO の返事「1」（2026-10-20）: 測り方の設計書を作る。

利用者に見える変化:
- 測るたびに、項目ごと（商品・状態・予約・発送日など）と段ごと（Gemini／システム）の正答率が、同じ形の表で出る。
- 読み落としの数が出る。
- 直す前と後を、同じ答えで比べられる。

## 3. 対象と対象外

対象:

## 4. 採点する9項目

| # | 項目 | どちらの段の仕事か | 答えの決め方 |
|---|---|---|---|
| E1 | 行の範囲（どの行がその件か） | Gemini | 正解表 G3 v3 の「必須の行・許容する行」と同じ決まり |
| E2 | 価格 | Gemini（写し）／システム（数値化） | G3 v3 の price |
| E3 | 数量 | Gemini（写し）／システム（数値化） | G3 v3 の quantity |
| A1 | 商品 | システム | 共用商品マスタの id。マスタに無い商品は「未登録」 |
| A2 | 状態（Sealed box・Single など） | システム | ADR-1031 ほか状態の ADR の決まり |
| A3 | 単位（Box・Case・Pack など） | システム | 状態の ADR と単位の決まり |
| A4 | 在庫あり・予約・売り切れ | システム | §5 の決まり（PO 確認） |
| A5 | 発送日 | システム | §5 の決まり（PO 確認） |
| C1 | 読み落とし | 両方 | 正解表の値段の行のうち、システムの件が1つも無い行 |

各項目の判定は「正しい／違う／答え無し（決まりで決まらない）」の3つ。答え無しは正答率の分母に入れず、件数を別に出す。

## 5. 判定の決まり（PO に確かめてもらう部分）

予約と発送日の答えは、システムの決まり（v102_status_context.py）ではなく、投稿の意味で決める。システムの決まりを答えにすると、システムの抜けが測れないため。

A4 の案:
- 予約: 投稿がその商品について、次のどれかを言っているとき。
  - 「予約」「pre-order」「受付」などの語
  - 発売日より前の投稿
  - 先の発送日・入荷日
  - 予約の見出しの下にある
- 売り切れ: 「完売」「sold」「〆」など、その件が今は買えないと言っているとき。
- 在庫あり: 上のどちらでもないとき。

A5 の案:
- 投稿に書かれた発送日・入荷日を、その件の答えにする。
- 範囲で書かれた日付はそのまま範囲。
- 書かれていなければ「無し」。

決まりで決まらない件（例: 見出しがどこまで効くか分からない）は「答え無し」にせず、PO 確認票に載せる。

## 6. 正解表の作り方

1. 見本を選ぶ（2026-10-20 改訂。下の「改訂の理由」）。
   - 母集団: 2026-10-13 00:00Z〜2026-10-20 00:00Z に受信し、v102-f_ct の解析結果が1件以上ある投稿。
   - 2つに分けて取る。並べ方は md5(投稿id || '20261020') の順。
     - 予約の語（予約・受付・発売・pre-order・preorder）を含む投稿から40件。
     - 含まない投稿から60件。
   - 1つの仕入元からは10件まで（偏りを避けるため）。
   - 予約の件数は、AI 2人の答えで数える（システムの status では数えない）。30件に届かなければ、予約の語を含む投稿を同じ順で足す。
   - 選んだ時点の解析の結果を手元に写して固定する（engine_version・computed_at つき）。あとで再解析されても、採点はこの写しで行う。
   - E1〜E3 の答えの決め方は、G3 v3 の決まり（`~/CC報告ファイル-keep/gold-extended-20261007/README.md`・criteria_copy.md・po_decisions.md）をそのまま使う。
   - 改訂の理由: G3 の125投稿は、本番の表に v102 の結果が5投稿にしか無い（10/07 の結果は本番外の試験の記録で、元の投稿の124件は後の投稿に置き換え済み。`~/CC報告ファイル-keep/accuracy-gold-20261020/step0-counts.md`）。G3 を土台にすると、本番が実際に出した結果を採点できない。KGI は変えない。
2. AI 2人が、互いを見ずに答えを付ける。
   - 材料は投稿の原文全文・共用商品マスタ・§5 の決まり。システムの結果は見せない。
3. 機械で2人の答えを突き合わせる。
   - 割れた件と、決まりで決まらない件だけを PO 確認票にする（上限60件。超えたら見本を減らす）。
4. PO が確認票に答える。答えを正解表に書き、PO 確認の日付を列に入れる。
5. 正解表の sha256 を track-record.md に書く。以後、正解表を書き換えたら版を上げる（v1→v2）。

商品マスタが後から直ると、A1 の答えが変わることがある。正解表に、マスタの更新時刻を一緒に残す（memory feedback_compare_master_timestamps）。

## 7. 採点のしかた

- 採点は機械で行う。AI にその場で判断させない。
  - 正解表と解析の結果を、投稿の id と行番号で突き合わせる。
  - 全項目を数える。
- 解析の結果の取り方は2つ。
  - (a) 今の本番の結果: 読み取り専用の道（ADR-1024、ai_ro の表示）で extraction_items と analysis_results を読む。1回200行までなので、投稿ごとに分けて読む。
  - (b) 直した後の結果: 本番を書き換えずに、保存済みの Gemini の応答（extraction_attempts.response_text）を使って、システム段だけを手元で流し直す。直す前と後を同じ答えで比べるため。
    - 保存済みの応答を流し直す道具は、v102-price-line-yen-retry（1,021回）で使われている。その道具の場所と使い方は、まだ確かめていない。便2の最初に確かめる。
- 段ごとの切り分け:
  - Gemini 段: E1〜E3、C1 を extraction_items で採点する。
  - システム段: A1〜A5 を、行の範囲が正しかった件の中で採点する。Gemini の間違いを数えないため。
  - あわせて、全件での通しの正答率も出す。
- 出力: 結果の表（項目×段の正答率・件数・答え無しの数）と、間違えた件の一覧。
  - 一覧は社外秘なので手元に置く。集計だけを track-record.md に1行足す。

## 9. 選ばなかった案

- **前回と同じく AI がその場で採点する**: 答えが固定されず、回ごとに比べられない。予約の欄の入れ忘れのような抜けも、また起きうる。
- **PO が全件の答えを付ける**: 100投稿で数百件になり、PO の手間が大きい。割れた件だけに絞る。
- **システムの決まりをそのまま答えにする**: システムの抜けを測れない。
- **本番で再解析して直した後を測る**: 本番の結果を上書きし、配信が動く。手元で流し直す。

## 10. リスクと対処

| リスク | 対処 |
|---|---|
| AI 2人が同じ間違いをすると、割れずに素通りする | 便1で、割れなかった件から20件を抜き出して Opus が原文と照らす。誤りが1件でもあれば、その項目は全件を PO 確認に回す |
| 予約の件が足りず、予約の正答率がぶれる | KGI-1 で30件以上を条件にする。足りなければ予約を含む投稿を足す |
| 正解表が社外秘のままリポジトリに混ざる | 道具は正解表のパスを引数で受け取る。正解表はリポジトリの外に置く。PR の前に、仕入元名が0件かを grep で確かめる |
| マスタが直ったあと、古い答えのまま採点する | 正解表にマスタの更新時刻を残す。マスタの変更で答えが変わる件は版を上げる |
| 決まりで決まらない件が多く、PO の確認が60件を超える | 見本を減らす。§5 の決まりを先に PO と詰める |
