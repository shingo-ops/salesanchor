## 3. 現在地の要点（recon.md の事実）

- マイクの印はスマホだけ: `frontend/src/features/secretary/SecretaryChat.tsx:255-265`。声で返事: `:59`・`:66`・`:83-97`・`:241-244`。
- 聞き取りは Web Speech API、日本語固定、1 回区切り: `useSecretaryListen.ts:115-117`。
- 送れる文は 1,000 字まで: 画面 `secretaryApi.ts:10`・backend `backend/app/schemas/assistant.py:44`（`max_length=1000`）。
- 秘書の返事は容器の AI が文 → JSON を一括で返す（`secretary-agent/server.mjs:131`）。流れる声を扱う口は無い。返事まで 5〜8 秒。上限は容器 80 秒・backend 85 秒・画面 100 秒。
- 本番の画面は `connect-src 'self'`（`nginx/nginx.conf:96`）。`/api/` の枠に WebSocket の設定は無い（`:294`）。マイクは `microphone=(self)` で許可済み（`:100`）。
- 台帳 `public.llm_usage_events` の purpose・sdk は DB の CHECK で固定。値を足すには CHECK を作り直す migration が要る（型: `migrations/20261117_100100_add_llm_usage_tts_characters.sql`）。
- backend は Gemini の鍵をすでに持つ（`docker-compose.yml:98`・`:246`）。本番の Gemini の利用は 30 日で $40.55（約 6,450 円、本番台帳の読み取り 2026-11-22）。Google の有料の契約はすでにある。

## 4. やり方の比べ（費用・速さ）

為替は 1 ドル = 159 円（XE 2026-11-18 の 159.3 円を丸めた値）。料金は Opus が Context7 で公式資料を確かめた値（2026-11-21）。「1 分」は、こちらが 30 秒・秘書が 30 秒話した 1 分。**会話の履歴が毎回のやりとりで入力として数え直されるため、実際の費用はこれより上がる。どれだけ上がるかは試しの便で測る**（推測で倍率を書かない）。

| | ① Gemini Live（2.5 Flash Native Audio）| ② OpenAI Realtime（gpt-realtime-2）| ③ 無料の組み合わせ（聞き取り＋今の秘書＋今の読み上げ）|
|---|---|---|---|
| 1 分の費用（履歴の数え直しを除く下限）| 入力 $0.0045/分・出力 $0.018/分 → 約 $0.011（約 1.8 円）| 入力 $0.0192/分・出力 $0.0768/分 → 約 $0.048（約 7.6 円）| 0 円（読み上げは月 90 万字までの無料枠の中）|
| 返事が出始めるまで | 第三者の実測 p50 1,242ms（別の版 Gemini 3.8 Live の値。2.5 は未測）| 第三者の実測 p50 1,022ms・1.21 秒 | 今の 5〜8 秒＋読み上げの取得 |
| 割り込み | あり（`serverContent.interrupted`）| あり（`interrupt_response` 既定 true）| 自前。読み上げ中の聞き取りは自分の声を拾うため、今の設計は読み上げ中にマイクを閉じる（ADR-1082 設計 `design.md:31`）→ 割り込めない |
| 考える間 | 黙りの長さを設定（`silenceDurationMs`）| `semantic_vad`（言い終わりを意味で判断）| Web Speech は 1 回区切りで切れる |
| 両方の文字 | 入力・出力の書き起こしあり（別料金）| あり | あり |
| 会社との契約 | 既にある（Gemini の有料枠・学習に使わない）| 新しく結ぶ（業務データは既定で学習に使わない・ログ 30 日）| 不要 |
| 1 回の長さ | 声だけの会話は 15 分まで（続ける方法は未確認）| 未確認 | 制限なし |

**選んだもの: ①**。理由:
1. L5（2 秒以内）と L6（割り込み）は ③ では作りの上で満たせない（5〜8 秒・読み上げ中はマイクを閉じる）。
2. ② と比べて 1 分の下限が約 4 分の 1。Google とは有料の契約が既にあり、新しい会社にデータを渡さない。
3. 速さは ② が少し速いという第三者の値があるが、① の版の値は測られていない。**試しの便（§10 便 T）で本番から実測し、L5 を満たさなければ ② に切り替える**（同じ形の口にして、切り替えは担当表の 1 行で済むようにする）。

## 5. LIVE の作り（秘書の仕事は今の道に任せる）

```
[画面] ──声──▶ [Gemini Live]（声の聞き取り・話す・割り込み・書き起こし）
   ▲                  │ 用事だと判断したら道具「秘書に頼む(文)」を呼ぶ
   │                  ▼
   │          [画面] が今の POST /assistant/messages に、その文を本人のログインで送る
   │                  │（名前探し・カルテ・決まり帳・下書きは今のまま）
   │◀─下書きの吹き出し─┘ 返事の文を Gemini Live に返し、Gemini Live が声で伝える
```

- Gemini Live に渡す道具は「秘書に頼む（文）」の 1 つだけ。Gemini Live は会社のデータを読む道も、何かを作る道も持たない。予定・請求書の判断と名前探しは今の秘書の道（ADR-1056）がする。データのある場所は今と同じで、写しを増やさない。
- 道具の結果は 6〜8 秒かかる。その間、Gemini Live は「確かめます」と短く言う（指示文で決める）。
- 両方の発言は、今の会話の吹き出し（`ChatBubble`）で同じ並びに出す。LIVE を終えても会話に残る（L8）。
- 「ゆっくり話して」は Gemini Live の指示文と会話の中で効かせる（L9）。効かなければ試しの便で分かる。

### 5-1 作る前の確かめ（L11）

- 下書きは今と同じ吹き出しで出て、「作る」ボタンがある（ADR-1056）。
- LIVE 中は、声の「はい」でも作れるようにする。ただし判断するのは AI ではない。**こちらの声の書き起こし**が、下書きが出ている間に決まった言葉（「はい」「作って」等の短い一覧・正本は画面の 1 か所）に一致したときだけ、画面が「作る」と同じ処理を呼ぶ。Gemini Live に「作る」の道具は渡さない。
- 下書きが出たら、Gemini Live は中身（相手・日時・金額）を読み上げてから「作りますか？」と聞く（McDonald's の失敗: 正確さ 80% 台前半で拡大を止めた・research.md F1）。

### 5-2 鍵を画面に出さない

- backend の新しい口 `POST /api/v1/assistant/live/session` が、Gemini の短い期限の札（ephemeral token・1 回だけ使える・開始まで 1 分）を作って画面に渡す。Gemini の鍵そのものは画面に出さない。守りは秘書と同じ（`_SECRETARY_DEPENDENCIES` `assistant.py:98-103`）。
- 札を出すときに、今月の上限を超えていないかを backend が見る（§6）。

### 5-3 本番の画面の安全設定

- 画面から Google へ直接つなぐため、CSP の `connect-src` に Gemini Live の接続先 1 つ（`wss://generativelanguage.googleapis.com`）だけを足す（`nginx/nginx.conf:96`）。他は変えない。nginx を変える配備は 2〜3 秒画面が止まる（`deploy.yml:570-575`）。
- 代わりの案（backend を中継にする）は、backend が声の流れを抱え、`/api/` の枠に WebSocket の設定と中継の処理が要る。作る量と止まる箇所が増えるため選ばない。

## 6. 費用・台帳・月の上限（L12）

- LIVE を 1 回終えるごとに台帳 `public.llm_usage_events` に 1 行書く。使いみち `secretary_live`、`sdk` は `google-genai-live`（新しい値。CHECK を作り直す migration 1 本・ADR-1058 の型）。量は Gemini Live が返す使用量（トークン）から backend の値段表で費用を出す。値段表の正本は `backend/app/services/llm_budget.py` の 1 か所。
- 画面が終わりの使用量を送るのではなく、backend が札を出したときの記録と Gemini の使用量の報告を突き合わせる方法は、試しの便で使用量の受け取り方を確かめてから決める（**未確認**: 画面を通らずに backend が使用量を受け取れるか）。
- 月の上限は backend が見る。超えたら札を出さない（LIVE が始まらない・文の秘書は使える）。上限の額は PO の決定（§12）。
- 1 回の LIVE は最長 15 分（Gemini の決まり）。黙ったままが 2 分続いたら自動で終える（費用の守り）。

## 7. (A) マイクの印

- 今の Web Speech の部品を、話している間ずっと聞く形にする（`continuous=true`・途中の文字を欄に出す）。PC にも出す（`isMobile` の条件を外す）。0 円で台帳に書かない（ADR-1082 What 1 のまま）。
- 長さ: 聞いている時間に上限は付けない。送れる文の 1,000 字（`assistant.py` の型 `schemas/assistant.py:44`）は変えるかを PO に確かめる必要があるが、**秘書の AI に長い文を送ったときの動き（容器の 80 秒の上限内か）は未確認**。便 A の前に試しで測る。それまでは 1,000 字を超えたら欄の下に字数を出して知らせる。
- iPhone のホーム画面のアプリで Web Speech が動かない報告がある（Apple フォーラム 748048・research.md §2）。動かなかった場合は、マイクの印も Gemini Live の書き起こしだけを使う形に切り替える（有料。台帳は §6 と同じ）。どちらにするかは便 T の実機の結果で決める。

## 8. iPhone の注意と対処

| 報告 | 対処 |
|---|---|
| 音は利用者の操作の中で鳴らし始める必要（WebKit 177292）| LIVE ボタンを押した処理の中で音の準備をする |
| 消音スイッチで Web Audio が鳴らない（WebKit 237878）| LIVE の画面に「消音スイッチを確かめて」の案内（翻訳キー）。便 T で実機確認 |

| 出力先の切り替えが効かない（WebKit 320087）| 出力先は選ばせない |

## 9. 守る決まり（画面）

- 文字は全部 `t("key")`（ADR-027）。`ja.json`・`en.json` に同じキー。
- 見た目は金型だけ（ADR-144）。LIVE の画面は `Sheet`・`Stack`・`IconToggleButton`・`ChatBubble`・`Button` を使う（recon.md 1-2）。絵柄は `frontend/src/constants/icons.tsx` の `SECRETARY_ICONS`（`:416`）に、LIVE・消音・終了を足す。色・余白はデザイントークンだけ（ADR-067）。新しい金型が要るときは作る前に PO に聞く。
- 機械の見張り（既にある）: i18n の検査・ADR-144 の UI ガバナンス検査・デザイントークンの検査が CI で走る。今回はこれに足す見張りを §11 に書く。

## 12. リスクと、PO に決めてもらうこと

- **有料の声の AI を使うこと**（費用が出る）。下限は 1 分約 1.8 円。上限の案: 便 T は月 1,000 円（約 $6.3）で始め、実測の 1 分の費用を見てから便 B の前に決め直す。
- **ADR-1056 との食い違い**: ADR-1056 は「AI 会社へ送るのは利用者が書いた文だけ。会社のデータは送らない」。LIVE では、こちらの声と、秘書の返事の文（相手の会社名・金額を含むことがある）が Google に送られる。Google は有料枠で学習に使わない。LINE の解析で既に会社のデータを Gemini に送っている。それでも決まりを改めるのは PO の決定。
- 外の事例の数値は電話・ドライブスルーの規模で、我々の社内の数人の使い方にそのまま当てはまらない（research.md §4-1）。だから便 T を本番で測ってから先へ進む。

## 14. 外の事例（research.md の要約）

- 成功（数値あり・すべてベンダーの自己申告）: Landry's 初日の封じ込め 87%／Hello Sugar 応答 100%・封じ込め 56%／米国の銀行 解決 30%・満足度 96%／Wendy's 22 秒速い・正確さ 99% は店員の補助込み。
- 失敗（数値あり）: McDonald's×IBM 正確さ 80% 台前半（必要 95%）・100 店超・約 3 年で停止／Presto 人の介入なしの完了は 30% 以下（SEC の書類）。
- **失敗の 3 件目は、数値の取れる事例が見つからなかった**（Taco Bell・Kinney Drugs は数値なしで数えない）。
- 我々に当てはめる学び: ①成果は「AI だけで正しく終えた割合」と「人の補助込み」を分けて測る（Presto）。②聞き間違いがそのまま事故になる操作の前に、中身を読み上げて確かめる（McDonald's）→ §5-1。③同じ製品でも仕事の種類で封じ込めが 5%〜87% と開く（PolyAI の各社）→ 便 T の本番の実測で決める。
