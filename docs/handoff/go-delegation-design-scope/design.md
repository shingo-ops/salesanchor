# design: GO 委任の範囲に「設計どおりの計画」を追加する

参照: recon.md（同じフォルダ）、ADR-1003（docs/adr/ADR-1003-go-delegation-to-opus.md）

## 目的
PO の 2026-10-15 の発言を委任の正式記録に残す。これで、次のセッションでも「設計どおりの計画は Opus が GO を出す。設計から外れたら PO に報連相する」を同じ前提で扱える。

## 変更前後
- 変更前：opus-delegation.md の委任の範囲は PR の GO だけ。無制限鍵での本番変更は、CLAUDE.md:30 により作業ごとに PO の GO が要る。
- 変更後：opus-delegation.md に「範囲の追加（2026-10-15：設計どおりの計画）」の節を足す。内容は次の4つ。
  - PO の原文
  - 範囲は、PO と決めた設計に収まる計画。無制限鍵での本番変更も含む。
  - 期限は無い（恒久）。
  - 設計から外れたら止めて PO に報連相する。既存の例外は引き続き PO 本人の GO が要る。
- あわせて、変更履歴に1行を足す。

## 対象外
- CLAUDE.md と ADR-1003 の本文は変えない。CLAUDE.md:57 は既に ADR-1003 の委任を指しているので、範囲の細部は正式記録が受け持つ。

## 受入条件
|基準|検証方法|
|---|---|
| opus-delegation.md に、PO の原文2つがそのまま入っている | `git diff` で目視 |
| 既存の「例外」節が残っていて、追加の範囲でも例外は PO 本人と書いてある | `git diff` で目視 |
| 変更履歴に 2026-10-15 の行がある | `grep -n 2026-10-15 docs/handoff/go-record-transcription/opus-delegation.md` |

## 外部事例
該当なし。社内の権限委任の記録を転記するだけで、技術的な選択を含まないため。

## 戻し方
この PR を revert する。または、PO が「委譲停止」と発言する（opus-delegation.md の「解除の方法」）。

## 維持の仕組み
GO を出すたびに、設計書のどの項目に当たるかを GO 記録に書く（追加した節の5）。
