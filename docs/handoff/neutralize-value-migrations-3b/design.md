# 設計：テナント作成と権限に関わる値の migration の無効化（ADR-1007 段3 の PR-3b、2026-10-07）

状態：設計案作成済み／Opus 自己審査 APPROVE（§7）／PO 承認済み（ADR-1007 の進め方「進めて良い」2026-10-05）。migrations を変える危険な PR なので、マージには PO の「GO #番号」が要る（ADR-136）。

**マージの順番（必須）**
1. #3986（system_key の列）
2. system_key のデータの変更
3. #4012（権限の計算とテナント作成の完全化）が本番に出る
4. この PR

理由：この PR で止める migration は、#4012 より前のテナントの作成と、所有者・管理者の権限を補っていたため。

## 1. 目的（PO に見える変化）
- 画面の見た目は変わらない。
- デプロイのたびに、テナントの設定・役割の印・権限の付与を上書きしたり足したりしていた 7本を止める。画面や今後の操作で決めた値が、デプロイで戻らなくなる。

## 2. 現在地（recon.md の要約）
- 止める 7本：080・023・075・025・018・024・20260604_180000
  - 080：tenant_settings の phase を A から B に変える
  - 023：システム管理者の is_system を立てる
  - 075：goals の権限と付与
  - 025：所有者と管理者に全部の権限を配る
  - 018・024・20260604_180000：権限のキーの追加
- 本番の値は、どれも今の migration の値と同じである（違う行は 0）。止めても、本番の今の値は変わらない。
- #4012 で、新しいテナントは作った時点でこれらの状態になる。所有者と管理者の権限は、system_key から計算する。
- 権限の表（public.permissions）は、2026-09-18 から migration-guard の Check 7 で、新しい migration からの書き込みが止められている（.github/workflows/migration-guard.yml:416）。今ある7本を止めても、使える道は減らない。

## 3. 既存の ADR との関係
- ADR-155：マスタの値を migration で扱わない。
- ADR-1007 の決定2（無効化）と、実施順序の段3 にあたる。#4012（決定3・4）が前提である。

## 4. 変更
- 7本の値を書く部分だけを止める。範囲は recon.md の表のとおり。
  - #3544 の形にならい、`-- NEUTRALIZED (ADR-1007 / ADR-155, 2026-10-07)` の印と NOTICE にする。
  - DDL（080 の DEFAULT 'B'、075 の goals の表・RLS・trigger など）は1文字も変えない。
- scripts/run_all_migrations.sh の登録は変えない（#3544 と同じ）。
- 触らない：アプリのコード、試験の期待値、本番。

## 5. 代替案と選んだ理由
- ファイルを登録から外す：#3544 の前例と形が違う。実行の記録との対応がずれる。
- #4012 より先に止める：新しいテナントの設定と、所有者・管理者の権限が、作った時点で欠ける。そのため順番を固定した。

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| #4012 より先にマージすると、新しく作るテナントの設定と権限が欠ける | マージの順番を PR の本文と、この文書の冒頭に明記する |
| 今後、権限のキーをどう足すかが決まっていない | この PR の範囲外とする（権限の正本の別の ADR で扱う。PO が後で判断する）。今でも migration からは足せない（Check 7） |
| scripts/migrate_phase1_redesign.py:50-53 が 018 を流す | 一度きりの手動のスクリプトで、自動の呼び出し元は無い（.github・scripts・backend・frontend で 0件）。run_all_migrations.sh にも登録されていない。スクリプト自身が「再実行禁止」としている（:55-59）。再実行したときだけ、新しい DB で 021 の menu.* の付与が 0件になる。本番は 123件あるので変わらない |
| schema-check（.github/workflows/schema-check.yml:171,173）が 018・024 を流している | 構造は残るので、比べる（表・列・型）結果は変わらない |

## 7. 受入条件と検証方法
| 基準 | 検証方法 |
|---|---|
| 7本に値を書く文が残らない。DDL は変わらない | 差分の目視と、migration-guard の Check 7・8 |

| 新しいテナントが完全な状態で作られる | #4012 の試験（test_permission_resolution_pg.py）が CI で通る |
