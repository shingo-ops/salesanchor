# 設計：migration の整備（ADR-1007 の起票）

状態：ADR を起票（PO 2026-10-05「進めて良い」、system_key「はい」、権限の計算「はい」）／実装は未着手（段1〜段5は別の PR）。

## 1. 目的
- migration を「構造の変更だけ・1回だけ流す」という正しい使い方にそろえる方針を、ADR-1007 として正式にする。
- そのために必要な前提（テナントの作成の完全化、所有者と管理者の権限の計算、試験の自立、値を書く migration の無効化、検査の強化）と、その順番を決める。
- この PR は文書だけである。

## 2. 現在地（recon.md の要約）
- 毎回 317本を流し直している。実行済みの記録は無い。
- 値を書く migration が 52本あり、毎回届くものが 28本（上書き型 8、補充型 20）ある。本番の今の値と同じである。
- テナントの作成（080・023・075・025）と試験（countries・集計の決まり・type_master など）が、流し直しに頼っている。
- 所有者と管理者を見分けられるのは、日本語の表示名だけである。
- migration-guard は、追加されたファイルしか見ない。全体の試し流しの対象から、162本が外れている。
- #3965（ADR-1005 案）は、記録して1回だけ流す設計である。ただし、値を書く migration と検査の範囲には触れていない。ADR-1005 の番号は #3942 と重なる。

## 3. 既存の ADR との関係
- ADR-155：値の操作を migration で行わない、という決まりを、既存の migration と全マスタに広げて守る。
- ADR-1002：毎回の再実行が設計であることは、背景に書かれていた。この ADR で改める。
- ADR-136：各段の PR のマージは、PO の GO による。
- PR #3965 の ADR-1005 案：内容を引き継ぐ（runner-design-from-3965.md・runner-recon-from-3965.md）。番号は 1007 に付け直す。

## 5. 代替案と選んだ理由
- #3965 の段階2（記録して1回だけ流す）を先に入れる案：実行済みのファイルの書き換えが止まり、値を書く migration を無効にできなくなる。また、テナントの作成と試験が壊れる。
- 所有者と管理者の権限を、1行ずつ持つ形のままにする案：権限を足すたびに配る手順が要り、025 の流し直しへの依存が残る。PO が計算の形を選んだ。
- 役割を日本語の名前で見分ける案：名前の変更に弱く、ハードコードになる。PO が system_key を選んだ。

## 8. 外部・過去事例の参照と我々への応用
- 外部事例：一般的な migration の道具（Alembic・Flyway・Rails）は、実行済みの記録の表を持ち、未実行のものだけを1回流す。この形を段5の目標にする。
- 過去事例：#3544 での漏れ（seed_product_marks）が、2026-10-05 の書き戻しにつながった。そのため、全体の一覧（recon.md §2）で漏れを無くしてから無効にする。
