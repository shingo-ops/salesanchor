# design: Gemini の指示書 d（まとめ書きの行の決まりを、見た目で確かめられる形にする）

- 作成：2026-10-06 Opus（設計）
- PO 承認（2026-10-06）：「temperature 0 の試しを取りやめ、指示書の決まりを書き直す試しに切り替えてよいですか？」→「y」
- PO の方針（2026-10-06）
  - Gemini の仕事は、原文の行番号の特定（と、価格・数量の文字）だけ。解析はすべてシステムが担当し、役割を完全に分ける。
  - Gemini の出来は、行番号の正答率で測る。
- recon：docs/handoff/gemini-prompt-d/recon.md
- 関係する ADR：ADR-100、ADR-1004、ADR-085、ADR-154
- 前の版：docs/handoff/gemini-v102/design.md、docs/handoff/gemini-omit-supplier-field/design.md

## 1. 目的（KGI）
- まとめ書きの行（例：※9/11発送分、親の見出し）を、Gemini が回によって lines に入れてしまう誤りを減らす。
- 判定の対象は、まとめ書きの行がある5投稿。各5回流し、まとめ書きの行を入れた回数を数える。今の指示書 c は 9/25 回。
- 書き方が素直な投稿の、行の正答率を下げない。
  - 基準：正解表の行（160件）。指示書 c のときは 156〜158/160。

## 2. 現在地（事実。詳細は手元のみ：/tmp/CC報告ファイル/v102/）
- 役割を分けた採点（正しい行をシステムに渡した場合）
  - システム：価格・数量・単位・件数は 160/160、状態は 158/158、発送は 160/160、商品名は包含で 160/160。
  - 誤りの元は、Gemini の行の選び方だった。
- Gemini の行の正答率（指示書 c、147投稿×2）
  - 素直な投稿：158/160、156/160
  - まとめ書きの行がある投稿：45/70、25/70。誤りはすべて「余分な行を入れた」。
- 仕入元ルールの発送日の欄を外しても、入れた回数は変わらなかった（付けた場合 9/25、外した場合 9/25。PR #3990 の試し）。
- Google の公式の資料（Context7 で確認、https://ai.google.dev/gemini-api/docs/gemini-3）
  - Gemini 3 では temperature を既定の 1.0 から下げないことを強く勧めている。
  - 答えをそろえたいときは、指示に明確な決まりを書くよう勧めている。
- 指示書 c は、まとめ書きの行を「複数の商品の上にまとめて置かれた行」という言葉と例で示しているだけで、見た目で確かめる方法を書いていない。

## 3. 変更
- 指示書 raw_copy_v101_d.txt を足す。本文は設計者（Opus）が書き、実装担当は1文字も変えない。
- c からの変更点
  - 【lines に入れない行】のまとめ書きの行を、確かめ方として書き直す。
    - 確かめ方：その行より下で、次のまとめ書きの行か投稿の終わりまでのあいだに、別々の商品の名前の行が2つ以上あれば、まとめ書きの行。
    - 同じ商品の価格違いは1つと数える。発送日が書かれていても入れない。
  - 商品名を含まない区分だけの行（【予約】など）は、下の商品が1つでも入れない。
  - 【書き出す前の確かめ】を足す：価格の行より上の行を1行ずつ確かめる。
  - 例を1つ足す（※10/20出荷分の下に別々の商品が2つある形。文は試験の投稿と変える）。
  - 既存の例の説明文を、確かめ方に合わせて直す。
- prompt_ab のコードは変えない。--prompt-name raw_copy_v101_d で使える（^raw_copy_v101_[a-z0-9_]+$）。

## 4. 触らない

## 5. 試験と受入条件
### 5-1. 試験（マージと本番への反映の後）
- 試験A
  - 対象：まとめ書きの行がある5投稿（41e54546、5fe1300b、5532ccae、d800fd79、ad7e7ab1）
  - 設定：--config v102 --prompt-name raw_copy_v101_d --repeat 5
  - 比べる相手：前回の指示書 c の結果（omit-with-ship、9/25）
- 試験B
  - 対象：正解表の19投稿
  - 設定：同じ設定で --repeat 1
  - 見るもの：行の正答率が、指示書 c（156〜158/160）より下がらないこと
- 費用の上限：合計 0.5 USD

### 5-2. 受入条件
| 基準 | 検証方法 |
|---|---|
| 指示書 d が設計者の本文と1文字も違わない | cmp |
| prompt_ab で d を指定できる | test_prompt_ab.py に足すテスト（resolve_prompt_path で raw_copy_v101_d が解決できること） |
| 本番の経路が変わらない | 差分のファイルが、指示書・tests・docs・台帳だけ |
| CI が緑 | gh pr checks |
| まとめ書きの行を入れた回数が c（9/25）より減る | 試験A |
| 素直な投稿の行の正答率が c より下がらない | 試験B（正解の行 G1） |

## 6. 外部・過去事例の参照と我々への応用
- Google の公式の資料（Context7、2026-10-06）
  - 出典：https://ai.google.dev/gemini-api/docs/gemini-3、https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.5
  - Gemini 3 は temperature を下げず、指示に明確な決まりを書いて答えをそろえる。
  - 例（few-shot）は「正しくできた姿」を見せる（https://ai.google.dev/gemini-api/docs/prompting-strategies）。
- 我々への応用
  - 言葉による定義ではなく、Gemini が原文の見た目で確かめられる手順として書く。
  - 足す例は1つだけにする。
- 過去事例（社内）：仕入元ルールの欄を外す試し（PR #3990）では差が無かった。そのため、指示書の側を直す。

## 7. リスクと戻し方
- リスク：同じ見出しの下の共有の行（【9/28発送】の形）まで外すおそれ。
  - 対策：確かめ方を「別々の商品の名前が2つ以上」に限り、同じ商品の価格違いは1つと数えると書く。その形を例に入れる。試験Bで、素直な投稿の正答率を確かめる。
- 戻し方：この PR を revert する。指示書は --prompt-name で選ぶので、使わなければ影響しない。

- 担当：本番の経路へ入れるときは、別の設計と PR で行う。
