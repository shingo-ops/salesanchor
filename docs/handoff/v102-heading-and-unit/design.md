見出しの件（2026-10-22 の毎朝の点検で見つかった誤り）: 仕入元が「傷あり」「未サーチ品」の見出しの下に並べた品目を、いつもの値（Sealed box／Searched pack）で自動確定していた。

## 決め方（変更後）

### T. 区分ごとに取れる単位の表

1. 表は設定 `public.tcg_distribution_settings` の key `v102_kubun_allowed_units` に JSON で持つ（列 `value` は TEXT。`migrations/20260921_110000_pipeline_tables_public.sql:354-359`）。値は次のとおり（単位の名前は `line_units.canonical`）。

   ```json
   {"箱系": ["Box", "Case", "Pack", "MasterCarton"], "プロモパック系": ["Booklet", "Pack"], "ブックレット系": ["Booklet"]}
   ```

   - 表に無い区分（シングル系・サプライ系・セット系・バルク系など）は調べない。今と同じ。
   - MasterCarton の綴りは、便1 のカードで本番の `line_units` を読んでから決める（recon 7）。
2. 読み込みで検査する。次のどれかなら、警告を出して表全体を使わない（今と同じ動き）。
   - key が無い。
   - JSON として読めない。区分名 → 文字列の配列の形でない。
   - 区分名が `tcg_product_categories.kubun_type`（有効な行）に無い。
   - 単位の名前が `line_units.canonical`（有効な行）に無い。
3. 判定は、状態から単位を決め直した後（`_resolve_unit_from_state` の後）に 1 回だけ行う。
   - 単位が無い、または表にある単位なら、何もしない。
   - 表に無い単位なら:
     - (a) 状態の単位（`masters.condition_unit[状態]`）が表にあれば、その単位に置き換える。`unit_basis` に `kubun_unit_fix: "a"` と元の単位を残す。
     - (b) なければ単位はそのまま、要確認の理由「単位不明」（`unit_unknown`。既にある理由。recon 4）を足す。`unit_basis` に `kubun_unit_fix: "b"` を残す。
   - 状態・商品は変えない。
4. 値段で単位を決める処理（ADR-1036）は、この後に保存処理の中で動く。決める単位は Box／Case／Pack だけで、箱系の表に入っている。表の判定の後で表に無い単位になることは無い。この組み合わせは K2 の置き換え（保存処理まで通す）で確かめる。

### M. 3 商品の区分直し

- `public.products` の 3 行の `product_category_id` を 4（セット系）→ 1（箱系）にする。`tenant_id IS NULL` と今の値 4 を条件にし、変わる行がちょうど 3 行でなければ取り消す。
- 区分の変更は Opus に任されている（PO 2026-10-16）。本番の書き込みは制限なしの鍵が要るので、PO が `!` で実行する（同意票）。
- 試しの実行（dryrun）→ 本実行の順。台本は社外秘フォルダ `set-to-box/` にある。
- T より前に入れても、T が無いあいだは単位 Set のまま。区分だけが箱系になる。値段で単位を決める処理（ADR-1036）の対象になるのは「単位の語で決まっていない行」だけで、この 3 商品の行は「セット」の語で決まっているので対象外。→ 便0 の後、T（便1）を入れるまで値は変わらない。K7 で確かめる。

### D2. 状態の見出し（便2。K5 合格が条件）

1. 品目の選択行（block）で状態の語が当たらないときだけ働く。当たれば今まで通り。
2. 品目の最初の行から上へ、見出しの行を探す。見出しは次をすべて満たす行。
   - 形が見出し（設定 `condition_heading_line_regex`。例: 記号で始まる行）。
   - 見出しでない印を含まない（設定 `condition_heading_not_regex`。例: @・在庫・円・4 桁以上の数）。
   - 状態の語を含む。状態の語は状態マスタの各行の検索の形で判定する（`_entry_hit`。recon 5）。**コードに語を書かない。**
3. 注意書きとの区別: 見出しの直後に品目の塊（次の空行までに値段がある行。値段の形は設定 `condition_heading_price_regex`）が来るときだけ見出しにする。見出しと品目のあいだは、説明の行 1 つ（値段なし・設定 `condition_heading_desc_max_len` 文字以内・単位の別名 `line_unit_aliases` を含む）と空行 1 つまで越えてよい。
4. 見出しが効く範囲: 見出しの次の行から、次の見出しの形の行・空行 2 連続・空行の次が品目でない行の、どれかの手前まで。
5. 見つかったら、見出しの行を block に足して状態を決め直す。変えるのは状態だけで、`condition_basis` を `R9:見出し:<語>` で始める。
6. 設定のどれかが無い・正規表現として読めないときは、警告を出して D2 全体を使わない。
7. 試算では語の一部（傷あり・サーチ不明・開封）を道具に直接書いた。これらが状態マスタの検索の形に無いと、DB から読む形では当たらない。**K5 の再試算で 31 行に届かないときは、足りない語を状態マスタに足す記録 SQL を別に設計し、PO に候補の語を見せてから入れる。** そのときは D2 を進めない。
