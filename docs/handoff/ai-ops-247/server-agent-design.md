## 1. 目的と、PO から見て変わること

- 目的（PO の言葉から）: Mac の負担を下げる。スマホから保守運用の担当に話しかけ、結果を受け取る。
- 変わること: Mac を閉じていても、スマホの Discord で保守運用の担当とやりとりできる。

## 2. 成功条件（○×で判定する）

| # | 基準 | 検証方法 |
|---|---|---|
| K1 | Mac の電源を切った状態で、PO がスマホの Discord に書いた指示に、担当が 2 分以内に返事をする | PO のスマホで 3 回試し、書いた時刻と返事の時刻を記録。3 回とも 2 分以内で ○ |
| K2 | サーバーを再起動したあと、人の操作なしで担当が立ち上がり直す | 再起動を 1 回行い、K1 と同じ試しを 1 回。○×（U-a） |
| K3 | 7 日間、担当が止まっていた時間の合計が 1 時間以下 | 監視の生存の記録（prod2 の Uptime Kuma に1つ足す）で数える |
| K4 | 担当が本番を変えられる道は PR だけ。マージと本番反映は今の GO の決まりのまま | 担当の設定の許可の一覧を読み、直接の書き込みの道が 0 件で ○ |
| K5 | Discord で担当に届くのは PO の書き込みだけ | 別のアカウントから 1 回書き込み、担当が反応しなければ ○ |

## 3. 置き場の案（D2）

| 案 | 中身 | 判断 |
|---|---|---|
| A 監視サーバー（prod2）に入れる | 費用は増えない | 選ばない。メモリが公式の条件（4GB 以上・F4）に届かない（全部で 3,915MB・F1）。スワップも無い。prod1 への鍵が置いてあり（F3）、担当が間違えたとき prod1 まで届く。監視が止まると、異常に気づく仕組みごと止まる |
| B 保守運用だけの小さなサーバーを別に借りる | さくらの VPS 4G（メモリ 4GB）。月額はおよそ 3,200〜3,800 円（U-d・未確認） | おすすめ。条件を満たし、監視と本番から切り離せる |
| C サーバーを置かない | スマホの Claude アプリから、今のクラウドの仕組み（claude.ai/code）を使う。Discord ではなく Claude アプリでやりとりする | 費用は増えない。Discord ではない。Remote Control（F9）は機械が動いたままの必要があるので、Mac の負担は減らない |

## 4. ログインのしかた（D1）

| 案 | 中身 | 判断 |
|---|---|---|
| 1 今のサブスクでログインする | 追加の費用なし | 24 時間の常駐が「ordinary, individual usage」に入るか公式に書いていない（F8・U-c）。ADR-1012:42 の未決と同じ問題。PO の事業判断 |
| 2 API の鍵で動かす | 使った分だけの別料金 | 規約の心配はない。費用は使い方で変わり、まだ測っていない |

設計担当はどちらとも決めない。D1 は事業の判断なので PO が決める。

## 5. 案 B の形（D2 が B のとき）

- 担当: 公式の Discord の道具（F5）で起動した Claude Code 1 つ。PO の書き込みだけを受ける（許可の一覧に PO 1 名）。
- 異常の知らせは今までどおり段階4 の仕組み（F11）が受ける。この担当は知らせの投稿を読まない（公式の道具はボットの投稿を捨てる・F6）。そのため自前で手直しした道具（F7・起動のたびに確認画面）は使わない。
- 担当ができること: 調べる（本番は読み取りの鍵だけ）・PR を作る。マージと本番反映は今の GO の決まり（ADR-136・ADR-1003）のまま。
- 置かないもの: 無制限の鍵・prod1 へのトンネルの鍵・本番のデータベースの書き込みの鍵。
- 見張り: 生存を prod2 の Uptime Kuma で見る（K3）。止まったら今の Discord の知らせに出す。
- 正本: 担当の決まりは `docs/ai-agents/ops-incident-agent.md` 1 か所を読む（ADR-1012 Decision 5 と同じ）。新しい記録の置き場は作らない。

## 6. 試し（実装カードの前）

## 7. リスクと対処

- 担当が間違った変更をする → 本番に届く道は PR だけ。GO の決まりは変えない（K4）。
- 規約（D1 の 1 を選んだとき）→ 使い方が変わったら、すぐ API の鍵に切り替えられるよう、手順を実装カードに書く。
- 研究プレビューの道具が変わる → 止まったら K3 の見張りで気づく。Mac の受付（ADR-1009）は予備として残す。
- 秘密の置き場が増える → サーバーには読み取りの鍵と Discord のボットの鍵だけを置く。値は GitHub と同じ決まりで扱い、文書に書かない。
