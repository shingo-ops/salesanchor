## 指摘と対応

1. 書込の大量検知は `count > 500`（窓の中で 501 回目以降すべて）で、窓の中で何行も入りうる。閲覧側は `count == 501` の 1 回だけにした（design §3-2）。閲覧は数が多いため、行が膨らまないようにする意図。書込側は今回変えない（S6 の範囲外）。→ 設計どおりでよい。
2. 書込と閲覧でキーを分ける（`bulk_access:`／`bulk_read:`）。同じキーにすると書込の検知の意味が変わるため。→ 設計どおりでよい。
3. 認証の無い GET（email が取れない）は数えない。ログイン前に取れる情報は大量取得の対象にならないため。→ 設計どおりでよい。
4. JWT の email は署名を確かめずに読む。偽の email で数えられる・記録される可能性はあるが、既存と同じログ用途で、認可には使わない。対象の GET は本体側で署名済みの認証と権限が要る。→ 受容。
