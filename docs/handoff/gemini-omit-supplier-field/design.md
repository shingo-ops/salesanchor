# design: 比較試験の道具に「仕入元ルールの欄を外す」切り替えを足す

- 作成：2026-10-06 Opus（設計）
- PO 承認（2026-10-06）：仕入元ルールの「発送日の書き方」の欄を付けた場合と外した場合で、Gemini の答えを比べる試し（費用 1.0 USD 以内）を進めてよいですか？→「y」
- recon：docs/handoff/gemini-omit-supplier-field/recon.md
- 関係する ADR：ADR-100、ADR-1004、ADR-085、ADR-154
- 前の版：docs/handoff/gemini-v102/design.md

## 1. 目的（KGI）
- Gemini が「まとめ書きの行」（例：※9/11発送分）や親の見出しを、試験の回によって商品の行に入れたり入れなかったりする。その原因が、仕入元ルールの発送日の書き方の欄（extraction_ship_format）にあるかを、実際に流して確かめる。
- 判定：同じ投稿・同じ指示書で、欄を付けた場合と外した場合を各5回流し、まとめ書きの行を入れた回数を比べる。

## 2. 現在地（事実。詳細は手元のみ：/tmp/CC報告ファイル/v102/）
- v10.2 の試験（147投稿×2）で、まとめ書きの行がある投稿の行の正答率は、1回目 45/70、2回目 25/70。誤りはすべて「余分な行を入れた」。
- 該当する仕入元のルールの発送日の書き方の欄
  - 25519：「見出し『※9/30発送分』」
  - 25524：「行末『発送日要相談』」
  - 25514：「冒頭『17時までの注文で当日発送』、【予約】発売日発送」
- 指示書は「複数の商品の上にまとめて書かれた行は入れない」と書いていて、ルールと食い違うおそれがある。
- Gemini の考えの要約は、Claude 側の安全装置により読めなかった。そのため、実際に流して確かめる。
- prompt_ab には、仕入元ルールを外す・差し替える引数が無い（backend/app/tools/prompt_ab.py:431-459）。

## 3. 変更（prompt_ab.py のみ）
- 引数 `--omit-supplier-field` を足す。何回でも指定できる。
  - 指定できる値は、仕入元ルールの欄名（extraction_ で始まる名前）だけにする。それ以外の値はエラーにする。
- 指定したときは、ctx.supplier_context から、その欄を除いた写し（新しい辞書）を作り、Gemini の呼び出しと dry-run の両方に渡す。元の ctx は変えない。
- JSONL の行に `omitted_supplier_fields`（外した欄の名前の一覧）を書く。指定しないときは書かない。
- 指定しないときの動きは、今と全く同じにする。
- gemini_raw_copy_v8.py と、本番の抽出経路（gemini_extraction_svc.py・tcg_extraction.py）は変えない。

## 4. 触らない
- 本番の抽出経路、v7〜v102 の取り出しの処理、指示書、DB、仕入元ルール、migrations、deploy.yml、scripts/、フロントエンド

## 5. 試験と受入条件
### 5-1. 試験（マージと本番への反映の後）
- 対象：41e54546、5fe1300b、5532ccae、d800fd79、ad7e7ab1 の5投稿（run_id で指定する）
- 設定：--config v102（指示書 c）。付けた場合と外した場合（--omit-supplier-field extraction_ship_format）を、それぞれ --repeat 5 で流す。
- 費用の上限：合計 1.0 USD
- 見るもの：投稿×回ごとに、まとめ書きの行（41e54546 L7、5fe1300b L5、5532ccae と d800fd79 の L19、ad7e7ab1 L7）を lines に入れた件があるか。付けた場合と外した場合の回数を比べる。

### 5-2. 受入条件
| 基準 | 検証方法 |
|---|---|
| 指定しないときの動きが変わらない | 既存の test_prompt_ab.py がすべて通る |
| 指定した欄だけが Gemini に渡る指示書から消え、元の ctx は変わらない | test_prompt_ab.py に足すテスト（build_prompt_v8 の結果に「発送日フォーマット」が無いこと、ほかの欄は残ること、元の辞書が同じこと） |
| extraction_ で始まらない値はエラーになる | test_prompt_ab.py |
| JSONL に omitted_supplier_fields が書かれる | test_prompt_ab.py |
| 本番の経路が変わらない | 差分のファイルが prompt_ab.py・tests・docs・台帳だけ |
| CI が緑 | gh pr checks |

## 6. 外部・過去事例の参照と我々への応用
- 過去事例（社内）：v10.1 の ABテスト（docs/handoff/gemini-v101/design.md）は、指示書の文だけを変えて差を測り、原因を切り分けた。
- 我々への応用：今回も、変えるのは1つの欄だけにし、ほかの条件はそろえる。Gemini は回によって答えが変わるので、各5回流して回数で比べる。
- 外部事例：不要と判断した。理由は、社内の道具と社内のデータでの原因の切り分けであり、外部の数値を当てはめられないため。

## 7. リスクと戻し方
- リスク：指定しないときの動きが変わるおそれ。対策：既定値を「外さない」にし、既存テストで守る。
- 戻し方：この PR を revert する。

## 維持の仕組み
- 記録：JSONL の omitted_supplier_fields で、どの欄を外して流したかを後から確かめられる。
- 守り手: backend/tests/test_prompt_ab.py が CI で毎回通ること。
- 担当：本番の経路は変えない。仕入元ルールの文を直すときは、PO の許可を得て別に行う。
