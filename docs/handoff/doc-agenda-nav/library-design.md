# 入口の文書の図書館化 設計（要件 library-requirements.md への答え）

作成: 2026-11-02 設計担当（クラウドの Planner）。状態: **設計の下書き（PO 未承認・審査前）**。入力: [library-requirements.md](./library-requirements.md)（§2 の合格の基準は PO 承認済み・変えない）。関連: [design.md](./design.md) §28〜§32、`scripts/dev/doc-entry-weekly-check.sh`。
このリポジトリは公開されている。個人の決まり（`~/.claude`・`~/kb`）の本文は書き写さず、節の名前・行数・文字数だけを書く。
この設計を書いた環境からは `~/.claude` と `~/kb` の本文が見えない。見えないものは推測で埋めず「**未確認（Opus が手元で照合）**」と書く。数値はすべて要件 §3・§4 と design.md §28・§29 の実測値か、そこからの算出（算出のときは式を書く）。

## 0. 要約（PO 向け・日常語）

- 毎回読む決まりの束（7.2k）を、合格線（6.5k）の下へ下げる。やり方は「毎回読む目録」と「場面で開く本」に分ける。
- 最初の段は、返事の言葉の決まり（chat-format.md）が「読み込み」と「入力のたびの表示」で2回読まれているのを1回にする。これだけで 7.2k → 6.7k（要件 §3 で試した実測値）。
- 次に、担当の呼び方と git の手順（`~/.claude/rules/common/` の2本・計45行）を本へ移し、目録に1行ずつ置く。見込み 6.7k → 約6.1k（推定。式は §3）。
- 1段ごとに測り、合格線を超えたら戻す。`~/kb` の中を変える段は PO の承認と save.sh が要る（台本だけ書く）。
- 本が「無い・開かれなかった・読み違えた」の3つは、K12 の練習問題と同じ形で数えて表に残す（§8）。

## 1. 用語（この設計の中だけ）

| 語 | 意味 | 機械で見分ける印 |
|---|---|---|
| **目録** | 会話の始まりに毎回読まれるもの。`~/.claude/CLAUDE.md`、そこから `@` で取り込むもの、`~/.claude/rules/` の paths 無しの .md、リポジトリの CLAUDE.md・AGENTS.md（＝K1 の範囲） | K1 の範囲そのもの（weekly-check の `K1_FILES=`） |
| **本** | 場面で開くもの。`~/.claude/books/<id>.md`。目録の「本の目録」節に1行ずつ案内がある | 1行目から始まる frontmatter に `book: <id>` の行 |
| **表示** | UserPromptSubmit フック（`~/kb/scripts/hooks/plain-lang/hook.py`）が入力のたびに出すもの | フックが読むファイル（今は chat-format.md の「## 言葉の選び方」以降） |

代替（採らない）: Claude Code のスキル（`~/.claude/skills/<id>/SKILL.md`）。説明文が毎回読まれ、本文は使うときだけ読まれる（要件 §5）ので本の形に合うが、(a) スキルの説明文が /context の Memory files に入るかが**未確認**で K9 の見込みが立たない、(b) 説明文と目録の行が同じ内容の2か所になり L2 の数え方が濁る。段3 までで足りなければ、スキル化を次の一手として PO に見せる。

## 4. 要件 §8-2 L2 重複の数え方と、毎週の点検

### 4-1. 数え方（2本立て。どちらも読むだけ）

- **番号で数える**: 決まりごとに `[R-nn]` を見出し行に付ける（§1）。対象ファイル ＝ 目録（K1_FILES）＋ 本（`~/.claude/books/*.md`）＋ 表示（フックが読むファイル）＋ paths 付き rules。同じ `R-nn` が2ファイル以上に出た数 ＝ `L2_DUP_ID`。
- **文で数える**: 同じ対象ファイルの本文行を正規化（先頭の `-`・`*`・数字・空白を除き、全角空白を半角に、末尾の句点を除く）し、20文字以上の行が2ファイル以上に同一で出た数 ＝ `L2_DUP_LINE`。番号を付け忘れた写しを拾う。
- 除外: 目録の行（`^- 本:` で始まる）と frontmatter と見出しだけの行は数えない。`@` の行も数えない。除外は「ファイル:文言」の組で台帳に理由付きで書く（design §32 D1 の K3 と同じ流儀。語ごとの除外はしない）。
- L2 ＝ `L2_DUP_ID` ＋ `L2_DUP_LINE`。合格は 0。

番号の台帳は本文を含まないので、リポジトリに置ける: `docs/handoff/doc-agenda-nav/library-ledger.md`（列: `R-nn`｜節の名前｜所在（ファイル:見出し）｜種別（目録/本/表示/paths）｜移した段）。節の名前だけ書き、本文は書かない（要件の冒頭の決まり）。

### 4-2. 毎週の点検に入れる

- 新しいスクリプト `scripts/dev/doc-library-check.sh`（読むだけ。差し替えの口 `DOC_ENTRY_HOME` を weekly-check と共有）が `L2_DUP_ID=`・`L2_DUP_LINE=`・`L2=`・§5 の `L3_*` を1項目1行で出す。
- `doc-entry-weekly-check.sh` の K9 の後に `bash "$SELF_DIR/doc-library-check.sh"` を呼んで行をそのまま出し、`L2` が 0 でなければ `add_ng "L2=<数>"`、`L3_MATCH` が yes でなければ `add_ng "L3_MATCH=no"`。合格線（0・yes）はスクリプトの先頭に置く。
- 試験 `scripts/dev/test_doc_library_check.sh`（一時ディレクトリに偽の `~/.claude` と `~/kb` を作る。本物には触れない）: 同じ `[R-01]` が2ファイル → `L2_DUP_ID=1`／同じ20文字の行が2ファイル → `L2_DUP_LINE=1`／目録の行だけ同じ → 0／本が1つ多い → `L3_MATCH=no`。
- これは `scripts/` の変更（危険パス）なので PR 本文に `### GO記録`（ADR-136。GO は ADR-1003 により Opus 発行）。定期実行「入口の文書 週次点検」（design §32 D3）は同じスクリプトを呼ぶので変えない。
- 初回の実測で L2 が 0 でなかったときの直し方: 重複の2か所のうち、目録側を消して本側を残す（本が正本）。表示と目録が重なるときは目録側を消す（段1 がこの形）。

## 5. 要件 §8-3 L3 目録と本の突き合わせ

- 目録の行の集合 A ＝ `~/.claude/CLAUDE.md` の `^- 本:([a-z0-9-]+) .+ → (\S+)$` に合う行の `<id>` と `<path>`。
- 本の集合 B ＝ `~/.claude/books/*.md` の frontmatter `book: <id>`。
- 判定: `L3_INDEX=<|A|>`・`L3_BOOKS=<|B|>`・`L3_MATCH=yes` は「A と B の id が集合として等しい」かつ「A の各 path が存在し、その frontmatter の id が一致する」かつ「B の各本に `[R-nn]` が1つ以上ある」のすべてを満たすとき。1つでも欠ければ `no` と欠けた id を出す。
- 「本に移した決まりの数 ＝ 目録の行の数」（要件 L3）は、本1冊に決まりが複数入るので、そのままでは等式にならない。この設計では「本の数 ＝ 目録の行の数」で L3 を満たし、本の中の決まりの数は台帳（§4-1）の `R-nn` の数と `grep -c '\[R-'` の合計が一致することで確かめる（`L3_RULES_LEDGER=<台帳の数>`・`L3_RULES_FOUND=<grep の数>`）。等式の読み替えは PO に示して承認を得る（§11 の承認項目 P3）。
- K11（移した行が移した先に在るか。ADR-1040 維持の節・design §32 D5「今後また移すときはその段の設計に書く」）: 段ごとに、写しの元の行範囲と本の frontmatter 以降を `diff` して差 0。これは L3 と別に段の受入条件に置く（§9）。

## 7. 要件 §8-5 「本が無い／開かれなかった／読み違えた」を数える仕組み

§6 の外部事例（誤答を「未収録・検索で当たらない・答え方が悪い」の3つに分ける）の形だけを借りる。

| 分類 | 意味 | 数え方 | どこで数えるか |
|---|---|---|---|
| **無い** | 必要な決まりがどの本にも目録にも無い（目録の行が指す path が無い、台帳にあるのにファイルに `[R-nn]` が無い、も含む） | 機械: §5 の `L3_MATCH=no`・`L3_RULES_FOUND < L3_RULES_LEDGER`。人: 練習問題の正解の本が存在しない | 毎週（weekly-check）＋ 練習問題のとき |
