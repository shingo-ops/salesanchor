# Phase 1 KGI — 知らない機械からのログインを止める（ADR-1013 の続き）

状態: **PO 承認済み**（2026-11-01、PO が選択肢「1. この9つの基準で進める」を選んだ）。

## 目的（PO の言葉）

- 2026-10-31「MetaとかGoogleみたいに知らないデバイスから不審なろぐいんがあったらまず入れずに登録済みのデバイスから許可しないと入れない仕組みも必要、サーバー攻撃とか犯罪が増えてるから」
- 2026-11-01「目的は不正ログインやサイバー攻撃から守ること、メタの仕組みを真似して取り入れられる？」
- 順番: 顔・指紋ログインの名前付けより先にこちらを作る（2026-11-01 PO「1」）

## 合格の基準（PO 承認済み・○×で判定）

| # | 基準 | 検証方法 |
|---|---|---|
| K1 | 初めて使う機械では、パスワードが正しくても中に入れない。画面に「いつもの機械で許可してください」と出る | 本番で新しいブラウザ（記録の無い機械）からログイン → 画面と認証の記録 |
| K2 | いつものスマホかパソコンに、1分以内に知らせが出る。知らせには場所の目安・機械の種類・時刻が書いてある | K1 の時刻と知らせの表示時刻の差（秒）・表示の中身 |
| K3 | 「許可」を押すと、待っていた機械が入れる | 許可の後、待っていた機械の画面が中へ進む |
| K4 | 「拒否」を押すと、待っていた機械は入れない。ほかの機械もすべてログアウトする | 拒否の後、待っていた機械は入れず、別の機械が次の操作でログイン画面へ戻る |
| K5 | 一度許可した機械は、次からは聞かれずに入れる | 同じ機械で再ログイン → 許可待ちが出ない |
| K6 | 予備の合言葉10個のうち1個で入れる。同じ合言葉は2回目には使えない | 1個目で入れる・同じものを再入力すると拒否 |
| K7 | 合言葉も無い人は、しんごさんか担当エンジニアが管理画面で許可するまで入れない。その許可は記録に残る | 管理画面で許可 → 入れる・記録に許可した人と時刻 |
| K8 | ログインした場所の一覧に、日時・場所の目安・機械の種類が出る。見覚えのない機械は、その場でログアウトさせられる | 一覧の表示・ログアウト操作の後にその機械が締め出される |
| K9 | ログインの記録に、誰が・成功か失敗か・失敗の理由・初めての機械かが残る。パスワードは残らない | 認証の記録の列と値（読み取り専用の鍵で確認） |

## 最初から守ること（PO に提示済み）

- 全員に最初から効かせる（オンにし忘れる人を出さない）
- 仕組みを入れた日にログインしている機械は、いつもの機械として扱う（入れた日に全員が締め出されない）

## 調べて決めること（PO に「調べたあとに案を出す」と伝え済み）

- 新しく入った人が最初にログインするとき（いつもの機械がまだ無い）の扱い
