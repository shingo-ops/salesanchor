# design: 検索欄をお手本と同じ作りにする（便12a）

> この文書は何か（1行）: 閲覧ページ（/viewer/）のスマホの検索を、お手本（メルカリ）と同じ
> 「**押すと検索の画面に移る → 確定してはじめて一覧が絞られる → 語は札で残る**」作りにする。
> 打っている途中に出す**候補**は便12b（別便）。

**recon**: docs/handoff/viewer-search-mercari/recon.md
**土台**: `release/viewer-search-mercari`（`origin/main` = 4f3a6e471＝便11 #4821 を含む）

## ① 区分：A（見た目と操作の変更）

データの読み書きは変えない。変えるのは**スマホの検索の仕方**だけ。PC は1px も動かさない（4-6）。

## ② KGI（PO が実機で○×を判定できる粒度）

PO 指示「**検索欄をまず同じ作りに**」（2026-10-27）。同日の決定3件:
**①動きもお手本と同じ（確定するまで絞らない）②結果画面に「←」は付けない ③タップ直後は「最近使った語」**。

| # | PO が見て○×を言えること |
|---|---|
| K1 | 検索欄を押すと**別の画面に変わり**、キーボードが出る（左に「←」） |
| K2 | **打っただけでは一覧は変わらない**。キーボードの検索キーで確定すると絞られる |
| K3 | 絞ったあと、検索欄に「**語 ✕**」の札が出る |
| K4 | 札の**✕を押すと語だけ消えて入力待ちになる**（一覧は動かない＝お手本の実測どおり。recon §1b E3） |
| K5 | 一度検索したあとに検索欄を押すと、「**最近使った語**」が並ぶ。押すとその語で絞られる |
| K6 | **PC は今までどおり**（打つたびにその場で絞られる・検索画面は出ない） |

## ④ 設計（How）

### 4-1. 画面の出し方 ― 既存の `Drawer` に任意プロパティを1つ足す

**新しい画面の金型は作らない**。絞り込みと同じ `Drawer`（右から入れ替わる・便2 で PO 承認済みの作法）を使う。
ただしお手本は**上の帯の中に「←」と検索バーが並ぶ**ので、帯の中身を差し替えられるようにする:

```ts
/** 帯の題の代わりに置く中身。渡したときだけ題の <h2> を読み上げ専用にして、この中身を並べる */
headerContent?: ReactNode;
```

- **渡さなければ今までどおり**（題＋✕）＝`Drawer` を使う35ファイルは不変。
- 読み上げのために `aria-labelledby` が指す `<h2>` は**残したまま `sr-only` にする**（`frontend/src/components/sr-only.css`・便4 で共通化済み）。
  見た目から題が消えても読み上げ名は消えない。
- フォーカスの輪・Esc・`inert`・閉じたら元へ戻る、は `Drawer` が既に持っている（便2・C8・D5）。**作り直さない**。

### 4-2. 状態の分け方 ― 「打っている文字」と「確定した語」を分ける

いまは `query` 1つを絞り込みが直接見ている（`frontend/src/pages/viewer/InventoryView.tsx:73`・`:129`）。これを2つに分ける。

| 名前 | 何 | 絞り込みに使うか |
|---|---|---|
| `draft` | 検索画面で**打っている途中**の文字 | **使わない** |
| `appliedQuery` | **確定した語**（＝札に出る語） | **使う**（`useMemo` の依存をこちらに差し替え） |

- **PC は `draft` を使わず、今までどおり `appliedQuery` を直接書き換える**（打つたびに絞られる）＝ PC の動きは変わらない。
- 確定の道は2つ: **キーボードの検索キー**（`<form onSubmit>`・`enterKeyHint="search"`）と**「最近使った語」の行を押す**。
- 確定すると: 画面を閉じる → `appliedQuery` に入れる → ページを1に戻す → 履歴に積む。

### 4-3. 札（確定した語の見せ方）

結果画面の検索欄は、**スマホでは入力欄ではなく「押すと検索画面が開くボタン」**になる。中身は:

| 状態 | 中身 |
|---|---|
| 未確定 | 虫眼鏡 ＋ 薄い文字で `viewer.search.placeholder` |
| 確定済み | 虫眼鏡 ＋ **札「語」** ＋ 札の中の **✕** |

**押せるものを入れ子にしない**（HTML で禁止）。外側は `<div>`、中に「開くボタン（幅いっぱい）」と「✕ボタン」を**並べて**置く。
✕の押せる範囲は 44px 以上（ADR-140）。`aria-label` は「検索語を消す」。

**✕を押したときの動き（2026-10-28 に実機で測り直し・PO 決定「お手本と同じ」）**:
`appliedQuery` は**変えない**（＝一覧は1件も動かない）。`draft` を空にして**検索画面を開く**（＝入力待ち）。
お手本の実測は recon §1b の E3（語だけ消えて入力待ち・一覧は前の結果のまま）。
**← で閉じたときは `appliedQuery` の札が戻る**。お手本にはこの操作が無い（結果画面に留まるため）ので、
**画面の表示と一覧の中身を一致させる側**に倒した。

**検索画面を開いたときの中身（同 E9 で訂正）**: 語があるときは**語を入れた状態**で開く
（お手本は語があると候補が出るが、候補は便12b。本便は「最近使った語」を出す）。

### 4-4. 「最近使った語」の保存 ― 端末の中だけ

- 置き場: `localStorage` のキー `viewer:recent-searches`。**サーバーには送らない**（閲覧ページは誰でも見られるため）。
- 形: 文字列の配列。**新しい順・重複なし・最大10件**。
- 読み書きは `frontend/src/pages/viewer/recentSearches.ts`（新規・純関数＋localStorage の薄い包み）にまとめ、**単体テストで固定する**
  （`localStorage` が使えない環境では**黙って空配列を返す**。プライベートモード等で落ちないこと）。
- 見出しは「最近使った語」。**消す道**は見出しの右の「すべて消す」1つだけ置く。
  **お手本の実測（recon §1b E10）**: 行の右に ♡（48dp）と ⋮（48dp）があり、⋮ から1件ずつ消せる。
  また**語とそのときの絞り込み条件をセットで覚える**（2段の行）。
  **うちは語だけ・まとめて消すだけ**にする（行の作りを単純に保つ）。この差は分かったうえでの選択。

### 4-5. 寸法（お手本の実測をそのまま置く）

| 何 | 値 | 根拠 |
|---|---|---|
| 検索バーの高さ | 48px（既存 `--field-h-tap`） | お手本 48dp・便10 で導入済み |
| 検索バーの角丸 | `--radius-full`（9999px） | お手本はピル。社内の先例は受信箱のスマホ検索欄（`InboxPage.css:2116`） |
| 虫眼鏡 | **24px**・バーの左から16px | お手本 24dp。幅の余裕はある（便10 で山形を16pxにしたのは横幅が足りなかったため。ここは全幅なので制約が違う） |
| 「最近使った語」の行 | **69px**（新トークン `--comp-search-row-h`） | お手本 68.7dp。便12b の候補の行も同じ値を使う |
| 行の文字 | `--font-base`（14.4px） | お手本 17.7dp箱 ÷1.2 ≒ 14.8dp の最近傍 |
| 行の文字の左位置 | **64px** | お手本どおり（左の印が48px分） |
| 見出しの文字 | `--font-md`（16px 相当の既存トークンを採る） | お手本 19.7dp箱 ÷1.2 ≒ 16.4dp |

**虫眼鏡のアイコンは `frontend/src/constants/icons-base.tsx` に1行足す**（いまは `X` だけ・`MagnifyingGlass` は
`frontend/src/constants/icons.tsx` 側にあり閲覧ページからは読めない）。JS は数百バイト増。

### 4-6. 触らないもの（この便の境界）

| 触らない | 理由 |
|---|---|
| **PC の検索**（1280px） | 検索画面も札も**スマホだけ**。PC には「確定」という考え方が無いので、打つたびに絞る今の動きを残す |
| 打っている途中の**候補** | **便12b**（お手本では「打つと履歴が候補に入れ替わる」） |
| 絞り込みパネルの中身 | 便12（札の横並び・幅83%）。この便とは別 |
| アプリの `/inventory` | 横展開は閲覧ページが固まってから（ADR-1019） |

## ⑤ Acceptance Criteria

`B` は画面検査（本物の Chromium）。スマホは **360px と 390px の両方**、PC は 1280px。`U` は単体テスト。

| # | 基準 | 測り方 |

## ⑨ 外部・過去事例の参照と我々への応用

- **お手本（一次情報・2026-10-27 に実機で測り直し）**: recon §1。タップ＝履歴、入力＝候補の**2段構え**。
  初版の調査は「タップで候補」と誤って書いていた。**状態を3つに切り分けて機械で読む**ことで訂正できた
  （`uiautomator` の `search_hint_item` の件数と `dumpsys input_method` の `mInputShown`）。
  **お手本の調査は「押す前・押した後・打った後」を分けて測る**を型にする。
  2026-10-28 に同じやり方で**操作11手を1手ずつ**測り直し（recon §1b）、
  「札の✕で全件に戻る」という**設計時の思い込みも訂正できた**。
  **お手本の動きは、画面の絵ではなく『1手ごとの状態の差』で確かめる**。
- **社内の先例**: 受信箱のスマホ検索欄が `--radius-full` でピル型（`frontend/src/pages/inbox/InboxPage.css:2116`）。
  `Drawer` への任意プロパティ追加は便2（`onBack`・`onEscape`）と同型で、既定不変が守られている。
- **WCAG 2.5.5（Target Size）**: ✕ の押せる範囲は 44px 以上にする。

## ⑩ 弊害・トレードオフ

- **打っただけでは絞られなくなる**（スマホ）。確定を忘れると何も起きない。PO の決定（動きもお手本と同じ）に基づく。
  緩和: キーボードの確定キーを**虫眼鏡（検索）**にし、「最近使った語」をすぐ押せる位置に置く。
- **`Drawer` を1つ増やす**（絞り込み・シリーズ/並び替え・検索で3つ）。閉じていても DOM に残る金型なので、
  **`supplier-drawer` の testid が3つになる**＝検査は `.comp-drawer-panel--open` で絞る（便5 の教訓）。
- **履歴は端末の中だけ**。同じ人でも端末が変われば出ない。消す道は「すべて消す」1つだけ。
- **新規トークン1件**（`--comp-search-row-h`）。PR 本文のチェックリスト4項目が要る。
  **`色トークンは` など4つの語を本文の他の場所に書かない**（便11 で踏んだ罠。`check-new-tokens.js` は
  語が最初に現れた行だけを見る。しかも本文を直しても `gh run rerun` では直らず、**新しいコミットが要る**）。
- **便12b（候補）が入るまで、打っている最中は何も出ない**。お手本との差が一時的に残る。
