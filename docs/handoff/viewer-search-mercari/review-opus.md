## 3. 空振りでないか

- **B1〜B3・B5〜B8 は直す前が赤**（検索画面そのものが無かった）＝空振りの余地が無い。
- **B3 は「打っても件数が変わらない」を件数で測る**（見た目ではない）。B4 は「確定すると件数が1になる」。
  この2本が同時に成り立つことが、`draft`／`appliedQuery` の分離の証明になる。
- **B9（PC）は直す前も緑**なので、**PC で実際に1文字打って件数が変わること**を測る形にしてある。
- 単体は実装担当が**実際に壊して赤を確認**したと報告（「新しい順」を「末尾に追加」に替えると 3 failed）。
  審査側で確認したのは**テストの中身が3つの決まり（新しい順・重複なし・10件）を実際に assert していること**と、
  復元後に 133 passed であること。

## 4. 審査で直させた2点

1. **札の✕の動きがお手本と違っていた**。実装は「全件に戻す」だったが、実機の実測（recon §1b E3）は
   「**語を消して入力待ちにするだけで一覧は動かない**」。事実を PO に提示して「お手本と同じ」を受領し、
   `appliedQuery` を触らない形に直させた。検査 B6 も新しい意味に書き直させた。
2. **「最近使った語」の行に印が無かった**（64px の余白が空いているだけだった）。
   お手本は**左48dp に時計の印**（候補の行は虫眼鏡で描き分けている）。時計を追加させ、
   **文字の左端64px と行の高さ69px は動かさない**形（印は絶対配置）にさせた。B8 に「印が1つある」を追加。

## 5. 残る懸念（PR 本文にも書く）

- **打っている最中は「最近使った語」が出たまま**（お手本は候補に入れ替わる）。便12b で解消する。
- **履歴はお手本より情報が少ない**（語だけ・まとめて消すだけ）。お手本は語＋絞り込み条件を覚え、行ごとに消せる。
- **札の✕のあと「←」で閉じると札が戻る**。お手本にはこの操作が無いため、
  「表示と一覧の中身を一致させる」側に倒した判断（design 4-3 に明記）。
- **画面検査はこの端末では走らない**（Playwright のブラウザが入らない）。B1〜B9 は CI が初出。
- **未確認のまま残したお手本の挙動**（推測で埋めない）: 履歴の上限件数／候補の行の右端「→」／空のまま確定したとき。
  便12b の着手時に同じやり方（1手ずつ測る）で確かめる。
