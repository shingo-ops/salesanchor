# design: 状態の語で決まった状態の単位を優先する／分類「セット系」（便SU）

参照: docs/handoff/v102-unit-state-set/recon.md、docs/handoff/v102-unit-state-set/card-SU.md、ADR-158、ADR-157、ADR-1007。

## 1. 目的（PO の言葉、2026-10-11）
- 30th CELEBRATION 22,000円がパック →「ペリ無しなので Opened box が正解」「状態が決まっているのであれば自然と単位が決まる気がする」
- 「カテゴリに箱系、シングル系、ブックレット系と追加でセット系を足せば…セット系の単位なしの場合は単位をセットにする」「状態は記載がなければ sealed box」
- 440301 9種セット →「正解が『セット』y」

## 4. 代替案
- 状態の単位を常に優先: R4（語の無い既定）の状態にも効き、原文に書かれた「200セット」が箱に書き換わる → 語で決まった状態だけ。
- 「統一箱」を単位の別名に足す: 同じ行に「パック」もあり、どちらが採られるかが行の並びで変わる → 使わない。
- 440301 だけを特別扱い（商品別の単位）: 商品別の単位の仕組みが無い（product_quantity_units は 0行・未使用）→ 分類で扱う（PO 案）。

## 5. リスクと対処
- 語で決まった状態と書かれた単位が本当に違う商品（例「カートン（検品のため開封済み）」）: 現行で該当0件。単位を変えると便UP（相場との比）が値段の食い違いを要確認にする。
- 単位・状態が変わると（商品,状態）の組が移り、古い投稿の行が現行に浮上する（便BB の教訓）→ デプロイ・投入後に48時間以内の全ジョブを再解析する。
