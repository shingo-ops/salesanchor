# 設計：seed_product_marks migration の無効化（ADR-1006 の PR-0、2026-10-05）

状態：設計案作成済み／Opus 自己審査 APPROVE（§7）／PO 承認は ADR-1006 の方針（2026-10-05「1,はい」）に含まれる。migrations を変える危険な PR なので、マージには PO の「GO #番号」が要る（ADR-136）。

## 1. 目的（PO に見える変化）
- デプロイのたびに、商品マスタの mark（型番）が古い値に戻される問題を止める。
- 実例：2026-10-05 00:33Z に MEGAドリームex の mark を M2a に直した（PR #3968）。02:38Z のデプロイで M3 に戻された。

## 2. 現在地（recon.md の要約）
- `migrations/20260604_010000_seed_product_marks.sql:23-25` は、商品名が完全に一致する `public.products` の mark を上書きする（125組。今は110商品に当たる）。
- `scripts/run_all_migrations.sh:264` に登録されていて、`.github/workflows/deploy.yml:514` から毎回流し直される。
- 02:38:41Z に 110商品の updated_at が同じ時刻に書き換わった。audit_log には何も無かった（アプリを通らない書き込み）。
- 同じ種類の seed は、PR #3544（2026-09-18、13本）で無効化済み。この1本だけが漏れていた。

## 3. 既存の ADR との関係
- ADR-155：「マイグレーションは構造変更にのみ使用する。値の操作は禁止する」。この seed はそれに反している。#3544 と同じ無効化で、ADR-155 に寄せる（CLAUDE.md「ADR を優先し、実装を ADR に寄せる」）。
- ADR-1006：「実施順序」の PR-0 にあたる。

## 4. 変更
- `migrations/20260604_010000_seed_product_marks.sql`
  - ヘッダは残す。
  - 本文を #3544 と同じ NEUTRALIZED の印と `DO $$ BEGIN RAISE NOTICE ... END $$;` にする。
- `scripts/run_all_migrations.sh` の登録は残す。番号のずれを避けるためで、#3544 と同じ扱い。
- 触らない
  - ほかの migration
  - tenant_004 向けの 20260902_110100 と 20260903_180000（public.products に触らず、表が無ければ飛ばす）

## 5. 代替案と選んだ理由
- 登録から外す案：#3544 の前例と違う形になる。実行の記録との対応がずれるおそれがある。
- seed の中の MEGAドリームex の行だけを直す案：migration で値を持ち続けることになり、ADR-155 に反する。次の修正でも同じ書き戻しが起きる。

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| 新しい環境で、mark が入らない | mark は画面か CSV で管理する（ADR-155）。本番の今の値はそのまま残る（この変更は値を書かない） |
| 手元で SQL を流して確かめていない（書き込みを防ぐ仕組みが、手元の DB の試験も止めた） | 変更後の本文は RAISE NOTICE だけで、表に触らない。CI の Migration SQL Test で流れることを確かめる |

## 7. 受入条件と検証方法
| 基準 | 検証方法 |
|---|---|
| 変更後の migration が表に書かない | 差分の目視（追加は NOTICE だけ）と、migration-guard の Check 7・8 |
| CI の migration の試験が通る | PR の checks |
| デプロイの後で、mark が上書きされない | デプロイの後に、本番で products の updated_at が一斉に変わっていないことを読み取りで確かめる |
| MEGAドリームex を M2a に直し直したあと、次のデプロイでも M2a のまま | 直し直しの後の、2回目のデプロイの後に読み取りで確かめる |

## 8. 外部・過去事例の参照と我々への応用
- 外部事例：該当なし。社内の migration の運用の問題であり、外部の事例は判断に影響しない。
- 過去事例
  - PR #3544（2026-09-18）の無効化の形を、そのまま使った。
  - 2026-10-05 02:38Z の書き戻しは、#3544 で1本が漏れていたことから起きた。

## 9. 維持の仕組み
- 守り手: 設計担当（Opus）。public.products の値を書き換える migration が残っていないかを、ADR-1006 の実装（PR-1〜3）の前に一覧で確かめる。
- migration-guard の Check 7・8 は、新しい値の変更を止める。この1本は検査ができる前からある migration なので、検査に引っかからなかった。
