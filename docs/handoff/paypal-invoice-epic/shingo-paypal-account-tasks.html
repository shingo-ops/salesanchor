PayPal 正規請求書 — しんごさんにお願いしたい作業
（Inc3 追跡 / Inc4 ケース管理 の前提）

コード側（アプリ実装）は私（Hikky-dev）が進めます。
ここに挙げるのは PayPal のアカウント／開発者ダッシュボード上の設定で、しんごさんにしかできない作業です。

作成日: 2026-06-12 ／ 作成: Hikky-dev (Claude Code) ／ 対象: しんごさん（PayPal アカウント管理者）

PayPal 正規請求書（Invoicing）機能のうち、Inc1（請求書発行＋写しPDF）は本番稼働済みです。次の Inc3（発送追跡を PayPal に登録）と Inc4（トラブル＝ケースの自動受信）を動かすには、PayPal の開発者設定でいくつか有効化していただく必要があります。各項目に「なぜ必要か」「どこで」を添えています。

全体像： アプリのコードは「PayPal に命令を送る」側です。PayPal 側のアプリ（REST アプリ）が その機能を許可されていないと命令が通りません。下記はその「許可」と「通知の宛先設定」です。すべて developer.paypal.com/dashboard 上の作業です。

1REST アプリで「請求書(Invoicing)」機能を有効化

必須Inc1〜Inc4 共通

なぜ： 請求書の発行・送信・ステータス取得は Invoicing 機能の権限が要ります（無いと「送信」で失敗します）。

どこで（手順）

  1. Dashboard → Apps & Credentials を開く（本番は Live、テストは Sandbox タブ）。
  2. 当社が連携に使っている REST アプリを選ぶ。
  3. Features（機能）一覧で 「Invoicing」 にチェックが入っているか確認。無ければ有効化して保存。

※ すでに Inc1 が本番で動いているので Live 側は有効な可能性が高いですが、念のため確認をお願いします。

2REST アプリで「ケース管理(Disputes)」機能を有効化 — Inc4 用

必須（Inc4）

なぜ： 顧客とのトラブル（ケース＝dispute）の発生・更新・解決を当社アプリが受け取るには、REST アプリで Disputes 機能が有効である必要があります（公式要件）。

どこで（手順）

  1. 上記と同じ Apps & Credentials → 当社 REST アプリ → Features。
  2. 「Customer Disputes」（または Disputes） を有効化して保存。

3Webhook に「ケース(Dispute)イベント」を追加購読 — Inc4 用

必須（Inc4）アプリ側で自動登録も可

なぜ： ケースが起きたとき PayPal が当社サーバーへ通知（webhook）を飛ばすには、その種類のイベントを購読しておく必要があります。

購読してほしいイベント（3種）

  • CUSTOMER.DISPUTE.CREATED（ケース発生）
  • CUSTOMER.DISPUTE.UPDATED（ケース更新）
  • CUSTOMER.DISPUTE.RESOLVED（ケース解決）

どこで（2通り・どちらでも可）

  • A. しんごさんが手動： REST アプリの Webhooks で、通知先 URL https://api.salesanchor.jp/api/v1/integrations/paypal/webhook に上記3イベントを追加。
  • B. アプリに任せる： 当社アプリの「PayPal 認証情報 保存」時に webhook を自動登録する仕組みがあります。Inc4 実装後、私の方で購読イベントに上記3種を加えるので、管理センターで一度「保存」し直すだけでもOK（手動が不要になります）。実装が出来たら案内します。

※ 入金通知 INVOICING.INVOICE.PAID は既に購読済み・本番稼働中です。

4「発送追跡(Add Tracking)」の利用可否を確認 — Inc3 用

必須（Inc3）

なぜ： 発送時に追跡番号を PayPal に登録すると、資金保留の解除が早まり・未着クレームの自動解決やセラープロテクション判定に使われます（公式の実益）。これには PayPal 側で追跡 API（Add Tracking）が使える状態である必要があります。

確認してほしいこと

  • 当社 REST アプリ／ビジネスアカウントで Transaction Search / Tracking（trackers-batch） が利用可能か（権限・本人確認の状況）。
  • 不明な場合は PayPal サポート／アカウントマネージャに「POST /v1/shipping/trackers-batch を使いたい」と確認。

補足： Inc3 は当社の「発送」処理に PayPal 追跡登録を差し込みます。現在 FedEx 連携（発送系）をしんごさんが実装中のため、コード側はその発送フローと調整してから着手します（衝突回避）。この項目はその前提確認です。

5Sandbox テスト用アカウント（任意・動作確認用） — Inc4 検証用

任意（実機確認したい場合）

なぜ： ケース機能を本番前に確認するには、Sandbox で「買い手がケースを起こす」操作が要ります。これには Sandbox の買い手アカウント設定が必要です（公式の Integration Guide 記載）。

  • Sandbox → Accounts に買い手（Personal）アカウントがあるか確認。
  • Sandbox で支払い済みのテスト請求書に対し、買い手アカウントからケースを起こせると、Inc4 の受信→表示まで実機確認できます。

※ ここは無くても Inc4 のコード自体は完成・本番反映できます（実機の最終確認だけ後回しになります）。

✓チェックリスト（この順でOK）

  • ① Invoicing 機能が REST アプリで有効（Inc1 稼働中なので Live はほぼ済のはず・要確認）
  • ② Disputes（ケース）機能を REST アプリで有効化（Inc4 必須）
  • ③ Dispute webhook 3種を購読 — 手動 or 「保存し直し」で自動（Inc4 必須）
  • ④ Add Tracking 利用可否を確認（Inc3 必須・発送フロー調整後に着手）
  • ⑤ Sandbox 買い手アカウント（任意・ケース実機確認用）
私（Hikky-dev）側の進め方： ②③が済めば Inc4（ケース受信→請求書/受注に紐づけ表示）を本番投入できます。コードは先行して実装・PR まで進めておきます（マージには migration を含むため、しんごさんの GitHub 承認をいただきます）。Inc3（追跡）は④の確認＋発送フロー調整後に着手します。
