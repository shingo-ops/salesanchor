# design: Discord の知らせのチャンネルを種類別にまとめる

- 状態: PO 承認済み・実行済み（2026-11-21 21:15〜21:20 JST）。方向は 2026-11-21 PO「1」（3 つにまとめる）、実行は同日 PO「1」（同意票の操作を実行する）。
- 根拠: `docs/handoff/discord-channel-consolidation/recon.md`（以下 recon）。
- 関連 ADR: ADR-1039（前の受付をやめる・:34）、ADR-1025（誤り報告チャンネル・:24-25・Proposed）、ADR-1012（24 時間保守）。

## 1. 目的（KGI）
PO が Discord の「アラート」分類を開いたとき、すぐ見る知らせ（急ぎ）と、あとで読めばよい知らせ（定期の報告）が別のチャンネルに分かれている。

## 2. 対象と対象外
- 対象: Sales Anchor サーバーの「アラート」分類の 7 チャンネル、送り口 8 個、GitHub の `DISCORD_WEBHOOK_SCHEDULED_REPORT`、Mac の前の受付の番人。
- 対象外: 別の Discord サーバーに届く知らせ（PR・CI・PLAN_REVIEW・レビューのメール。Bot が入れず中を確かめられない・recon §3）。会社ごとの通知（アプリの中の設定・DB）。「全体」「チケット」分類。ログイン失敗の鳴り方（別の作業で 11/21 18:20 以降に本番へ出す）。コードの変更（今回は 0 行）。

## 3. 変更前 → 変更後
| 今のチャンネル | 変更後 | 届くもの |
|---|---|---|
| サーバー監視アラート | 名前を「🚨急ぎ」に変える（id はそのまま） | 見張りの発火と解消・Uptime Kuma・さくらのメール・画面点検の不合格・反映の止まり／戻し・FedEx の失敗 |
| 運用アラート | 名前を「📋定期の報告」に変える（id はそのまま） | アプリの毎日・毎週の点検・GitHub の週次と月次の報告・Mac の見張り・kb 見回り |

| 画面点検調査報告・approval-test・検証用サーバーのテストチャンネル | 新しい分類「使っていない（12/5 に消す）」へ移す | 何も届かなくなる |

## 4. 手順（1 つずつ。各手順の後に確かめる）
1. 前の受付の番人を止める: `launchctl bootout gui/$(id -u)/jp.salesanchor.ops-intake-watchdog`、plist を `~/Library/LaunchAgents/disabled/` へ移す（消さない）。根拠: ADR-1039 :34。
2. 送り口「API接続障害」を サーバー監視アラート へ付け替える（Bot で `PATCH /webhooks/1544914720987807804` の `channel_id`）。URL は変わらないので secret は触らない。
3. 送り口「approval-test」を 運用アラート へ付け替える（同 `PATCH /webhooks/1559254844735361134`）。
4. GitHub の `DISCORD_WEBHOOK_SCHEDULED_REPORT` を、運用アラートの送り口の URL に入れ替える。値は prod1 の `ADMIN_NOTIFICATION_DISCORD_WEBHOOK` を ssh の標準出力から `gh secret set` の標準入力へ直接渡す（画面・ファイルに出さない）。
5. 名前の変更: サーバー監視アラート →「🚨急ぎ」、運用アラート →「📋定期の報告」。
6. 分類「使っていない（12/5 に消す）」を作り、3 チャンネルを移す。消すのは 12/5 以降に PO の確認を取ってから（消すと戻せない）。

## 6. 代替案と選んだ理由
- 新しいチャンネルを作り、全部の送り口を移す: 前の投稿が残らず、読む側の id も直す必要がある。採らない。
- 名前を変えて id を残す（採用）: 読む側も送り口の URL も変わらない。戻すのは名前を戻すだけ。
- 送り元ごとに分ける（PO が選ばなかった案 2）: 採らない。
- Mac の見張りの異常だけ「急ぎ」へ分ける: Mac の台本に 2 つ目の送り口を足すコード変更が要る。お客様に影響しない知らせなので今回は定期の報告にまとめる。要るなら別の作業にする。

## 7. リスクと対処
- secret の入れ替えを間違えると週次報告が届かない → 手順 4 の直後に `gh workflow run .github/workflows/weekly-stale-pr.yml` を 1 回流し、定期の報告に届くのを読む。
- 名前の変更がチャンネルごとの権限で止められる → Bot の返事を見て止まり、PO に Discord の画面での操作を頼む。
- 番人を止めると前の受付が止まっても気づけない → 前の受付は ADR-1039 でやめると決まっている。今の受け口は agent-console 側で見張る。

## 8. 戻し方
- 手順 1: plist を戻して `launchctl bootstrap`。
- 手順 2・3: `PATCH /webhooks/{id}` で元の channel_id（recon §2）に戻す。
- 手順 4: `DISCORD_WEBHOOK_SCHEDULED_REPORT` を prod1 の `DISCORD_WEBHOOK_URL`（元と同じ送り口・recon §3）で入れ直す。
- 手順 5・6: 名前と分類を元に戻す。
