# 設計 — 受信箱のドラッグ&ドロップ添付

> この文書は何か（専門用語なしの1行）:
> 画像を画面に落とすだけで添付できるようにするための作り方。

対象ADR: ADR-091
recon: docs/handoff/inbox-drag-drop-attach/recon.md
親テーマ: docs/specs/attachment-storage/README.md

## 1. あるべき姿

顧客とのやり取りに必要な操作が、少ない手数で終わる。

## 2. recon（実測）

docs/handoff/inbox-drag-drop-attach/recon.md を参照。要点は次の3つ。

- ファイル選択の処理は既にある。ドラッグ&ドロップだけが無い。
- スレッドのルート要素は main で、position の指定が無い。
- オーバーレイの前例が同じCSSファイルにある。

## 3. design（技術How）

PO決定（2026-09-04）は次の5点である。

1. スレッド全体を対象にする
2. ドラッグ中はオーバーレイを出す
3. ここにドロップという表示を出す
4. どこに落としても添付される
5. 画面外に出るとオーバーレイが消える

main 要素に4つのハンドラを付ける。
ドラッグ中だけオーバーレイを表示する。

落としたファイルが画像であれば、
既存のファイル選択と同じ処理に流す。画像以外は無視する。

オーバーレイは position: absolute でスレッド内に限定する。
画面全体を覆う fixed は使わない。

## 4. 外部・過去事例の参照と我々への応用

dragleave は子要素をまたぐたびに発火する。
子要素の上を通過するだけでオーバーレイが消えてしまうため、
出入りの回数を数えて 0 になったときだけ消す方法が広く使われている。

本設計もその方法を採る。

また dataTransfer の types に Files が含まれるかを見て、
テキストの選択範囲をドラッグした場合などを除外する。

我々への応用: ドラッグ中の状態は入れ子の要素で乱れやすい。
数え上げで管理し、ドロップ時には必ず 0 に戻す。

## 5. 弊害・トレードオフ

- 弊害: 複数のファイルを落としても最初の1つだけを受け取る。
  既存のファイル選択も1つだけであり、挙動を合わせた。
- 弊害: オーバーレイはスレッド内に限定される。
  画面の外側に落とした場合は反応しない。
- トレードオフ: pointer-events を無効にしてオーバーレイを通過させる。
  オーバーレイ自体がドロップを受けるのではなく、
  下の main 要素が受ける形にした。

## 6. 受入基準

| 基準 | 検証方法 |
|---|---|
| ドロップ処理がある | grep で handleDrop が2件以上 |
| ドラッグ状態を持つ | grep で dragActive が4件以上 |
| オーバーレイがある | grep で inbox-drop-overlay が JSX と CSS に各2件 |
| 基準位置を指定する | grep で position: relative が1件以上 |
| 翻訳キーがある | grep で dropImageHere が日英に各1件 |
| JSON が壊れていない | python3 の json.load が例外を出さない |
| useInboxState を変更していない | git diff に当該ファイルが現れない |
| 実環境で動く | 画像をスレッドに落として添付されることを確認する |

## 7. 維持の仕組み

- 守り手: 人手で守る
- 理由: ドラッグ&ドロップは実ブラウザでの操作を伴い、
  現在のテスト基盤では再現できない。
- 対象: 落としても添付されなくなること。
  オーバーレイが消えなくなること。
- 検知方法: PO による実機確認。画像をスレッドに落として動作を見る。
