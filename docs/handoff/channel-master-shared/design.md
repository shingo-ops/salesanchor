## 2. 新しい表 `public.channel_masters`（migration・形だけ）

```sql
CREATE TABLE IF NOT EXISTS public.channel_masters (
    id                 INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id          INTEGER NULL REFERENCES public.tenants(id) ON DELETE CASCADE,  -- NULL=共用（運営が管理）
    platform           VARCHAR(50) NOT NULL,        -- leads.channel_type 等に入る値
    display_name       VARCHAR(100) NOT NULL,
    connection_type    VARCHAR(10) NOT NULL CHECK (connection_type IN ('auto','manual')),
    conversation_store VARCHAR(20) NOT NULL CHECK (conversation_store IN ('meta_messages','conversation_logs')),
    is_verbatim        BOOLEAN NOT NULL DEFAULT TRUE,  -- 会話の文がお客さんの原文か（電話・対面は要約なので FALSE）
    conversion_item    VARCHAR(30) NULL CHECK (conversion_item IN ('baseline','channel_whatsapp','channel_instagram')),
    is_active          BOOLEAN NOT NULL DEFAULT TRUE,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT channel_masters_item_shared_only CHECK (tenant_id IS NULL OR conversion_item IS NULL),
    CONSTRAINT channel_masters_tenant_manual_only CHECK (tenant_id IS NULL OR connection_type = 'manual')
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_channel_masters_shared_platform ON public.channel_masters (platform) WHERE tenant_id IS NULL;
CREATE UNIQUE INDEX IF NOT EXISTS uq_channel_masters_tenant_platform ON public.channel_masters (tenant_id, platform) WHERE tenant_id IS NOT NULL;
CREATE UNIQUE INDEX IF NOT EXISTS uq_channel_masters_conversion_item ON public.channel_masters (conversion_item) WHERE conversion_item IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_channel_masters_tenant_id ON public.channel_masters (tenant_id);
```

- RLS は ADR-145 の4つの守り（SELECT: NULL行＋自社行／INSERT・UPDATE・DELETE: NULL行は `app.is_operator='true'` だけ・会社行は自社だけ）を、表名だけ変えて写す（`migrations/20260626_130000_force_rls_public_products.sql:5-38`）。ENABLE と FORCE の両方。
- 会社を消したときの片付け: 会社の物理削除は `public.tenants` の行を消す（`backend/app/routers/super_admin_tenants.py:105` の関数の「public.tenants DELETE（CASCADE）」の段）。2つの新しい表の `tenant_id` に `REFERENCES public.tenants(id) ON DELETE CASCADE` を付け、会社行と隠す設定が一緒に消えるようにする（前例 `migrations/20260604_080000_create_registration_tokens.sql:8`）。FORCE RLS の下でも連鎖で消えることは §5 の PG 試験で確かめる（2回目の審査で未確認だった点）。
- `conversion_item` を共用行だけに限る理由: 成約の分析は15項目で固定（`backend/app/services/lead_conversion_factors.py:70-87`）。会社が足した手段で項目が増減すると、分析の形が会社ごとに変わるため。
- 会社行を manual だけに限る理由: 自動で取り込む手段は連携の部品が名前を書くため、会社が足しても届かない（今の POST も manual 固定 `backend/app/routers/conv_logs.py:508-510`）。

## 2-2. 会社ごとの「隠す」設定（D1 の PO 回答）

- PO 回答（2026-11-06 原文）: 「2,管理センター側で設定画面を設けてそこで設定できるようにする」
- 置き場: 名簿の行は写さない。会社ごとの「隠す」だけを別の表に1行で持つ（値は名簿1か所・設定は設定1か所）。

```sql
CREATE TABLE IF NOT EXISTS public.channel_master_tenant_settings (
    tenant_id          INTEGER NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
    channel_master_id  INTEGER NOT NULL REFERENCES public.channel_masters(id) ON DELETE CASCADE,
    is_hidden          BOOLEAN NOT NULL DEFAULT FALSE,
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by_user_id INTEGER NULL,
    PRIMARY KEY (tenant_id, channel_master_id)
);
```

- RLS: SELECT・INSERT・UPDATE・DELETE とも自社の行だけ（`tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::INTEGER`・ADR-145 の書き方 `migrations/20260626_130000_force_rls_public_products.sql:12` にそろえる）。ENABLE と FORCE。PR-A で名簿の表と一緒に作る。
- 他社の行を指せないようにする: INSERT・UPDATE の WITH CHECK に `EXISTS (SELECT 1 FROM public.channel_masters cm WHERE cm.id = channel_master_id AND cm.connection_type = 'manual' AND (cm.tenant_id IS NULL OR cm.tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::INTEGER))` を足す。API の `set_hidden` も同じ条件で行を探し、無ければ 404。試験（§5）に「B社の行の番号で隠すと 404、DB へ直接入れても RLS で拒まれる」を足す。
- 行が無い＝隠していない。本番の初期値は0行（今隠している会社は0・recon §4）。データ変更は要らない。
- 隠せる行: 手入力の行（共用の電話・対面・WhatsApp と、会社が足した行）。自動で取り込む Messenger・Instagram・Discord は隠せない（届く会話は連携の部品が書くため、隠しても届き続け、画面と食い違う）。API は auto 行に 400。
- 会社が足した行の「消す」（is_active=false）は今のまま残す。「隠す」は戻せる切り替え、「消す」は名簿からの取り下げ。
- 設定画面: 管理センターの「チャネル設定」（`frontend/src/pages/management-center/ManagementCenterPage.tsx:83` の channel-masters・`frontend/src/App.tsx:407` で `frontend/src/pages/admin/ChannelMastersPage.tsx` を出す）に「この会社で使う」の切り替えを各行に置く。部品は金型 `frontend/src/components/Toggle.tsx`（ADR-144）。見出しと説明は i18n キー `channelMasters.visible`・`channelMasters.visibleHelp` を ja/en 同時に足す（ADR-027）。
- 変えられる人: 画面を開ける人と同じ `tenant.profile.edit`（`frontend/src/pages/management-center/ManagementCenterPage.tsx:83`）。API にも `require_permission("tenant.profile.edit")`（`backend/app/auth/dependencies.py:589`）を付ける。
- 事実（2026-11-06）: 今の追加・無効化の API（`backend/app/routers/conv_logs.py:491-518`・`:524-557`）は、ログインしていれば権限を見ずに通る（`get_current_user` と `get_current_tenant` だけ）。自社の名簿の中に限られるが、PR-B で同じ権限を付けて閉じる。
- 隠した行の効き目: §9 D1-2 の PO 回答で決める。今の「消す」がどこまで効くかの事実は recon §6。
