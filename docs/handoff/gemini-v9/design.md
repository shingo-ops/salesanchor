### 2-1. 価格の無い件は違反ではなかった（訂正）
- 機械点検の「範囲に価格の行が無い件」（minimal 71件、high 113件）を、1件ずつ分類し直した。
- 当初は違反として PO に報告したが、内訳は次のとおりで、ほぼすべてが正しい書き出しか、点検の側の見落としだった。

| 内訳 | minimal | high |
|---|---|---|
| 「完売」「残り」「在庫」の言葉を持つ件（梱包違いの完売など） | 52件 | 111件 |
| 「残28」のように、「残」の後に数字が続く件 | 2件 | 0件 |
| 価格の行なのに、点検の規則（円・@・¥・×）に当たらなかった件（「単価：468,000」など） | 16件 | 2件 |
| 範囲の誤り（価格の行を範囲に入れていない） | 1件 | 0件 |
| 計 | 71件 | 113件 |

- 例として、ある投稿では「◆商品名」の下に「完売」の行があり、その次に「パック@160円」の行がある。
  - Gemini は、これを2件に分けた。1件目は price が none で state が「完売」（BOX が完売という意味）、2件目はパックの件。
  - もし「完売」を、パックの件の注記として範囲に含めていたら、売っているパックを完売と誤って判定する。
- よって、価格の無い件を減らす修正はしない。PO の決定①（完売は書かれた欄に写し、システムが拾う）にも合う。
- v9 では、今の書き出し方を指示書に明文化する（§3）。
  - 「完売」だけの行は、ほかの価格の行の注記にしない。

原因（事実）は2つ。
- 発送について、指示書は「その件の行か見出し」に限っている（raw_copy_v8.txt:13）。区切りの行の扱いが書かれていない。
- 発送について、指示書は「その件の行か見出し」に限っている（:13）。区切りの行（【大阪発送】のように、複数の商品の上にまとめて書かれた発送の行）の扱いが書かれていない。目視では、Gemini はこの行から写していた（目視シートの9・34）。
- 取り込みは、範囲がどの件の見出しの範囲と重なっても、その件を捨てる（gemini_raw_copy_v8.py:308-317）。そのため、商品名と価格が同じ行にある書き方は必ず落ちる。

## 3. 指示書 v9（backend/app/prompts/raw_copy_v9.txt として新規）
v8 との違いは「1件の決め方」の2行、state・ship・source・heading の各欄、新しい欄 state_line・ship_line、例4〜例6。
```
あなたは書き写し担当です。判断・推測・補完・言い換え・翻訳はしません。
入力は LINE の投稿本文で、各行の先頭に行番号（例 [L0001]）が付いています。
価格が書かれた行を1件として、指定の JSON 形式で書き出してください。

【1件の決め方】
- 価格が書かれた行ごとに1件です。同じ商品の下に価格の行が複数ある場合（状態違い・梱包違いなど）は、それぞれを別の1件にします。
- 商品（梱包違いを含む）に価格が無く、「完売」「残りN」などだけが書かれている場合は、price を none にして1件として書き出します。その言葉は書かれている欄（例「数量：完売」なら quantity）に写し、欄が分からない単独の「完売」は state に写します。
- 「完売」だけの行は、その前後にある価格の行の注記にしません（価格のある件の範囲に含めません）。
- 送料・転送料・連絡事項など、商品ではない行は書き出しません。

【各欄】
- product_name：その件の商品名を原文のまま写す。価格の行に商品名が無い場合は、その上にある商品名の行（見出し）から写す。
- price, quantity, unit：その件の範囲の行に書かれている文字を、そのまま写す。書かれていなければ none。単位を推測で補わない。
- state：その件の範囲の行か、その件の見出しの行に書かれた状態の言葉（例：シュリ無し、未開封、状態A-）を写す。BOX・カートン・セットなどの梱包や単位の言葉は、state に写さない。無ければ none。
- state_line：state を写した行の番号。state が none なら null。
- 「完売」「残りN」などは、書かれている位置の欄にそのまま写す（在庫の判定はしない）。
- ship：その件の範囲の行、その件の見出しの行、または区切りの行に書かれた発送の情報を写す。区切りの行とは、複数の商品の上にまとめて置かれた発送の行（例：【大阪発送】【9/28発送】）で、次の区切りの行までの件にかかる。投稿全体の注意書き（例「14時までのご注文で当日発送」「100BOX以上で送料無料」）は写さない。無ければ none。
- ship_line：ship を写した行の番号。ship が none なら null。
- source_line_start / source_line_end：その件の価格の行と、その件だけに付く注記の行の範囲。その件だけに付く注記の行は、価格の行の前にあっても後ろにあっても範囲に含める。商品名の見出しの行、区切りの行、ほかの件の行は含めない。
- heading_line_start / heading_line_end：商品名を写した見出しの行。商品名が価格と同じ行にあるとき、または見出しが無いときは null。
- multi_note：1つの行の中に同じ種類の値が2つ以上ある場合（例：1行に2つの価格）だけ使い、その値を原文のまま「／」でつないで写す。それ以外は none。

【例】
（例1〜例3は v8 と同じ。各件に "state_line" と "ship_line" を足す。例1の state_line は 427 と 429、例3の2件目の state_line は 15。それ以外は null）
```

## 5. 受け取り（parse_v9_response）
v8 の検査（必須の欄・型・範囲・見出し・重なり）に、次の3つを足す。
- I-1：見出しの範囲が自分の範囲と同じなら（商品名と価格が同じ行）、見出しを null として受け取る。
  - この件の見出しは、ほかの件との重なりの検査の対象にも入れない。
  - 見出しが自分の範囲と一部だけ重なる場合は、v8 と同じく捨てる。
- I-2：state_line と ship_line の検査。
  - 型は、整数か null。違えば件を捨て、理由を記録する。
  - 値が none なのに行番号がある場合は、件は残す。行番号を null にして、理由を記録する。
  - 値があるのに行番号が null の場合は、値を確かめられない。件は残し、その欄の値を none にして、理由を記録する。
  - 行番号は 1〜行数の内側であること。外なら、件は残す。その欄の値を none、行番号を null にして、理由を記録する。
- I-3：値と原文の照合。
  - state・ship の文字（NFKC で正規化し、空白を除く）が、書かれた行番号の行（同じく正規化）に含まれていなければ、件は残す。その欄の値を none、行番号を null にして、理由を記録する。
- 戻り値の形は v8 と同じ (items, errors)。
  - items のキーは、v8 のキーに raw_state_line と raw_ship_line を足したもの。
  - 件を残して値だけ空にした場合は、errors に {"index", "error", "item", "kept": True} を入れる。件を捨てた場合の errors は、v8 と同じ形にする（kept のキーを持たない）。
