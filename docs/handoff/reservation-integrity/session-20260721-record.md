## 2. 幽霊台帳の掃除（reservation-integrity 段A）
- 幽霊の正体: マージ済み/削除済みブランチが本体active-work.mdにIN_PROGRESSで居残る「剥がし忘れの残骸」。
- 供給源: reaper-worktree.shがworktree存在ブランチのみ走査し、worktreeなき残骸を掃除しない盲点。
- 実在照合ロジック（試作・全数実測）: IN_PROGRESS行を「実在×未マージ=本物／消滅・マージ済み=幽霊」に全数仕分け。本物26件は複数回測定で不変。
- 段A実掃除: PR #3023でIN_PROGRESS 91→27（幽霊64件をDONE化）。mergeCommit 43852f14・ANCESTOR=OK。本物欠落0・行削除0を検算。他セッション停止＝台帳凍結下で一発着地・MERGE_RETRY発火0。
- 重要発見: 本体active-work.mdは既に「凍結アーカイブ（新規登録廃止・分割台帳active-work.d/へ移行）」化済み。幽霊の新規供給は構造上停止しつつある。

## 3. 未完・次セッション最優先（段B=再発防止）
- reaperの盲点修理: worktreeなき残骸を実在照合で自動DONE化する機能をreaper-schedule.ymlに載せる。
- 本体台帳の残IN_PROGRESS 27件の経過監視。
- 経時観測: 掃除後に幽霊が再増殖しないことを数日おきにtrack-recordへ記録し「再発しない」を実証（時間軸の証拠・1セッションでは取得不能）。
- コンフリクト対策: 本体台帳直接編集はコンフリクトを生む（#3023で実測）。掃除は競合しない自動方式へ寄せる。

## 4. 本日の重大な学び
- 「配備≠完了」: scripts/ワークフローを置いただけでは完了でない。動作を実測した生ログがあって初めて完了。
- 動く共用ファイルへの書き込みは、他セッション停止で的を止めれば一発で通る（#3023着地で実証）。
- 恒久化候補: 「動作実測ゲート（proof-of-behavior）」=scripts/.github/workflows変更PRに動作実測欄を必須化する関所（未起票・次テーマ）。
