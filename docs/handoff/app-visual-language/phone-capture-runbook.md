# スマホでのベンチマーク記録 手順書（段階2の準備）

> この文書は何か（専門用語なしの1行）: スマホの中の Claude Code が、WhatsApp と Meta Business Suite の画面を安全に記録し、数値だけの観察メモをPRにするための手順書。

親: [design.md](../../specs/design-system/visual-language/design.md)（§5） / 合格条件: [kgi.md](../../specs/design-system/visual-language/kgi.md)

- 状態: PO合意済み（2026-10-05）。内容は、設計パートナーの提示した条件5つに PO が「y」と回答したもの。
- 担当: スマホ（Android）の Termux で動く Claude Code。以下「スマホ担当」と書く。
- 確認役: Mac 側の設計パートナー（Opus）。PR のマージ前に中身を確認する。

## 0. 絶対に守ること（1つでも破りそうなら止めて報告）
1. **元データ（写真・構造データ・録画）を Git に入れない。** 顧客の名前やメッセージ本文が写るため。PR に入れてよいのは観察メモ（数値と画面の構造）だけ。
2. **観察メモに、人の名前・メッセージ本文・電話番号・メールアドレス・アカウント名を書かない。** 部品の種類・大きさ・位置・数・画面のつながり・タップ数だけを書く。
3. **文字の入力をしない。** `adb shell input text` は使用禁止。キーボードを開く操作もしない。
4. **押してよい操作は、次の4つだけ。**
   - 一覧の項目を開く
   - 戻る
   - 下部タブ・上部タブを切り替える
   - メニュー（︙ など）を開いて、何も選ばずに閉じる
5. **押してはいけないもの。** 送信・削除・転送・アーカイブ・ブロック・通話・録音（マイク）・長押しメニューの中の項目・設定変更・ログアウト。長押しは、メニューを表示させて撮影するためだけに使ってよい。表示させたら、項目は選ばずに「戻る」で閉じる。
6. **最初は1画面だけ試す（§3）。** 結果を報告して、PO または設計パートナーの続行の指示を受けてから次へ進む。
7. **PR をマージしない。** マージは、Mac 側で中身を確認してから行う。
8. 迷ったら止める。止めたときは、事実（コマンドとその出力）だけを報告する。

## 1. 準備（PO が行う）
1. スマホの設定を開き、開発者向けオプション → ワイヤレスデバッグ をオンにする。
2. 「ペア設定コードによるデバイスのペア設定」を開いたままにする。画面に IP・ポート・6桁のコードが出る。
3. Termux で、GitHub に `shingo-cc` 名義でログインする（`gh auth login`）。鍵をスマホに置くことは PO が判断済み。

## 2. 道具の確認（スマホ担当）
公式資料で確認済みのコマンドと、まだ確認していないコマンドを分けて書く。確認していないものは、使う前にスマホ上でヘルプを出して確かめる。

| 用途 | コマンド | 確認状況 |
|---|---|---|
| adb を入れる | `pkg install android-tools`（Termux 本体で実行する。Ubuntu の中では実行しない） | パッケージ名は termux-packages で確認済み（android-tools 37.0.0）。コマンドの文言は未確認 |
| ペア設定 | `adb pair <IP>:<ペア用ポート>` を実行し、聞かれたらコードを入力する | 公式で確認済み（developer.android.com/tools/adb。Android 11 以上） |
| 接続 | `adb connect <IP>:<接続用ポート>`（ペア用とは別のポート）→ `adb devices` | 公式サンプルで確認済み（AOSP adb_wifi.md） |
| 画面写真 | `adb exec-out screencap -p > <名前>.png`（-p は PNG 形式の意味） | 公式で確認済み |
| 録画 | `adb shell screenrecord --time-limit 30 /sdcard/<名前>.mp4` → `adb pull`（上限は180秒） | 公式で確認済み |
| 部品の構造 | `adb shell uiautomator dump /sdcard/<名前>.xml` → `adb pull` | **未確認**。使う前に `adb shell uiautomator help` の出力を記録する |
| タップ・戻る | `adb shell input tap <x> <y>` ／ `adb shell input keyevent 4`（戻る） | **未確認**。使う前に `adb shell input` の使い方の表示を記録する |
| スマホ自身への接続 | Termux から、同じ端末のワイヤレスデバッグに接続する | **公式資料なし（未確認）**。§3 で実際に試して確かめる |

## 3. 最初の1画面の試し（スマホ担当）
1. §2 の未確認のコマンドについて、ヘルプの出力をすべて記録する。
2. PO が WhatsApp を開いて、受信箱の一覧を表示しておく。
3. 画面写真と部品の構造を1回ずつ撮る。
4. 次の3つを報告して止まる。
   - 写真が黒くないか（ファイルサイズと、画面に写っているものの説明。名前は書かない）
   - 構造データに部品が出ているか（要素の数）
   - 接続できたか（`adb devices` の出力）
- どれか1つでもダメなら、そこで止める。

## 4. 記録する画面（続行の指示が出てから）
WhatsApp と Meta Business Suite のそれぞれで、次の状態を1件ずつ記録する。
1. 受信箱の一覧（未読あり／検索中／絞り込み中）
2. 会話の画面（送信・受信・画像・日付の区切り。テスト用の会話を推奨）
3. 入力欄（何も入力しない状態／添付メニューを開いた状態）
4. 長押しメニュー（表示して撮るだけ。項目は押さない）
5. 連絡先の詳細画面
6. 下部タブ・上部バー・戻る操作の流れ（録画）
7. タップ数。「会話を開く」「別の会話に移る」を、何回のタップで終わるかを数える。送信を伴う操作は数えるだけにして、実行しない

## 5. 観察メモの書き方
- 置き場所: `docs/specs/design-system/visual-language/benchmark/<アプリ名>-<画面名>.md`
- 書く内容（数値はすべて構造データから計算する。目で見た推定値は書かない）:
  - 画面の幅と高さ（px）
  - 部品ごとの種類・位置・幅・高さ・部品間の余白
  - 押せる部品のうち 48dp／44px 未満の数
  - 文字の高さ（構造データの文字の枠の高さ）
  - 画面のつながり（どこを押すとどこへ行くか）
  - タップ数
- 書いてはいけないもの: §0-2 のとおり（人の名前・メッセージ本文・電話番号・メールアドレス・アカウント名）。
- 色: 写真の画素値から読み取った値だけを書く。読み取ったコマンドも一緒に書く。

## 6. PR の出し方（スマホ担当）
1. `git fetch origin main` → `git switch -c release/app-visual-language-benchmark-<日付> origin/main`
2. 観察メモだけを追加する。`git status` で、元データ（png・xml・mp4）が含まれていないことを確認し、その出力を PR に貼る。
3. コミットメッセージの最後に `Co-Authored-By: Claude <noreply@anthropic.com>` を付ける。
4. `gh pr create --base main --draft` で出す。本文に書くもの:
   - 対象ADR: ADR-144
   - recon: docs/handoff/app-visual-language/recon.md
   - 設計: docs/specs/design-system/visual-language/design.md
   - 触るファイル: 追加した観察メモの一覧
   - 削除するファイル: なし
5. マージはしない。PR の URL を PO に伝える。
6. 元データは、PR がマージされたあとに削除する。それまではスマホ内の専用フォルダ1つにまとめておく。

## 7. Mac 側の確認（設計パートナー）
- 観察メモに、§0-2 で禁止した情報がないかを読んで確認する。
- 数値に、それを出したコマンドが添えられているかを確認する。
- 問題がなければ、CI が緑になったあとにマージする。問題があれば PR にコメントして、スマホ担当に修正を依頼する。
