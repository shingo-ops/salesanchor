## 4. 外部・過去事例の参照と我々への応用

Python の import は実行時に解決される。
関数の内側に書かれた import は、その関数が呼ばれるまで評価されない。

本件の3箇所はいずれも関数の内側にある。
そのため、存在しないモジュールを指していても
起動時にはエラーにならず、静的解析でも見逃されやすい。

実際、2397行は画像送信を試すまで表面化しなかった。
1448行と1516行は呼ばれる頻度が低く、現在も表面化していない。

我々への応用: 関数の内側に import を書く場合、
参照先が実在するかを書いた時点で確認する。
既に同じ関数を使っている箇所があれば、その import 文を写す。

## 7. 維持の仕組み

- 守り手: 人手で守る
- 理由: 関数内の import は呼ばれるまで評価されない。
  現在の静的解析は関数内の import 先の実在を検査していない。
  検査を追加するには別テーマの recon と設計が要る。
- 対象: 存在しないモジュールを参照する import が混入すること。
- 検知方法: PO による実機確認。受信箱から画像を送り、画面を見る。
