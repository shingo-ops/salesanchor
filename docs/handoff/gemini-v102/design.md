## 3. 変更
### 3-1. システムの確認と直し（--config v102 のときだけ。純粋関数。記録を残す）
- 行の役割の決め方（v10.1 §3-4）のあと、次の順に行う。直したものは件の fixes に {rule, line, detail} で記録する。
- F1 親の見出しを外す（R2）
  - 条件（すべて満たすとき）
    - ある行 X が2つ以上の件の lines にある。
    - X に発送の言葉（発送|出荷|入荷|発売）がある。
    - その全部の件で、X より後ろで自分の price_line より前に、自分だけの名前の行がある。
      - 自分だけの名前の行：ほかの件と共有しない、空でない、役割が name で、記号を除いて3文字以上、単位の別名だけではなく、発送の言葉を含まない行。
  - そうなら、X をその全部の件の lines から外す（名前にも発送にも使わない）。
  - 事前の試作（v10.1 の試験の出力、案A 147・案A 19・案B 19×2）で、この条件に当たったのは4投稿の「■…カードセット[問]発送日要相談」（各9件）だけ。
    - 外してはいけない形には当たらなかった。例：「【世界最強の戦士 OP-17】」（下が「美品」「カートン」）、「◆30th CELEBRATION Booster BOX」（下が空の行）、「🌈UNION ARENA」（発送の言葉なし）、【9/28発送】の共有。
- F2 名前の無い件に前の件の名前を付ける（R1）
  - 条件
    - 件の名前（v10.1 §3-5）から、記号・単位の別名だけの語・「数字＋単位」の語・在庫の言葉を除くと、空になる。
      - 例：「カートン /13カートン」は空になる。「151」「GD05 残3カートン」は空にならない。
    - その件の price_line のすぐ前の空でない行が、ほかの件の price_line で、そのほかの件に名前の行が無い（名前がその価格の行にある）。
  - そうなら、そのほかの件の名前（価格の行から価格・数量などを除いた残り）を、その件の名前の前に付ける。
- F3 まとめ書きの行を名前に使わない（R3）
  - 行の全体が 【…】 か ━…━ で囲まれた行は、ほかに名前の行があれば名前に使わない。
  - その行の発送の言葉は、その件の発送にしない。
- F4 数字の無い数量（R4）
  - raw_quantity に数字が無いときは、quantity_normalized を None にし、印 quantity_no_number を付ける。
  - 「完売」などの言葉は status で扱われる。
- F5 末尾の連絡の行（R5）
  - 投稿の最後の price_line より後ろの行で、件の lines に入っていて、役割が名前の行のものは、名前に使わない。
  - 印 possible_footer_line（行番号）を付ける。
  - possible_missing_item の範囲は、最初の件の最初の行から、最後の price_line まで（末尾の行は含めない）。
- F6 数量の確認の直し（R6）
  - quantity_not_in_text の判定で、数をカンマ・全角を除いた数字の並びとして比べる。「2,000」と「2000」は同じ。
  - 原文の数字の並びも、同じくカンマを除いて独立した数として探す。

### 3-2. 指示書 raw_copy_v101_c.txt（案B＋例）
- raw_copy_v101_b.txt の本文をそのまま使い、例を2つ足す。
  - 「【ガンダムカードゲーム未開封BOX】」のようなまとめ書きの行と、その下の群の見出し（「9/11発送の商品」）は、どの件にも入れない（文は試験の投稿と変える）。
  - 末尾の「・買取品」「・発送地 東京」のような連絡は、最後の件にも入れない（文は試験の投稿と変える）。
- 本文は設計者（Opus）が書く。実装担当は1文字も変えない。

### 3-3. prompt_ab
- --config v102 を足す。
  - 型と受け取りは v101 と同じ。
  - 取り出しは v101 に F1〜F6 を加えたもの。付け直し（v10.1 §3-4）は on。
  - 指示書の既定は raw_copy_v101_c。--prompt-name は ^raw_copy_v101_[a-z0-9_]+$ を使える。
- JSONL の v102 の行に v102_items と v102_flags を書く。v101 の欄は書かない。
- v7〜v101 の動きは変えない。

## 7. リスクと戻し方
- リスク：F1 が、親の見出しでない共有の行を外すおそれ。
  - 対策：条件を「全部の件に、共有ではない名前の行がある」に限る。外してはいけない形をテストに入れる。当て直しで、外した行を全件、目で確かめる。
- リスク：F2 が、別の商品の名前を付けるおそれ。
  - 対策：条件を「すぐ前の空でない行が、名前つきの価格の行」に限る。当て直しで全件、目で確かめる。
- 戻し方：この PR を revert する。
