### 3-2 自動選定タブ（A1 に式1本。人は触らない）
出す列: 商品ID, 状態, 型番, 日本語名, Item, 値段, 仕入元, 在庫数, 投稿日時, シリーズ, 発売日。

選び方（商品ID×状態の組ごと）:
1. 在庫集計のうち、商品IDが空でない・在庫 > B2・仕入元が D2 で選ばれていない・状態が F2 で選ばれていて J 列に行がある・シリーズが H2 で選ばれている・値段が数として読める行だけ残す（F2 か H2 が空なら手順5の知らせだけを出す）。
2. 組の中に在庫 ≥ B3 の行があれば、その行だけに絞る。無ければ絞らない。
3. 一番安い値段を見て、その値段＋B4 以内の行に絞る。
4. 在庫の多い順、同じなら安い順に並べ、先頭の1行を採る。
5. Item = 英語名（空なら日本語名）＋ J:K の印。
   - 印が未登録の状態（PO 2026-11-09「1」）: 選ばれた状態のうち J 列に行が無いものは、その状態の行を出さない。自動の欄の先頭に「状態『〇〇』が条件タブのJ列にありません。J列に足してください」と出す（複数あれば『』を「、」でつなぐ）。文は 11-09 の PO 承認時は「状態『〇〇』の印を登録してください」だったが、「印」が伝わらないため、何をどこに足すかが分かる文に改めた（読みやすさの直し・PO の確認待ち。戻す場合は文だけ戻す）。理由: 印を書き忘れると品名が Sealed box と重なり、請求書が違う値段を拾うため。印なしのまま出すことも、状態の名前を勝手に付けることもしない。
   - 先頭の知らせの順: 「状態を選んでください」→「シリーズを選んでください」→「J列に足してください」。前の2つが出ているときは自動の行を1行も出さない。印の知らせのときは、登録済みの状態の行は出す。
   - 確かめ: 試しのシートで、J 列に無い状態（例 Case）を選ぶ。Case の行が0行・先頭に「状態『Case』が条件タブのJ列にありません。J列に足してください」が出る・Sealed box と No shrink box の行は今までどおり出ること。

### 3-6 SA から届くマスタタブ（PO 2026-11-07「1」・SA の変更を伴う）

書く時と道:
- 配信のたび、本体の在庫集計の書き込みが成功した配信先にだけ書く（要確認タブ `_export_review_tab`（`:903-935`）と同じ置き方）。
- 書き込みは今の共通の関数 `_write_tab_sync`（`:627-700`）を使う。安全装置 #1・#3〜#5 はそのまま効く。
- 書く前にタブがあるかを見る。無ければ書かずに「タブが無いので書かなかった」を記録し、成功として扱う。Discord には知らせない。
- 記録の置き場（PO 2026-11-07「2」）: 動きの記録（ログ）だけに書く。DB は変えない（移行なし）。
  - 書き方: INFO の1行。`[dist] SAマスタタブ無しのため書かず（正常）: target=<配信先名>`。ERROR にはしない（エラーログの画面に出さない）。
  - 残る場所（実物）: 各コンテナのログは手元で 20MB×5本まで（`docker-compose.yml:182-183`・`:321-322`）。全コンテナのログは監視のサーバーへ集めている（`monitoring/promtail/promtail.yml` の `containers`）。集めたログの保存期間の設定は 30日（`monitoring/loki/loki-config.yaml:29`）。
  - 定期の配信は celery-worker で動き、ログの段階は info（`docker-compose.yml:228`）。画面からの手動の配信は backend で動く。backend で INFO が出るかは未確認なので M3 で確かめる。
- 安全装置 #2（タブを勝手に作らない）は守る。タブを作るのはお客さん側（または PO）。
- 本体のタブ（在庫集計）が無いときは、今までどおり失敗として扱う。マスタタブだけの例外。
- タブがあって書けなかったときは、要確認タブと同じく、本体の結果は変えずに Discord で知らせる。

シート側の使い方: 条件タブの状態・仕入元の選択欄は「範囲からのプルダウン」で `SAマスタ!A2:A`・`SAマスタ!B2:B` を指す。範囲が変われば選択肢も自動で変わる（Google の公式ヘルプ https://support.google.com/docs/answer/186103）。

選択欄の形（PO 2026-11-08「2」: 1つの欄で複数選ぶ）:
- 状態と仕入元の除外は、それぞれ1つの欄に「範囲からのプルダウン＋複数選択」を置く。
- スマホのアプリでは複数を選べない（Google の公式ヘルプ）。PO はこれを承知で選んだ。
- 試しのシートで確かめた事実（2026-11-08。確かめた後に値と規則は消した）:
  - 選んだ値は「, 」（カンマと空白）でつながった1つの文字になる。3つ選ぶと `Sealed box, No shrink box, "A, B co"`（`EXACT` で TRUE、長さ 36）。
  - 値の中にカンマがあると、その値は `"` で囲まれる（画面の知らせ「カンマを含むデータ値は引用符で囲みます。」）。
  - 「プルダウン（範囲内）」にも「複数選択できるようにする」がある。
- 式での見分け方（1行ずつ、在庫集計の値 c が選ばれているか）: `LET(t,IF(ISNUMBER(FIND(",",c)),""""&c&"""",c),ISNUMBER(FIND(", "&t&", ",", "&選択欄&", ")))`。
  - 試しの結果: `A, B co`→TRUE、`A`→FALSE（`A, B co` の一部でも当たらない）、`Sealed box`→TRUE、`Damaged sealed box`（選んでいない）→FALSE。
  - `FIND` は大文字小文字を区別する。値の元は在庫集計とマスタタブで同じ DB なので、書き方は一致する。
- 値の中の `,` と `"`: 2026-11-09 に本番 DB を読み取り専用で数え、状態24・仕入元241・シリーズ18 のどれにも0件。値に入るようになったら見分ける式を見直す。
- シリーズ（PO 2026-11-08「1」）: 状態と同じく1つの欄で複数を選ぶ。選択肢は `SAマスタ!C2:C`。見分け方は状態と同じ式。
  - 並び順は、選んだ順ではなく `SAマスタ` C 列の行の順（DB の `sort_order`）に従う。複数選択の値の中の順番が「クリックした順」か「範囲の順」かはまだ確かめていない。そのため、その順番には頼らない。§3-2 手順6 はこの順に読み替える。
  - 空なら、自動の行は1行も出さず「シリーズを選んでください」と出す。状態とシリーズの両方が空なら「状態を選んでください」を先に出す。
- 空の欄の意味: 仕入元の除外が空なら、だれも外さない。
- 状態が空のとき（PO 2026-11-08「1」）: 自動の行は1行も出さない。見積もり用の自動の欄の先頭に「状態を選んでください」と出す。すべての状態や決めた2つに読み替えない。理由: 消し忘れや操作ミスで、意図しない状態（傷ありの箱など）の値段が載るのを防ぐ。
  - 確かめ: 試しのシートで状態の欄を空にし、自動の行が0行・先頭に「状態を選んでください」が出ること。手入力の行はそのまま出ること。

### 7-8 ワンピースを型番の頭（OP・EB・ST）でまとめる（2026-11-10・PO 決定）
- PO の言葉: 「ワンピースだがOP，EB、STでグループごとにまとめてほしいと要望があった、切り替えの機能は持たせられる？」→ 選択肢に「1」（OP・EB・ST のどれにも入らない行は最後に「その他」として新しい順）。続けて「ワンピースのグループのまとめは関数で対応できる？自動選定の時点もしくはワンピースタブに入るときにグループでまとめたい」。

  - U3「並び」/ V3 プルダウン「発売日順」「型番の頭でまとめる」。
