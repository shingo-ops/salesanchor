# design: 見積シートへの自動反映（段階3）

状態: 設計案（PO 未承認）／作成: 2026-11-07 Claude Opus
参照: [recon.md](./recon.md)、ADR-1066（配信15列＋商品ID）

## 1. 目的と利用者に見える変化
- 目的: のりゆきさんが見積もり用タブに手で値段を打つ手間をなくす。SA が配った在庫集計から、商品名と値段が自動で並ぶ。
- 変更前: 見積もり用の A〜E は手入力。値段は人が在庫集計を見て決める。
- 変更後: 見積もり用の A〜E は式で埋まる。同じ商品・同じ状態は、条件タブの決まりに合う1件だけが出る。条件の数字を変えると、その場で選び直される。

### PO 決定（このセッション）
| 決定 | PO の答え |
|---|---|
| GAS でなく関数で作る | 「2」 |
| 手で書く行は別タブに置き、自動の行のすぐ下に積む | 「1」 |
| 商品名は英語名＋状態の印。英語名が空なら日本語名。請求書の探す範囲を広げる（古い名前の請求書は空になってよい） | 「1」 |
| 見積もり用には条件に合う商品をすべて並べる（伊藤さんが選んだ商品だけに絞らない） | 「2」（2026-11-07） |

## 2. 対象と対象外
- 対象: お客さんの Google シート（まず PO の写し「開発_見積もり のコピー」で試す）。タブ「条件」「自動選定」「手入力」を新しく作り、「見積もり用」A2 と請求書タブ G 列の式を変える。
- 対象外: SA のコード・DB・配信の仕組み（ADR-1066 のまま）。見積もり用 G〜O 列（今も空）。為替タブ。

## 3. 作り（4つのタブ）

### 3-1 条件タブ（人が数字を変える場所）
| セル | 中身 | 最初の値 |
|---|---|---|
| A2 / B2 | 在庫がこの数以下は使わない | 10 |
| A3 / B3 | この数以上の在庫がある申し出があれば、その中だけから選ぶ | 50 |
| A4 / B4 | 一番安い値段からこの差以内なら、在庫が多いほうを選ぶ | 100 |
| D1, D2:D | 使わない仕入元（1行に1人） | 空 |
| F1, F2:F | 見積もりに出す状態 | Sealed box / No shrink box（今の見積もり用に出ている2つ。recon §2-1） |
| H1, H2:H | 出すシリーズ（空なら全部） | ポケモン / ワンピース（今の見積もり用に出ている2つ。recon §2-1） |
| J1:K1, J2:K | 状態ごとの名前の後ろにつける印 | Sealed box→空 / No shrink box→` no shrink`（今の D8 `Storm Emeralda  no shrink` などの書き方に合わせる） |

### 3-2 自動選定タブ（A1 に式1本。人は触らない）
出す列: 商品ID, 状態, 型番, 日本語名, Item, 値段, 仕入元, 在庫数, 投稿日時, シリーズ, 発売日。

選び方（商品ID×状態の組ごと）:
1. 在庫集計のうち、商品IDが空でない・在庫 > B2・仕入元が D 列に無い・状態が F 列にある・シリーズが H 列にある（H が空なら全部）・値段が数として読める行だけ残す。
2. 組の中に在庫 ≥ B3 の行があれば、その行だけに絞る。無ければ絞らない。
3. 一番安い値段を見て、その値段＋B4 以内の行に絞る。
4. 在庫の多い順、同じなら安い順に並べ、先頭の1行を採る。
5. Item = 英語名（空なら日本語名）＋ J:K の印。
6. 全体を、条件タブ H 列に書いたシリーズの順（H が空なら文字の順）、同じシリーズの中は発売日の新しい順に並べる。文字の並び順に頼らないため（PO 2026-11-07 の問いを受けて）。

式（在庫集計の値は文字なので `VALUE()` で数に直す。recon §6）。**改行を入れずに1行で貼る**（セルに打つと改行で入力が終わる。2026-11-07 試しのシートで「=LET(」だけが入り解析エラーになった）:
```
=ARRAYFORMULA(LET(src,FILTER('在庫集計'!A2:O,'在庫集計'!O2:O<>""),lo,'条件'!B2,big,'条件'!B3,tol,'条件'!B4,ex,IFERROR(FILTER('条件'!D2:D,'条件'!D2:D<>""),"#なし#"),st,FILTER('条件'!F2:F,'条件'!F2:F<>""),sr,'条件'!H2:H,pr,IFERROR(VALUE(CHOOSECOLS(src,7)),-1),qt,IFERROR(VALUE(CHOOSECOLS(src,8)),0),keep,(pr>=0)*(qt>lo)*ISNA(MATCH(CHOOSECOLS(src,11),ex,0))*ISNUMBER(MATCH(CHOOSECOLS(src,6),st,0))*((COUNTA(sr)=0)+ISNUMBER(MATCH(CHOOSECOLS(src,13),sr,0))>0),d,FILTER(HSTACK(src,pr,qt),keep>0),keys,UNIQUE(CHOOSECOLS(d,15,6)),head,{"商品ID","状態","型番","日本語名","Item","値段","仕入元","在庫数","投稿日時","シリーズ","発売日"},body,REDUCE(head,SEQUENCE(ROWS(keys)),LAMBDA(acc,i,VSTACK(acc,LET(grp,FILTER(d,CHOOSECOLS(d,15)=INDEX(keys,i,1),CHOOSECOLS(d,6)=INDEX(keys,i,2)),grpa,FILTER(grp,CHOOSECOLS(grp,17)>=IF(MAX(CHOOSECOLS(grp,17))>=big,big,0)),mn,MIN(CHOOSECOLS(grpa,16)),grpb,FILTER(grpa,CHOOSECOLS(grpa,16)<=mn+tol),best,CHOOSEROWS(SORT(grpb,17,FALSE,16,TRUE),1),en,INDEX(best,1,5),jp,INDEX(best,1,4),sfx,IFERROR(VLOOKUP(INDEX(best,1,6),'条件'!J2:K,2,FALSE),""),HSTACK(INDEX(best,1,15),INDEX(best,1,6),INDEX(best,1,3),jp,IF(en="",jp,en)&sfx,INDEX(best,1,16),INDEX(best,1,11),INDEX(best,1,17),INDEX(best,1,1),INDEX(best,1,13),INDEX(best,1,12)))))),picked,CHOOSEROWS(body,SEQUENCE(ROWS(body)-1,1,2)),sl,IFERROR(FILTER(sr,sr<>""),"#なし#"),so,IFERROR(MATCH(CHOOSECOLS(picked,10),sl,0),999),IFERROR(VSTACK(head,SORT(picked,so,TRUE,10,TRUE,11,FALSE)),head)))
```
- 2026-11-07 の試しで直した2点（観測）:
  - `ARRAYFORMULA` で全体を包む。包まないと LET の中の `VALUE(CHOOSECOLS(...))` や比べる式が1つの値しか返さない（`SUM(--(pr>=0))` が包まないと 1、包むと 88）。
  - LET の名前にセル番地と同じ形（`g2`・`g3`）を使わない。`#NAME?`「関数 LET の引数 3 は有効な名前ではありません。」になる。`grp`/`grpa`/`grpb`/`best`/`picked` に替えた。
  - 旧い式は途中のエラーを `IFERROR` が隠し、見出しだけ・見出しの繰り返しが出ていた。
- 列の番号: 在庫集計の 1〜15 ＋ 16=数にした値段、17=数にした在庫。
- 残る行が0件のときは途中がエラーになり、最後の `IFERROR(…, head)` で見出しだけ出す。

### 3-3 手入力タブ
- A 型番 / B 日本語名 / C 状態 / D Item / E 値段。見出しは1行目。状態は空でもよい（PO 2026-11-07「2」で状態の列を追加）。
- 今の見積もり用 96〜106行目（特別な箱とカードのまとめ売り、11行）を写す。
- 行を足せば見積もり用の自動の行の下に出る。

### 3-4 見積もり用（状態の列を Item の左に足す・A2 は式1本で1行で貼る）
- 列: A NO / B 型番 / C 日本語名 / **D 状態**（PO 2026-11-07「2」）/ E Item / F Unit price。
- 手順: 見積もり用の D 列を右クリック →「左に1列挿入」→ D1 に `状態`。列の挿入で、同じファイルの中で見積もり用を指す式（請求書 G 列・P 列の式）はシートが自動で1列ずらす（試しのシートで観測: `'見積もり用'!$D:$E` → `$E:$F` に変わり、`Aura Seeker` で 11000 が出たまま）。
- 手入力タブも C 列の左に1列挿入して C1 に `状態`。
```
=ARRAYFORMULA(LET(auto,IFERROR(FILTER(CHOOSECOLS('自動選定'!A2:K,3,4,2,5,6),'自動選定'!A2:A<>""),{"","","","",""}),hand,IFERROR(FILTER('手入力'!A2:E,'手入力'!D2:D<>""),{"","","","",""}),both,VSTACK(auto,hand),rr,FILTER(both,CHOOSECOLS(both,4)<>""),IFERROR(HSTACK(SEQUENCE(ROWS(rr)),rr),"")))
```
- Item の後ろの状態の印（J:K）は残す。請求書は Item 名だけで値段を探すため、同じ商品の未開封とシュリンクなしを名前で分ける必要がある。
- 【未確認】公開の価格表が IMPORTRANGE で見積もり用を読んでいる場合、その範囲は文字で書かれているので列の挿入では自動でずれない。伊藤さんに確かめる。
- 列を挿入したあと、A2:F106 の今の値・式を消す（残っていると式が広がれず `#REF!` になる）。
- 消す前に見積もり用タブを丸ごと複製し「見積もり用_元」として残す（戻し方）。

### 3-5 請求書タブ G 列
- 列の挿入のあとは `'見積もり用'!$E$1:$F$107` になっている。これを `'見積もり用'!$E:$F` に替える（G4:G24 の21セル）。行が107を超えても探せる。

## 4. 影響範囲
- 見積もり用 A2:E106 の手入力の値はすべて式の結果に置き換わる。`ask` の9行と「-1000」の8行の決まりは消える。手で残したい行は手入力タブへ移す。
- 今の94行のうち、配信データで埋まるのは75行。残り19行は自動では出ない（recon §7）。要る行は手入力タブに足す。
- 並ぶ件数は今の94行から111件に増える（2026-11-06 のデータ。recon §7）。
- Item の名前が変わる（例: `Aura Seeker (Nov27)` → `Aura Seeker`）。古い名前で作った請求書は G 列が空になる（PO 承認済み）。
- P71:P95 の式は D 列を参照する。行の中身が変わるので、出る文字も変わる（用途は未確認）。
- 公開の価格表が見積もり用を IMPORTRANGE で読んでいる場合、範囲が固定なら下の行が届かない（未確認）。

## 5. 代替案と選んだ理由
| 案 | 結果 |
|---|---|
| GAS で配信を検知して書く | 不採用。API の書き込みではトリガーが動かない（recon §4） |
| GAS を時間で回す | 不採用。PO が関数を選んだ（「2」）。遅れが出る |
| 関数（本案） | 採用。配信のたびにその場で選び直る。サーバーも鍵も要らない |

## 6. リスクと対処
| リスク | 対処 |
|---|---|
| SA が書くとき一瞬タブが空になり、見積もり用が手入力の行だけになる | 数秒で戻る。請求書を作る作業とぶつかったら開き直す。運用の注意として伊藤さんに伝える |
| 請求書の値段が配信のたびに変わる（G 列が生きた式のため） | 送った請求書は「値だけ貼り付け」で固める。伊藤さんに伝える |
| 同じ Item 名が2つの商品に出ると VLOOKUP は上の1つを拾う | 受入条件 K7 で重複0を確かめる。出たら印で分ける |
| 在庫集計の値が文字 | 式で `VALUE()` を通す。数にできない値段の行は使わない |
| 行が多くて式が重い | 在庫集計1383行・組は数百。K9 で表示の時間を測る |

## 7. 受入条件と確かめ方
数字の例は 2026-11-06 の写しのデータ（recon §2-3）。
| # | 基準 | 確かめ方 |
|---|---|---|
| K1 | ハドウシーカー Sealed box の値段が 11,000（在庫50の申し出） | 条件が 10/50/100 のとき自動選定タブを見る |
| K2 | 同じ商品ID×状態は1行だけ | 自動選定で `=COUNTA(A2:A)-ROWS(UNIQUE(FILTER(A2:B, A2:A<>"")))` が 0 |
| K3 | B3 を 200 にすると K1 の行が 13,000（在庫1440の申し出） | 数字を変えて見る。戻す |
| K4 | D2 に K1 で選ばれた仕入元の名前を入れると K1 の行が 11,800（在庫100の申し出） | 入れて見る。消す |
| K5 | 手入力の11行が自動の行のすぐ下に出る。手入力に1行足すと増える | 見積もり用の最後の行を見る |
| K6 | 請求書で108行目より下の Item を入れると値段が出る | E 列に名前を入れて G 列を見る |
| K7 | 自動の行で Item が空の行0・同じ Item 名の重複0 | 見積もり用で数える式 |
| K8 | 英語名が空の商品は日本語名で出る | 英語名が空の商品を1つ選んで見る |
| K9 | 条件を変えてから表示が変わるまで10秒以内 | 時計で測る |

### 7-1 試しのシートでの結果（2026-11-07・PO の Drive の新しい試しのシート。伊藤さんのシートと PO の写しは触っていない）
- 入れたデータ: 在庫集計 88行（2026-11-06 の写しから抜き出し）、条件 10/50/100・状態2つ・シリーズ2つ。
- 自動選定: 8行が出た。先頭が ハドウシーカー（商品ID 466045）Sealed box 11,000・在庫50 → **K1 ○**。
- 見積もり用: 自動の8行の下に手入力の1行（SR 100cards 41,000）が続き、NO が 1〜9 → K5 の前半 ○。
- 請求: E4 に `Aura Seeker` → G4 に 11000 が出た。
- 状態の列（PO「2」）: 見積もり用 D 列に Sealed box / No shrink box が出た。手入力の行は状態が空のまま出た。列の挿入のあとも請求 G4 は 11000。
- 7行目と8行目の Item がどちらも `TWO LEGENDS`（商品ID 68 と 83）→ **K7 ×**（§9 のとおり商品マスタの英語名を直すまで）。
- K2〜K4・K6・K8・K9 はまだ試していない。

## 10. 維持の仕組み
- 条件の数字・除外・状態・シリーズは伊藤さんが条件タブで変える。式は触らない。
