## 2. design（実現方針）

### 2-1. 骨組み（親子の木） — 図: ./parent-child-structure.svg

あるべき姿 → KGI →（recon / KPI / 進捗表 / design）→（実装計画書 / 実装計画進捗表）。
双方向リンク: 親には「子の一覧」、子には「親への戻り札」を必ず置く。

### 2-2. 維持のしかた — 図: ./ci-gate-and-maintenance.svg

- 関所（CI）が強制するのは「親リンクが在るか」の骨組みだけ。文言（1行説明の書き方等）は軽い規約のまま。
- 再マージの近道: あるべき姿・KGI・recon・design・KPI は書き直さない。実装計画書に1行足すだけで、既存 design に紐づけ再提出 → 関所は親リンク確認 → 緑。手間は増えず、変更履歴が実装計画書に残る。

## 3. やること / やらないこと

- やる: ⑤正本に1節追記（親子双方向リンク＋1行説明を必須手順化・お手本参照）／③子文書にも1行説明。
- やらない: ①②④は達成済みで触らない。他テーマ文書への一斉展開なし（ビッグバン禁止）。

## 4. 関所育成（別便・危険変更）
