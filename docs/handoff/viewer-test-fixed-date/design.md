# 設計 — 閲覧ページの試験の固定日時をやめる

**日付**: 2026-10-17　**現在地**: docs/handoff/viewer-test-fixed-date/recon.md　**ADR**: ADR-1019（閲覧ページ。この ADR の決定は変えない）

## 目的
日付が変わると CI が必ず落ちる状態をなくす。今は、backend を変える PR がすべて止まっている。

## 変更
両方の試験で、固定日時を `(datetime.now(timezone.utc) - timedelta(hours=1)).replace(microsecond=700000)` にする。試験の狙いは変えない。狙いは「password_changed_at が .700 秒のとき、同じ秒の iat は通り、1 秒前は 401 になる」こと。アサーションも変えない。

触らないもの: 製品コード、ほかの試験。

## 受入条件
| 基準 | 検証方法 |
|---|---|
| 対象の 2 本が日付に関係なく緑 | 手元で変更前は 2 failed、変更後は 34 passed（/tmp/CC報告ファイル/viewer-test-date/after.txt）。CI の Backend Tests が緑 |
| 製品の動きは変わらない | 差分が backend/tests の 2 ファイルだけ |

## 外部・過去事例の参照と我々への応用
- 過去事例（社内）: 今回の 2 本は、固定日時と有効期限つきのトークンを組み合わせていた。そのため、作った翌日に落ちた。
- 応用: 有効期限を調べる試験では、基準の時刻を「今」から作る。

## 維持の仕組み
- 見張り: CI の Backend Tests が毎回この 2 本を走らせる。
- 担当: 閲覧ページの試験を変える PR を設計する Opus。

## 戻し方
PR を Revert する。

## 審査（Opus 自己審査・同一 AI）
APPROVE。試験の基準時刻だけを変える。試験の意味と製品の動きは変わらない。
