# 画面を使わず解析・配信へ接続する
この文書は、既存の確認・解析・配信処理を管理操作から使う方法です。
親: [商品マスタ](../../specs/product-master/README.md)
現在地: [recon](recon.md)（docs/handoff/line-import-delivery/recon.md）。ADR-072 / ADR-154を維持。

## 範囲
KGIは、対象取込の確認→確定→抽出/解析の観測→指定済み配信先の更新結果を実測で確認すること。今回ユーザーは配信までの接続を依頼。未登録仕入先の同一性と実送信先は確認待ち。
Termuxのキー権限は増やさず、管理者workflowに用途限定CLIを追加。device_idで有効な既存super-admin所有者を検証し、import_job_idのuploaded_by一致を検査する。任意SQL/コマンドは受け付けない。
inspectはDB読み取り専用。氏名/本文/シートIDを公開ログへ出さず、未解決名のSHA256と集計を返す。名前は端末の原本とハッシュで照合できる。
commitは既存関数を呼び未解決者があれば停止。createは明示指定の名前ハッシュ1件のみ、対象jobの名前集合から特定して既存登録処理を呼ぶ。自動で全員登録しない。assignは既存マスタ名を上書きするため提供しない。
distributeは対象取込の完全な進捗・未完了/エラー/要確認0・結果欠落0・有効原文の存在を確認後、必須target_idへ既存run_distributionを呼ぶ。配信範囲は既存全体集計であることを明示確認値で要求。既存安全装置を維持し、自動再試行はしない。既存配信は外部clear/appendの2操作であり途中失敗時には結果不明として照合する。
ユーザーがPR #3447提示後に「確認後マージしたらスマホから送信して配信まで完了できるかテストして」と明示承認。最終CI確認後にコード反映する。新しいDB/フロント/端末API変更はない。

## 外部・過去事例の参照と我々への応用
PR #3445で既存SSH手動workflowによる端末登録と実ファイル2件受付を実証。同じ経路に固定の既存関数呼出しを追加する。新規外部ライブラリやプロトコル採用なし。

## 維持の仕組み
- 守り手: backend/tests/test_line_import_admin.py
- 人手で守る: 未登録名の同一性、配信対象の承認、外部書込失敗時の照合。自動再送・安全装置解除をしない。

## 名前の出力形式差の実物照合
ユーザーは39名がAndroid/PC形式差か真の未登録かの確認を依頼。推測で登録しない。inspectへ任意のRSA4096公開鍵を渡すと、未照合名・全仕入先名/有効性・配信先情報をAES256-GCMで暗号化し、その鍵をRSA-OAEP SHA256で包んで返す。既存cryptography依存を使用。秘密鍵は端末外へ出さない。公開ログに平文の名簿は出さず、端末内で復号・比較する。
