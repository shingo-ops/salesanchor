## 目的
本番サーバー（prod1）はお客さんにアプリを出す仕事だけをする。重い組み立ては GitHub でする。完成品は会社の組織アカウント（GEN-RYU-System）の非公開の倉庫にしまい、本番は指紋（sha256）で受け取って並べるだけにする。

## 成功条件（PO が画面・出力で ○× を付けられる形）
| # | 基準 | 測り方 |
|---|---|---|
| K1 | 本番への入れ替え1回の記録に、本番サーバー上の組み立て（`docker compose build`・`docker build`）が 0 回 | 切り替え後の入れ替え 10 回の GitHub の実行記録を数える |
| K2 | 完成品は GEN-RYU-System の倉庫にあり、公開になっているものが 0 個 | 倉庫の一覧（`gh api`）で見える状態を全件数える |
| K3 | 本番で動く自前の箱は、すべて指紋（`@sha256:`）指定で受け取ったもの | 本番の箱の一覧と、入れ替え手順の書き方を数える |
| K4 | 外部の人の変更の提案では、組み立ても倉庫への書き込みも動かない | 動く条件の書き方を読む・試しの提案で実行が 0 件 |
| K5 | 空きメモリの1日平均が、係を入れ直した後 7 日続けて MemTotal の 30% 以上（約 1,170MiB 以上） | Grafana の Prometheus（読み取り）の1日平均 |
| K6 | 1つ前の完成品へ戻す時間が 2 分以内で、戻すときも組み立て 0 回 | 戻しの練習を1回して記録を読む |
| K7 | 非公開の置き場の自動作業が、月の無料枠（約 2,000 分）の中に収まる | 30 日分の実行時間の合計 |
| K8 | 入れ替え1回の時間（中央値）が、今の 3.1 分より長くならない | 切り替え後 30 回の中央値 |
