## 結果

### 移行の接続の行（`-U` を文で探した）
`scripts/run_all_migrations.sh:25`
```
PSQL="psql -U jarvis -d jarvis_db -v ON_ERROR_STOP=1"
```
`run_sql`（:119 付近）は `docker exec ... -i "${POSTGRES}" ${PSQL} < "${REPO_DIR}/${file}"` でこの変数を使う。ほかに `-U` が出るのは :165 の read-probe（`-U jarvis -d jarvis_db`、読み取りのみ）だけ。
run_py は `-e DATABASE_URL="${ADMIN_DATABASE_URL:-$DATABASE_URL}"`（:84-85）で接続する（利用者名は URL の中。本便では値を読まない）。

### スキーマを作る文
`migrations/20261017_130100_create_ai_ro_views.sql`
```
:8  DROP SCHEMA IF EXISTS ai_ro CASCADE;
:9  CREATE SCHEMA ai_ro;
```
:2 のコメント「持ち主は実行ユーザー（run_sql の jarvis）のまま」。この SQL は毎回の `_ai_ro_create_on_exit`（run_all_migrations.sh:230 付近）で流れる。
同種: `migrations/20261024_100000_create_ai_cloud_meta.sql:10` `CREATE SCHEMA IF NOT EXISTS ai_cloud_meta;`、`migrations/20261031_210000_create_ops_case.sql:9` `CREATE SCHEMA IF NOT EXISTS ops_case;`

## 合否の線
- 利用者の名前: `jarvis`（SQL の移行）。run_py は `ADMIN_DATABASE_URL`（無ければ `DATABASE_URL`）。
- スキーマを作る文の引用: 上のとおり（`CREATE SCHEMA ai_ro;` は :9。設計の「:9」と同じ位置）。
- 設計の根拠（本番で毎回通っている事実）の突き合わせは Opus の本番読み取りで行う。ここでは未確認。
