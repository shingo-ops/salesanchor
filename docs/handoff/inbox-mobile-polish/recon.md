# recon: スマホの受信箱が「チープに見える」原因の特定（現状把握）

調査日 2026-10-13 / ブランチ `release/inbox-mobile-polish`（`origin/main` 起点）

PO 指摘: 「WhatsApp とくらべてチープ感があるのだがプロっぽくできる？金型のデザインが悪い？」
PO 選択: 適用範囲は「受信箱・スマホだけで試す」（2026-10-13）

## 0. 測り方（印象ではなく画素）

実機（1080x2340 @480dpi＝360 CSS px・ライトモード）で本番の受信箱を撮影し、本文領域（`y=111-2130`）の画素を2px間隔で数えて色ごとの面積比を出した。**Chrome の翻訳案内（私たちの UI ではない）が `y=200-580` を覆っていたため、その範囲は集計から除外**した。お手本の数値は既に記録済みの実測（`docs/specs/design-system/visual-language/benchmark/whatsapp-color-structure.md`）を使う。

## B. 原因の特定（画素の位置まで追った）

| # | 事実 | 根拠 |
|---|---|---|
| B1 | ページの地が出ているのは**一覧の最後の行より下**（`y=1431〜2125`＝**231dp**）と**左端の列（全高）** | 画素分布の測定（`--bg-primary` がほぼ全幅を占める帯は この2箇所のみ） |
| B2 | 左の帯の出どころは `frontend/src/pages/inbox/InboxPage.css` の `.inbox-wrapper` にある `padding-left: var(--space-3)`（コメントに「他ページと揃える 12px 左余白」と明記） | 同ファイルの `.inbox-wrapper` 規則 |
| B3 | 行は `[36,291]-[1080,519]`＝**左12dp・右0** の非対称。行の要素自体（clickable=true）の座標 | 実機の構造データ |
| B4 | 下の帯の出どころは、一覧の面（`.inbox-left-panel`・基底で `background: var(--bg-surface)`）が**画面の高さまで伸びていない**こと。`.inbox-wrapper` の `height: 100%` が親まで届いていない | 基底の `.inbox-wrapper { height:100% }` / `.inbox-main-area { flex:1 }` / `.inbox-columns { flex:1 }` は揃っているが、実測では面が内容の高さで止まっている |
| B5 | 12px の副文字は `.conv-time` と `.conv-preview-text` が `--text-muted` を使っている | `frontend/src/pages/inbox/InboxPage.css` の該当規則（`--text-muted` は `frontend/src/index.css:25` の `#718096`） |
| B6 | 会話の吹き出しは受信が**純灰**、送信が**紫**。テーマの強調色はネイビー（`frontend/src/index.css:33` の `--accent`） | `frontend/src/index.css:101-102` の `--bubble-inbound-bg` / `--bubble-outbound-bg` ＋ `frontend/src/pages/inbox/InboxPage.css:521,527` での参照 |
| B7 | 受信の吹き出しは画素で **9.9%** を占め、他の面（青みがかった灰）と色の系統が違う（純粋な灰色） | 会話画面の画素測定。位置 `y=567-815`・`x=84-888` |
| B8 | 会話画面の地も**覆われていない領域のページ地**（`.inbox-messages` に背景指定は無い） | `.inbox-messages` 規則（flex/overflow/padding のみ） |

## C. 自分の初期診断の誤りと訂正

| # | 誤り | 事実 |
|---|---|---|
| C1 | 「強調色が使われていない」 | **誤り**。未読バッジは既にネイビー（`.conv-unread-badge { background: var(--accent) }`）。強調色が0%だったのは**いまの本番データに未読が1件も無いため**（構造データで未読バッジ0件を確認）。ただし一覧画面には未読以外に強調色を持つ要素が無く、FAB も無いため、**未読が無いときは画面に芯が無い**状態になるのは事実 |
| C2 | 「行の左右が非対称」は文字の枠かもしれない | **非対称は実在**。行の要素（clickable=true）自体が `[36,...]-[1080,...]`（B3） |

## D. 「金型のデザインが悪いのか」への答え（事実ベース）

**形（寸法・構造）はお手本と一致している**: 行の高さ76dp・区切り線なし・行全体が押せる（A の下3行）。**悪いのは色の決まり（トークンの割り当て）**で、形ではない。

ただし次の2点は残る:
- 受信箱の行はまだ金型（`ListRow`）に置き換わっていない（ADR-144 §5 で移行は別トラック）。同じ直しを将来2箇所に入れる必要がある。
- 吹き出しの紫は PC 側が ADR-064（Meta 完全再現・Accepted）の範囲。**スマホのみ変更**とし、PC は触らない。
