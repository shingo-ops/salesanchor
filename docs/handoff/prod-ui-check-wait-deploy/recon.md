## 0. 既存 ADR の検索

- `git grep -n "配備中のため見送り\|見送り" origin/main -- docs` と `docs/adr/README.md` の一覧で探した。この件を決めているのは ADR-1051 だけ。
- `docs/adr/ADR-1051-prod-ui-black-box-check.md:27`「配備（deploy.yml）が動いている間は 10 分待って 1 回だけ確かめ直し、まだ動いていれば見送る（不合格にしない）。」← 本件で改訂する行。
- ADR-1053（全画面の速さを毎日記録する）: 速さの記録は毎朝の点検の中でだけ動く（§1-4）。

## 1. 今の作り（観測事実）

- `.github/workflows/prod-ui-check.yml:8-9` 毎朝の起動は `cron: "0 22 * * *"`（JST 07:00）。
- `.github/workflows/prod-ui-check.yml:11-14` 配備（Deploy to VPS）が終わったときにも起動（workflow_run）。
- `.github/workflows/prod-ui-check.yml:26-28` `concurrency: group: prod-ui-check / cancel-in-progress: false`。同時に動くのは 1 本。
- `.github/workflows/prod-ui-check.yml:36` 仕事の上限 `timeout-minutes: 60`。
- `.github/workflows/prod-ui-check.yml:38-61` 「配備中の確認」: deploy.yml の in_progress・queued・waiting を数え、1 本以上なら `sleep 600`（10 分）して 1 回だけ数え直す。まだ 1 本以上なら `skip=true` と要約に「配備中のため見送り」を書き、仕事は success で終わる。
- `.github/workflows/prod-ui-check.yml:106-107` 「本番の画面点検を実行」は `skip != 'true'` のときだけ。
- `.github/workflows/prod-ui-check.yml:118-119` 不合格の知らせは `failure() && skip != 'true'`。見送りでは知らせない。
- `.github/workflows/prod-ui-check.yml:157-161` 「画面の速さを記録（判定なし）」は `skip != 'true' && event_name != 'workflow_run'`、段の上限 46 分。→ **速さの記録は毎朝（と手動）の実行でしか動かない。毎朝が見送られると、その日の速さの記録は 0 件になる。**

## 3. GitHub の決まり（Context7 `/websites/github_en_actions` で確認）

- schedule: 「GitHub Actions が混む時間（毎時 0 分を含む）は schedule が遅れることがある。十分に混むと捨てられることもある。遅れを減らすには毎時 0 分以外に置く」（events-that-trigger-workflows）。
